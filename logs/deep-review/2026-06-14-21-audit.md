## 抽检结论

### 维度 1：源码引用准确性
- 评分：5/5
- 问题数：0
- 结论：未发现 P0/P1 源码错误。
- 复核点：
  1. AVD 线程退化链路仍可在 AOSP `android-16.0.0_r1` `AnimatedVectorDrawable.java` 定位：`draw(Canvas)` 中 `!canvas.isHardwareAccelerated()` + `VectorDrawableAnimatorRT` + `mPendingAnimationActions` 触发 `fallbackOntoUI()`；`forceAnimationOnUI()` 直接切 UI 线程。
  2. `PowerManager.addThermalStatusListener()`、`OnThermalStatusChangedListener`、`THERMAL_STATUS_MODERATE/SEVERE` 和 `IThermalService` 字段仍在 AOSP `android-16.0.0_r1` `PowerManager.java` 中，章节未把热状态 API 写成不存在的 `ThermalManager`。
  3. `View.LAYER_TYPE_HARDWARE` / `setLayerType()` / `buildLayer()` 在 AOSP `android-16.0.0_r1` `View.java` 中存在，硬件层缓存表述成立。
  4. SF CLIENT 合成链路仍能在 AOSP `android-16.0.0_r1` 中定位：`SurfaceFlinger::composite()` 调用 `CompositionEngine::present()`，再到 `Output::present()` / `composeSurfaces()` / `RenderEngine::drawLayers()`；`OutputLayer::requiresClientComposition()` 以 `Composition::CLIENT` 判断客户端合成。

### 维度 3：版本差异覆盖
- 评分：4.5/5
- 问题数：0（P0/P1）
- 结论：未发现需要回炉的版本错误。
- 复核点：
  1. SurfaceFlinger 版本入口与正文一致：Android 10 `handleMessageRefresh()`，Android 11/12 `onMessageRefresh()`，Android 13+ `SurfaceFlinger::composite()`。
  2. `ComponentCallbacks2` 的 Android 14+ 边界成立：AOSP `android-16.0.0_r1` 已标注 `TRIM_MEMORY_RUNNING_*` 等旧等级自 API 34 起不再通知 App；章节代码只依赖 `TRIM_MEMORY_UI_HIDDEN`，未误用旧 running trim level。
  3. Android 官方 cached-apps-freezer 文档当前写明 Android 14+ cached 进程进入 cached state 后 10 秒冻结。正文 L532 写“10-30 秒内冻结进程”偏宽，但带“可能”口径，且不影响本节关于清理窗口不可依赖异步任务的结论；本轮记为 P3 口径收紧建议，不写 queue / suggestions。
  4. `android-17.0.0_r1` tag 本轮在 `frameworks/base` / `frameworks/native` 未查到；本轮未使用 main/master 作为正文结论，也未引入 Android 18 / API 38+ 内容。

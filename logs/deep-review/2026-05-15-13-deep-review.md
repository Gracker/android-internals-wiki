## 详细问题单

### P0
1. **[原理断裂/源码准确性] L125-L132** — 正文写成对象不可达后才包装成 `FinalizerReference`。AOSP `FinalizerReference.java` L33-L45、L60-L69 显示，finalizable 对象进入堆时已经被 `FinalizerReference.add()` 加入链表；GC 后续只是把 referent 移到 zombie 并把既有 reference 挂到 `ReferenceQueue.unenqueued`。建议改成“注册 → GC referent→zombie → enqueuePending → doFinalize”的链路。

### P1
1. **[原理断裂] L82-L83、L169、L299-L330** — Cleaner 路径未区分：`sun.misc.Cleaner` 在 `ReferenceQueue.enqueuePending()` 中由 RQD 直接 `cl.clean()`；`java.lang.ref.Cleaner.Cleanable` 在 `FinalizerDaemon.processReference()` 中 `doClean()`。建议补 daemon / 方法 / API 对象对照表。
2. **[版本差异] L244、L295、L299、L321-L330** — 适用范围覆盖 Android 8-16，但 `android.util.CloseGuard` Added in API 30，`java.lang.ref.Cleaner` Added in API 33。建议补 API 26-29、30-32、33+ 的治理方案边界。

### P2
1. **L119** — `remove()` 等待期间释放 monitor，表述需改。
2. **L283-L285** — watchdog 行号与 ReferenceQueueDaemon 连续超时阈值需补。
3. **frontmatter L15-L18** — AOSP tag/path 写法需规范化。

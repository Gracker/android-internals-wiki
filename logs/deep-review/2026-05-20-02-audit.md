[P0] L514-L516 — RecyclerView 中 `ComposeView` 的 Recomposer 与释放策略写错。正文称每个 item 都持有独立 `WindowRecomposer`，并建议在 `onViewRecycled()` 主动 `disposeComposition()`。AndroidX ui-android 1.10.0 `AbstractComposeView.resolveParentCompositionContext()` 实际优先使用显式 parent context、ViewTree composition context、cached context，最后才落到 window-level recomposer；不是每个 item 独立 `WindowRecomposer`。官方 Compose-in-Views 文档与 `ViewCompositionStrategy.Default` 源码也说明，默认策略在 `RecyclerView` 这类 pooling container 中会等容器 detach 或 item discarded（pool full）时释放 composition。建议改为依赖默认 `DisposeOnDetachedFromWindowOrReleasedFromPool`，只在确认不复用/有泄漏时手动 dispose，并说明代价。

## 证据摘录
- Android Developers Blog, “What’s new in the Jetpack Compose December ’25 release”：Compose 1.10；“Pausable composition in lazy prefetch is now enabled by default”；runtime can pause work and resume next frame；适用语境是 lazy layout prefetch / CacheWindow。
- AndroidX Compose Runtime release notes：`androidx.compose.runtime:runtime-*:1.10.0` 于 2025-12-03 release；1.10.x bugfix 多次提到 pausable composition；1.10.0-alpha01 还记录 default minSdk 从 API 21 移到 API 23，未出现 Android 16 平台门槛。
- AndroidX `ui-android:1.10.0` 源码 `ComposeView.android.kt`：`resolveParentCompositionContext()` 为 `parentContext ?: findViewTreeCompositionContext()?.cacheIfAlive() ?: cachedViewTreeCompositionContext?.get()?.takeIf { it.isAlive } ?: windowRecomposer.cacheIfAlive()`。

- Android Developers “Using Compose in Views”：`ViewCompositionStrategy.Default` 在 RecyclerView 这类 pooling container 中等 pooling container detach 或 item discarded（pool full）时 dispose。

### 维度 1：源码引用准确性

[P0] L703 Java Heap Sampling — 正文把传统 Java Heap Dump 举例为 `android.app.ActivityManager.getProcessMemoryDump`。Android public API 中没有这个方法；ActivityManager 只有 `getProcessMemoryInfo(int[])` 这类内存信息接口，heap dump 应改指向 `android.os.Debug.dumpHprofData()`、`adb shell am dumpheap`、Android Studio Profiler Dump Java Heap，或本节后文的 `android.java_hprof`。 建议：删除 `ActivityManager.getProcessMemoryDump`；若要对比 Heap Dump 与 Sampling，写成 `Debug.dumpHprofData()` / `am dumpheap` / Android Studio Profiler / `android.java_hprof`。
  2. [P0] L679-L682 Native Heap Profiling 字段说明 — 正文写 `process_cmdline` 不设置则对所有进程生效。`HeapprofdConfig` proto 里全进程采样是单独的 `all: true` 字段；`process_cmdline` 为空不等于 profile all，可能导致没有目标进程被采样或行为与预期不符。 建议：改为：`process_cmdline` 限定目标进程；如确实要 profile 所有符合条件的进程，必须显式写 `all: true`，并提示 userdebug 上可能导致 heapprofd 过载/系统风险。

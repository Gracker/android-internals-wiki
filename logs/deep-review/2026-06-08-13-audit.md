## 核验证据
- AOSP `android-16.0.0_r1`：`frameworks/base/core/java/android/os/Parcel.java`
  - `Parcel` 文档仍说明它不是通用序列化机制，而是高性能 IPC transport；持久化旧 Parcel 数据可能受底层实现变化影响。
  - `writeTypedObject` / `writeTypedArray` / `writeTypedList` 与对应读取 API 仍不写入原对象 class 信息，读取方通过 `Parcelable.Creator` 明确类型。
  - `writeValue()` 文档仍把 `Serializable` 放在支持列表末尾，并说明 generic serialization 方式更低效，应尽量避免。
- AOSP `android-16.0.0_r1`：`frameworks/base/core/java/android/os/TransactionTooLargeException.java`
  - Binder transaction buffer 仍标注为 fixed size currently 1MB，并由进程内进行中的事务共享。
  - 异常仍是大事务失败的 heuristic，无法仅凭异常区分请求未发出还是响应未返回。
- 上游库文档快速复核：Gson README 的 Android 不推荐说明、Moshi Codegen 说明、FlatBuffers 直接访问序列化数据说明仍能对上章节正文。

## 问题单

### P1-1 [版本差异] ApplicationExitInfo reason API 级别差异未覆盖
- 位置：L180-L188
- 证据：Android Developers API reference 标注 `REASON_FREEZER` Added in API 33；`REASON_PACKAGE_STATE_CHANGE` / `REASON_PACKAGE_UPDATED` Added in API 34；API 34 前包更新/组件状态变化使用 `REASON_USER_REQUESTED`。
- 影响：Android 11-13 设备上的线上退出记录会被按 Android 14+ 常量口径误分组。
- 建议：补 API 30 / 33 / 34 reason 差异表，并说明历史样本迁移口径。

### P1-2 [知识盲区] Android 15 ApplicationStartInfo 缺失
- 位置：L118-L128、L253-L258
- 证据：AOSP `ApplicationStartInfo.java` 与 `ActivityManager#getHistoricalProcessStartReasons()` 提供启动历史、启动类型和时间戳；ProfilingTrigger `TRIGGER_TYPE_COLD_START` 文档引用 `ApplicationStartInfo.getStartType() == START_TYPE_COLD`。
- 影响：慢启动决策表从自有埋点直接跳到 ProfilingManager / COLD_START，缺少 Android 15 官方启动追溯入口。
- 建议：在版本能力表补 `ApplicationStartInfo`，并与 8.2 / 8.10 对齐。

### P2 建议
1. L217、L221、L261：ProfilingTrigger 常量统一写完整 `TRIGGER_TYPE_*`。
2. L219、L225：补 OOM trigger 对默认 UncaughtExceptionHandler 的依赖。
3. L217：补 `requestRunningSystemTrace(tag)` 与 `TRIGGER_TYPE_APP_REQUEST_RUNNING_TRACE` 的关系。

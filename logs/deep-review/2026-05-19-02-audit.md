### 维度 1：源码引用准确性 / API 可用性

- 评分：3/5

1. [P1][版本差异/API 可用性] L305-L309 — 正文把 RSS 写成“用 `Debug.getRss()` 或 `dumpsys meminfo` 看驻留页变化”，但章节适用 Android 8.0-16。AOSP `core/api/current.txt` 在 `android-13.0.0_r1`、`android-14.0.0_r1` 中没有 public `Debug.getRss()`；`android-15.0.0_r1`、`android-16.0.0_r1` 中该方法出现，但标注 `@FlaggedApi("android.os.remove_app_profiler_pss_collection")`。因此它不能写成 Android 8-16 通用 App 侧 API。
   - 建议：拆成版本表：Android 15/16（且编译 SDK / flag 能力满足）使用 `Debug.getRss()`；Android 8-14 使用 `/proc/self/status` 的 `VmRSS`、`/proc/self/statm`、低频 `dumpsys meminfo` 或 `Debug.MemoryInfo`/PSS 作为替代；示例代码加 `Build.VERSION.SDK_INT` 守卫。

2. [P2][源码表述精度] L299-L311 — 正文仍写 `Debug.getPss()` “直接读 `smaps`”。`android-16.0.0_r1 frameworks/base/core/jni/android_os_Debug.cpp` 中 `getPssPid()` 先叠加 memtrack graphics/gl/other，再调用 `ProcMemInfo.SmapsOrRollup(&stats)` 汇总 `pss/uss/rss/swap_pss`；这不是固定直读 `/proc/<pid>/smaps`。
   - 建议：改成“`Debug.getPss()` 走 `ProcMemInfo.SmapsOrRollup()` 聚合 `smaps_rollup/smaps`，并叠加 memtrack 与 swapPss；适合低频校准，不适合高频轮询”。若保留“Android 14+ 节流/历史值”，需明确它指系统侧 PSS 采集或 ActivityManager 口径，而不是同进程 `Debug.getPss()` 一概返回缓存值。

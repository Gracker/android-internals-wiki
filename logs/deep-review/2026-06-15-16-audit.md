## 复核证据
- AOSP android-16.0.0_r1 `system/core/libprocessgroup/profiles/cgroups.json`：`blkio` controller 默认挂载 `/dev/blkio`。
- AOSP android-16.0.0_r1 `system/core/libprocessgroup/profiles/task_profiles.json`：`LowIoPriority` 加入 `blkio/background`，`SCHED_SP_FOREGROUND` 聚合 `HighIoPriority`，`SCHED_SP_TOP_APP` 聚合 `MaxIoPriority`。
- AOSP android-16.0.0_r1 `system/vold/FsCrypt.cpp` / `Utils.cpp`：`fs_prepare_user_storage()` 使用 `BuildDataSystemDePath()`、`BuildDataMiscDePath()`、`BuildDataUserDePath()` 路径生成函数。
- AOSP docs `dynamic_partitions/implement`：Dynamic Partition 由 `super` metadata + `dm-linear` + first-stage `init` 实现；launching with Android 10 且使用 dynamic partitions 的设备不得使用旧 system-as-root 口径。
- AOSP docs `fuse-passthrough` / Android Developers `shared/media`：Android 11 direct file paths 与 Android 12+ FUSE passthrough 的边界仍成立，direct file paths 随机读写可慢到约 2 倍，建议用 MediaStore。
- AOSP docs `file-based` / `metadata`：Android 10+ launching devices 要求 FBE；metadata encryption 的 `dm-default-key`、`wait_for_keymaster` 与 `/metadata` key material 口径仍成立。
- AOSP docs `virtual_ab`：Virtual A/B delta 写入 snapshot；Android 12+ compressed snapshots 使用 dm-user + snapuserd + Android COW format；Android 13+ snapshot/merge 由 snapuserd userspace component 执行；空间表显示 Virtual A/B / VABC 的额外 OTA 空间主要落在 `/data`，不是统一的 `super` 内 COW 区。

## 一手资料复核
- `packages/modules/UprobeStats` android-16.0.0_r4：`src/UprobeStats.cpp` 从 `/data/misc/uprobestats-configs/config` 读配置，经 Guardrail 允许后解析 probe；`src/Bpf.cpp` 通过 `/sys/bus/event_source/devices/uprobe/type` + `perf_event_open` + `PERF_EVENT_IOC_SET_BPF` 附加 uprobe BPF 程序；`src/Android.bp` binary 名为 `uprobestats`。
- `external/perfetto` android-16.0.0_r4：`data_source_config.proto` 存在 `ftrace_config` 与 `perf_event_config` 字段，不存在 `linux_perfetto_config` / `sys_events_config`。
- Android common kernel android16-6.12：`include/trace/events/syscalls.h` 的通用 syscall tracepoint 系统名为 `raw_syscalls`，`sys_enter` entry 提供 `id` 与 `args[6]`；`include/linux/vmalloc.h` 中 `vmalloc_noprof(unsigned long size)` 只有 size 入参，地址来自返回值。
- `frameworks/native` android-16.0.0_r4：`services/gpuservice/bpfprogs/gpuMem.c` 挂载 `tracepoint/gpu_mem/gpu_mem_total`，维护 GPU memory total map；不是 `amdgpu/amdgpu_cs_ioctl`。
- `system/bpf` android-16.0.0_r4：`loader/bpfloader.rs` 的 `main()` 调用 `load_libbpf_progs()` 后调用 `vendorBpfLoader()`；map/prog pin 到 `/sys/fs/bpf`，owner/group 按 descriptor 或 BPF 宏配置。

### 维度 1：源码引用准确性
- 评分：1/5
- 问题数：7
- 具体问题：
  1. [P0] syscall tracepoint 示例仍未修：`syscalls/sys_enter_openat` / `sys_enter_socket` / `sys_enter_sendto` 被写成 `trace_event_raw_sys_enter + ctx->args[]`，且 openat 注释把 args[0] 同时写成 syscall_nr 与 fd。

[P0] L83、L97 — `View.buildDrawingCache()` 被写成 API 28 后“基本 no-op”，并进一步写“现代 `LAYER_TYPE_SOFTWARE` 走 RenderNode 软件 layer 路径”。AOSP android-16.0.0_r1 的 `View.updateDisplayListIfDirty()` 在 `LAYER_TYPE_SOFTWARE` 下仍调用 `buildDrawingCache(true)` / `getDrawingCache(true)` 并 `drawBitmap(cache, ...)`；`View.buildLayer()` 对 software layer 也调用 `buildDrawingCache(true)`；`RenderProperties.h` 明确 `LayerType::Software` 不能直接构建 render layer，software layer 管理由 Java 侧处理。当前说法会把“应用侧 drawing cache API 已废弃”误写成“内部软件层实现不再走 Bitmap/drawing cache”。

## 证据锚点
- AOSP android-16.0.0_r1 `View.java`：`updateDisplayListIfDirty()` 中 `LAYER_TYPE_SOFTWARE` 分支调用 `buildDrawingCache(true)`、`getDrawingCache(true)` 与 `drawBitmap(cache, 0, 0, mLayerPaint)`；`buildLayer()` 的 software 分支调用 `buildDrawingCache(true)`。
- AOSP android-16.0.0_r1 `RenderProperties.h`：`LayerType::Software` 注释说明 software layer 不能直接构建，管理由 Java 侧完成。
- AOSP android-16.0.0_r1 `Surface.cpp`：`Surface::lock()` 调用 `dequeueBuffer()`、基于 `mPostedBuffer` 做 `copyBlt()` copyback、再 `lockAsync()`；`unlockAndPost()` 调用 `unlockAsync()` 后 `queueBuffer()`。

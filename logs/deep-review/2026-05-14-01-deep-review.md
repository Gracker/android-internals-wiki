## 资料复核
- AOSP android16-release：`Bitmap.java` 的构造路径保存 `mNativePtr` 并通过 `NativeAllocationRegistry.registerNativeAllocation()` 注册 native allocation；`getAllocationByteCount()` 文档说明复用 / `reconfigure()` 后可能大于 `getByteCount()`。
- AOSP android16-release：`BitmapFactory.Options#inBitmap` 文档确认 Android 4.4+ 复用条件为 decoded `byteCount <= allocationByteCount`，`Options.validate()` 会拒绝 `Config.HARDWARE` 和 `inMutable + HARDWARE` 组合。
- AOSP android16-release：`BaseCanvas` 软件渲染遇到 `Config.HARDWARE` 会抛 `IllegalArgumentException("Software rendering doesn't support hardware bitmaps")`；`ImageDecoder` 默认 immutable，通常为 `Config.HARDWARE`。
- AOSP main / libmeminfo：`android_os_Debug.cpp` 调用 `ExtractAndroidHeapStats()`；VMA 分类规则实际在 `system/memory/libmeminfo/androidprocheaps.cpp`，其中 `[heap]`、`[anon:libc_malloc]`、`[anon:scudo:*]`、`[anon:GWP-ASan*]` 归入 Native Heap，`.so/.jar/.apk` 分别归入对应 code 类统计。
- AOSP android-16.0.0_r1 ART：`Heap::ShouldAllocLargeObject()` 条件为 `byte_count >= large_object_threshold_ && (primitive array || String)`；`GetMaxMemory()` / `GetFreeMemoryUntilOOME()` 与文中堆上限口径一致。

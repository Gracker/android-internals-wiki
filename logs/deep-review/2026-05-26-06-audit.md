- 既有 P2 仍保留：L331 将 RenderEffect / Hardware Layer 的共同底层描述成 FBO，并只锚 `SkiaOpenGLPipeline::draw()`。android-16.0.0_r1 同时存在 `SkiaOpenGLPipeline` 与 `SkiaVulkanPipeline`，二者都会进入 `renderFrame()`；`RenderProperties::promotedToLayer()` 在 `mImageFilter != nullptr` 时进入 RenderLayer，`RenderNodeDrawable` 再对 layer surface 做 snapshot/filter。建议仍按既有 P2 改成 backend-dependent offscreen render target / layer surface，不把 FBO 当成跨后端通用名。

### 维度 3：版本差异覆盖
- 评分：4.0/5
- P0/P1：0
- 复核结论：Android 10/11 与 Android 12+ 的自动升层条件分界成立。AOSP android-10.0.0_r47 / android-11.0.0_r48 的 `promotedToLayer()` 包含 functor 与 alpha+overlap；android-12.0.0_r1 起加入 ImageFilter 与 StretchEffect；android-16.0.0_r1 仍保持该组合并补正宽高 > 0 条件。
- 既有 P2 仍保留：L322/L359 的 Compose 1.10 `graphicsLayer` 离屏缓冲池化、LazyLayout item 纹理复用，仍缺 AndroidX release note、源码 CL、类名或 benchmark 锚点。官方 Compose UI release notes 当前显示 stable 1.11.2（2026-05-19），能确认 `GraphicsLayer` API 在 1.7.0-alpha05 引入、`CompositingStrategy` 在 1.4.0-alpha02 引入，但本轮未找到能直接支撑“Compose 1.10 离屏缓冲池化”的官方条目。
- P3 记录：L85 “Android 4.0 开始硬件加速默认开启”建议后续补 targetSdk 边界。官方文档口径是 target API level >= 14 时默认开启；对于 Android 3.0/3.1/3.2 或 targetSdk < 14 的历史应用，需要显式开启。该点不影响现代 targetSdk 场景下的主结论。

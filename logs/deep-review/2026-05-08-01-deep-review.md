## 问题单

### 19.17 Firebase Performance

1. [P0][API/源码错误] L151 — Android attribute key 上限写错。
   - 现状：正文写 attribute key 最多 32 个字符。
   - 证据：`firebase-perf/src/main/java/com/google/firebase/perf/util/Constants.java` 当前为 `MAX_ATTRIBUTE_KEY_LENGTH = 40`、`MAX_ATTRIBUTE_VALUE_LENGTH = 100`、`MAX_TRACE_CUSTOM_ATTRIBUTES = 5`；Android API reference `HttpMetric` 也暴露相同常量。
   - 建议：改成 Android 端 key 40、value 100、每个 Trace/HttpMetric 5 个 attribute；补 reserved prefix 与首字符规则。

2. [P0][API/源码错误] L170 — Cronet 兜底 API 写错。
   - 现状：正文称 Cronet 需要用 `FirebasePerfUrlConnection` 包装或手动添加拦截器。
   - 证据：`FirebasePerfUrlConnection.instrument(Object connection)` 只在 `connection instanceof HttpsURLConnection` / `HttpURLConnection` 时返回 wrapper，否则原样返回；Cronet `UrlRequest` 不属于 URLConnection。
   - 建议：Cronet/native/自研网络栈改用 `HttpMetric` 手工 network trace，并写清 start/stop、response code、request/response payload、content type 的设置点。

3. [P1][源码准确性/待验证结论] L171 — OkHttp EventListener 冲突结论缺源码证据。
   - 现状：正文称自定义 OkHttp `EventListener` 占据全局槽位会导致 Firebase 网络采集静默失败。
   - 证据：公开 Firebase Android SDK 源码中 OkHttp 自动采集由 `FirebasePerfOkHttpClient.execute/enqueue()` 包装 `Call`，异步路径用 `InstrumentOkHttpEnqueueCallback`；未发现 EventListener 依赖。
   - 建议：删除该因果，或标注 `[待验证]` 并补复现条件/commit/版本；保留 Gradle 插桩、Logcat、completed request、Content-Type、自定义网络栈的验证路径。

4. [P2][源码准确性/版本差异] L138/L143 — App start 起点口径需要拆开。
   - 现状：正文把 API 24+ 起点概括为 `Process.getStartUptimeMillis()`，容易让读者以为 Firebase 控制台 `_app_start` 已直接用该起点。
   - 证据：当前 `AppStartTrace` 构造函数用 `Process.getStartElapsedRealtime()` 保存 process-start；`logAppStartTrace()` 对 `_app_start` 仍使用 `getClassLoadTimeCompat()`；实验 TTID 使用 `getStartTimerCompat()`。
   - 建议：把“平台 API 可用”和“Firebase 当前指标口径”分开写。

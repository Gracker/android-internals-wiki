### 维度 1：源码引用准确性
- 评分：4.6/5
- P0/P1：0
- 结论：frontmatter 中 `ApplicationExitInfo.java`、`ActivityManager.java`、`AppExitInfoTracker.java`、`system/core/debuggerd/proto/tombstone.proto` 均能在 android-17.0.0_r1 对应项目中找到。
- 复核点：`ActivityManager.getHistoricalProcessExitReasons(packageName, pid, maxNum)` 的 `packageName=null`、`pid=0`、`maxNum=0`、按时间倒序返回语义与 AOSP 注释一致。

### 维度 3：版本差异覆盖
- 评分：4.5/5
- P0/P1：0
- 结论：正文 API 21-29 / API 30 / API 31+ 能力边界正确；API 30 有 ApplicationExitInfo 与 ANR trace，API 31+ native crash 可经 `traceInputStream` 读取 tombstone protobuf。
- 复核点：`REASON_FREEZER` 在 Android 13 / API 33 出现；`REASON_PACKAGE_STATE_CHANGE`、`REASON_PACKAGE_UPDATED` 在 Android 14 / API 34 出现，Android 14 之前包更新使用 `REASON_USER_REQUESTED` 表示。正文没有把这些常量写成 API 30 即存在。
- P2（仅日志）：L135、L270、L290-L291 的分类表适合后续补一个 API 30-32 / API 33 / API 34+ 的 server-side mapping 注脚，避免读者把包更新和 freezer 归因外推到所有 API 30+ 设备。

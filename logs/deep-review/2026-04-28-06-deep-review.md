### P0/P1 问题单
1. [P0] [源码错误] L103-L110 Wakelock 类型表
   - 问题：PowerManager 官方 API 文档中 SCREEN_BRIGHT_WAKE_LOCK deprecated in API 15，FULL_WAKE_LOCK 与 SCREEN_DIM_WAKE_LOCK deprecated in API 17；正文把 SCREEN_BRIGHT_WAKE_LOCK / FULL_WAKE_LOCK 写成 API 13，并写成 Android 只提供四种 wakelock 类型，遗漏 PROXIMITY_SCREEN_OFF_WAKE_LOCK 这一公开 wake-lock level。
   - 建议：修正废弃 API：SCREEN_BRIGHT=15，SCREEN_DIM/FULL=17；表格改为“常见 CPU/屏幕类 wake-lock level”，或补入 PROXIMITY_SCREEN_OFF_WAKE_LOCK 并说明它与屏幕/距离传感器相关，不是 CPU 保活主路径。
2. [P0] [代码错误] L661-L681 Coroutine + Lifecycle-aware 封装
   - 问题：Kotlin 示例声明 fun withWakeLock(block: suspend () -> Unit)，但函数本身不是 suspend，却在 try 块内直接调用 suspend lambda block()；这段代码不能通过编译。
   - 建议：改为 suspend fun withWakeLock(block: suspend () -> Unit)，或把参数改成普通 () -> T 并返回 T；保留 acquire(timeout) 与 finally release 的结构。

### P2 建议
1. [数据缺失] L506-L556 Perfetto 中的 wakelock 分析 — 正文说明 activate/deactivate 需要 SQL 配对，但没有给出可运行模板。建议补一条按 wakeup_source 名称配对并计算持有时长的 SQL，说明不同 Perfetto 版本下 ftrace args 字段名需先用 schema/args 探测。
2. [版本差异] L715-L728 版本演进表 — 正文已经解释 Android 10 SystemSuspend 取代 libsuspend 直写路径，但版本演进表漏掉 Android 10 这一关键节点。建议补 Android 10 SystemSuspend / ISystemSuspend 行，避免读者只看到 Doze、Bucket、FGS 等策略变化。

- 具体问题：
  1. [P0][API/代码错误] L542-L552（ASan Gradle 示例） — 示例把 packagingOptions { doNotStrip "**/*.so" } 放在 defaultConfig.ndk 下，并称其可启用 ASan。该配置既不是启用 ASan 的 Gradle/NDK 方式，位置也不符合常见 AGP DSL；复制后不会产生 ASan 插桩。 建议：改成官方可验证路径：NDK/Clang 编译参数 -fsanitize=address、链接对应 ASan runtime，并按 Android NDK 文档配置 wrap.sh / packaging；如果只想保留 doNotStrip，应标注它只保留符号，不启用 ASan。
  2. [P0][命令错误] L568-L571（heapprofd --java） — 正文写 adb shell heapprofd --pid=<PID> --java。Perfetto/heapprofd 没有稳定公开的 --java 选项；Java allocation profiling 应通过 Perfetto heap_profile 脚本指定 --heaps com.android.art，或在 TraceConfig 的 heapprofd_config 中配置 ART heap。 建议：删除 --java 命令，改给 Perfetto tools/heap_profile --name <pkg> --heaps com.android.art 或 TraceConfig 示例，并说明 Android 12+ 才支持 Java allocation profiling。
  3. [P0][API 错误] L763-L778（ApplicationStartInfo 峰值内存 API） — 正文称 Android 17/API 37 的 ApplicationStartInfo 新增 getPeakRssKb()/getPeakAnonKb()，并给出 peakRssKb/peakAnonKb Kotlin 代码。本轮检索官方 API 未发现这些方法，属于不可发布的 API 断言。 建议：删除该 API 示例；若要讨论 MemoryLimiter 诊断，改用已公开的 ApplicationExitInfo、ProfilingManager 触发器或 [待验证] 的 AOSP commit/SDK 文档锚点。
  4. [P1][版本差异] L590-L647、L817-L820（onTrimMemory 等级） — 章节适用 Android 8-17，但仍按所有 TRIM_MEMORY_RUNNING_*、MODERATE、COMPLETE 都会投递来写。API 34+ 这些等级已废弃或不再投递给 App；正文建议在 Android 14+ 设备上会误导释放策略。 建议：按 API <=33 与 API 34+ 分开写；保留 UI_HIDDEN 等仍有意义的回调，废弃等级只作为历史兼容处理，并提醒不要依赖 COMPLETE 作为“即将被杀”信号。
  5. [P1][原理/计量口径] L284（Hardware Bitmap） — 正文写 Hardware Bitmap “不计入 App 的 PSS / 不占内存”。更准确口径是像素不在 Java Heap，通常落在 Graphics/GL/memtrack/driver 侧，是否归入单进程 PSS 与 OEM/memtrack 实现有关，但它仍然形成系统内存压力。 建议：改成“不计入 Java Heap；在 dumpsys meminfo 中常见于 Graphics/GL/memtrack/Other dev 等口径，设备差异大，不能写成不占内存”。
  - [P2][数据缺失] L169（GC 暂停 3ms / 掉帧率 3-5 倍） — 正文写“实测数据表明，将 GC 暂停从 5ms 降到 3ms，应用掉帧率通常下降 3-5 倍”，未给设备、刷新率、样本、Trace 或 benchmark 条件。 建议：补 Perfetto FrameTimeline + art_gc trace、测试设备和样本；没有数据前，保留帧预算推导，删除“通常下降 3-5 倍”。

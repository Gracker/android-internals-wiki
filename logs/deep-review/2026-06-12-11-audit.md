## 核验依据
- AOSP Gitiles：`android-17.0.0_r1` 当前不可取，manifest refs 未列出 Android 17 tag；按版本边界回退到可复现的 `android-16.0.0_r1` 源码锚点，不使用 main/master 作为正文结论。
- AOSP `android-16.0.0_r1`：
  - `ActivityManagerShellCommand.java`：`runDumpHeap()` 支持 `-n`、`-g`、`-m`，并调用 `IActivityManager.dumpHeap(...)`。
  - `ActivityManagerService.java`：`dumpHeap()` 要求 `SET_ACTIVITY_WATCHER`，调用 `enableFreezer(false)`，再转发 `IApplicationThread.dumpHeap(...)`。
  - `ActivityThread.java`：`handleDumpHeap()` 分别调用 `Debug.dumpHprofData()`、`Debug.dumpNativeMallocInfo()`、`Debug.dumpNativeHeap()`。
  - `art/runtime/hprof/hprof.cc`：Java HPROF 路径包含 `ScopedGCCriticalSection`、`ScopedSuspendAll`，输出 `JAVA PROFILE 1.0.3`。
  - `external/perfetto/protos/perfetto/config/profiling/java_hprof_config.proto`：`JavaHprofConfig` 包含 `process_cmdline`、`continuous_dump_config`、`min_anonymous_memory_kb` 等字段。
- Perfetto 官方文档：
  - `android.java_hprof` 数据源 Android 11+ 可用；ART heap dump 是引用图，不等同于标准 JVM/HPROF 完整对象数据。
  - OOME case study 从 Android 14 起可通过 `adb shell perfetto -c - --txt ...`、`android.java_hprof.oom` 与 trigger config 等待 Java `OutOfMemoryError`。
- Android Developers Blog：Android 17 app memory limits 使用 `ApplicationExitInfo.REASON_OTHER` + `MemoryLimiter:AnonSwap` 描述，并可用 `ProfilingTrigger.TRIGGER_TYPE_ANOMALY` 自动捕获 heap dump。

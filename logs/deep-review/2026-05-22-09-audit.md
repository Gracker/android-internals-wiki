## 维度 1：源码引用 / SQL schema 准确性
- 评分：3/5
- 问题数：1

1. [P0] L875-L889 — `main_lock_span` 没有输出 `utid`，但 `SPAN_JOIN(main_lock_span PARTITIONED utid, sp_sched)` 按 `utid` 分区。
   - 证据：Perfetto stdlib `android_monitor_contention` 提供 `blocked_utid` / `blocking_utid`；本章 L817-L818 也用 `contention.blocked_utid = ft_thread.utid`。
   - 影响：Trace Processor 无法创建虚拟表，示例直接执行失败。
   - 建议：`SELECT blocked_utid AS utid, ts, dur, blocking_thread_name ...`，并与 `sp_sched PARTITIONED utid` 对齐。

## 维度 3：版本差异覆盖
- 评分：3/5
- 问题数：1

1. [P1] L190-L202、L213-L230、L606-L613、L637-L641、L805-L824 — 多处 SQL 精确匹配 `slice.name = 'Choreographer#doFrame'`。
   - 证据：AOSP `Choreographer.java` Android 10/11 使用 `Trace.traceBegin(..., "Choreographer#doFrame")`；Android 12 使用 `"Choreographer#doFrame " + vsyncEventData.id`；Android 13+ 使用 `"Choreographer#doFrame " + preferredFrameTimeline().vsyncId / timeline.mVsyncId`。
   - 影响：章节适用范围写 Android 10-17，但 Android 12+ trace 中这些查询会漏掉主线程帧、启动首帧窗口和帧内锁竞争。
   - 建议：改为 `slice.name GLOB 'Choreographer#doFrame*'` / `LIKE 'Choreographer#doFrame%'`，并补充 Android 10/11 与 Android 12+ 的 trace 名版本边界。

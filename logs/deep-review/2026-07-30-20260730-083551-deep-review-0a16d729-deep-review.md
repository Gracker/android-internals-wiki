## 审查与修复

### [P0] Predictive Back 回调接口（已修复）

**问题**：原文将 `OnBackPressedCallback`（AndroidX）与 `OnBackInvokedCallback`（平台）并列，并暗示"需要连续进度时使用支持 started/progressed/cancelled/invoked 生命周期的接口"，但没有点明该生命周期属于哪个接口；同时上下文引用了未在 AOSP 中核实的 `predictive_back_progress` 标准 counter。

**核实**：
- `OnBackInvokedCallback`（`android.window.OnBackInvokedCallback`，API 33+）只有 `onBackInvoked()`，无进度回调。
- 连续进度生命周期来自 `android.window.OnBackAnimationCallback`（API 33+），提供 `onBackStarted` / `onBackProgressed` / `onBackCancelled` / `onBackInvoked`，依赖 `android:enableOnBackInvokedCallback="true"`。
- `OnBackPressedCallback`（AndroidX Activity 1.6+）通过 `OnBackPressedDispatcher` 分发，只有 `handleOnBackPressed()`。
- AOSP `BackEvent`、`OnBackAnimationCallback`、SystemUI `EdgeBackGestureHandler` 精确搜索未核到名为 `predictive_back_progress` 的标准内置 Perfetto counter；返回手势进度由 SystemUI/WM Shell transition 与 Winscope 记录。

**补丁**：将 Predictive Back 段重写为三个接口的显式拆分（含触发条件与是否提供进度），并在诊断清单中显式标注 `OnBackAnimationCallback` 与 `onBackCancelled`；新增一段明确说明 `predictive_back_progress` 不是平台标准 counter，给出正确的可观察途径（应用自插桩 `Trace.beginSection` / Winscope Shell 参与者）。

### [P1] Fragment commit 与 Choreographer 时序（已修复）

**问题**：原文"它没有承诺与某个 VSync 对齐"方向正确，但未给出为何不存在固定顺序的源码依据，易被读成"`execPendingActions()` 早于/晚于 `doFrame`"的固定顺序。

**核实**（与 `src/.../17-fragmenttransaction-commit-jank.md` 源码链一致）：
- `commit()` → `commitInternal(false,true)` → `enqueueAction()` → `scheduleCommit()` → 宿主 `Handler.post(mExecCommit)`。
- `scheduleCommit()` 只在 `mPendingActions.size()==1` 时移除旧 callback 并 post `mExecCommit`。
- `mExecCommit` 与 Choreographer 帧回调共享同一主 Looper；实际先后取决于主 MessageQueue 已有消息、同步屏障、异步 Choreographer 消息、`commit()` 发生时刻；`commitNow()` 在调用栈同步执行会改变相对位置。源码不支持任何"`execPendingActions()` 必定早于/晚于某次 `doFrame`"的固定顺序。

**补丁**：在 Fragment transaction 段补充 `enqueueAction()`/`scheduleCommit()`/`Handler.post(mExecCommit)` 链路，显式说明执行先后取决于 MessageQueue/同步屏障/异步消息/调用时刻，并指出不存在固定顺序、`commitNow()` 会改变相对位置。

## 复核证据

- AOSP Power profiles：BatteryStats 通过组件状态与持续时间估算耗电，display / CPU 等组件成本来自 power profile；显示亮度按停留时间乘以插值后的亮度成本，正文 L95 / L110 口径成立。
- Android Developers / arXiv：arXiv:2604.25587 仍为 v1（2026-04-28），摘要覆盖亮度、刷新率、连接状态、主题、省电配置、视频分辨率和消息长度等用户可控变量；正文对论文适用边界没有外推到所有设备。
- Android Developers frame-rate + AOSP android-16.0.0_r1 `Surface.java`：`Surface.setFrameRate()`、`FRAME_RATE_COMPATIBILITY_DEFAULT/FIXED_SOURCE/AT_LEAST` 等 API 存在，系统可因其他 layer / display 能力选择倍频或近似匹配，正文 L124 / L194 口径成立。
- AOSP Multiple refresh rate：DisplayManager 策略包含 default / peak / min refresh rate、app requested mode、Battery Saver；低功耗模式由 `Settings.Global.LOW_POWER_MODE` 表示且刷新率限制到 60Hz 或更低，正文 L126 / L197 口径成立。
- AOSP ARR + Android Developers ARR：ARR 属于 Android 15 引入、Android 15-QPR1+ 且依赖特定 HWC HAL/API 的设备能力；ARR 通过离散 VSync 步进让刷新率按内容 cadence 变化，正文 L126 / L196 的版本边界成立。
- AOSP android-16.0.0_r1 `View.java` / Android Developers reference：`View.setRequestedFrameRate(float)`、`setFrameContentVelocity(float)` 与 `REQUESTED_FRAME_RATE_CATEGORY_*` 存在；`Display.hasArrSupport()` / `getSuggestedFrameRate(int)` 属于 API 36 查询入口，已由 2.18 详细承接，11.7 表格不需要在本节展开。
- Android Developers Battery Historian：官方页面仍说明 System Stats 包含 cell signal levels 和 screen brightness，同时提示 Battery Historian 不再活跃维护并建议 system tracing / Macrobenchmark PowerMetric / Power Profiler；正文 L177 已把 Power Profiler、Perfetto power rail、Macrobenchmark `PowerMetric` 放在短场景与回归测试入口，未形成过期工具建议。

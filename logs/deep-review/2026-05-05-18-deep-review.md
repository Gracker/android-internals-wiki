### 9.5 案例集

[P0][源码错误] L277 进程冻结案例版本边界 — 正文称 Android 15+ 通过 `InputDispatcher::setFrozen` 检查连接状态避免冻结活跃 Input 连接进程。AOSP android-15/16 `InputDispatcher.cpp` 不存在 `InputDispatcher::setFrozen`；只有 `setInputDispatchMode(bool enabled, bool frozen)` 这种全局 dispatch freeze 状态。Cached app freezer 的冻结资格在 AMS / OomAdjuster / ProcessCachedOptimizerRecord 的 `shouldNotFreeze`、CPU capability 与 binding 传播路径里计算，不是 InputDispatcher 逐连接 `setFrozen`。
  2. [P0][源码错误] L225 SharedPreferences `apply()` 等待点 — 正文称 BroadcastReceiver 与 ContentProvider 的写入等待点分别在 `ActivityThread.handleReceiver()` 与 `ActivityThread.handleRelaunchActivity()`。AOSP android-14/16 `ActivityThread.java` 中 `QueuedWork.waitToFinish()` 出现在 Service start/destroy、Activity pause(pre-Honeycomb) 与 Activity stop(non-pre-Honeycomb) 路径；`handleReceiver()` / `handleRelaunchActivity()` 没有 `waitToFinish`。`BroadcastReceiver.PendingResult.finish()` 只在有 pending work 时 queue 一个 `sendFinished` runnable，不阻塞主线程等待。

[P1][Trace观察点错误] L449-L455 InputDispatcher WaitQueue 观察点 — `dumpsys input` 的 `WaitQueue: length=` 有 AOSP dump 支撑，但正文写 Perfetto counter 为 `android.input.input_event_waiting_duration`。AOSP android-14/16 `InputDispatcher::traceWaitQueueLength()` 使用 `ATRACE_INT` 输出 counter 名 `wq:<window/input_channel>`，不是该名称；当前段落把等待时长 track 与队列长度判据混在一起。

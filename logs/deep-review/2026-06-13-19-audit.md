## 复核证据
- OkHttp Events 官方文档：`EventListener` 事件序列包含 `dnsStart/dnsEnd`、`connectStart`、`secureConnectStart/End`、`requestHeadersEnd`、`responseHeadersStart`，并建议用 `EventListener.Factory` 为并发请求创建独立 listener。
- OkHttp Connections 官方文档：OkHttp 通过 `ConnectionPool` 复用 HTTP/1.x 连接并 multiplex HTTP/2 连接，连接复用、TLS 握手与路由重试口径与正文一致。
- Android Developers `NetworkCapabilities#getLinkDownstreamBandwidthKbps()`：API 21 起提供，公开文档明确该值是 estimated first-hop transport bandwidth；正文“不等同真实吞吐 / RTT”的边界成立。
- Android Developers `PerformanceHintManager.Session#setPreferPowerEfficiency(boolean)`：API 35 起提供，语义是声明线程可偏向 power-efficient scheduling，不保证低功耗核心或固定降频；正文 Android 15 ADPF 边界成立。
- Android Developers Cronet / Google Play services CronetProviderInstaller：`QuicOptions.Builder.addAllowedQuicHost()` 是 QUIC host allowlist，`enableTlsZeroRtt(boolean)` 是 TLS 0-RTT 开关；Play Services provider 可避免随 APK 打包 native Cronet 并随 Play services 更新，正文 provider 成本边界成立。
- Android 17 官方资料：`SubscriptionInfo#getStreamingAppMaxDownlinkKbps()` / `getStreamingAppMaxUplinkKbps()` 为 API 37 新增；`ACCESS_LOCAL_NETWORK` 为 API 37 dangerous permission。本轮未使用 Android 18/API 38+ 资料。

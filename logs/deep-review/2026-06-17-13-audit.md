## 维度 1：源码引用准确性
- 评分：4.5/5
- P0/P1：0
- 结论：Perfetto CPU Frequency 官方文档仍确认两条采集来源：`power/cpu_frequency` ftrace 事件与 `linux.sys_stats.cpufreq_period_ms` 轮询；`linux.system_info` 记录可用频点；频率和 idle state 在 SQL 层通过 `counter` + `cpu_counter_track` 表查询，`cpuidle=0xffffffff` 表示回到非 idle。正文 L102-L146、L228-L247 与官方口径一致。
- 结论：PerfettoSQL prelude 当前仍列出 `cpu.id`、`cpu.cpu`、`cpu.cluster_id`、`cpu.capacity` 与 `cpu_freq.ucpu -> cpu.id`，正文 L179-L188 的 cluster / capacity / `cpu_freq` 关联口径成立。
- 低风险观察（P2，仅日志）：L252-L269 的 SPAN_JOIN 示例把 `sched.ucpu` 别名为 `cpu_id`，而频率侧用 `cpu_counter_track.cpu` 别名为 `cpu_id`。官方 Getting Started 示例使用同名 `cpu` 分区；当前 SQL tables 文档把 `sched.ucpu` 定义为 `CpuTable::Id`。在普通单机 Android trace 中 CPU id 和 CPU index 通常一致，本节不会因此形成 P0/P1；后续如果整理 SQL 模板，可统一改成两侧都按展示 CPU index 分区，减少多 machine / 非连续 CPU id 场景的歧义。

## 维度 3：版本差异覆盖
- 评分：5/5
- P0/P1：0
- 结论：Perfetto 文档标注 CPU frequency / idle states 数据源在 Linux 与 Android P 起可用，正文 applicable_versions 写 Android 9 (API 28) - Android 17 (API 37)，边界匹配。
- 结论：正文已覆盖事件驱动缺初始频率、sysfs 轮询采样间隔、Intel 内部 DVFS 不暴露事件、Android ARM SoC 通常更可靠、idle 后频率值语义变弱等差异；这些仍与官方文档一致。
- 结论：L304-L314 的移动端 LLM DVFS 论文边界为 Android 13、Pixel 7 / Pixel 7 Pro、Google Tensor G2、root/open 设备与固定实验条件；未把结论外推到 Android 18 或所有 Android 设备。
- 结论：L340 提到 Android 15 起 `ProfilingManager` 支持 system trace / heap dump / heap profile / stack sampling，API 35 在 Android 17 范围内，未越过版本上限。

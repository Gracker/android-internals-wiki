## 审查结果

### 维度 1：源码引用准确性
- 评分：3/5
- 问题数：5
- 具体问题：
  1. [P0] Canvas.drawRect() 代码片段 — native_drawRect 方法签名错误。文中写为 `native_drawRect(mNativeCanvasWrapper, left, top, right, bottom, paint.mNativePaint, paint.mShaderDensity, paint.mAlpha)`，传入了 mShaderDensity 和 mAlpha 两个不存在的参数。AOSP 实际签名为 `native_drawRect(long nativeCanvas, float left, float top, float right, float bottom, long nativePaint)`，只传 Paint 的 native handle，不传单独字段。
  2. [P1] GraphicBuffer.java 代码片段标注 @ AOSP android-16.0.0_r1，但展示的 mWidth/mHeight/mFormat/mUsage/mRefCount 字段并非 AOSP 实际结构。AOSP GraphicBuffer 内部只有一个 `long mNativeObject` 指针，对外通过 getWidth()/getHeight()/getFormat()/getUsage() 方法访问。标注暗示这是源码，实际是简化伪代码，应改标注。
  3. [P2] Gralloc HAL 代码使用 HIDL 4.0 接口（IAllocator.hal），Android 16 已迁移到 AIDL 接口（hardware/interfaces/graphics/allocator/aidl/）。HIDL 接口仍存在但已 deprecated。
  4. [P2] glDrawArrays vs vkQueueSubmit 对比不对称 — glDrawArrays 是单个 draw call，vkQueueSubmit 是提交整批命令缓冲区。更公平的对比应该用 vkCmdDraw。虽然结论（Vulkan CPU 开销更低）正确，但示例代码对比有误导性。
  5. [P2] frontmatter 中 chapter: "2" 应为 "2.10"，与 section 字段不一致。

### 维度 2：原理链完整性
- 评分：3.5/5
- 问题数：4
- 具体问题：
  1. [P1] 缺少 TBR（Tile-Based Rendering）移动 GPU 架构的核心解释。仅在 [待验证] 笔记中提及 TBR，但未展开。几乎所有移动 GPU（Mali/Adreno/PowerVR）都使用 TBR/IMR 混合架构，这决定了：为什么过度绘制在移动 GPU 上代价更高（每个 tile 的中间结果需要保留）、为什么 load/store 操作是关键性能点、为什么 render pass 合并对移动 GPU 特别重要。作为 GPU 渲染深入章节，这是核心知识缺环。
  2. [P1] "降低分辨率到 720p 判断瓶颈类型"方法不适用于标准 Android UI 渲染。Android UI 分辨率由系统决定，App 无法独立将渲染分辨率降到 720p（除非使用 SurfaceView 或特殊配置）。这个方法来自游戏开发，直接搬到 Android UI 场景会误导读者。
  3. [P2] 缺少 Skia 后端选择机制的说明 — Skia 如何在 OpenGL ES 和 Vulkan 之间切换、ThreadedRenderer 如何决定使用哪个后端。读者无法理解从 Canvas API 到具体 GPU API 的完整路径。
  4. [P2] GPU 渲染到 BufferQueue 的衔接缺失。章节讲了 GraphicBuffer 和 Gralloc 但未解释渲染完成后 GPU 如何通过 fence 通知 SurfaceFlinger、Buffer 的生命周期在 GPU 侧如何管理。

### 维度 3：版本差异覆盖
- 评分：3/5
- 问题数：4
- 具体问题：
  1. [P1] Vulkan 版本引入时间线错误。章节称"Android 16 标志着...Vulkan 成为官方默认图形 API"，给人 Vulkan 在 Android 16 才引入的印象。实际上 Vulkan 从 Android 7.0（2016）就已支持。正确叙述应为：Android 7.0 引入 Vulkan 1.0 → Android 10 要求新设备支持 Vulkan 1.1 → Android 13 要求 Vulkan 1.1 → Android 16 以 ANGLE 将 GLES 统一翻译到 Vulkan 后端。
  2. [P1] ANGLE 的版本演进缺失。ANGLE 在 Android 10 已可选集成，Android 13 扩大覆盖到部分 App，Android 14 进一步扩展，Android 16 设为默认 GLES 实现。章节只在 Android 16 上下文中提到 ANGLE，缺少从 10→13→14→16 的渐进覆盖线。
  3. [P2] AGI（Android GPU Inspector）已弃用/归档，被 Android Studio 内置 GPU profiler 替代。章节推荐使用 AGI 但未提及替代方案。
  4. [P2] applicable_versions 覆盖 Android 5.0-16 但正文中 RenderThread 增强在 Android 12 的具体变化未说明（只说"进一步优化了这一分工"），过于模糊。

### 维度 4：知识盲区
- 评分：3/5
- 盲区数：4
- 具体问题：
  1. [P1] 缺少 GPU culling 机制（Early Z-Test、Hierarchy Z-Buffer）。这是理解过度绘制对 GPU 实际性能影响的关键 — 移动 GPU 的 Early Z 能在一定程度上自动跳过被遮挡的像素，所以并非所有过度绘制都等比例增加 GPU 负载。忽略这个机制会让读者高估过度绘制的实际影响。
  2. [P2] 缺少 GPU Compute Shader 和 GPGPU 在 Android 上的讨论。随着端侧 AI 推理的普及，GPU 的非图形计算任务越来越重要，与图形渲染共享 GPU 资源。
  3. [P2] 缺少 GPU 内存压力回调机制（onTrimMemory/GPU memory pressure）的讨论。
  4. [P2] 缺少不同 GPU 厂商（Adreno/Mali/PowerVR）在 TBR 实现差异上的对比。

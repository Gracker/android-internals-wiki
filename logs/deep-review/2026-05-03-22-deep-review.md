## 详细问题单
  1. [P0] L141-L146（完成通知接口与线程模型） — 正文写 BroadcastReceiver 通过 IApplicationThread.finishReceiver() 向 AMS 发送完成通知，且“这些完成通知都运行在 Binder 线程上，与主线程异步”。AOSP android-14.0.0_r1 的 IApplicationThread.aidl 没有 finishReceiver；实际是 ActivityThread.handleReceiver() 在主线程执行 receiver.onReceive() 后调用 data.finish()/IActivityManager.finishReceiver。Service 的 serviceDoneExecuting() 与 ContentProvider 的 publishContentProviders() 也分别在 ActivityThread.handleServiceArgs()/installContentProviders() 主线程路径中发起 Binder 调用。 建议：把本段改成“超时计时在 system_server 异步运行；应用侧完成回调通常在主线程完成组件回调后发起 Binder 调用（goAsync/异步 finish 另论），system_server 在 Binder 线程接收并取消超时”。同时将 IApplicationThread.finishReceiver 修正为 IActivityManager.finishReceiver。
  2. [P0] L211-L213（ContentProvider 发布超时常量） — 正文写 ContentProvider 发布超时常量是 ActivityManagerService.java 中的 CONTENT_PROVIDER_PUBLISH_TIMEOUT。AOSP android-14.0.0_r1 中 ActivityManagerService 定义的是 CONTENT_PROVIDER_PUBLISH_TIMEOUT_MSG，超时时长来自 ContentResolver.CONTENT_PROVIDER_PUBLISH_TIMEOUT_MILLIS = 10 * 1000 * Build.HW_TIMEOUT_MULTIPLIER；不存在文中这个常量名。 建议：把源码锚点改为 ActivityManagerService.CONTENT_PROVIDER_PUBLISH_TIMEOUT_MSG + ContentResolver.CONTENT_PROVIDER_PUBLISH_TIMEOUT_MILLIS，并说明 AMS handler message 使用 ContentResolver 中的 10s 时长。
  3. [P0] L360（ApplicationExitInfo 读取 ANR trace 的 API） — 正文写可通过 Process.getErrorStateMemoryRegion() 或 ActivityManager.getHistoricalProcessExitReasons() 程序化读取 ANR 堆栈。AOSP android-14/15/16 的 android.os.Process 中未发现 getErrorStateMemoryRegion；ApplicationExitInfo 读取 trace 的公开入口是 ApplicationExitInfo.getTraceInputStream()，对象由 ActivityManager.getHistoricalProcessExitReasons() 返回。 建议：删除 Process.getErrorStateMemoryRegion()；改为“ActivityManager.getHistoricalProcessExitReasons() 获取 ApplicationExitInfo，再通过 ApplicationExitInfo.getTraceInputStream() 读取关联 trace”。
  4. [P2] L211（getProviderMimeTypeAsync 版本线） — 正文把 getProviderMimeType()/getProviderMimeTypeAsync 写成 API 31+ 的通用当前路径。AOSP android-12 的 IActivityManager 确有 getProviderMimeTypeAsync；android-14 的 ContentResolver.getType() 已走 IContentProvider.getTypeAsync() / ActivityManager.getMimeTypeFilterAsync() 等路径，原表述会把 Android 14+ 读者带到旧接口。 建议：拆成 Android 12 引入 getProviderMimeTypeAsync 的历史节点，以及 Android 14+ ContentResolver.getType()/getTypeAsync/getMimeTypeFilterAsync 的当前路径。
  5. [P2] L400-L404（ANR trace 文件存储演进） — Android 10 段已写“按时间和进程分别存储”，Android 13 段又写“改为按进程独立存储”，两个版本节点的差异边界重叠。 建议：重新核对 AOSP trace 文件命名/写入路径演进，把 Android 10 的 traces.txt→/data/anr/anr_* 与 Android 12/13 的可靠性或按进程改进拆清楚，避免重复归因。

## 抽检结论

### 维度 1：源码引用准确性
- 评分：4.5/5
- 问题数：0（P0/P1）
- 结论：未发现需要回炉的源码路径、公开 API 名称或示例代码错误。
- 复核点：
  1. AOSP `android-16.0.0_r1` `frameworks/base/core/java/android/view/FrameMetrics.java` 仍包含 `COMMAND_ISSUE_DURATION`、`TOTAL_DURATION`、`FIRST_DRAW_FRAME`、`GPU_DURATION`、`DEADLINE`，且 `GPU_DURATION` / `DEADLINE` 为 API 31+ 口径，正文表格和示例代码未写错公开常量。
  2. 同一源码中还存在 `INTENDED_VSYNC_TIMESTAMP`、`VSYNC_TIMESTAMP` 和 flagged `FRAME_TIMELINE_VSYNC_ID`；正文表格标题写“完整耗时分项”，实际只列常用耗时与 jank 判定指标。此处是 P2 口径收紧建议，不影响现有监控方案结论，本轮不写 queue。
  3. AndroidX `androidx-main` `JankStatsApi16Impl.kt` / `JankStatsApi24Impl.kt` / `JankStatsApi31Impl.kt` 复核：低版本回退 `OnPreDrawListener`、API 24 路径基于 `FrameMetrics`，API 31 路径读取 `FrameMetrics.DEADLINE`，`jankHeuristicMultiplier` 默认 2.0；正文 JankStats 机制未发现 P0/P1。
  4. AOSP `android-16.0.0_r1` `ApplicationExitInfo.java` 与 Android Developers 文档一致：`getTraceInputStream()` API 30，ANR trace 通常可用，API 31 起 native crash tombstone trace 可能以 protobuf 返回且可能为 null；正文 ANR 退出历史口径成立。

### 维度 3：版本差异覆盖
- 评分：4.5/5
- 问题数：0（P0/P1）
- 结论：未发现 Android 7-16 范围内会误导接入方案的版本边界错误。
- 复核点：
  1. `ProfilingManager` 官方 API 文档当前仍标注 API 35 引入 `requestProfiling()` 与 system trace / heap dump / heap profile / stack sampling 类型；`addProfilingTriggers()` 为 API 36，正文 Android 15/16 边界成立。
  2. `ProfilingTrigger` 官方 API 文档标注 `TRIGGER_TYPE_ANR`、`TRIGGER_TYPE_APP_FULLY_DRAWN` 为 API 36，并会返回 running system trace snapshot；正文只引用这两个 Android 16 触发器，未引入 Android 18 / API 38+ 内容。
  3. 官方 `ProfilingTrigger` 页面同时列出 Android 17 / API 37 的 `TRIGGER_TYPE_COLD_START`、`TRIGGER_TYPE_OOM`、`TRIGGER_TYPE_ANOMALY` 等新增触发器。由于本节 frontmatter 的 `applicable_versions` 截止 Android 16 / API 36，本轮仅记录为后续扩展机会，不作为正文缺失问题。
  4. `android-17.0.0_r1` tag 本轮在 `frameworks/base` / `art` 未查到；本轮未使用 main/master 源码作为正文结论，也未写入 Android 18 / API 38+ 资料。

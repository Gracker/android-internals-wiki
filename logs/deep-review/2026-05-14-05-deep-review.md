### 4.5 App 内存优化

#### 维度 1：源码引用准确性
- 评分：2.0/5
- 问题数：5
- 具体问题：
  1. [P0] L888 System.gc() 误区 — 正文写“GC 会回收一些可达但暂时未引用的对象”。可达对象不会被 GC 回收；只有不可达对象才可回收。 建议：改为“清空缓存后原先被缓存强引用的对象变为不可达，GC 才可能回收”。
  2. [P0] L548-L557 malloc debug 示例 — `LIBC_DEBUG_MALLOC_OPTIONS=backtrace_tracker` 未在已核实 bionic malloc debug 选项中出现，wrap 命令形式也不足以作为可执行示例。 建议：按官方 `backtrace` / `backtrace_enable_on_signal` 等选项重写，并补 force-stop / 重启流程。
  3. [P1] L207 Message.obtain() — `Handler.sendMessage(Message)` 使用调用方传入的 Message，并不会内部调用 `Message.obtain()`；`post` / `obtainMessage` / `sendEmptyMessage` 才涉及池化获取。 建议：拆开 Message 池 API 与 Handler 发送路径。
  4. [P1] L253、L898 Bitmap Native 内存释放 — Android 8.0+ Bitmap 像素释放写成 finalize 机制过时；AOSP 当前应以 `NativeAllocationRegistry` / Cleaner 路径描述。 建议：用 `frameworks/base/graphics/java/android/graphics/Bitmap.java` 当前实现重写释放链路。
  5. [P1] L593-L604 ASan 配置 — wrap.sh 只 export `ASAN_OPTIONS`，缺 ASan runtime、`LD_PRELOAD`、packaging 等关键运行条件。 建议：补官方 API 27+ wrap.sh 配置步骤，明确 debug-only 边界。

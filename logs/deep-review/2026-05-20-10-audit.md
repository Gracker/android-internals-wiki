- 具体问题：
  1. [P0][源码错误/API 使用错误] EGL Sync Objects（精确控制）代码块 L241-L249 — 示例用 `eglCreateSyncKHR(display, EGL_SYNC_FENCE_KHR, NULL)` 创建 KHR fence sync 后调用 `eglDupNativeFenceFDANDROID(display, sync)` 导出 native fence FD。`EGL_ANDROID_native_fence_sync` 规范要求 `eglDupNativeFenceFDANDROID` 复制的是 EGL native fence sync 对象的 `EGL_SYNC_NATIVE_FENCE_FD_ANDROID`，导出 FD 的 sync 类型应为 `EGL_SYNC_NATIVE_FENCE_ANDROID`。当前示例会误导跨进程 fence / Android native fence 用法。
     - 建议：拆成两种示例：只做 CPU 等 GPU 完成时使用 `EGL_SYNC_FENCE_KHR + eglClientWaitSyncKHR`；需要导出 native fence FD 时使用 `EGL_SYNC_NATIVE_FENCE_ANDROID`，必要时在 flush 后调用 `eglDupNativeFenceFDANDROID`。
  2. [P2][源码边界] L196 / L200-L212 — “Android 12+ `eglSwapBuffers` 内部走 BLAST Transaction”“GLES 通常配置 3 个 Slot”方向基本成立，但表述应补边界：BLAST 是 SurfaceView/Surface 包装层提供的 `BLASTBufferQueue`，不是 EGL API 自身逻辑；buffer 数由 `mMaxAcquiredBufferCount`、`mMaxDequeuedBufferCount`、async / cannot-block 共同决定。`BLASTBufferQueue::onFirstRef()` 当前默认 `setMaxDequeuedBufferCount(2)`，传统 BufferQueue 路径和 OEM 改动不能简单等同为固定三缓冲。
     - 建议：下次维护时补 AOSP 锚点，并把“三缓冲”改成“常见 Surface/BLAST 路径会允许 3 个在途 buffer，但不是 EGL 规范保证”。

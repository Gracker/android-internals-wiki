### 维度 1：源码引用准确性

- 问题数：1（P2，既有建议）
- 具体问题：
  1. [P2][既有建议仍成立] L438 — `RemoteCallbackList` 的 `FrozenCalleePolicy` 被写成“自动丢弃高频数据回调”。android-16.0.0_r1 源码定义的是 callback recipient 进程被冻结时的策略集合：`FROZEN_CALLEE_POLICY_DROP`、`ENQUEUE_ALL`、`ENQUEUE_MOST_RECENT`、`UNSET`；是否丢弃取决于构造 RemoteCallbackList 时选择的 policy。本问题已在 `intake/suggestions.md` 的 2026-05-13 Task9 Deep Review 条目记录，本轮不重复写入。
- 复核通过项：
  1. `ProcessState.cpp` 中 `BINDER_VM_SIZE ((1 * 1024 * 1024) - sysconf(_SC_PAGE_SIZE) * 2)`、`DEFAULT_MAX_BINDER_THREADS=15`、`setThreadPoolMaxThreadCount()` 启动后不能缩小、`makeBinderThreadName()` 线程命名逻辑，与正文 mmap / 线程池口径一致。
  2. `IWindowSession.aidl` 的 `addToDisplay*()` 入口存在，正文没有把窗口添加入口错误写成 `IWindowManager.addView()`。
  3. Perfetto main `android/binder.sql` 当前仍提供 `android_binder_txns`，字段包含 `aidl_name`、`interface`、`method_name`、`client_dur`、`server_dur`、`is_sync`、`is_main_thread`、`client_process`，正文与 SQL 示例口径一致。
  4. kernel common `binder.h` 当前保留 `binder_transaction_data_sg`、`BC_TRANSACTION_SG`、`BC_REPLY_SG`、`BINDER_TYPE_PTR`、`BINDER_ENABLE_ONEWAY_SPAM_DETECTION`，正文对 scatter-gather 与 oneway spam detection 的源码锚点未发现错配。

### 维度 3：版本差异覆盖
- 评分：4/5
- 问题数：0（P0/P1）
- 具体结论：
  1. Android 11 cached apps freezer / binder-freezer 行为与 source.android 当前文档一致：同步事务发往 frozen remote process 时系统终止 remote process；oneway 事务会缓冲，buffer overflow 时 recipient 进程可能被终止。
  2. Android 11 AIDL HAL 迁移口径与 source.android `aidl-hals` 一致：where possible 迁移到 AIDL；上游 HAL 仍使用 HIDL 时继续使用 HIDL。正文保留 HIDL passthrough 不经过 Binder 的边界，未发现版本错配。
  3. Android 16 `RemoteCallbackList` FrozenCalleePolicy 源码锚点存在；除上面的 P2 语义过窄外，版本归属没有发现 P0/P1。
  4. Android 16 + 16KB page size 段已使用 `1MiB - 2 * page_size` 公式和“公开资料缺 Binder 专项 benchmark”的保守口径，未发现新的量化误引。

  1. [P1] [版本差异] L218/L468/L534 — 正文把 BLASTBufferQueue 统一写成 Android 12 引入/取代 BufferQueue；AOSP Android 11 的 ViewRootImpl 已存在 mBlastBufferQueue 与 BLASTBufferQueue 迁移入口，Android 12 更适合写成范围扩大和后续稳定化。 建议：拆成 Android 11 预迁移/主窗口路径与 Android 12+ 后续演进，避免把 BLAST 起点后移。
  2. [P1] [原理断裂] L222 — “App 不再需要等待 SurfaceFlinger 释放 Buffer 才能获取新的 Buffer”过度绝对。BLAST 改进 Buffer+Transaction 的异步提交与同步边界，但 App 在 buffer slot 耗尽或 release fence 未 signal 时仍可能在 dequeue/复用旧 buffer 前被 back-pressure 卡住。 建议：改为“BLAST 将 buffer 与 transaction 绑定并改善几何/内容同步；不能消除 release fence 与 slot 数量导致的反压”。
  3. [P1] [版本差异/知识盲区] L187-L193/L471 — Graphite、Android 16 部署、Front-to-Back/Early-Z 与“自动消除不透明过度绘制”被连成强结论，但缺少 AOSP android-16 启用路径、系统属性/feature flag、设备范围和 Perfetto/Skia backend 验证方法。 建议：补 Graphite 是否启用的判定方法、设备/OEM 边界和 Skia/HWUI 源码锚点；在证据不足前把“开发者不需要优化过度绘制”改成条件化描述。
  - [P2] [数据缺失] L472 版本演进表 16KB 页 — “TLB 命中率提升约 9%，渲染管线有效带宽增益”没有给出设备、内核、负载、计数器或官方来源。16KB page size 的公开数据更多围绕启动、功耗、相机等宏观指标，不能直接推出渲染带宽收益。 建议：删除 9% 裸数字，或补充同机 4KB/16KB、GPU/CPU counter、fence/RenderThread trace 的可复现实验。
### 2.16 Sync Fence 框架与帧同步机制
- 文件：src/part1-fundamentals/ch02-rendering/16-sync-fence.md
- 结果：needs-rework
- 技术评分：源码 2/5 · 原理 2/5 · 版本 2/5 · 盲区 3/5 · 数据 2/5 · 交叉引用 4/5
- P0/P1/P2/P3：1/3/1/0

  1. [P0] [源码错误/原理错误] L274 — 正文写 Timeline Semaphore 用一个 64 位计数器替代 acquire / release / present 的多个一次性 fd，等同于替代 Android 图形管线 native fence。实际 BufferQueue / SurfaceFlinger / HWC 跨进程边界仍以 native fence / sync_file fd 交换；Vulkan timeline semaphore 属于 Vulkan 同步模型，需要通过 semaphore fd / sync fd interop 才能和 Android native fence 边界衔接。 建议：把 Vulkan 内部 timeline semaphore 与 Android native fence fd 分层写清：应用/驱动内部可用 timeline；ANativeWindow、BufferQueue、HWC 边界仍要说明 acquire/release/present fence fd 的传递。
  2. [P1] [原理断裂] L256-L280 — Android 16 Vulkan 1.4 / timeline semaphore 要求与 HWUI / SurfaceFlinger / HWC fence 传递链之间缺少 interop 解释，读者无法判断哪些等待来自 Vulkan queue，哪些等待来自 sync_file fd。 建议：补充 VkSemaphore 可导出/导入 fd、EGL/Vulkan native fence interop、SkiaVulkanPipeline/VulkanManager createReleaseFence 与 BufferQueue 交接的最小链路。
  3. [P1] [版本差异] L288-L294 — Android 17 “去 fd 化”“逐步移除图形管线 fd 依赖”的路线图未找到公开 CDD、source.android.com 或 AOSP tag 依据，当前写成确定政策会误导版本判断。 建议：降级为待验证展望；除非补到 Android 17 正式 CDD/API/AOSP 变更，否则不要写成平台路线。
  4. [P1] [数据支撑/原理断裂] L282-L286 — 16KB 页能缩短 fence signal 到 SurfaceFlinger 唤醒、并让 fence wait 尾部抖动更小，缺少 kernel ftrace/perf/TLB miss 或同机 A/B trace 证据。该结论把大页的通用 TLB 收益直接投射到 fence 路径。 建议：保留为研究假设，补 irq/dma_fence signal、sched wakeup、TLB miss/perf counter 与 Perfetto fence wait 的同机 4KB/16KB 对比。
  - [P2] [数据缺失] L278-L280 Timeline Semaphore 可观测性 — “在 Perfetto 中仍会以 fence wait 的形式呈现”缺少 producer、driver、Vulkan/Surface 边界前提。Vulkan 内部 timeline wait 不一定自动等价于 Android graphics fence wait slice。 建议：补 trace producer/driver 条件；区分 Vulkan 队列内部等待、sync_file fd 等待、SurfaceFlinger latch/present 等待。

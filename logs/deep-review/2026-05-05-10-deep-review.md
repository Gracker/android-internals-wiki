[P0] L251 TrimMemory 机制与 Jank 的关联 — 正文把 `android_lmk_proc_state` 和 `linux.lowmemorykiller` 写成 Perfetto 追踪点。Perfetto mainline stdlib 的 LMK 入口是 `android.memory.lmk` 模块和 `android_lmk_events` 表；lmkd.cpp 现行记录是 `lmk,...` ATrace/lowmemorykiller track，旧路径是 `kill_one_process` counter 或 legacy ftrace `lowmemorykiller/lowmemory_kill`。未查到 `android_lmk_proc_state` 或 `linux.lowmemorykiller` 这两个可用事件/表。 建议：改成“INCLUDE PERFETTO MODULE android.memory.lmk; 查询 android_lmk_events”；若讲底层采集，区分 2025+ instant lowmemorykiller track、Aug 2021 legacy `lmk,*` slice、2022 前 `kill_one_process` counter、legacy kernel `lowmemorykiller/lowmemory_kill`。
  2. [P0] L598 Binder Transaction 数据流 — 正文仍把 `binder_reply` 列为“内核 ftrace 原始事件”。Android common kernel `drivers/android/binder_trace.h` 中存在 `binder_transaction`、`binder_transaction_received`、`binder_transaction_alloc_buf`、`binder_return`，不存在 `binder_reply`。Perfetto `binder.sql` 里的 `binder_reply` 是内部 CTE/服务端 reply slice 命名，不是 kernel tracepoint。 建议：将原始事件列表改为 `binder_transaction` / `binder_transaction_received` / `binder_transaction_alloc_buf` / `binder_return`，并单独说明 Perfetto stdlib 会把 flow 另一端归一成 server-side reply slice。
  3. [P1] L328 FrameMetrics 示例注释 — 注释称 “FrameMetrics 其他常量从 API 24 引入” 不成立。官方文档显示 `VSYNC_TIMESTAMP` API 26、`DEADLINE` 和 `GPU_DURATION` API 31、`FRAME_TIMELINE_VSYNC_ID` API 36。章节 frontmatter 覆盖 Android 16/API 36，遗漏 `FRAME_TIMELINE_VSYNC_ID` 会错过线上 FrameMetrics 与 Perfetto FrameTimeline token 对齐的新版能力。 建议：改成常量分版本表：API24 基础阶段指标；API26 `VSYNC_TIMESTAMP`；API31 `DEADLINE`/`GPU_DURATION`；API36 `FRAME_TIMELINE_VSYNC_ID`。在 Android 16 段补一句它可作为线上帧数据与 trace 帧时间线的关联键。
  4. [P1] L378-L384 JankStats 说明 — 正文写 JankStats “基于 `TOTAL_DURATION > DEADLINE` 自动判断” 且“数据精度和覆盖范围没有差异”。AndroidX `JankStatsApi31Impl` 实际用 UI duration 与 `FrameMetrics.DEADLINE * jankHeuristicMultiplier` 判断 `isJank`，`TOTAL_DURATION - DEADLINE` 只是 `frameOverrunNanos`；API24 实现也用 UI duration 与按显示刷新率计算的 expected duration。官方文档还说明 API24+ 用 FrameMetrics，早期版本用 OnPreDrawListener。 建议：改成“API24+ 采 FrameMetrics，但 JankStats 上报的是 FrameData/FrameDataApi24/Api31 的抽象字段；isJank 由 UI duration 与 expected duration（受 jankHeuristicMultiplier 影响）判断，API31 额外提供 total/overrun”。不要写成完全等价于手写 FrameMetrics。

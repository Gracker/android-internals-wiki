#### P1 问题
1. [P1][原理断裂] L152-L166《性能面板的数据可信度》
   - 问题：该节只写“适合用途/需要复核”，没有说明 FPS、CPU、内存、网络流量的采集来源和刷新频率。源码复核显示 DoKit 的 PerformanceDataManager 中 FPS 通过 Choreographer.FrameCallback 统计，FPS 采样间隔为 1000ms；CPU/内存普通采样间隔为 500ms，CPU 在 Android O+ 走 `top -n 1`，低版本读 `/proc/stat` 和 `/proc/<pid>/stat`；内存走 Debug.getMemoryInfo 或 ActivityManager.getProcessMemoryInfo。
   - 建议：补一张“指标 / 源码入口 / 采集方式 / 刷新频率 / 误差来源 / 应复核工具”表，把“DoKit 只能做现场判断”的结论和采集实现绑定。
2. [P1][源码锚点缺失] L130-L150《Debug 工具箱的工程结构》+ L179-L186《平台网络上报与合规边界》
   - 问题：正文列了统计上报类，但没有给 DoKit 无侵入网络/方法监控的编译期插桩锚点。源码复核显示 `Android/dokit-plugin/src/main/kotlin/.../DoKitPlugin.kt` 使用 `registerTransform` 注册 Transform，`Okhttp3ClassTransformer` 在 `okhttp3.OkHttpClient` 构造逻辑里插入 `OkHttpHook.addDoKitIntercept(OkHttpClient)`。该实现也解释了网络监控、慢方法等能力为什么会引入运行时开销和 AGP 8.x 兼容风险。
   - 建议：在工程结构后补 `dokit-plugin` / Transform / ASM ClassTransformer 的代码阅读索引，至少列 `DoKitPlugin.kt`、`Okhttp3ClassTransformer.kt`、`PerformanceDataManager.java` 三个入口；同时说明当前源码仍依赖 Transform API，AGP 8.x 兼容性不能只按 README 的 AGP 3.3.0+ 推断。

1. [P1][原理断裂] L99-L110《Microbenchmark 测小代码段》+ L231-L256《Microbenchmark 写法要避免测错对象》
   - 问题：大纲 L48 要求覆盖 Blackhole/state，但正文只讲 setUp 与 measureRepeated，没有讲 Dead Code Elimination。AndroidX `BlackHole.kt` 明确说明 Kotlin 编译器和 R8 可能移除被测代码，应把结果传给 `BlackHole.consume`；类名为 `androidx.benchmark.BlackHole`（大写 H），不是 external-review 写的 `Blackhole`。

   - 建议：在工程形态里补 target app 依赖和 AGP 7.0+ 前提；在 Baseline Profiles 小节区分 `BaselineProfileRule.collect()` 生成 profile 与 `MacrobenchmarkRule` 验证启动/滚动收益，并修正生成设备的 API 边界。

#### P2 建议
1. [P2][数据支撑] L293-L304《CI 中的噪声控制》

#### 具体问题
1. [P0] L160 Binder transaction buffer / BINDER_VM_SIZE — [P0] 正文把 AOSP main `ProcessState.cpp` 的 `BINDER_VM_SIZE` 写成 `(1*1024*1024) - (4096 * 2)`。当前源码为 `((1 * 1024 * 1024) - sysconf(_SC_PAGE_SIZE) * 2)`；在 16KB page size 设备上可用映射区约为 1MB - 32KB，不是固定减 8KB。 建议：按源码改为 `sysconf(_SC_PAGE_SIZE) * 2`，并补一句版本边界：4KB 与 16KB 设备的 Binder transaction buffer 可用空间不同，`约 1MB` 只能作口径化描述。
1. [P0] L271-L298 `Parcel::writeBlob()` / memfd sealing — [P0] 正文写 `BLOB_INPLACE_LIMIT` 是 16 machine words（64 位约 128B），并给出 `memfd_create` + `ftruncate` + `write` + `fcntl(F_SEAL_FUTURE_WRITE)` 的直接调用链。AOSP main `Parcel.cpp` 当前为 `BLOB_INPLACE_LIMIT = 16 * 1024`；大 blob 路径调用 `ashmem_create_region("Parcel Blob", len)`，memfd/fallback 与 `F_SEAL_FUTURE_WRITE` 在 `system/core/libcutils/ashmem-dev.cpp` 的 ashmem-compatible 层完成；`art/libartbase/base/memfd.cc` 路径也不是正文写的 `bionic/libartbase/base/memfd.cc`。 建议：重写这一节源码链：`Parcel::writeBlob()` 只负责阈值判断、`ashmem_create_region`、`mmap`、immutable 时 `ashmem_set_prot_region(PROT_READ)` 和 fd 写入 Parcel；memfd/seal 作为 libcutils ashmem-compatible 实现细节单独说明，阈值改为 16KB。
1. [P2] L415-L419 使用频率统计 — “Binder ~90% 的 IPC 调用、Unix Socket ~5%”缺少统计口径：没有限定设备、进程集合、采样窗口、trace 配置或统计 SQL，容易被读者当成 AOSP 通用事实。 建议：改成“示意图/经验估计”并标注 `[待验证]`，或补一组可复现统计方法：例如基于 binder driver trace、socket syscall trace 和目标系统进程列表给出采样窗口与 SQL/脚本。

### 4.7 16KB Page Size 与 Android 性能
#### 维度评分
- 源码引用准确性：2/5；问题数：2
- 原理链完整性：3/5；问题数：0
- 版本差异覆盖：4/5；问题数：2
- 知识盲区：3/5；问题数：0
- 数据与案例支撑：4/5；问题数：0
- 交叉引用一致性：4/5；问题数：0
#### 具体问题
1. [P0] L391-L393 mTHP 与 contpte — [P0] 正文写 16KB 基础页下 contpte 是 16 个 16KB 页组成 256KB，并说单个 TLB entry 覆盖 256KB。Linux arm64 当前 `ARM64_CONT_PTE_SHIFT` 在 `PAGE_SIZE_16KB` 下默认 7，`CONT_PTES = 1 << 7 = 128`，`CONT_PTE_SIZE = 128 * 16KB = 2MB`；LWN/内核讨论也把 16K/64K contpte size 描述为 2MB。 建议：把 16KB contpte 覆盖粒度改为 2MB，并区分 mTHP 可分配的多种 folio size 与 arm64 contiguous PTE hint 的硬件压缩粒度；不要把 64KB/256KB mTHP 直接等同于 contpte TLB entry 覆盖范围。
1. [P0] L240-L247 `kCompatPageSize` 与加载分支源码锚点 — [P0] 正文称 `kCompatPageSize` 定义在 `bionic/linker/linker_phdr_16kib_compat.cpp` 行 48，并称分支在 `phdr_table_load_segment()`。AOSP main 当前 `kCompatPageSize = 0x1000` 定义在 `bionic/linker/linker_phdr.h`；调用分支位于 `ElfReader::LoadSegments()`，函数名不是 `phdr_table_load_segment()`。 建议：按当前 AOSP main 改源码锚点：常量引用 `linker_phdr.h`，分支引用 `linker_phdr.cpp` 的 `ElfReader::LoadSegments()`；如保留 commit 历史，需要注明该 commit 对应的历史文件布局。
1. [P1] L149 / L234 NDK r27 linker flags — [P1] 正文只给 `-Wl,-z,max-page-size=16384`。Android 官方 16KB 迁移文档对 NDK r27 及更低版本给出的 linker flags 是 `-Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384`；少写 `common-page-size` 会让读者的 ndk-build/CMake 修复步骤不完整。 建议：构建工具链要求与底层原理两处都补上 `-Wl,-z,common-page-size=16384`，并说明 NDK r28+ 默认满足 16KB ELF alignment，预编译 `.so` 仍需单独替换。
1. [P2] L225-L230 控制接口总览 — `pm.16kb.app_compat.disabled` 被写成“安装时预检”。官方文档把它作为强制开启/关闭 16KB backcompat 的设备属性；Android 17 还支持 `bionic.linker.16kb.app_compat.enabled=fatal` 使不兼容 binary 立即 abort。 建议：把该行改为“设备级强制关闭 compat / 配合 linker 属性控制 backcompat”，并补 Android 17 `fatal` 模式；不要把它归类为安装时预检。

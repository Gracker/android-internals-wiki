## 审查结果

### 维度 1：源码引用准确性
- 评分：3/5
- 问题数：2
- 具体问题：
  1. [P0] "schedutil 的工作流程" 节 sugov_get_util() 代码片段 — 函数签名和实现均为伪代码：返回类型写成了 `unsigned int`（实际 `void`），缺少 `unsigned long boost` 参数，函数体用 `cpu_util_cfs() + cpu_util_rt()` 简化（实际走 `effective_cpu_util()` 含 DL bandwidth / IRQ / boost 多路归并）。Linux 6.6 真实签名为 `static void sugov_get_util(struct sugov_cpu *sg_cpu, unsigned long boost)`。标注了 `@ linux-6.6` 但内容与该版本源码不符。
  2. [P1] Perfetto SQL — 两个查询使用了 `thread_state_slice` 表名。Perfetto trace processor 标准表为 `thread_state`，不含 `_slice` 后缀。`thread_state_slice` 不是 schema 中的表或视图。查询直接执行会报错。

### 维度 2：原理链完整性
- 评分：3/5
- 问题数：3
- 具体问题：
  1. [P1] PELT 机制未展开 — 全文 6 次提到 `util`/`PELT`，但未解释 PELT 的计算方式（几何级数衰减、32ms 半衰期、`sched_pelt_period`），读者无法理解"util 值怎么来的、为什么它会滞后于瞬时负载"。
  2. [P1] CPU capacity 推导缺失 — `capacity` 是 EAS 选核和 schedutil 调频的核心输入，但章节未解释它在内核中怎么确定（`arch_scale_cpu_capacity` / `/sys/devices/system/cpu/cpuN/cpu_capacity` / `max_freq × efficiency_factor`）。
  3. [P2] schedutil 与 cpufreq_driver 交互链断裂 — 从 `sugov_get_util()` 到最终频率生效，中间的 `sugov_update_next_freq()` → `cpufreq_driver->fast_switch()` / `target()` 路径未交代。读者无法理解"频率决策到实际生效"之间有多少延迟。

### 维度 3：版本差异覆盖
- 评分：3/5
- 问题数：2
- 具体问题：
  1. [P1] Android common kernel 的 schedutil 补丁未提及 — AOSP/Android common kernel 在 schedutil 上有大量客制化 patch（如 RT boost、input boost 集成、per-task boost），与上游 Linux 行为差异显著。章节引用了 Linux 6.6 源码但未区分两者。
  2. [P2] 版本演进表使用日历年而非 Android 版本 — 与全书惯例（按 Android 版本标注）不一致，且未关联具体 Android 版本引入的变化（如 Android 9 大规模采用 schedutil、Android 10 引入 EAS + uclamp）。

### 维度 4：知识盲区
- 评分：2/5
- 盲区数：3
- 具体问题：
  1. [P1] uclamp（Utilization Clamping）完全缺失 — uclamp 是 Android 影响 schedutil 和 EAS 决策的核心机制（通过 `uclamp_efficient` / `uclamp_rq_util_with`），用于 per-task boost 和 min-cap 约束。Android Framework 通过 `ScheduleGroup` / `TaskProfile` 设置 uclamp 值。缺少它，读者无法理解"为什么前台线程的 util 被 boost 了"。
  2. [P2] CPU hotplug / online-offline 未提及 — 许多 Android 设备在低负载时会把大核 offline，负载来时再 online。这个 on/off 延迟影响核心迁移的实际可用选项，也是 Perfetto 中"某些 CPU 完全没有调度活动"的解释。
  3. [P2]schedtune → uclamp 演进 — Android 从 schedtune (Android 9-10) 迁移到 uclamp (Android 11+)，这是理解版本差异的关键知识点。

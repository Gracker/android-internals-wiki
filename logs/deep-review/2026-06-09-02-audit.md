## 维度 1：源码引用准确性
- 评分：4/5
- P0/P1：0
- 复核结果：`PixelCopy.request(Window, Rect, Bitmap, listener, Handler)`、`WebViewClient.onRenderProcessGone()`、`WebViewRenderProcessClient`、`WebView.postVisualStateCallback()`、`evaluateJavascript()` 的路径、类名和方法名均可在 Android SDK sources / 官方 reference 中核对。
- 证据：
  - `android.view.PixelCopy` 在官方 reference 标为 API 26；Window + Rect 重载使用 Window backing surface，并要求 DecorView/backing surface 已存在。
  - `android.webkit.WebViewClient.onRenderProcessGone()` 在 API 26+ source/reference 中存在，文档要求退出后的 WebView 不可继续使用，应移除并清理引用，返回 true 表示应用已处理。
  - `android.webkit.WebViewRenderProcessClient` 在 android-29 sources 中存在，android-28 sources 中无该类；正文写 API 29+ 准确。
  - `WebView.postVisualStateCallback(long, VisualStateCallback)` 官方语义是当前 DOM 状态在下一次 draw 可见，并明确不包含 video tag 状态；正文边界基本准确。
- P2 观察：
  1. L160 仍把 `onPageCommitVisible()` 写成“新内容首次绘制到屏幕”。Android source/reference 的语义更细：旧导航内容不再绘制，下一次 draw 可能只是背景色或部分新页面内容；这属于既有 P2，不影响主结论。
  2. L270 的 MethodChannel 延迟 1-5ms、批量延迟 50ms+、常规误差 <20ms 仍缺少可复现实验条件；这是既有 P2 数据口径问题，不升级为 P1。

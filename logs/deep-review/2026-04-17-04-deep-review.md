## 审查结果

### 维度 1：源码引用准确性
- 评分：3/5
- 问题数：4
- 具体问题：
  1. [P1] JIT 代码片段使用虚构方法名 — 文中 `MaybeDoJitCompilation(ArtMethod* method)` 在 AOSP 中不存在。实际方法为 `Jit::MaybeCompileMethod(ArtMethod* method, Thread* self)`，位于 `art/runtime/jit/jit.cc`。虽然标注了"简化示意"，但方法名完全虚构会误导读者在 AOSP 中搜索。此外 `method->GetCounter()` 非标准 API，实际通过 `method->GetHotnessCount()` 或 interpreter 内部计数器追踪。
  2. [P1] `bg-dexopt` 术语过时 — 全文多次使用"bg-dexopt 后台编译守护进程"。Android 14+ 中后台编译由 ART Service (`com.android.art` 模块) 的 `MaintenanceJobs` 调度管理，而非独立的 `bg-dexopt` 守护进程。章节 `applicable_versions` 声明 7.0-17，但未区分 14 前后的架构差异。
  3. [P2] `hot_method_threshold_` 声明位置不准确 — 文称位于 `art/runtime/jit/jit.cc`，实际该字段在 `art/runtime/jit/jit.h` 中声明，`jit.cc` 中进行初始化。`AndroidRuntime.cpp` 解析 `dalvik.vm.jitthreshold` 的描述也需要更精确——实际上 ART 通过 `ParsedOptions.cc` 解析 `-Xjitthreshold:` 参数，`AndroidRuntime.cpp` 负责读取系统属性并构造参数字符串。
  4. [P2] JIT 代码缓存默认值缺少版本标注 — `dalvik.vm.jitinitialsize` 默认 64KB 和 `dalvik.vm.jitmaxsize` 默认 64MB 在不同 Android 版本和设备配置上可能有差异，未标注验证版本。

### 维度 2：原理链完整性
- 评分：3.5/5
- 问题数：2
- 具体问题：
  1. [P1] Deoptimization 机制完全缺失 — 这是 ART 编译管线的核心环节。当 AOT 编译的代码因类加载变化、新依赖等原因失效时，ART 必须去优化（deoptimize）回解释执行。去优化在 Perfetto 中表现为 `Deoptimization` Slice，在调试编译覆盖率时是关键观测点。作为"编译管线"章节，完全不讨论去优化就像讲 GC 不讨论 GC 触发条件。
  2. [P2] Cloud Profiles 与 Baseline Profiles 的合并策略未说明 — 第三层 Profile 提到"Cloud Profiles 会跟 Baseline Profiles 合并"，但未解释合并的优先级、冲突处理、何时生效。读者无法判断自己的 Baseline Profiles 是否会被 Cloud Profiles 覆盖。

### 维度 3：版本差异覆盖
- 评分：3/5
- 问题数：2
- 具体问题：
  1. [P1] 版本演进表存在显著空白 — applicable_versions 声明 7.0-17，但版本表只有 7 个条目（4.4/5.0-6.0/7.0/9.0/12/14/16/17），遗漏了 Android 8.0（JIT code cache 大小调整、并发 GC 改进影响编译）、10（hidden API 限制影响编译假设）、11（R8 全模式引入）、13（ Baseline Profiles 可通过 Google Play 系统更新推送）等版本的关键变更。
  2. [P2] `quicken` 编译级别描述不精确 — 称"Android 11 及以下的首次启动"，实际上 `quicken` 在 Android 7.0 引入，Android 12 被合并入 `verify`。表述应为"Android 7.0-11 可用的编译级别"。

### 维度 4：知识盲区
- 评分：3/5
- 盲区数：3
- 具体问题：
  1. [P1] 缺少 1.12 AutoFDO 章节交叉引用 — 本章用一整个小节讨论 AutoFDO（内核级 PGO），但 `related_chapters` 和正文中均未引用 1.12（AutoFDO 反馈导向编译优化）。读者可能不知道有专门章节深入讨论此主题。

  3. [P2] OEM 定制的编译策略覆盖不足 — 未提及部分 OEM 通过 `pm.dexopt.*` 系统属性覆盖默认 compiler filter 的情况。实际工作中常见的"为什么我的 App 编译级别不对"排查需要了解 OEM 定制。

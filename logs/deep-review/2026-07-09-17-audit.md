## 维度 1：源码引用准确性
- 评分：5/5
- 问题数：0
- 复核证据：
  1. `frameworks/native/libs/binder/ProcessState.cpp`（android-17.0.0_r1）仍定义 `BINDER_VM_SIZE = (1MB - page_size * 2)` 与 `DEFAULT_MAX_BINDER_THREADS = 15`，正文 Binder buffer 与线程池口径成立。
  2. `frameworks/native/libs/binder/Parcel.cpp`（android-17.0.0_r1）`Parcel::writeBlob()` 仍以 `!mAllowFds || len <= BLOB_INPLACE_LIMIT` 走 inplace，`BLOB_INPLACE_LIMIT = 16 * 1024`，否则经 `ashmem_create_region()`、`mmap()`、`ashmem_set_prot_region()`、`writeFileDescriptor()` 传 fd；正文没有把该路径误写成端到端零拷贝。
  3. `frameworks/native/libs/input/InputTransport.cpp`（android-17.0.0_r1）`InputChannel::openInputChannelPair()` 使用 `socketpair(AF_UNIX, SOCK_SEQPACKET, ...)`；`frameworks/base/core/java/android/view/InputChannel.java` 标注 `Parcelable` 且 `describeContents()` 返回 `CONTENTS_FILE_DESCRIPTOR`，正文“Binder 控制面 + socket 数据面”表述成立。
  4. `system/core/libutils/Looper.cpp`（android-17.0.0_r1）构造函数创建 `eventfd(0, EFD_NONBLOCK | EFD_CLOEXEC)` 并注册 epoll，正文未把 Android 8-17 Looper 唤醒误写为 pipe。
  5. `system/core/libcutils/ashmem-dev.cpp`（android-17.0.0_r1）仍是 ashmem-compatible 层，`use_memfd()` 受 `sys.use_memfd`、`memfd_class` capability、`ro.vendor.api_level >= 202604`、app target SDK min 37 等条件约束；`MemoryFile.java` 是 `SharedMemory` wrapper，`CursorWindow.cpp` 仍调用 `ashmem_create_region()`。正文通用共享内存 / dmabuf-heaps / FMQ 三线拆分成立。
  6. `bionic/libc/platform/bionic/reserved_signals.h`（android-17.0.0_r1）定义 `BIONIC_SIGNAL_DEBUGGER = __SIGRTMIN + 3`；`system/core/debuggerd/client/debuggerd_client.cpp` 中 Java backtrace 使用 `SIGQUIT`，native dump 使用 `BIONIC_SIGNAL_DEBUGGER`，正文 signal 锚点成立。
  7. `frameworks/native/libs/binder/RpcTransportRaw.cpp` 与 `RpcSession.cpp`（android-17.0.0_r1）走 socket transport，binder RPC 测试覆盖 `AF_VSOCK` 路径；正文 RpcBinder/vsock 不继承 Binder driver transaction buffer 的边界成立。

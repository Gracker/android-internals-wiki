### 维度 1：源码引用准确性
- 评分：2/5
- 问题数：6
- 具体问题：
  1. [P1] Python API `trace_summary()` — 正文把 `tp.trace_summary()` 写成旧版 `tp.metric()` 的替代品（"Trace Summarization" API）。Perfetto Python 包当前公开接口为 `tp.metric()`，`trace_summary()` 是否为真实方法名缺少验证。如果方法不存在或名称不同，读者照抄会直接报错。
  2. [P1] `BatchTraceProcessor.query_and_flatten()` — 方法名未经验证。`BatchTraceProcessor` 类存在于 perfetto 包，但 `query_and_flatten` 是否是真实的公开方法需要核对。实际可能是 `query()` + 手动合并，或 `metric()` + 合并。
  3. [P1] `TraceProcessorConfig(add_sql_packages=[...])` — `add_sql_packages` 参数名未经验证。Perfetto Python API 加载自定义 SQL/Proto 的方式可能是 `bin_path`、`sql_functions_path` 或其他名称，需要对照 `perfetto` 包的公开 API 确认。
  4. [P2] 冷启动 SQL 中 `s.name IN ('activityStart', 'activityResume', 'Choreographer#doFrame', 'DrawFrame')` — 四个 slice name 全部需要核实。Perfetto 中 Choreographer 的 doFrame 实际 slice name 可能是 `Choreographer#doFrame`（含 `#`），也可能是 `doFrame`；`activityStart` 和 `activityResume` 在系统 atrace 中的写法可能与 App 端自定义 Trace 不同；`DrawFrame` 在 RenderThread 中的准确名称也需要验证。正文已对 FirstFrame 标注 [待验证]，但这四个同样需要。
  5. [P2] 内置 Metric 表中 `android_simpleperf` — 该 Metric 是否为 Perfetto 标准内置 Metric 需要核对 perfetto.dev 文档。Perfetto 的标准 Metric 列表中不常见此名称。
  6. [P2] "字段号在 450–500 范围内用于本地开发" — 自定义 Metric 的 protobuf 字段号范围需要对照 Perfetto 官方文档核实，当前写法没有引用来源。

### 维度 2：原理链完整性
- 评分：3/5
- 问题数：4
- 具体问题：
  1. [P1] 自定义 Trace Point 节严重不完整 — outline 承诺覆盖 `atrace_begin / TRACE_EVENT`，但正文只写了 Java 层 `Trace.beginSection()` 一个示例就结束了。缺少：(a) Native 层 `atrace_begin()` / `atrace_end()` 的用法和性能特征；(b) Perfetto SDK 的 `TRACE_EVENT`、`TRACE_COUNTER`、`TRACE_EVENT_BEGIN/END` 等宏的使用方式；(c) Async trace point 的说明；(d) Kotlin 协程/挂起函数中的 Trace 实践。这是 outline 中明确标注的锚点，但只完成了约 20%。
  2. [P1] Perfetto SDK Native 层使用 — outline 将此列为扩展锚点，正文完全未涉及。Perfetto SDK 提供了完整的 C++ tracing API（`TraceForCategory`、`TrackEvent`、`DebugAnnotation`），这是 Native 开发者使用 Perfetto 自定义追踪的核心入口。考虑到本章定位是"高级用法"，这个缺失影响面较大。
  3. [P2] "旧版 Metric vs Trace Summarization" 过渡段 — 正文用一段话说"新项目应使用 Trace Summarization API"，但没有解释两者的接口差异、迁移路径、或官方推荐的过渡方案。读者无法判断自己的项目是否需要迁移、怎么迁移。
  4. [P2] Trace Processor 数据模型说明 — 提到了 `track` / `slice` / `counter` / `sched` 等核心表，但缺少 `flow`（跨 Track 因果关系）、`actual_frame_timeline`（帧时间线）、`android_log`（logcat）等高级表的介绍。这些表在高级分析场景中频繁使用。

### 维度 3：版本差异覆盖
- 评分：3/5
- 问题数：3
- 具体问题：
  1. [P1] Python perfetto 包的版本演进 — 正文完全没有提到 `perfetto` Python 包本身的版本变化。不同版本的 API（如 `TraceProcessor` 构造函数参数、`metric()` 方法签名）可能有差异。如果读者安装的版本与正文不一致，代码可能跑不通。
  2. [P2] `Trace.beginSection()` 的限制未充分说明 — 正文只提到"必须同一线程成对出现"。实际上 `Trace.beginSection()` 还有：(a) 名称长度限制（127 字符，超出会被截断）；(b) 不支持嵌套（在同一线程内，一个 begin 只能有一个 end，不能 begin-begin-end-end）；(c) 在 Android 12+ 中系统会自动限流（trace buffer 快满时丢弃低优先级事件）。这些限制在实际使用中很重要。
  3. [P2] 参考资料"Perfetto v52/v54 大改版"未在正文中回扣 — frontmatter 列出的参考素材提到 `android_anrs.anr_type`、`slice_self_dur`、`regexp_extract` 等新功能，正文完全未提及。如果这些与"高级用法"相关，应在正文中介绍；如果不相关，应从参考资料中移除。

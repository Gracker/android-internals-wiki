  2. [P2/仅日志记录] L516-L520 “当用户触摸屏幕时 InputDispatcher 从 WMS 获取当前所有可见 Window 的区域和 Z-order”容易被读成每次触摸同步查询 WMS。AOSP main 中 InputDispatcher 通过 `SurfaceComposerClient::addWindowInfosListener()` 接收 WindowInfo 更新，触摸命中时调用 `findTouchedWindowAtLocked()` 使用缓存的 WindowInfoHandle；WMS/SurfaceControl 侧通过 `Transaction#setInputWindowInfo()` 等路径推送窗口输入信息。建议后续编辑改为“窗口状态变化时同步/推送 WindowInfo 快照，InputDispatcher 按缓存快照做 hit-test”。

### 维度 3：版本差异覆盖
- 评分：4/5
- P0/P1：0
- 观察：
  1. [P2/仅日志记录] L405/L478 对 `android:recreateOnConfigChanges` 的版本归因过窄。AOSP `attrs_manifest.xml` 在 android-14/15/16/main 均已有该 attr，且 flags 仅 `mcc` / `mnc`；它不应写成“API 37 Beta 中的重建策略信号”。建议改为：该 attr 长期存在且只覆盖 mcc/mnc；Android 17 相关的是 target API 37 后 large-screen orientation / resizability opt-out 不再可用。
  2. [P2/仅日志记录] L477-L478 的官方参考锚点应改成 target-specific 页面：Android 16 的 `about/versions/16/behavior-changes-16`，Android 17 的 `about/versions/17/behavior-changes-17`。当前 frontmatter/表格使用 `behavior-changes-all`，不能直接支撑 target API 36/37 的 orientation、resizability、aspect ratio 口径。
  3. [通过] Predictive Back Android 15/16 口径与当前官方指南一致：Android 15 后开发者选项不再是系统动画显示前提；Android 16 增加 `PRIORITY_SYSTEM_NAVIGATION_OBSERVER`、`finishAndRemoveTaskCallback()`、`moveTaskToBackCallback()` 等回调。

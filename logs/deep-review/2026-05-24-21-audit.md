[P2] L135 — `activity_manager_native_boot_use_freezer` 写成单一配置标志不够精确。android-16.0.0_r1 `CachedAppOptimizer.updateUseFreezer()` 读取的是 `DeviceConfig.NAMESPACE_ACTIVITY_MANAGER_NATIVE_BOOT` 命名空间下的 `KEY_USE_FREEZER = "use_freezer"`，并同时支持 `Settings.Global.CACHED_APPS_FREEZER_ENABLED` 开发者选项覆盖。现文意图正确，但建议后续改成 `device_config get activity_manager_native_boot use_freezer` 这种 namespace/key 口径。
  2. [P2] L174 — `usapReceive` 作为 Perfetto 观察点仍缺源码或 trace 样本锚点。本轮复核 android-16.0.0_r1 `ZygoteServer.fillUsapPool()` 可见 `Trace.traceBegin(..., "Zygote:FillUsapPool")`，`Zygote.java` 可见 `forkAndSpecialize()` / `PostFork` 路径；未在 `frameworks/base` Java 侧命中 `usapReceive` 字符串。该点不影响 USAP 机制判断，但发布前最好补真实 trace 截图或 native ATrace 来源。

### 维度 3：版本差异覆盖
- 评分：4/5
- 问题数：0（P0/P1）
- 具体结论：
  1. Cached Apps Freezer 的 Android 11+ 主线与正文一致。官方文档写明 Android 11（API 30）或更高版本支持 cached apps freezer；android-16.0.0_r1 源码中 `CachedAppOptimizer` 仍通过 `enableFreezer()` 与 `mFreezer.setProcessFrozen(pid, uid, true/false)` 控制冻结/解冻。
  2. USAP Pool 的 Android 16 口径与正文一致。`ZygoteConfig.USAP_POOL_ENABLED_DEFAULT = false`、`USAP_POOL_SIZE_MAX_DEFAULT = 3`；`ZygoteProcess` 注释明确 USAP Pool 只支持 primary / secondary Zygote，child Zygote 不能创建或使用 USAP Pool，正文对 App Zygote / `android:useAppZygote` 的边界成立。
  3. 参考资料 L296 的 `kernel/sched/` 是 Linux / Android common kernel 路径，不属于 `platform/frameworks/base` 这类 AOSP platform tree。当前不构成事实错误，但后续可补成 `android.googlesource.com/kernel/common` 对应分支路径，减少读者误解。

## P0 — 硬伤（技术事实错误，必须修复）

### P0-1: Perfetto 配置字段名全部错误（L233-235）

**现状**:
```
name: "linux.heapprof"
heapprof_config {
    target_cmdline: "com.example.myapp"
```

**应改为**:
```
name: "android.heapprofd"
heapprofd_config {
    process_cmdline: "com.example.myapp"
```

**证据**:
- `data_source_config.proto` L303: `android.heapprofd`（非 `linux.heapprof`）
- `data_source_config.proto` L307: `heapprofd_config`（非 `heapprof_config`）
- `heapprofd_config.proto` L128: `process_cmdline`（非 `target_cmdline`）
- 来源: `android.googlesource.com/platform/external/perfetto/+/refs/heads/main/protos/perfetto/config/`

### P0-2: `adb shell heapprofd -n` 不是有效命令（L220）

**现状**: 文中列出"方式二：直接调用 heapprofd"，命令为 `adb shell heapprofd -n com.example.myapp`。

**事实**: `heapprofd` 是系统守护进程，不是用户可调用的 CLI 工具。Perfetto 官方文档推荐使用 `tools/heap_profile` 脚本（`-n` 参数指定进程名）。

**证据**: `perfetto.dev/docs/data-sources/native-heap-profiler` 明确写了三种方式：Manual configuration、`tools/heap_profile` script (recommended)、Perfetto UI Recording page。没有"直接调用 heapprofd"这种方式。

**修复建议**: 删除"方式二"，或改为 `tools/heap_profile -n com.example.myapp`。

### P0-3: `kill -SIGHUP` 不能触发 GC（L153）

**现状**: `adb shell kill -SIGHUP <pid>   # 触发 GC`

**事实**: SIGHUP（信号 1）会导致进程终止（除非被捕获）。`am dumpheap` 自带 `-g` 选项用于在 dump 前强制 GC。发送 SIGHUP 不是触发 GC 的有效方式。

**证据**: `ActivityManagerShellCommand.java` 的 `runDumpHeap()` 方法：`opt.equals("-g") -> runGc = true`，帮助文本: `-g: force GC before dumping the heap`

**修复建议**: 删除 L153，改为 `adb shell am dumpheap -g <pid> /data/local/tmp/heap.hprof`。

### P0-4: malloc_debug 信号错误——SIGUSR1 → SIGRTMAX-19（L411/415/418/421）

**现状**: 文中多处写 `SIGUSR1` 用于触发 `backtrace_enable_on_signal`。

**事实**: bionic malloc_debug README 确认使用 `SIGRTMAX - 19`（Android 上为信号 45），不是 `SIGUSR1`。

**证据**: `android.googlesource.com/platform/bionic/+/main/libc/malloc_debug/README.md`

### P0-5: 404 链接（L265）

**现状**: `https://perfetto.dev/docs/data-sources/native-heap-profiling`
**事实**: 返回 404。正确 URL: `https://perfetto.dev/docs/data-sources/native-heap-profiler`

## P1 — 重要问题（影响读者理解和实操）

### P1-1: `android:profileable="true"` 语法错误（L261）

**现状**: "声明 `android:profileable="true"`"
**事实**: `profileable` 不是 `<application>` 的属性，而是独立 manifest 元素。正确语法: `<profileable android:shell="true"/>`
**证据**: `developer.android.com/guide/topics/manifest/profileable-element`、`perfetto.dev/docs/data-sources/native-heap-profiler`

### P1-2: MTE 启用范围过于宽泛（L475）

**现状**: "Android 12+ 的系统组件已经启用了 MTE"
**事实**: 仅 3 个系统应用启用 MTE：Nfc、Bluetooth、SecureElement（均为 Async 模式）
**证据**: `source.android.com/docs/security/test/memory-safety/mte-configuration`

### P1-3: MTE "不需要重新编译"不完整（L472）

**现状**: "不需要重新编译：可以在系统层面启用，对已有应用也有效"
**事实**: heap bugs 可通过 manifest/compatibility change 启用无需重编；stack bugs 需要使用 instrumented build 重新编译
**证据**: `developer.android.com/ndk/guides/arm-mte`

### P1-4: HWASAN 版本要求误导（L457）

**现状**: "HWASAN 可用于 Android 10+ 的 AArch64 设备"
**事实**: Android 14+ 才可通过 `wrap.sh` 在非 root 设备上使用；Before Android 14 需修改系统镜像；only available on 64-bit Arm devices
**证据**: `developer.android.com/ndk/guides/hwasan`

### P1-5: libmeminfo 源码路径过时（L372）

**现状**: `system/core/libmeminfo/`
**事实**: 该路径 404。实际路径: `system/memory/libmeminfo/`
**证据**: `android.googlesource.com/platform/system/memory/libmeminfo/+/main/` → 200

### P1-6: malloc hooks 的 [已验证] 标签指向错误页面（L448）

**现状**: `[已验证: 官方文档, https://developer.android.com/ndk/guides/sanitizers]`
**事实**: 该 URL 是 sanitizers 文档，不是 malloc hooks 文档。malloc hooks 声明在 bionic `malloc.h` 头文件中（`Available since API level 28`）。

### P1-7: 交叉引用不一致（L518 vs frontmatter）

**现状**: L518 提到 4.2 和 4.3，但 frontmatter `related_chapters` 只有 `["10.1", "10.2", "10.3", "14.1", "13.1"]`。
**修复**: 补充 4.2、4.3 到 frontmatter，或确认章节存在且标题正确。

### P1-8: dumpheap 命令注释误导（L151）

**现状**: 注释 `# 触发 GC（可选但推荐）`，但命令 `adb shell am dumpheap --user 0 <pid>` 没有 `-g` 参数，不会触发 GC。`--user` 是指定用户 ID，与 GC 无关。

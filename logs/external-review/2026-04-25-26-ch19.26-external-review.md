## 四、P0 问题（事实错误）
- **[P0][源码准确性][H5 白屏检测]**
- **原文问题**：大纲中提到“基于 Native 层的屏幕像素截帧（Bitmap 采样）对比法”。
- **风险点**：若正文推荐使用 `View.draw(Canvas)` 采样，会导致严重的 UI 卡顿（Jank）。
- **源码 / 一手资料锚点**：`android.view.PixelCopy` (API 26+)。
- **运行原理说明**：`PixelCopy.request()` 通过监听硬件渲染器的输出，在渲染线程或 GPU 侧完成拷贝，完全不阻塞 UI 线程。
- **建议修正方向**：正文必须明确区分旧版（API < 26）的同步 `draw` 方案与新版的异步 `PixelCopy` 方案。

## 五、P1 问题（重要缺失）
- **[P1][原理链完整性][Flutter APM 融合]**
- **原文问题**：仅提到“UI/Raster 线程卡顿如何暴露”。
- **缺失内容**：未提及 **`FrameTiming` API** 这一 Flutter 官方标准性能接口。
- **运行原理说明**：Flutter 的 `window.onReportTimings` 提供 `buildDuration` 和 `rasterDuration`，是区分业务逻辑卡顿还是引擎渲染卡顿的唯一依据。
- **建议补充方向**：补充 `FrameTiming` 与 Android `Choreographer` 信号的对齐逻辑。

- **[P1][版本差异覆盖][WebView 进程监控]**
- **缺失内容**：Android 12+ 针对 WebView 渲染进程独立化的监控。
- **源码锚点**：`android.webkit.WebViewRenderProcessClient`。
- **建议补充方向**：在监控维度中加入“渲染进程稳定性”监控（如 `onRenderProcessGone` 处理）。

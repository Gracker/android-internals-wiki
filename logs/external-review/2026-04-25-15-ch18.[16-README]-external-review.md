## 四、技术审计详情

### 16-game-engine.md (游戏引擎渲染链路)
- **[P1][版本差异]**：文中提到 `SurfaceView` 从 Android 14 起支持 arbitrary alpha，这不仅是 API 的增强，更是合成器（Compositor）逻辑的改变（从 Hole Punch 模式升级为 Alpha Blended Composite）。建议补充：若 `setZOrderOnTop(true)`，透明度直接应用到 Surface 内容；若为默认 Z-Below，透明度应用到“打孔”上。
- **[可复用资产]**：Swappy 的 Vulkan 集成顺序极度敏感，文中描述的 `SwappyVk_determineDeviceExtensions` 必须在 `vkCreateDevice` 之前调用的结论已通过 AOSP 核验。

### 17-hardware-buffer-renderer.md (Hardware Buffer Renderer)
- **[P1][源码准确性]**：Java 层的 `HardwareBufferRenderer.RenderResult` 方法名为 `getFence()`，返回 `SyncFence` 对象。文中部分位置可能存在 `getSyncFence()` 的潜在混淆（AndroidX 风格），应统一为原生 SDK 命名的 `getFence()`。
- **[P1][版本差异]**：NDK 部分提到的 `ASurfaceTransaction_setBufferWithRelease` 准确标记为 API 36 (Android 16)，但需强调此 API 的核心优势是解决了 `OnComplete` 无法精确感知单个 Buffer 释放时机的痛点。

### 18-pip-freeform.md (PIP 与自由窗口渲染)
- **[P2][原理链]**：在分析 Freeform Resize 错拍时，建议补充：Android 12+ 的 Shell Transition 将窗口管理和动画逻辑从 System Server 剥离到 SysUI 进程，这使得分析 `WindowContainerTransaction` 时的轨迹更集中。

### 19-variable-refresh-rate.md (可变刷新率渲染管线)
- **[P0][版本差异]**：文中将 ARR 主体归为 Android 15-QPR1+，需精准修正：`View.setRequestedFrameRate` 是 **API 35 (Android 15)** 引入，而 `Display.hasArrSupport()` 是 **API 36 (Android 16)** 引入。读者在 API 35 上无法调用 `hasArrSupport`。
- **[可复用资产]**：SQL 示例中使用的 `android_frames.timeline` 模块是 Perfetto 标准库的最佳实践，建议保留。

### 20-pipeline-analysis-methodology.md (渲染管线分析方法论)
- **[P2][实战性]**：`dumpsys SurfaceFlinger --latency` 在现代 Android (BLAST 架构) 下的参考价值正在下降，建议在方法论中增加对 **Winscope** (SurfaceFlinger trace) 的优先级推荐。

### 21-eyedropper-crossdevice.md (EyeDropper API)
- **[P1][原理链]**：对于 API 37 (Android 17) 的 EyeDropper，需明确指出其隐私隔离机制：系统会拦截 `secure window` 和 `protected buffer` 的像素，返回的 `EXTRA_COLOR` 将被强制置黑。

- **源码 / 一手资料锚点**：Perfetto `android.gpu.renderstages` 数据源（Android 10+ 支持）。
- **关键代码逻辑**：Vulkan 渲染管线的 Binning/Rendering/Clears 阶段需要通过专门的渲染阶段轨道观测。
- **运行原理说明**：如果不开启 renderstages，开发者只能看到 GPU Busy 情况，无法看到具体的 RenderPass 耗时分布，这对于 Vulkan 游戏的 DrawCall 优化和 Overdraw 分析是致命缺失。
- **建议补充方向**：明确建议开启 `android.gpu.renderstages`，并提及某些设备需 `adb shell setprop security.perfetto.gpu_counters.privileged 1` 权限。

- [P1][原理链完整性][Headroom API 风险点]
- **原文问题**：虽然提到了 Headroom API 的 1ms+ 耗时，但未明确强调其在 120Hz/144Hz 游戏中的“破坏性”。
- **核验结论**：在 120fps 下，一帧只有 8.33ms。1ms 的同步 Binder 阻塞意味着消耗了 12% 的帧预算。
- **建议修正方向**：在“Android 16：ADPF Headroom API”小节中，进一步强调严禁在渲染主线程调用，建议采用低频异步轮询模式。

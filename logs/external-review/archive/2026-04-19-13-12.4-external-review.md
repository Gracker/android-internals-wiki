## 五、P1 问题（重要缺失）

- [P1][知识盲区][实战落地：Perfetto 观测]
  - **原文问题**：“在 Perfetto 中，一次 TLS 握手对应 cronet 或 okhttp track 中一段连续的 connect + handshake 区域”
  - **缺失内容**：OkHttp 默认**不会**在 Perfetto 中自动输出 `ATRACE` (Trace track)。
  - **运行原理说明**：Cronet 作为底层 C++ 库，深度集成了系统的 base/tracing；但 OkHttp 是纯 Java 层网络库，如果不显式注入追踪代码，系统层面的 Perfetto 是看不到 `okhttp` track 和具体的 `dns` / `handshake` 阶段的。
  - **为什么这是重要缺失**：读者如果直接打开 Perfetto 抓取纯 OkHttp 的应用，会发现根本找不到这段 track，导致实战排查方法失效。
  - **建议补充方向**：必须说明：若要在 Perfetto 中观测 OkHttp 耗时，需要自定义 `okhttp3.EventListener`，在 `connectStart` 和 `secureConnectEnd` 等回调中手动调用 `android.os.Trace.beginSection("TLS_Handshake")`。

- [P1][原理链完整性][ECH 机制]
  - **原文问题**：“ECH 的工作流程依赖 DNS-over-HTTPS（DoH）或 DNS-over-TLS（DoT）：客户端先通过加密 DNS 查询获取目标域名的 ECH 公钥配置...”
  - **缺失内容**：没有解释**为什么**强烈依赖 DoH/DoT。
  - **运行原理说明**：ECH 的公钥存在 DNS 的 HTTPS (Type 65) 记录中。如果通过明文 UDP 端口 53 请求 DNS，网络中间商（ISP / 防火墙）可以直接篡改或丢弃该 HTTPS 记录的响应。这称为“降级攻击（Downgrade Attack）”。这种情况下，客户端因为没拿到 ECH 密钥，只能退化为明文 SNI（如果平台策略允许），从而导致 ECH 形同虚设。
  - **为什么这是重要缺失**：讲清楚“降级攻击”，读者才能深刻理解加密 DNS 和 ECH 的绑定关系，不仅仅是为了“找公钥”，而是为了“防篡改”。
  - **建议补充方向**：在 ECH 原理部分补充一句关于明文 DNS 下“降级攻击”的风险机制。

- [P1][知识盲区][OkHttp 0-RTT 支持]
  - **原文问题**：“OkHttp 从 4.x 版本开始支持 TLS 1.3，但默认不启用 0-RTT，需要开发者手动配置。”
  - **缺失内容**：过于轻描淡写，掩盖了 Android 上配置 0-RTT 的复杂性。
  - **运行原理说明**：OkHttp 的 API 并没有类似 `client.enable0Rtt()` 的简单开关。在 Android 上，要真正启用 0-RTT，通常需要直接通过 Conscrypt API（如 `Conscrypt.setUseSessionTickets(sslSocket, true)`）来干预 SSLSocket 的创建，并且开发者需要自行控制仅在幂等请求（GET）时发送 early data，防止重放攻击。
  - **为什么这是重要缺失**：给读者传递了“只要改个配置就能用 0-RTT”的错觉，实际落地时会碰壁。
  - **建议补充方向**：明确说明 OkHttp 目前对 0-RTT 的支持依赖底层安全提供者（Conscrypt），需要通过 `SSLSocketFactory` 和 Conscrypt 专有 API 才能完整开启。

- **可复用的技术结论**：**OkHttp Perfetto Trace 原理**。OkHttp 作为 Java 库，本身没有引入 `android.os.Trace`。要在 Perfetto 分析 OkHttp 的 TCP/TLS 耗时，最佳实践是：
  ```kotlin
  class PerfettoEventListener : EventListener() {
      override fun dnsStart(call: Call, domainName: String) {
          Trace.beginSection("OkHttp_DNS")
      }
      override fun dnsEnd(call: Call, domainName: String, inetAddressList: List<InetAddress>) {
          Trace.endSection()
      }
      // 同理实现 connectStart/connectEnd/secureConnectStart/secureConnectEnd
  }
  ```
  将其通过 `eventListenerFactory` 注册到 `OkHttpClient` 中，即可在 Perfetto 中精准分析 TLS 时延。
- **为什么值得保留**：这是解决网络优化排查“睁眼瞎”的最有效实战手段，属于极具价值的工程资产。

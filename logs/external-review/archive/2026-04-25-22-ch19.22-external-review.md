## 四、 P1 问题（重要缺失）

### 1. [P1][版本差异][AndroBench SQLite 陷阱]
- **原文位置**：`## AndroBench：Micro 和 SQLite`
- **原文问题**：未提及 Android 10+ 上 SQLite 跑分暴跌现象。
- **技术背景**：AndroBench 手动设置 `journal_mode=WAL`，在旧版本 Android 上会自动对应 `synchronous=NORMAL`。但在 Android 10+ 中，若非通过官方 API 开启 WAL，系统常默认 `synchronous=FULL`，导致每次事务必触发 `fsync`，TPS 会从 4000+ 跌至 500-。
- **建议修正方向**：补充“版本避坑指南”，解释为什么在新设备上 AndroBench 数据不可直视，建议结合 `sqlite3` 命令或自定义测试代码验证。

### 2. [P1][知识盲区][专业工具：fio]
- **原文问题**：全文未提及 `fio`。
- **技术背景**：`fio` (Flexible I/O Tester) 是 AOSP 开发者和存储厂商唯一认可的底层工具。它支持 `ioengine=psync` 和 `direct=1`，能精确控制块大小和 IO 深度。
- **建议补充方向**：增加“进阶工具：fio”小节，给出 adb 推送可执行文件及运行 4K 随机写测试的命令示例。

### 3. [P1][知识盲区][现代工具：CPDT]
- **原文问题**：过度依赖过时的 A1 SD Bench。
- **技术背景**：`CPDT` 支持实时速度曲线。对于 UFS 存储，观察写入过程中是否因为 Thermal Throttling 或 GC 导致的“掉速抖动”比看平均分重要得多。
- **建议补充方向**：引入 `CPDT` 实时速度图的概念。

## 五、P1 问题（重要缺失）

- [P1][原理链完整性][基本用法]
- **原文问题**：只展示了 Kotlin `trace {}` 块，未提及 Java 侧的异常安全要求。
- **源码 / 一手资料锚点**：`androidx.tracing.Trace` (Java API)
- **关键代码逻辑**：`trace {}` 内部通过 `try-finally` 保证了 `endSection` 必定触发。Java 用户若直接调用 `beginSection`/`endSection` 且未加 `try-finally`，一旦代码抛出异常，会导致整个线程后续的 Trace 嵌套全部乱序。
- **运行原理说明**：Atrace 栈是基于线程局部的，必须配对。
- **建议修正方向**：补充 Java 侧使用 `try-finally` 的标准代码示例。

- [P1][知识盲区][同步和异步区间要分开]
- **原文问题**：未提及协程挂起（Suspension）对同步 Trace 的破坏性影响。
- **关键代码逻辑**：在协程中使用 `trace("section") { ... }` 时，若包含 `delay` 或 `withContext` 等挂起点，协程挂起后线程可能去执行其他任务，但 `endSection` 尚未调用。这会导致 Perfetto 视图中出现极长的、错误的 Slice 占用。
- **核验结论**：这是现代 Android 开发中最常见的 Tracing 错误。应引导用户在协程中使用 `Trace.beginAsyncSection` 或使用 `androidx.tracing:tracing:2.0.0-alpha` 引入的 `traceCoroutine`。
- **建议补充方向**：增加“协程陷阱”说明，警告不要在包含挂起点的代码块中使用同步 `trace {}`。

- [P1][原理链完整性][线上关系]
- **原文问题**：缺失与 JankStats Context 的集成说明。
- **缺失内容**：大纲明确要求说明 trace 名称如何与 JankStats context 建立同名索引。
- **为什么这是重要缺失**：JankStats 的 `PerformanceMetricsState` 提供的状态标记（如 `Home#Scrolling`）应当与 `androidx.tracing` 的 Slice 名称对齐，这样在线下 Perfetto 分析和线上 Jank 数据之间才能建立“共同语言”。
- **建议补充方向**：在“线上和线下边界”或“线上指标关联”部分，增加如何将 Trace 名称与 `JankStats` 的 `putState` 字段对齐的建议。

- [P1][原理链完整性][和 btrace、Perfetto SDK 的区别]
- **原文问题**：缺失 Macrobenchmark Trace Section 的分工。
- **缺失内容**：文中区分了 btrace 和 Perfetto SDK，但漏掉了 Macrobenchmark。
- **为什么这是重要缺失**：在编写 Macrobenchmark 时，通常会用 `androidx.tracing` 在 App 侧打标，然后在 Benchmark 侧通过 `FrameOverrun` 或自定义追踪区间进行校验。

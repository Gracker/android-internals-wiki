## 四、P0 问题（事实错误）
- **[P0][版本差异覆盖][全文]**
- **原文问题**：标称支持 Android 17，但未提及 Android 17 对 `MessageQueue` 的彻底重构——DeliQueue。
- **源码 / 一手资料锚点**：`frameworks/base/core/java/android/os/MessageQueue.java` (Android 17 Cinnamon Bun), `googleblog.com` 关于 DeliQueue 的技术分享。
- **关键代码逻辑**：Android 17 引入无锁（Lock-free）Treiber 栈替代监视器锁，解决了输入事件分发时的优先级反转和锁竞争。
- **运行原理说明**：DeliQueue 允许 `InputDispatcher` 和 `Looper` 在无锁状态下交换消息，大幅降低了输入抖动（Jitter）。
- **核验结论**：标称支持版本与实际内容不符。
- **建议修正方向**：在“调度优化”或“Android 17 特性”小节中加入 DeliQueue 的技术原理及其对输入延迟（掉帧率减少 4%-7.7%）的影响。

## 五、P1 问题（重要缺失）
- **[P1][原理链完整性][预测输入小节]**
- **原文问题**：对 `MotionPredictor` 的版本演进描述止步于 API 34。
- **缺失内容**：Android 16 引入的 `hasArrSupport()`、`getSuggestedFrameRate()` 以及系统级预测 API 的标准化。
- **版本差异**：Android 16+ 优先调用底层 `inputflinger` 的原生预测实现，而非 Jetpack 的启发式算法。
- **为什么这是重要缺失**：开发者若不了解 Android 16 的系统级标准化，可能仍在使用低效的旧版库实现，无法利用硬件加速。
- **建议补充方向**：细化 API 34 (14)、API 35 (15)、API 36 (16) 的演进差异。

- **[P1][源码准确性][Perfetto 分析小节]**
- **原文位置**：`ViewRootImpl.java` 中的 `InputMetricsListener`。
- **源码锚点**：`frameworks/base/core/java/android/view/ViewRootImpl.java` (Android 16.0.0_r1)。
- **关键代码逻辑**：`reportTimeline` 的参数在最新 AOSP 中确认为 `(int inputEventId, long gpuCompletedTimeNanos, long presentTimeNanos)`。
- **建议修正方向**：核实并补充 `android_input_id` 的生成时机（通常在 `InputPublisher::publishMotionEvent` 时生成）。

## 五、P1 问题（重要缺失）
- [P1][原理链完整性][ANR Signal Handler 实现]

  - 缺失内容：拦截 `SIGQUIT` (信号 3) 是线上 ANR 监控的高阶方案（如 Matrix 的实现）。系统在发生 ANR 时会发送 `SIGQUIT`。APM 通过信号处理函数拦截此信号，可以在系统生成 traces 文件的同时，在端侧快速获取堆栈和运行时状态。
  - 建议修正方向：补充一小节“高阶方案：SIGQUIT 信号拦截”，解释 APM 如何抢在 `SignalCatcher` 之前（或配合它）获取 ANR 现场。

- [P1][知识盲区][ProfilingManager 与定向全量采样]
  - 原文问题：在“监控数据的采样策略”中，未提及 Android 15/16 最核心的自动化采样工具。
  - 源码 / 一手资料锚点：`android.os.ProfilingManager`, `TRIGGER_TYPE_ANR` (API 36)。
  - 缺失内容：Android 15+ 的 `ProfilingManager` 允许应用注册“系统触发分析”。在 Android 16 中，系统检测到 ANR 或启动超标时，可以直接触发一段 Perfetto 采样并回传给应用。这正是文中“定向全量采集”的最优实现。
  - 建议补充方向：将 `ProfilingManager` 显式列为“异常触发补证据”的首选方案，并简述 API 36 自动化触发器的优势（利用系统环形缓冲区追溯历史现场）。

- [P1][源码准确性][ApplicationExitInfo 的 Native Crash 支持]
  - 原文问题：仅讨论了其在 ANR 中的应用。
  - 源码 / 一手资料锚点：`REASON_CRASH_NATIVE`, `getTraceInputStream()` (API 31+)。
  - 缺失内容：在 Android 12+ 之后，`ApplicationExitInfo` 的 trace stream 对于 Native 崩溃可以返回 Protobuf 格式的 Tombstone。这是线上监控 Native 稳定性的关键数据源。
  - 建议补充方向：补充说明 `ApplicationExitInfo` 在监控 Native 崩溃方面的扩展能力。

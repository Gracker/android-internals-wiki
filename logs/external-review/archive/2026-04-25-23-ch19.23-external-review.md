## 五、P1 问题（重要缺失/误导）

- **[P1][源码准确性][2.2 EventListener 示例代码]**
  - **原文问题**：提供的 `NetworkMetricEventListener` 类内部使用了 `mutableListOf(Attempt())` 等实例变量，但未说明其注册方式。
  - **源码 / 一手资料锚点**：`okhttp3.OkHttpClient.Builder#eventListener(EventListener)` 会为所有 Call 使用同一个实例；而 `eventListenerFactory(EventListener.Factory)` 才会为每个 Call 创建新实例。
  - **为什么错**：如果读者按照常见的单例模式将此 Listener 传给 `OkHttpClient`，由于 OkHttp 的请求是并发的，多个请求会竞争同一个 `attempts` 列表，导致数据完全错乱且存在内存泄漏。
  - **建议修正方向**：在代码注释或正文中明确指出该实现必须配合 `EventListener.Factory` 使用，或者展示如何通过 `Factory` 来实例化该类。

- **[P1][源码准确性][4.2 PLT Hook 符号职责]**
  - **原文问题**：文中提到 `send / recv`：明文传输字节数；`SSL_write / SSL_read`：TLS 封装后的读写。
  - **核验结论**：对于 HTTPS 请求，`SSL_write/SSL_read` 处理的是加密前的**明文**数据；而 `send/recv` 是系统调用层，处理的是经过 TLS 封装后的**密文**数据。
  - **为什么错**：描述刚好相反。这会误导开发者在实现 Native 抓包时挂载错符号，导致拿到的全是乱码。
  - **建议修正方向**：更正为：`SSL_write/read` 负责拦截**解密前/加密后**的业务明文；`send/recv` 负责拦截 **Socket 层传输的原始（加密）数据**。

- **[P1][逻辑完整性][3. 字节码插桩范围]**
  - **原文问题**：插桩范围建议优先使用 `PROJECT`。
  - **逻辑矛盾**：本节锚点要求“Hook HttpURLConnection 和三方 SDK 内部封装的网络请求”。
  - **为什么这是缺失**：在 AGP 中，`InstrumentationScope.PROJECT` 仅作用于当前模块代码。由于 `HttpURLConnection` 的调用通常散落在各个三方 SDK（如广告、地图 SDK）中，如果不开启 `InstrumentationScope.ALL`，APM 根本无法捕获到这些 SDK 的行为。
  - **建议修正方向**：明确说明若要覆盖三方 SDK，必须使用 `InstrumentationScope.ALL`，并补充在 `ALL` 作用域下如何通过包名过滤来控制编译开销。

## 六、P2 问题（建议改进）

- **[P2][原理链完整性][3. ASM Hook 细节]**
  - **问题描述**：ASM 伪代码仅展示了 `openConnection()` 的替换。
  - **建议**：实战中 `URL.openConnection(Proxy)` 也是极常用的重载版本，且 `URL.openStream()` 内部也会触发连接。建议在“工程边界”段落提醒读者注意重载方法的覆盖。

- **[P2][知识盲区][2.2 EventListener 阶段重叠]**
  - **问题描述**：文中提到“复用连接时 DNS/TCP/TLS 字段可能为空”，描述准确。
  - **建议**：补充一点：在 HTTP/2 多路复用场景下，只有第一个请求会触发 `connectStart`，后续并发请求会直接从 `connectionAcquired` 开始。这对于解释为何看板上大量请求没有建连耗时非常关键。

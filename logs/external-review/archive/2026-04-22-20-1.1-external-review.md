## 四、P1 问题（重要缺失）

- [P1][原理链完整性][Android 经典五层架构]
- **原文问题**：仍沿用 Linux Kernel 为最底层的五层架构图。
- **源码 / 一手资料锚点**：`packages/modules/Virtualization/` (AVF), `source.android.com/docs/core/architecture/virt`
- **关键代码逻辑**：pKVM 运行在 EL2，Android (Host) 运行在 EL1。pVM (如 Microdroid) 实现安全负载隔离。
- **运行原理说明**：Android 16 中，AVF 不再仅用于安全，还支撑了 Linux 终端（Ferrochrome）等通用功能。
- **为什么这是重要缺失**：现代 Android 性能分析已涉及跨虚拟机开销（virtio-fs, vCPU 调度），只看 5 层模型会丢失 EL2 层的盲区。
- **建议修正方向**：在“五层架构”之前或之后，增设“现代架构补充：虚拟化层 (AVF)”小节，说明 pKVM 对系统拓扑的改变。

- [P1][版本差异覆盖][Android 16 架构层面的最新变化]
- **原文问题**：遗漏了 Android 16 最核心的发布制度变更。

- **缺失内容**：Major (Q2) 与 Minor (Q4) SDK 发布周期的架构影响。
- **为什么这是重要缺失**：Minor 版本不包含不兼容的架构变更，这改变了开发者对“版本升级”的预期。
- **建议补充方向**：在 Android 16 章节明确提及双发布周期对 API 和架构稳定性的影响。

## 四、P0 问题（事实错误）
- [P0][源码准确性][Microbenchmark API 限制]
- **原文问题**：描述 Microbenchmark 最低 API 为 14。
- **源码 / 一手资料锚点**：`androidx.benchmark.junit4.BenchmarkRule`
- **关键代码逻辑**：Microbenchmark 依赖现代 AndroidJUnit4 运行器及特定的性能隔离技术。
- **核验结论**：官方推荐最低 API 为 **21**。API 14 (ICS) 虽在极早期实验版中提及，但当前 Jetpack 库的主流稳定版均要求 21+。
- **为什么错**：混淆了旧版 Android 测试库与现代 Jetpack Benchmark 库的边界。
- **建议修正方向**：修正为 API 21。

## 五、P1 问题（重要缺失）
- [P1][知识盲区][缺失 Monkey 工具]
- **原文问题**：全篇未提及 Monkey。
- **缺失内容**：Monkey 压力测试在性能自动化中的位置。
- **为什么这是重要缺失**：自动化性能测试不只是测“速度”，还包括测“稳定性”和“长时间运行下的资源泄漏”。Monkey 是探测 OOM 和 ANR 的最廉价且高效的自动化手段。
- **建议补充方向**：在“自动化工具”分类中增加 Monkey，说明其在压力测试和稳定性测试中的角色。

- [P1][知识盲区][缺失 SoloPi / Appium]
- **原文问题**：未提及三方自动化/性能专项工具。
- **缺失内容**：SoloPi (支付宝开源) 的非侵入式性能监控能力。
- **为什么这是重要缺失**：在真实工程中，SoloPi 常用于快速测量启动耗时和录制性能脚本，其视觉拆帧算法比系统 API 更接近用户感知。
- **建议补充方向**：补充 SoloPi 作为专项性能测试工具的推荐，对比其与 Macrobenchmark 的使用场景差异。

- [P1][版本差异覆盖][指标 API 级别限制缺失]
- **原文问题**：未注明 `FrameTimingMetric` 的高级指标限制。
- **核验结论**：`frameOverrunMs` 等精确掉帧指标仅在 **API 31+** 可用；`StartupTimingMetric` 的 TTFD 依赖开发者正确调用 `reportFullyDrawn()` 且在 **API 30+** 统计更准。
- **建议补充方向**：在指标介绍表单中增加 API 版本限制列。

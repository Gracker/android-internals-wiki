## 五、P1 问题（重要缺失）

### [P1][源码准确性][Metrics List] 缺失 `GPU_DURATION` (API 31+)
- **原文问题**：主要指标表中漏掉了 API 31 引入的 `GPU_DURATION`。
- **源码锚点**：`android.view.FrameMetrics#GPU_DURATION` (Index 12)
- **核验结论**：在 Android 12+ 中，该指标是判断“GPU 渲染压力”最直接的证据。
- **为什么重要**：现代性能优化需要区分 CPU 瓶颈（Layout/Draw）和 GPU 瓶颈（Shader/Overdraw）。
- **建议修正方向**：在主要指标表中加入 `GPU_DURATION`，并说明其在 API 31+ 的可用性。

### [P1][源码准确性][代码示例] `FrameMetricsTracker` 存在生命周期 Bug
- **原文位置**：`接入方式` 章节的代码块。
- **原文问题**：`stop()` 方法调用了 `thread.quitSafely()`。
- **源码锚点**：`android.os.HandlerThread#quitSafely()`
- **运行原理说明**：一旦 `HandlerThread` 被退出，其关联的 `Looper` 将停止工作。再次调用 `start()` 时，`handler` 依然指向旧的（已关闭的）Looper，导致监听失效。
- **为什么是 P1**：该代码作为“推荐做法”会误导开发者写出无法二次启动的监控组件。
- **建议修正方向**：在 `start()` 中创建线程，或者在 `stop()` 中不彻底销毁线程（如果考虑复用），或者在 `start()` 时检查线程状态。

### [P1][版本差异覆盖][代码示例] `DEADLINE` 缺乏版本守护
- **原文位置**：`DEADLINE 让高刷新率口径更稳` 章节的代码块。
- **原文问题**：直接使用了 `metrics.getMetric(FrameMetrics.DEADLINE)` 且没有版本判断。
- **源码锚点**：`FrameMetrics.DEADLINE` (API 31)
- **为什么是 P1**：虽然编译器会内联常量，但在 API 31 以下设备运行这段代码，如果开发者直接引用类字段会触发 `NoSuchFieldError`，且 `getMetric(13)` 会返回 `-1`。
- **建议修正方向**：代码块应增加 `if (Build.VERSION.SDK_INT >= 31)` 或在说明中明确标注。

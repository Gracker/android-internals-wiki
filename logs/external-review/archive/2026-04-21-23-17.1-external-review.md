## 五、P1 问题（重要缺失）
1.
- **[P1][源码准确性][应用冻结技术/cgroup freezer]**
- **原文问题**：“在 AOSP 中，这个机制由 ActivityManager 的 `setProcessFrozen` 和 `enableFreezer` 两个隐藏 API 控制。”
- **源码 / 一手资料锚点**：`frameworks/base/core/java/android/os/Process.java` 以及 `frameworks/base/services/core/java/com/android/server/am/CachedAppOptimizer.java`
- **关键代码逻辑**：`setProcessFrozen` 实际上是 `android.os.Process` 类里的 native 方法，而不是 ActivityManager 的 API。在 Framework 层面，是 `ActivityManagerService` 内部的 `CachedAppOptimizer` 通过计算 OOM Adj，最终调度并调用了 `Process.setProcessFrozen(pid, app.uid, true)`。
- **为什么这是重要缺失**：指错了最核心的源码位置，如果读者去 ActivityManager 中搜索这两个 API，会一无所获，破坏了 AIW 源码级指导的初衷。
- **建议补充方向**：更正 API 的归属，指明由 `android.os.Process.setProcessFrozen` 执行底层冻结，而在 Framework 层由 `CachedAppOptimizer` 统筹调用策略。

2.
- **[P1][知识盲区][应用冻结技术/cgroup freezer]**
- **原文问题**：只提到了进程被挂起，不占用 CPU 时间，但完全没有提到进程冻结对跨进程通信（Binder）的致命影响。
- **缺失内容**：当其他活跃进程（或系统服务）试图向被冻结的进程发起 Binder 调用时，会发生什么？
- **运行原理说明**：如果是**同步 Binder 请求**发给被冻结的进程，由于目标处于 SIGSTOP/cgroup freeze 状态无法响应，系统为了防止发起端线程死锁（长时间挂起），会直接**杀死**被冻结的进程并返回错误。如果是**异步 (Oneway) 请求**，消息会被缓存在内核缓冲区中，若积压过多导致缓冲区溢出，进程同样会被杀。
- **为什么这是重要缺失**：这是开发者在线上排查中遇到“Cached Apps Freezer 导致 App 莫名其妙死亡”的最常见原因。了解这一点，读者才能真正明白在实战中如何应对冻结（例如使用 Foreground Service 提升状态避免被冻结）。
- **建议补充方向**：在“cgroup freezer”小节末尾或“常见问题”小节中，补充说明冻结进程在处理 Binder 调用时的行为差异和系统的查杀机制。

### 9.4 可复用知识资产（高价值新增知识）
1.
- 章节：17.1
- 一手资料链接：[Cached Apps Freezer 官方文档](https://source.android.com/docs/core/perf/cached-apps-freezer)
- 关键源码路径：`frameworks/base/core/java/android/os/Process.java` (`setProcessFrozen`) 以及 `CachedAppOptimizer.java`
- 关键类 / 方法 / 字段：`CachedAppOptimizer`, `Process.setProcessFrozen`
- 关键调用链 / 代码逻辑摘要：当进程进入 `CACHED` 状态且经过一定延迟（DebounceTimeout），`CachedAppOptimizer` 通过内部 Handler 触发 JNI 方法 `Process.setProcessFrozen`，将 cgroup 的 `cgroup.freeze` 置为 1。
- 版本差异摘要：Android 11 QPR3 正式引入基于 cgroup v2 freezer；在 Android 14 中进一步加强了与 OEM（如 Samsung）的后台管理 API 规范和一致性。
- Trace / Perfetto 观察点：在 Perfetto 中可直接观察到名为 `Freezer` 的 Track，冻结时进程线程会彻底从 CPU 调度队列中消失。
- 可直接复用的技术结论：通过 cgroup 冻结的进程不仅是不占 CPU，更关键的是**当它被同步 Binder 唤醒时往往会遭遇系统防死锁机制的直接“击杀”**。
- 为什么这条知识值得保留：这是连接“系统底层冻结原理”与“App 日常诡异死亡 Bug”之间最直接的桥梁，是极具实战指导意义的高手经验。

## 四、P0 问题（事实错误）
- [P0][源码准确性][Android 文字渲染管线全景]
- **原文问题**：文中给出的 `SkiaCanvas::drawGlyphs` 代码片段显示其内部使用 `SkTextBlobBuilder` 并最终调用 `mCanvas->drawTextBlob`。
- **源码锚点**：`frameworks/base/libs/hwui/SkiaCanvas.cpp` (Android 12+ / API 31+).
- **核验结论**：在 API 31 引入 `Canvas.drawGlyphs` 后，对应的 Native 实现 `SkiaCanvas::drawGlyphs` 直接调用 Skia 的 `canvas->drawGlyphs` 指令，不再经过 `SkTextBlobBuilder` 封装。文中描述的是旧版 `drawText` 或 `drawTextRun` 的某些变体行为。
- **为什么错**：混淆了 `drawText` (构建 TextBlob) 和 `drawGlyphs` (直接绘制已测量的字形) 的路径。
- **建议修正方向**：更新代码片段，明确 `drawGlyphs` 路径的简洁性，并区分它与 `drawText` 的不同。

## 五、P1 问题（重要缺失）
- [P1][原理链完整性][PrecomputedText]
- **原文问题**：对 `PrecomputedText` 的描述为“不替代最终布局”，表述模糊。
- **源码锚点**：`android.graphics.text.MeasuredText` (API 29+).
- **运行原理说明**：`PrecomputedText` 核心在于持有了 Native 层的 `MeasuredText`。当 `StaticLayout` 构建时，如果发现输入是 `PrecomputedText`，会调用 `MeasuredText.getNativePtr()`，直接在 Native 层跳过 `computeLayout`。
- **缺失内容**：未明确指出它在 Native 层跳过了最耗时的 Shaping 和 Line Breaking。
- **建议补充方向**：明确提及 `android.graphics.text.MeasuredText` 的角色。

- [P1][知识盲区][版本演进]
- **问题描述**：遗漏了 Android 15/16 对 **16-KB Page Size** 的支持对渲染性能的影响。
- **为什么重要**：16-KB 页大小对内存密集型的字体缓存和 Atlas 内存对齐有显著性能提升/适配要求，是 AOSP 近期高频变动点。

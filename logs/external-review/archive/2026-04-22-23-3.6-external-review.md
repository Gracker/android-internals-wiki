## 五、P1 问题（重要缺失）

- [P1][源码准确性][GestureDetector 双击判定]
- **原文位置**：`GestureDetector：手势状态机的设计哲学` -> `双击检测机制` -> 第 3 点
- **原文问题**：原文称双击判断通过 `mAlwaysInTapRegion` 检查位移。
- **源码 / 一手资料锚点**：`frameworks/base/core/java/android/view/GestureDetector.java` -> `isConsideredDoubleTap` 方法。
- **关键代码逻辑**：源码实际检查的是 `mAlwaysInBiggerTapRegion`。在 `ACTION_MOVE` 中，`mAlwaysInTapRegion` 使用 `mTouchSlopSquare` (8dp) 更新，而 `mAlwaysInBiggerTapRegion` 使用 `mDoubleTapTouchSlopSquare` 更新。
- **运行原理说明**：虽然在 `ViewConfiguration` 默认实现中两者都取自 `config_viewConfigurationTouchSlop`，但在逻辑上它们是隔离的。`mAlwaysInBiggerTapRegion` 允许在双击过程中有稍微放宽的位移限制（尽管默认值相同），这种设计允许 OEM 针对双击操作单独调优。
- **核验结论**：原文描述忽略了这一状态变量的独立性，会导致读者在分析 OEM 定制行为时产生困惑。
- **建议修正方向**：明确区分 `mAlwaysInTapRegion` (对应单击/滚动判定) 和 `mAlwaysInBiggerTapRegion` (对应双击前置判定)。

- [P1][版本差异覆盖][Android 10+ Input Classification]
- **原文位置**：`GestureDetector：手势状态机的设计哲学` -> `核心状态转换`
- **原文问题**：遗漏了 `MotionEvent.getClassification()` 对状态机的影响。
- **源码 / 一手资料锚点**：`frameworks/base/core/java/android/view/GestureDetector.java` 中的 `ACTION_MOVE` 分支逻辑。
- **缺失内容**：Android 10 (API 29) 引入了 `CLASSIFICATION_AMBIGUOUS_GESTURE` 和 `CLASSIFICATION_DEEP_PRESS`。
- **运行原理说明**：当分类为 `AMBIGUOUS_GESTURE` 时，`GestureDetector` 会将 `LongPressTimeout` 乘以一个倍率（通常是 1.5x 或 2x），并增加 `TouchSlop` 的判定阈值。这是为了解决系统手势（如边缘返回）与 App 手势冲突时的抖动问题。
- **为什么这是重要缺失**：这直接影响了“手势延迟感知”和“长按响应速度”的性能分析。在 Perfetto 中看到长按响应慢时，如果不了解这个机制，可能会误认为是主线程卡顿。
- **建议补充方向**：在状态机或性能优化章节补充 `Classification` 机制及其对 `TouchSlop` 动态调整的影响。

## 六、P2 问题（建议改进）

- [P2][原理链完整性][onSingleTapConfirmed 的触发时机]
- **原文位置**：`双击检测机制` -> 第 4 点
- **原文问题**：原文称“超时还没有第二次点击，Handler 处理 TAP 消息时才回调”。
- **证据或观察依据**：`GestureDetector.java` 中的 `GestureHandler` 和 `ACTION_UP` 逻辑。
- **问题描述**：这只描述了一半情况。如果用户在 `TAP` 消息超时（300ms）后才抬手，`TAP` 消息在处理时会发现 `mStillDown == true`，此时仅设置 `mDeferConfirmSingleTap = true`；真正的回调是在 `ACTION_UP` 时触发的。
- **建议**：补充描述“延迟确认”的两种触发路径：1. Timer 到期（已抬手）直接触发；2. 抬手动作触发（Timer 已到期但手指未离地）。

- [P2][源码准确性][TouchSlop 单位歧义]
- **原文位置**：`TouchSlop 与 VelocityThreshold` -> `TouchSlop`
- **原文问题**：原文写 `TOUCH_SLOP = 8; // 默认值，单位 dp`。
- **证据或观察依据**：`ViewConfiguration.java` 源码。
- **问题描述**：在 Java 代码常量中，`private static final int TOUCH_SLOP = 8;` 是原始像素值（作为 fallback），并非 dp。只有在资源文件 `config.xml` 中定义的才是 `8dp`。
- **建议**：更正描述，明确指出 8 是代码内的硬编码 fallback（像素），而 `8dp` 是系统资源的默认值。

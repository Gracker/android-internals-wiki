## 五、P1 问题（重要缺失）
- [P1][版本差异覆盖][Predictive Back 回调模型]
- **原文问题**：未深入强调 `PRIORITY_SYSTEM_NAVIGATION_OBSERVER` 的“不破坏动画”特性。
- **源码 / 一手资料锚点**：`frameworks/base/core/java/android/window/OnBackInvokedDispatcher.java` (API 36)
- **关键代码逻辑**：此优先级是专门为了解决“埋点需求”与“预测性动画预览”之间的矛盾。在 API 36 之前，任何 Callback 注册都会导致系统默认动画被拦截，直到 App 明确不消费。
- **运行原理说明**：OBSERVER 回调是 **Non-consuming** 的，它允许系统在不等待 App 逻辑反馈的情况下直接启动 `back-to-home` 预览。
- **为什么这是重要缺失**：它是 Android 16 推进全系统预测性动画的关键基石，对开发者处理埋点逻辑具有极强的指导意义。
- **建议补充方向**：在 Android 16 演进表或回调模型章节补充此优先级的非消耗性特征。

- [P1][源码准确性][triggerBack 触发路径]
- **原文问题**：描述 `triggerBack()` 仅在 `mBackAnimation == null` 时注入 `KEYCODE_BACK`。
- **源码 / 一手资料锚点**：`packages/SystemUI/src/com/android/systemui/navigationbar/gestural/EdgeBackGestureHandler.java`
- **关键代码逻辑**：在 Android 15/16 中，即使 App 没有 opt-in 预测性返回，系统也可能启动 `cross-activity` 动画（由系统托管）。
- **运行原理说明**：此时 `mBackAnimation` 可能不为 null，但最终仍可能产生一个 Back 事件分发。
- **建议修正方向**：微调表述，强调“App 显式拦截”与“系统托管动画”的差异，而不仅仅是 `mBackAnimation` 对象的 null 检查。

## 六、P2 问题（建议改进）
- [P2][知识盲区][Exclusion Limit]
- **原文问题**：提到 `mSystemGestureExclusionLimit` 限制，但未明确维度。
- **证据依据**：AOSP `DisplayContent.java` 中默认 200dp 限制是针对 **高度（Height）** 的汇总。
- **问题描述**：读者可能误以为是宽度或滑动距离限制。
- **建议**：明确指出“每侧边缘的排除区域**总高度**不能超过 200dp”。

- [P2][源码准确性][Gesture Blocking Activity]
- **原文问题**：提到“Gesture Blocking Activity”但未说明来源。

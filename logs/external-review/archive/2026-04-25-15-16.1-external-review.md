## 五、P1 问题（重要缺失）
- [P1][原理链完整性][窗口管理：BLASTBufferQueue]
- 原文问题：仅提及 `syncNextTransaction()` 和 `mergeWithNextTransaction()` 解决 buffer latch 与 transaction apply 错位。
- 源码 / 一手资料锚点：`frameworks/native/libs/gui/BLASTBufferQueue.cpp` 和 `WindowContainerTransaction`
- 缺失内容：未讲清 BLASTBufferQueue 是如何通过 `SurfaceControl.Transaction` 跨进程传递并最终由 SystemServer (WMS) 统一 apply 的。
- 运行原理说明：App 端绘制完 buffer 后，并不直接提交给 SurfaceFlinger，而是将 buffer 封装在 Transaction 中，通过 Binder 传给 WMS。WMS 将该 Transaction 与系统窗口状态变化的 Transaction merge 后，统一 apply 给 SurfaceFlinger，确保画面和窗口几何变化严格同帧。
- 为什么这是重要缺失：这是 BLAST 架构的核心目的，仅仅说“对齐”而忽略 WMS 的参与，会导致读者对跨进程同步理解断层。
- 建议补充方向：补充 App -> WMS -> SurfaceFlinger 的 Transaction 传递链。

## 三、回炉问题摘要（P0 / P1）

### 1. [P1][源码准确性][第 237-244 行] Macrobenchmark CompilationMode 命名部分不准确

- **原文问题**：
  - 第 240 行：「**`SpeedProfile()`**：先跑几次 warmup 收集 profiling 数据…」
  - 第 239 行：「**`DEFAULT()`**：如果 App 包含 Baseline Profile，会先安装 Profile 再测量…」
- **核验结论**：
  - **`SpeedProfile()` 不存在**。正确的 API 名称是 `CompilationMode.Partial()`。`Partial` 有多个构造方式：
    - `Partial(baselineProfileMode = BaselineProfileMode.Require)` — 使用 Baseline Profile 编译
    - `Partial(warmupIterations = 3)` — 先跑 warmup 收集 profile 数据再编译
  - **`DEFAULT()` 也已变更**。在较新版本的 Macrobenchmark 中，`DEFAULT` 等同于 `Partial(baselineProfileMode = BaselineProfileMode.Include)`。
  - `None()` 和 `Full()` 的描述是正确的。
- **一手资料锚点**：
  - 官方文档: `developer.android.com/reference/androidx/benchmark/macro/CompilationMode`
  - Macrobenchmark 源码: `androidx.benchmark:benchmark-macro` 库
- **建议修正方向**：
  1. 将 `SpeedProfile()` 改为 `Partial(warmupIterations = N)`
  2. 说明 `DEFAULT()` 等同于 `Partial(baselineProfileMode = BaselineProfileMode.Include)`
  3. 保留 `None()` 和 `Full()` 的描述

### 4. 可直接复用的技术结论
- 启动时间测量至少 10 次，取中位数；帧率测量至少 5 次完整滑动

- Baseline Profile 带来的启动优化幅度可达 30%
- 测试前设备温度应 <40°C，电量 50%+

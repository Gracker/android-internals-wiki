## 五、P1 问题（重要缺失/描述不准）
- [P1][原理链完整性][五种核心状态 - Runnable (R)]
- **原文问题**：描述 Runnable 为“蓝色（浅绿色或白色）”。
- **核验结论**：在现代 Perfetto UI 中，Runnable 为 **浅绿色 (Light Green)**。**白色 (White/Transparent)** 严格对应 **Sleeping (S)**。将两者混淆会导致读者在观察 Trace 时无法区分排队等待和主动休眠。
- **建议修正方向**：明确 Runnable 为浅绿色，Sleeping 为白色/透明色。

- [P1][知识盲区][从线程状态分析性能瓶颈的方法论 - SQL 量化分析]
- **原文问题**：第一个 SQL 脚本中使用 `CASE state WHEN 'R' THEN 'Runnable' ...` 统计。
- **核验结论**：Perfetto `thread_state` 表中存在 **`R+`** 状态表示被抢占（Preempted）。如果只统计 `R`，会漏掉所有因抢占导致的调度延迟，导致统计数据偏低。
- **建议修正方向**：修改 SQL 使用 `WHEN 'R' THEN 'Runnable' WHEN 'R+' THEN 'Runnable (Preempted)'` 或 `WHEN state LIKE 'R%' THEN 'Runnable'`。

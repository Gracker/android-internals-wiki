## 五、P1 问题（重要缺失）

- [P1][版本差异/知识盲区][Android 16 渲染特性]
- **原文问题**：提到 Android 16 Vulkan 默认化，但未提及 **VPA16 (Vulkan Profile for Android 16)** 这一强制标准。
- **源码 / 一手资料锚点**：Khronos `VP_ANDROID_16_minimums.json`, Vulkan 扩展 `VK_EXT_host_image_copy`。
- **缺失内容**：VPA16 强制要求支持 **Host Image Copy**。该技术允许 CPU 直接将纹理流式传输到 GPU 内存，绕过 Staging Buffer。
- **性能红利**：纹理加载时的峰值内存占用可降低约 **50%**，并能显著消除因 GPU 命令提交导致的渲染卡顿（Stutter）。
- **建议补充方向**：在“Vulkan vs OpenGL ES”章节补充 VPA16 对硬件驱动的硬性要求，强调 Host Image Copy 的原理。

- [P1][知识盲区/源码准确性][图形内存管理]
- **原文问题**：对 Gralloc 的描述停留在旧版本，未提及 **AIDL-based Gralloc 5.0** 以及 **GPU Syscall Filtering**。
- **源码 / 一手资料锚点**：`hardware/interfaces/graphics/allocator/aidl/`, Android 16 针对 API 36 的 `GPU Syscall Filtering` 变更。
- **缺失内容**：Android 16 引入了 GPU 系统调用过滤，限制应用直接执行 IOCTL，强制通过标准 API。
- **为什么重要**：这改变了底层优化的边界，以往通过私有驱动接口做的黑科技优化在 Android 16 下将失效。
- **建议补充方向**：在“GPU 内存管理”章节补充 Gralloc 的 AIDL 化趋势及 16KB 页对齐带来的内存碎片风险。

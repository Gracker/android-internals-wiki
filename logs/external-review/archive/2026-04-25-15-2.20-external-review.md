## 四、P0 问题（事实错误）
- **[P0][源码准确性][2.20 - recreateOnConfigChanges 的公开语义]**
- **原文问题**：声称 `recreateOnConfigChanges` 仅针对 `mcc|mnc` 变化，且不适用于屏幕尺寸/方向变化。
- **源码 / 一手资料锚点**：
  - `frameworks/base/core/res/res/values/attrs_manifest.xml` (AOSP master/main)
  - `frameworks/base/core/java/android/content/pm/ActivityInfo.java`
- **关键代码逻辑**：在 AOSP 最新提交中，`recreateOnConfigChanges` 是一个通用属性。虽然在 Android 15 中针对 `mcc|mnc` 的默认行为发生了变化（默认重启），但该属性本身是设计用来覆盖 *所有* 没在 `android:configChanges` 中声明的变化。
- **运行原理说明**：Android 16 为了强制大屏适配，引入了“即使声明了 configChanges，部分关键配置也可能强制 recreate”的实验性逻辑。
- **核验结论**：原文对该属性的定位过窄，且将其误传为“Android 17 新增且仅限 mcc|mnc”。
- **为什么错**：混淆了“属性引入的背景事件（mcc|mnc 默认行为变更）”与“属性本身的通用定义”。
- **建议修正方向**：明确 `recreateOnConfigChanges` 是控制配置变化是否触发重启的通用开关，并重点说明 Android 16 如何利用这一机制（或类似机制）确保 `sw >= 600dp` 设备的自适应布局。

## 五、P1 问题（重要缺失）
- **[P1][版本差异覆盖][2.20 - Android 16/17 大屏边界]**
- **原文问题**：提到了 Android 16 会忽略 `screenOrientation` 等限制，但未提及其核心前提：**强制 Activity 重启（Recreation）逻辑的增强**。
- **一手资料锚点**：[Android 16 Developer Preview 1 - Behavior Changes](https://developer.android.com/about/versions/16/behavior-changes-16#large-screens)
- **缺失内容**：在 `sw >= 600dp` 且 `targetSdkVersion >= 36` 时，若 App 尝试通过声明 `configChanges` 来回避重启以维持固定比例，系统可能会强制进行 recreation 或使用特定的兼容性绘制。
- **为什么这是重要缺失**：开发者如果只看到“忽略限制”，会以为只是 UI 拉伸，而不知道背后可能伴随强制生命周期销毁重造。
- **建议补充方向**：说明 API 36+ 在大屏上对 `onConfigurationChanged` 接管能力的“削弱”。

- **[P1][知识盲区][2.20 - 多 Display 下的 VSync 与帧率对齐]**
- **原文问题**：提到 Connected Display，但未解释 SF 如何处理两个不同刷新率（如 60Hz 手机 + 120Hz 显示器）的 VSync。
- **原理说明**：多窗口/多显示器场景下，SF 必须决定主时钟。这会导致其中一块屏幕出现不规则的 `PresentationDeadline` 偏移或掉帧。
- **为什么这是重要缺失**：多窗口分析中最头疼的往往是“由于副屏刷新率不同导致的系统级掉帧”。
- **建议补充方向**：在“SurfaceFlinger 侧多了什么工作”中补充多 VSync 源的冲突点。

## 六、P2 问题（建议改进）
- **[P2][数据/案例支撑][2.20 - SQL 过滤建议]**
- **原文问题**：SQL 示例未过滤 `display_id`。
- **问题描述**：在 Connected Display 场景下，`surfaceflinger_layers_snapshot` 会同时包含两块屏幕的 layer。不加 `display_id` 过滤会导致统计出的 layer 数量翻倍，误导分析。
- **建议**：SQL 中加入 `WHERE l.display_id = 0` (内屏) 或其他标识。

- **[P2][数据/案例支撑][2.20 - 图表占位符]**

- **建议**：补全截图，并给出“当 Client Composition 占比超过 X% 时应警惕 GPU 负载”的经验值。

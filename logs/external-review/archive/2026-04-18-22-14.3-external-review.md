## 四、P0 问题（事实错误）
- [P0][版本差异覆盖][实战分析方法 - MAT 分析 Bitmap]
- 原文问题：“在 Dominator Tree 中选中一个 Bitmap 对象，在 Inspector 面板中可以看到 `mBuffer`（像素数据）... 导出为 `.data` 文件后... 就能看到这张 Bitmap 的实际内容。”
- 源码 / 一手资料锚点：Android 8.0 (API 26) `android.graphics.Bitmap` 源码变更
- 关键代码逻辑：在 Android 7.x 及以前，Bitmap 的像素数据存储在 Java 堆的 `byte[] mBuffer` 中，可以通过 MAT 直接导出。但在 Android 8.0 及以后，像素数据被移到了 Native 堆，Java 层的 `Bitmap` 对象只保留一个指向 Native 内存的 `mNativePtr` 指针。
- 运行原理说明：由于标准的 Java HPROF 文件只包含 Java 堆的快照，因此在 Android 8.0+ 导出的 hprof 文件中，你根本找不到这个 `mBuffer` 数组，MAT 也无法直接提取其 Native 内存中的像素数据。
- 版本差异：此技巧仅适用于 API 25 及以下，对于文章声称的适用版本（Android 8-16）完全失效。
- 核验结论：这是一个经典的“过时经验误导当前开发”的问题。
- 建议修正方向：明确指出该 MAT 技巧在 Android 8.0+ 已失效。并补充：在现代 Android 开发中，若要查看堆中的 Bitmap 像素内容，应当直接使用 Android Studio 的 Memory Profiler，它会自动读取 Native 内存并展示图片缩略图。

## 四、P0 问题（事实错误）

### P0-1：Jetpack API 类名全部为虚构
- [P0][源码准确性][基本使用：从零到跑通]
- 原文问题：整个代码示例使用了 `androidx.tracing.perfetto.Tracing`、`androidx.tracing.perfetto.ProfilingResult`、`androidx.tracing.perfetto.SystemTraceRequestBuilder`、`androidx.tracing.perfetto.JavaHeapDumpRequestBuilder`、`androidx.tracing.perfetto.HeapProfileRequestBuilder`、`androidx.tracing.perfetto.StackSamplingRequestBuilder` 等类。
- 源码 / 一手资料锚点：Maven Central `androidx.tracing` 包索引 / developer.android.com ProfilingManager API Guide
- 关键代码逻辑：`androidx.tracing` 库（截至 1.3.0 版本）主要提供 `Trace` 和 `TracingKt` 等类，用于向 Systrace/Perfetto 写入自定义 trace section。不存在 `Tracing.requestProfiling()` 这样的静态方法，也不存在 `SystemTraceRequestBuilder` 等 Jetpack 封装。实际的 ProfilingManager API 只在平台层（`android.os.ProfilingManager`）提供，通过 `getSystemService(ProfilingManager.class)` 获取实例后调用 `requestProfiling()`。
- 核验结论：文章虚构了一整套 Jetpack 封装层 API，开发者按照示例编写的代码完全无法编译通过。
- 建议修正方向：将所有代码示例改为使用平台原生 API（`android.os.ProfilingManager`），或者在文前明确说明 Jetpack 封装尚在开发中/尚未公开发布，代码为预期用法而非实际可用 API。

### P0-2：触发器版本归属表多处错误
- [P0][版本差异覆盖][可用的触发器类型]
- 原文问题：文章中的版本对照表将 `TRIGGER_TYPE_COLD_START` 和 `TRIGGER_TYPE_KILL_EXCESSIVE_CPU_USAGE` 标记为 Android 16 引入。
- 源码 / 一手资料锚点：`developer.android.com/reference/android/os/ProfilingTrigger` 官方 API 参考
- 核验结论：根据官方 API 参考文档：
  - `TRIGGER_TYPE_ANR` → API 36 (Android 16) ✅
  - `TRIGGER_TYPE_APP_FULLY_DRAWN` → API 36 (Android 16)（文章未提及此常量）
  - `TRIGGER_TYPE_COLD_START` → **API 37** (Android 17) ❌（文章标为 Android 16）
  - `TRIGGER_TYPE_KILL_EXCESSIVE_CPU_USAGE` → **API 37** (Android 17) ❌（文章标为 Android 16）
  - `TRIGGER_TYPE_OOM` → API 37 (Android 17) ✅
  - `TRIGGER_TYPE_ANOMALY` → API 37 (Android 17) ✅
  - `TRIGGER_TYPE_APP_REQUEST_RUNNING_TRACE` → version 36.1
- 建议修正方向：按照官方 API 参考重新整理触发器版本对照表，特别注意 `TRIGGER_TYPE_COLD_START` 是 API 37 而非 36。同时补充遗漏的 `TRIGGER_TYPE_APP_FULLY_DRAWN`（API 36）和 `TRIGGER_TYPE_APP_COMPAT`（API 37）。

## 五、P1 问题（重要缺失）

### 5.1 [P1][原理链完整性][LiteRT 架构演进]
- **原文位置**：`LiteRT / TFLite 管线与 Delegate 选择` 章节。
- **原文问题**：仅描述了 `Interpreter` + `Delegate` 的 V1 架构。
- **源码 / 一手资料锚点**：`com.google.ai.edge.litert.CompiledModel`；[LiteRT CompiledModel API Docs](https://ai.google.dev/edge/litert)。
- **关键代码逻辑**：LiteRT 正在推行 V2 架构，使用 `CompiledModel` 取代 `Interpreter`。它将 Delegate 配置抽象为 `Accelerator` 选择，并强制推行异步执行模式，这是 Android 14+ 性能调优的基准。
- **运行原理说明**：`CompiledModel` 支持针对特定硬件（如特定型号 NPU）进行预编译，减少了 V1 模式下复杂的算子映射和内存对齐开销。
- **版本差异**：V2 是 LiteRT 重命名（2024）后的核心卖点，旨在解决 NNAPI 废弃后的硬件抽象问题。
- **为什么构成 P1**：如果读者仍按 `Interpreter` 模式优化，将无法利用零拷贝（Zero-copy）和 AICore 的多租户调度特性。
- **建议修正方向**：补充 CompiledModel API 章节，说明它如何通过 AICore 路由到 NPU V2。

### 5.2 [P1][知识盲区][NPU AOT 编译]
- **原文位置**：`模型优化技术` 章节。
- **原文问题**：提到了量化、裁剪、蒸馏，但完全没提 AOT（Ahead-of-Time）编译。
- **关键代码逻辑**：`CompiledModel` 支持在安装时或首次启动时将模型转换为硬件原生二进制（Vendor-specific Binary）。
- **运行原理说明**：NPU 的加载成本（Loading/Preparation time）往往是冷启动卡顿的元凶（常达 500ms+）。AOT 编译能将此成本降至 50ms 以内。
- **为什么构成 P1**：在高性能 App（如相机、实时翻译）中，初始化性能是第一考核指标，AOT 是必选项。
- **建议补充方向**：增加“推理冷启动优化：从 JIT 到 AOT”小节。

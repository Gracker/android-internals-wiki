## 四、P1 问题（重要缺失）

- **[P1][知识盲区][Android 16 MessageQueue 反射破坏]**
  - **原文位置**：§1.5.2 "Looper → MessageQueue → Handler：消息驱动模型"
  - **原文问题**：提到了 Android 16 并存三套实现，但未提及 `ConcurrentMessageQueue` 对外部工具的影响。
  - **源码 / 一手资料锚点**：`frameworks/base/core/java/android/os/ConcurrentMessageQueue.java`；[Google Blog: Android 16 Performance Enhancements]
  - **关键代码逻辑**：在 `ConcurrentMessageQueue` 中，传统的 `mMessages` 链表字段始终保持为 `null`，消息存储在 Trebier Stack 或 ConcurrentSkipListSet 中。
  - **运行原理说明**：为了保持二进制兼容性，字段虽在，但内容已空。这会导致所有通过反射访问 `mMessages` 来检测队列状态的测试框架（如旧版 Espresso、Robolectric）失效。
  - **版本差异**：仅限 Android 16 (API 36) 及更高版本且开启并发队列模式。
  - **为什么构成 P1**：这是 Android 16 升级中最容易导致自动化测试崩溃的“暗雷”，必须告知读者。
  - **建议修正方向**：在描述 Android 16 重构时，补充一段“注意：反射破坏风险”，提醒开发者更新测试框架。

- **[P1][版本差异覆盖][Android 16 对 Java 21 虚拟线程的支持现状]**
  - **原文位置**：§1.5.6 "从 AsyncTask 到 Kotlin Coroutine：异步编程的演进"
  - **缺失内容**：明确说明 Android 16 暂不支持 Java 21 的虚拟线程（Project Loom）。
  - **核验结论**：Android 16 虽然支持了 Java 21 的部分语法，但 `Thread.isVirtual()` 始终返回 `false`，且未开放 `startVirtualThread` API。ART 架构目前仍与 Linux 内核线程紧密绑定。
  - **为什么构成 P1**：读者看到 Android 16 覆盖范围时，会自然联想到 Java 21 的最大特性“虚拟线程”。如果不明确指出其缺失，读者可能会尝试在 Android 16 上使用该特性导致失败。
  - **建议补充方向**：在“现代异步方案”部分，增加一个小节说明：尽管 Android 16 升级了 Java 21 语言特性，但虚拟线程（Virtual Threads）尚未落地，Kotlin 协程仍是唯一的轻量级调度方案。

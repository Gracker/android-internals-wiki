## 四][P0 问题（事实错误）
- [P0][内核调度][16KB Page 与 VMA 锁红利]
- **原文问题**：将“内核锁竞争”视为在 Android 15+ 上依然高频的 D 状态诱因。
- **技术背景**：Android 15 强制适配 16KB Page Size 并配合 Linux 6.6+ 内核引入了 **Per-VMA Lock**。
- **核验结论**：获取 `mmap_lock` 的频率降低了 75%，且不再是进程级互斥。这意味着在 Android 15+ 设上，以往由于“主线程频繁映射资源导致卡死”的场景已基本消失。
- **建议修正方向**：明确告知开发者：在 API 35+ 设备上，若主线程进入 D 状态且无密集 I/O 证据，应重点排查硬件驱动层锁而非内核 VMA 锁。

## 五、P1 问题（重要缺失）
- [P1][自动诊断][焦点缺失自动化闭环]
- **原文问题**：将“no focused window”视为需人工比对 EventLog 的疑难场景。
- **技术背景**：Android 16 `ProfilingManager` 在捕获 ANR Trace 时会自动包含 WMS 焦点切换序列。
- **核验结论**：开发者无需手动拉取 EventLog，直接在系统 Trace 文件的元数据中即可判定焦点是被哪个进程“带走”后未归还（例如 Dialer 启动失败案例）。
- **建议补充方向**：在“躺枪场景 1”中增加“自动化定性”操作建议。

- [P1][厂商差异][OEM 私有日志补强]
- **原文问题**：分析 system_server 繁忙时仅推荐了 AOSP 的 `Slow operation`。
- **技术背景**：国内主流厂商（华为、小米、OPPO 等）在 `ActivityManager` 中增加了更细粒度的私有监控。
- **建议补充方向**：提供一份简单的“厂商私有 Slow Looper 日志关键词表”，帮助开发者在海量 Bugreport 中快速识别系统侧的异常。

## 四、P0 问题（事实错误）
- [P0][源码准确性][扩展：Hook 机制对比]
- 原文问题：“Rhea 在 Hook atrace 相关函数时使用了基于字节跳动自研 ByteHook 的方案，它结合了 PLT Hook 和 Inline Hook 的特点。”以及参考资料中“ByteHook GitHub: https://github.com/bytedance/android-inline-hook (字节跳动 Inline Hook)”
- 源码 / 一手资料锚点：字节跳动开源库官方文档（bhook / shadowhook）
- 关键代码逻辑：字节跳动开源了两个截然不同的 Hook 库：`bhook` (ByteHook) 纯粹是一个 PLT Hook 库；而 `shadowhook`（以及早期的 android-inline-hook）才是 Inline Hook 库。ByteHook 并不结合 Inline Hook 的特点，它就是标准的 PLT Hook。
- 核验结论：概念张冠李戴。将 ByteHook 称为 Inline Hook 是事实错误。
- 建议修正方向：明确区分 ByteHook（PLT Hook）和 ShadowHook（Inline Hook），并修正底部的参考资料链接，将 ByteHook 指向 `bhook` 仓库，如果提到 Inline Hook 则应指向 `shadowhook` 仓库。

- [P0][版本差异覆盖][Booster 的局限性]
- 原文问题：“AGP 8.0 中虽然仍可使用，但官方更推荐迁移到 Instrumentation API”及后续“虽然 AGP 8.0 将 Transform API 标记为 deprecated 并推荐 Instrumentation API，但 Transform API 在当前版本仍然可用。”
- 源码 / 一手资料锚点：Android Gradle Plugin 8.0 Release Notes
- 运行原理说明：AGP 7.0 标记 Transform API 为 Deprecated；**AGP 8.0 彻底移除了 Transform API**。任何依赖旧版 Transform API 的插件在 AGP 8.0+ 的环境下都会直接抛出 `ClassNotFoundException` 或构建失败。不存在“仍然可用”的说法。
- 核验结论：版本兼容性说明完全错误，会严重误导在现代项目中进行架构选型的开发者。
- 建议修正方向：明确指出 Transform API 在 AGP 8.0 中已被**彻底移除**。第三方编译期框架（如 Booster 最新的兼容版本）必须通过 `AsmClassVisitorFactory` (Instrumentation API) 等新接口来实现字节码修改。

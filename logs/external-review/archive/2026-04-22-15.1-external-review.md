- [P1][源码准确性][使用 Profiler API 在代码中触发 profiling]
- 原文问题：原文提到了 `TRIGGER_TYPE_EXCESSIVE_CPU`。
- 源码 / 一手资料锚点：Android 16 (API 36) `ProfilingManager` API 文档。
- 缺失内容：Android 16 API 36 实际引入的异常触发器是 `TRIGGER_TYPE_ANOMALY`（用于检测 Binder 调用过多或内存异常等），而非 `TRIGGER_TYPE_EXCESSIVE_CPU`。
- 运行原理说明：系统会在检测到 ANR、OOM 或特定 Anomalies 时触发预先注册的 profiling 请求。
- 为什么这是重要缺失：这是 Android 16 最新的核心性能 API，常量名称写错会导致开发者查不到 API 无法落地。
- 建议补充方向：将 `TRIGGER_TYPE_EXCESSIVE_CPU` 修正为 `TRIGGER_TYPE_ANOMALY`，并说明其涵盖的异常类型（如过度 Binder 调用）。

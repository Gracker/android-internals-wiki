## 五、P1 问题（重要缺失）
- [P1][原理链完整性][同步 / 异步]
  - 原文问题：“同步和异步区间要分开”一节中，纠正异步调用的做法是“在每个关键线程上标记自己的阶段”。
  - 缺失内容：大纲要求“区分同步 slice、async trace”。
  - 建议补充方向：必须补充真正的 Async Trace API（如 `androidx.tracing.Trace.beginAsyncSection` 和 `endAsyncSection`）。解释它需要传入一个独特的 `cookie`（如递增 ID），从而让 Perfetto 在一条专属的 Async Track 上画出一段跨越多线程调度、不与单一线程绑定的横条。这才是监控长耗时异步网络/数据库请求的标准姿势。

- [P1][原理链完整性][基本用法]
  - 原文问题：只展示了 Kotlin 的 `trace {}` 高阶函数用法，完全不提 Java 的 `beginSection` 及其陷阱。
  - 缺失内容：大纲要求“覆盖 Kotlin trace {}、Java begin/end、异常安全”。
  - 建议补充方向：补充 Java 代码示例。必须强调 `Trace.beginSection()` 之后必须紧跟 `try { ... } finally { Trace.endSection(); }`，否则一旦发生异常，Trace 未闭合会导致整个 Perfetto 时间线在这个线程上的渲染全部错乱甚至崩溃。

- [P1][数据/案例支撑][阅读方式]
  - 原文问题：通篇没有教读者如何在 Perfetto 中查看打好的 Trace。
  - 缺失内容：大纲要求“写清在 Perfetto UI 中如何找到 slice、看线程、看嵌套、看 gap 和 scheduler”。
  - 建议补充方向：新增一段实操指南。例如：如何在 Perfetto UI 顶部的搜索栏输入 `Home#diffAndBind`；找到 slice 后，如何看上方的线程调度状态（Running / Runnable / Sleep）；如果两个相连的 Trace 之间有 Gap（空白），说明这段时间 CPU 被谁抢占或处于什么状态。

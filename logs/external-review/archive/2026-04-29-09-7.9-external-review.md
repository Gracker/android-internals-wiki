## 四、P1 问题（重要缺失）
- [P1][工具链][AppJankStats 精度限制]
- **原文问题**：对 Android 16 新增 API 评价过于正面。
- **核验结论**：`RelativeFrameTimeHistogram` 的 API 显式暴露的精度仅为 **1ms**。
- **为什么这是重要缺失**：在 120Hz（8.33ms/帧）环境下，1ms 的统计误差意味着该工具会漏掉所有小于 12% 的步幅波动。
- **建议修正方向**：明确告知开发者：官方统计 API 无法替代应用侧纳秒级位移采样，仅适用于粗粒度性能画像。

- [P1][版本差异][ARR 复合效应]
- **原文问题**：步幅波动分析未考虑 ARR 切换点。
- **技术背景**：Android 15+ 频繁触发自适应刷新率切换（如 60->90->120）。
- **核验结论**：在非整数周期跳变点（如 11.1ms），毫秒取整误差会与周期漂移叠加，产生肉眼可见的瞬时“阶跃感”。
- **建议补充方向**：在“成因分析”中增加子节，说明 ARR 动态窗口下步幅波动的隐蔽性。

## 五、P2 问题（建议改进）
- [P2][原理链][插值器斜率]
- **建议**：补充插值器（Interpolator）对步幅的影响。对于步幅敏感场景，应推荐使用控制点切线斜率平滑的 `PathInterpolator`，并配合 `Choreographer.FrameData` 实现时间戳的绝对对齐。

- **技术结论**：Android 16 的 `RelativeFrameTimeHistogram` 采用离散的 1ms 桶计数，不具备微秒级单帧分析能力。

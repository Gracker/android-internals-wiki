## 五、P1 问题（重要缺失）

### [P1][原理链完整性][SoloPi 启动耗时部分]
- **原文问题**：仅提到“启动耗时工具支持双点标记和广播调用”，未说明其核心算法。
- **源码 / 一手资料锚点**：SoloPi GitHub README / 支付宝技术博客。
- **关键代码逻辑**：SoloPi 采用 **MediaProjection 录屏 + OpenCV 图像识别** 方案。
- **运行原理说明**：
  1. **分帧对比**：录制启动过程，利用 OpenCV 对分帧后的图片进行相似度计算。
  2. **视觉终点**：当屏幕内容从启动图变为稳定页面（变化率低于阈值）时，判定为“视觉首屏完成”。
  3. **计算公式**：`耗时 = 结束帧时间戳 - 起始点击时间戳`。这比 `am start -W` 记录的系统内部时间更符合用户真实感受。
- **为什么这是重要缺失**：这是 SoloPi 作为“非侵入式工具”能提供高准确度耗时数据的技术基石。

### [P1][版本差异覆盖][Android 13+ 权限部分]
- **原文问题**：提到“Android 12+ 需要逐机验证”，但未指明 Android 13/14 最核心的“受限设置”阻断。
- **源码 / 一手资料锚点**：Android 13+ Restricted Settings 特性。
- **缺失内容**：从 Android 13 开始，非商店安装（Sideloaded）的 APK 在开启无障碍服务时会提示“为了您的安全，此设置目前不可用”，开关呈置灰状态。
- **运行原理说明**：系统对非受信任来源的 App 限制了敏感权限。
- **修正方向**：必须在文章中补充规避路径：`设置 -> 应用 -> SoloPi -> 应用详情页右上角三点 -> 允许受限设置`。这是在高版本系统上使用 SoloPi 的先决条件。

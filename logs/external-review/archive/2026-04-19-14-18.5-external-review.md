## 四、P0 问题（事实错误）
- [P0][源码准确性][全链路执行流程 - 阶段三]
- **原文问题**：“从 Android 12 开始，RenderThread 引入了更轻量的 'push' 模式，UI Thread 只需短暂等待 DisplayList 引用交换即可返回”
- **源码 / 一手资料锚点**：`cs.android.com`: `frameworks/base/libs/hwui/renderthread/DrawFrameTask.cpp` 中的 `drawFrame()` 与 `syncFrameState()` 逻辑。
- **关键代码逻辑**：UI 线程调用 `ThreadedRenderer.draw()` 时，会创建并投递 `DrawFrameTask` 到 RenderThread，随后立刻调用 `mSyncCondition.wait(mLock)` 阻塞等待。RenderThread 处理该 task 时执行 `syncFrameState()`，完成后调用 `mSyncCondition.notify_one()` 唤醒 UI 线程。
- **运行原理说明**：根本没有所谓的 "push 模式"。无论是 Android 9 还是 Android 15，UI 线程在同步时都必须通过 ConditionVariable 死等 RenderThread 过来执行同步操作。如果 RenderThread 正在忙着画上一帧，UI 线程就必须干等。
- **核验结论**：原文对 Android 12 优化的描述为 AI 幻觉，完全不符合 HWUI 架构的真实代码逻辑。
- **建议修正方向**：直接删除关于 "push 模式" 的错误段落，准确描述 `DrawFrameTask` 的阻塞-唤醒机制。

## 五、P1 问题（重要缺失）
1. **[P1][原理链完整性][时序图与阶段说明]**
- **原文问题**：未能点透 `Window B` 的 Traversal 耗时为什么会长，只说是“串行”。
- **源码 / 一手资料锚点**：`frameworks/base/core/java/android/view/ViewRootImpl.java` 的 `performTraversals()` -> `performDraw()`
- **关键代码逻辑**：UI Thread 执行 Window B 的 `performTraversals` 时，测量和布局可能很快，但很快就会调用到 `nSyncAndDrawFrame` 进行绘制同步。而此时 **RenderThread 正在专心执行 Draw A**！
- **缺失内容**：由于 RenderThread 单线程排队，B 的 `DrawFrameTask` 必须等 `Draw A` 结束才能被处理。这就导致 UI Thread 实际上是在 B 的 `performTraversals` 中，被 `Draw A` 跨线程死死卡住了。
- **为什么这是重要缺失**：这才是读者在 Perfetto Trace 中看到 `Traversal B` 极其耗时的根本原因（里面大部分时间是在休眠等待锁），不点透这个，读者在看 trace 时会误以为是 B 的 Layout 很慢。
- **建议补充方向**：在时序图和文本中明确补充“流水线气泡”：UI 线程在 Traversal B 的阶段，实际上大部分时间处于阻塞状态，等待 RT 完成 Draw A。

2. **[P1][知识盲区][多窗口场景分析]**
- **原文问题**：“分屏模式下，两个 Activity 同时 RESUMED，UI Thread 的竞争更加激烈... 底层仍然是同一个 Choreographer 串行分发”
- **缺失内容**：未界定进程边界。绝大多数用户的分屏是 App A 和 App B 分屏，此时是跨进程的，各自有独立 UI Thread 和 RT，**完全并行**，没有竞争。
- **为什么这是重要缺失**：读者如果不清楚进程边界，会误以为只要分屏就会引起 Choreographer 竞争。
- **建议补充方向**：明确限定场景为“**同一进程内**的多个 Activity 分屏（如 Android 12L+ 引入的 TaskFragment / ActivityEmbedding，或支持 multi-instance 的同一应用）”。

### 9.4 可复用知识资产（高价值新增知识）
- **章节**：`18.5 Android View 多窗口链路`
- **一手资料链接或来源类型**：`cs.android.com` / AOSP
- **关键源码路径**：`frameworks/base/libs/hwui/renderthread/DrawFrameTask.cpp`
- **关键调用链 / 代码逻辑摘要**：`ViewRootImpl.performTraversals` -> `ThreadedRenderer.draw` -> `nSyncAndDrawFrame` -> `DrawFrameTask::drawFrame` (UI Thread blocks on `mSyncCondition.wait`) -> `DrawFrameTask::run` (on RenderThread) -> `syncFrameState` -> `mSyncCondition.notify_one()`。
- **Trace / Perfetto 观察点**：如果在同一帧处理两个窗口，第二个窗口的 `Choreographer#doFrame` -> `performTraversals` 尾部会存在一个极长的休眠状态（Runnable/Sleeping），因为此时 RenderThread 处于 Running 状态执行前一个窗口的 `DrawFrame`。

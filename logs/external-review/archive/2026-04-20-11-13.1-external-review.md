## 五、P1 问题（重要缺失）

- [P1][原理链完整性][Perfetto 的架构 / traced]
- **原文问题**：“Producer 先把事件写进与 traced 共享的 shared memory，traced 再把这些数据汇聚到 central trace buffers” —— 缺少了 Producer 与 traced 之间是如何建立连接并协商 shared memory 的关键机制。
- **源码 / 一手资料锚点**：`external/perfetto/perfetto.rc` 中定义的 UNIX Domain Sockets：`/dev/socket/traced_producer` 和 `/dev/socket/traced_consumer`。
- **缺失内容**：IPC 通信机制。
- **运行原理说明**：Producer 并不是直接凭空拿到 shared memory，而是必须先通过 `/dev/socket/traced_producer` 与 `traced` 建立 IPC 连接，注册自己的 Data Source 能力。当 trace 开始时，`traced` 会通过该 socket 传递文件描述符 (fd) 给 Producer，Producer 再通过 `mmap` 映射出 SMB (Shared Memory Buffer)。
- **为什么这是重要缺失**：如果不讲 UNIX socket 的角色，读者在排查 "App 无法写入 perfetto" 的权限问题（如 SELinux 拦截 socket 访问）时将毫无头绪。
- **建议补充方向**：在架构图或原理解释中，补充 UNIX Socket (`traced_producer` / `traced_consumer`) 作为控制通道、Shared Memory 作为数据通道的双通道架构。

- **源码 / 一手资料锚点**：Perfetto 官方文档或 AOSP 中的 `android.surfaceflinger.frametimeline`。
- **缺失内容**：开发者在手写 pbtx 配置时，不知道该开启哪个 Data Source 来抓取 FrameTimeline。
- **为什么这是重要缺失**：只讲概念不给落地的配置名，导致读者无法在自定义 TraceConfig 中实际使用该能力。

## 四、主要发现与讨论点
- **SQL 表与状态值的一致性**：文中提供了一段统计不同 CPU 状态耗时的 SQL（使用 `CASE state WHEN 'Running' THEN ...`）。这是极其正确的实战经验：在内核的原始 ftrace 中虽然只有 R/S/D 等字母，但在 Perfetto 的 `thread_state` 视图中，当前正在 CPU 上执行的时间片会被明确转换为字符串 `'Running'`，这一细节被准确捕捉，展现了极强的实操底蕴。
- **D 状态与 Block Reason**：强调了 `sched_blocked_reason` 事件作为定位不可中断睡眠原因的利器，并解释了它的 Android 定制属性。这是极高价值的结论。

## 五、P2 问题（微瑕建议，非必需）
- [P2][原理链完整性][Wall 时间的构成]
- **原文表述**：“它们的关系是：`Wall = CPU + Runnable + Sleep`。”
- **建议**：严谨地说，`Wall` 在 Perfetto 的 slice 生命周期内应包含所有非运行态，即 `Wall = CPU (Running) + Runnable + Sleep (S) + Uninterruptible Sleep (D) + 其他`。虽然日常中常用 Sleep 统称，但考虑到本章特意将 Sleeping(S) 和 Uninterruptible Sleep(D) 拆为两节深入讨论，建议在公式中补充 D 状态或解释 Sleep 在此处为广义等待。

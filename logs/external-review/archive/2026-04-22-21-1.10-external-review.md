## 五、P1 问题（重要缺失）

- [P1][版本差异][1.10 章节 - ContentProvider 的版本演进]
- **原文问题**：称 `getProviderMimeTypeAsync` 是 Android 12 (API 31) 引入的。
- **源码 / 一手资料锚点**：AOSP `ContentResolver.java`, `IActivityManager.aidl` (API 30)。
- **运行原理说明**：该异步方法是为了解决同步 `getType` 在 AMS 主线程阻塞 1s 导致的系统级 ANR 风险。
- **核验结论**：该 API 实为 **Android 11 (API 30)** 引入。
- **建议修正方向**：更正版本号为 Android 11，并强调这是从“同步阻塞”向“异步响应”转化的关键里程碑。

- [P1][版本差异][1.10 章节 - ContentProvider 的版本演进]
- **原文问题**：称 `setDetectNotResponding` 是 Android 11 引入。
- **源码 / 一手资料锚点**：`ContentProviderClient.java` (added in API 18 as `@hide`)。
- **运行原理说明**：允许客户端主动设置超时阈值。
- **核验结论**：该方法自 **Android 4.3 (API 18)** 起便存在于 AOSP，长期作为 `@hide` 接口被系统组件使用。
- **建议修正方向**：明确其历史渊源，说明其在 Android 11 左右变得更为“公开/重要”，而非“新引入”。

- [P1][知识盲区][1.10 章节 - 与其他机制的关系 / 版本演进]
- **原文问题**：未提及 **归因标签 (Attribution Tags)** 对 ContentProvider 审计的影响。
- **源码 / 一手资料锚点**：`android.content.AttributionSource`, `ContentProvider.getCallingAttributionSource()`。
- **缺失内容**：对于 Target API 31+，必须在 Manifest 中显式声明 `<attribution>`，且调用方应使用 `createAttributionContext` 才能在 Provider 侧正确记录审计。
- **为什么这是重要缺失**：这是 Android 现代隐私审计架构的核心，不适配会导致权限审计记录不完整或报错。
- **建议补充方向**：增加一节专门讲解如何使用归因标签进行细粒度审计及对性能（极微量 IPC 开销）的影响。

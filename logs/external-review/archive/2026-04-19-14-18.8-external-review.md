## 四、P0 问题（事实错误）

- **[P0][原理链完整性][渲染循环时序] Continuous 模式与 VSync 的关系**
  - **原文问题**：“Continuous 模式下...不等待 VSync 信号。帧率受 eglSwapBuffers 内部 dequeueBuffer 的 BufferQueue 可用性限制，而非 VSync 驱动”
  - **源码 / 一手资料锚点**：`frameworks/native/libs/gui/BufferQueueProducer.cpp` 的 `dequeueBuffer`。
  - **运行原理说明**：虽然 GLThread 没有注册 `Choreographer` 显式监听 VSync-App 信号，但并不意味着它“非 VSync 驱动”。当 BufferQueue （通常为 3 个 slot）塞满后，`dequeueBuffer` 会被阻塞。而 SurfaceFlinger 消费并 `releaseBuffer` 将插槽还给 BufferQueue 的动作，是严格受**硬件 VSync（VSync-SF / VSync-HWC）** 驱动的。因此，GLThread 的帧率在宏观物理上**是被 VSync 背压（Backpressure）机制隐式节流和驱动的**。
  - **为什么错**：原文的表述会误导读者以为 GLES 渲染完全独立于屏幕刷新率跑在一个无限高的帧率上，忽略了图形管线的背压设计。
  - **建议修正方向**：说明虽然未直接注册 Choreographer，但依然受到 BufferQueue 满了之后的阻塞机制影响，最终消费节奏受 SurfaceFlinger VSync 控制，即“隐式 VSync 背压”。

## 五、P1 问题（重要缺失）

- **[P1][源码准确性][eglSwapBuffers 详解] BLAST 机制的抽象层级归属**
  - **原文问题**：“Android 12+ 的 eglSwapBuffers 内部走 BLAST Transaction 路径”
  - **源码 / 一手资料锚点**：`frameworks/native/opengl/libs/EGL/eglApi.cpp` -> `eglSwapBuffers` -> 最终调 `ANativeWindow::queueBuffer`。
  - **缺失内容与原理**：`eglSwapBuffers` 是 Khronos 标准，EGL driver 层面根本不知道 BLAST。它调用的是下层 `ANativeWindow` 的标准接口。之所以走了 BLAST，是因为在 Android 12+，上层传入的这个 `ANativeWindow` 实例，其背后的实现是由 `BLASTBufferQueue` 生成的 `Surface`。
  - **为什么这是重要缺失**：混淆了图形驱动 API 层和 Android GUI 框架层的作用边界，不利于读者排查跨层问题。
  - **建议补充方向**：明确 `eglSwapBuffers` 本质是对 `ANativeWindow` 执行 queue/dequeue，而 Android 12+ 改变了 `Surface` 的底层实现（引入了 `BLASTBufferQueue`），从而使得最终提交路径在 Trace 中表现为 BLAST Transaction。

- **[P1][原理链完整性][Buffer 流转与 Triple Buffering] Triple Buffering 状态分配不准确**
  - **原文问题**：“3 个 Buffer：Display 用一个、SurfaceFlinger 持有一个、App 用一个”
  - **运行原理说明**：标准状态并不是 SurfaceFlinger 主动持有。三个状态通常为：1. 正在屏幕上 Scanout（被 HWC/Display 锁定）；2. 已经画好排队等待下一次 VSync 被消费（Queued）；3. App 正在画（Dequeued）。
  - **为什么这是重要缺失**：概念过于模糊，不符合 BufferQueue 的真实内部状态机（FREE, DEQUEUED, QUEUED, ACQUIRED）。
  - **建议补充方向**：修正为“一个正在屏幕显示，一个在队列中准备下一帧显示，一个正在被 App 绘制”。

- **[P1][知识盲区][GLSurfaceView vs 原生 EGL 集成] 缺失最常见坑点：EGL Context 丢失与生命周期**
  - **原文问题**：未提及 GLSurfaceView 在 Activity onPause/onResume 时默认行为导致的 EGL Context 销毁问题。
  - **为什么这是重要缺失**：实战开发中，App 切后台再切回来黑屏，是 Android GLES 新手最容易踩坑的 P0 级 Bug。
  - **建议补充方向**：明确补充 `setPreserveEGLContextOnPause(true)` 这个高频实战知识点，以及 EGL Context 在系统资源紧张时被回收重建的机制。

## 五、P1 问题（重要缺失）
- [P1][原理链完整性][Bitmap 像素内存分配的版本差异]
- 原文问题：提到 Android 8.0 之后像素数据回到 Native heap，但未解释 Java 层如何管理和释放这块 Native 内存。
- 源码 / 一手资料锚点：`libcore/luni/src/main/java/libcore/util/NativeAllocationRegistry.java` 及 `android/graphics/Bitmap.java` 中的相关注册代码。
- 缺失内容：缺少对 `NativeAllocationRegistry` 的说明。这是 Android 8.0+ 能够安全地将大量像素内存放置在 Native 堆的关键基石。它允许将一段 Native 内存的生命周期与一个 Java 对象（Bitmap壳）绑定，Java 对象被 GC 回收时，底层会自动调用释放函数（如 `free()`）清理 Native 内存。
- 运行原理说明：读者往往会疑惑：“既然存放在 Native，Dalvik/ART 的 GC 怎么能管到它？” 答案正是 `NativeAllocationRegistry` 向 ART 注册了这笔巨大的 native size，所以 ART 才会因为 native 内存水位过高而触发 GC。
- 为什么这是重要缺失：这是现代 Android Bitmap 内存管理的基础，缺失这一环会导致开发者对“为什么不需要手动 recycle() 也能在 native 及时释放”产生误解。
- 建议补充方向：补充 Android 8.0+ 依赖 `NativeAllocationRegistry` 进行 Java 壳与 Native 像素内存生命周期绑定的原理解释，并说明这部分内存会影响 ART 的 GC 调度。

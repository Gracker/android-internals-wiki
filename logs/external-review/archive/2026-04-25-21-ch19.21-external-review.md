## 五、P1 问题（重要缺失）

- [P1][版本差异覆盖][测试规范 / 机型分层方法]
- **原文问题**：机型分层部分完全采用自定义 Benchmark 分数，未提及 Android 官方的 **Performance Class (PC)** 体系。
- **一手资料锚点**：[developer.android.com - Performance Class](https://developer.android.com/guide/topics/manifest/uses-native-heap-tag#performance-class)
- **关键代码逻辑**：`androidx.core.performance.DevicePerformance` 可在运行时查询 `mediaPerformance Class`。
- **运行原理说明**：Google 通过 PC12/13/14/15 等标准定义了内存、I/O、相机、编解码的硬性门槛，是 OEM 和大厂 App 做机型分层的官方首选依据。
- **版本差异**：Android 11 (PC30) 起步，Android 15 (PC35) 引入了 12GB RAM 和 Vulkan 1.3 硬性要求。
- **为什么这是重要缺失**：作为 Internal Wiki，不提官方标准会导致读者偏离主流工程实践。
- **建议补充方向**：在“机型分层方法”中加入 Performance Class 对照表，说明如何结合 Benchmark 与 PC 等级做精细化治理。

- [P1][知识盲区][安兔兔、PCMark、Vellamo 的使用边界]
- **原文问题**：存储测试仍推荐 AndroBench。
- **一手资料锚点**：AndroBench 5.0.1 (Last updated 2017)
- **核验结论**：AndroBench 已停止维护，无法准确测算 UFS 4.0 且极易受 Linux Page Cache 干扰导致数据虚高。
- **为什么这是重要缺失**：推荐过时且数据不准的工具会误导性能基线测试。
- **建议补充方向**：推荐 **CPDT (Cross Platform Disk Test)** 或 **PCMark Storage 2.0** 作为现代 Android 存储基准，并解释“关闭缓存测试”对获取物理 I/O 能力的重要性。

# 20.27 Kotlin 协程泄漏诊断与结构化并发性能监控

<!-- outline-start -->
## 要点

### 🔹 结构化并发模型与泄漏定义
- CoroutineScope 生命周期绑定与作用域树
- SupervisorJob / Job 父子关系与取消传播
- 协程泄漏的定义：超出预期生命周期的活跃协程
- 与传统线程泄漏的区别：协程"隐式持有"而非"匿名运行"

### 🔹 协程泄漏的常见模式
- GlobalScope 滥用与未绑定作用域
- CoroutineScope(Dispatchers.IO) 手动创建后忘记取消
- lifecycleScope / viewModelScope 的正确绑定与误用
- produce / channel 未关闭导致的订阅泄漏
- SharedFlow 收集器未随生命周期终止

### 🔹 协程线程资源开销
- Dispatchers.Default / IO / Main 的线程池实现
- Kotlin coroutines 线程池与 Java ExecutorService 的映射关系
- limiting.parallelism() 资源限流
- 协程调度器与 Android 线程优先级

### 🔹 CoroutineTracing API 与调试基础设施
- kotlinx.coroutines 1.7+ CoroutineTracing
- DebugCoroutinesInfo 与 correlate() 调试钩子
- -Dkotlinx.coroutines.debug=on 系统属性
- Android 17 上 coroutine name 在 Perfetto trace 中的可见性

### 🔹 线上协程监控方案设计
- 协程创建/完成的 hook 点：CoroutineStackFrame / recoverStackTrace
- ThreadContextElement 与线程切换追踪
- 协程名称命名规范与线上聚合策略
- CoroutineScope 引用链分析与泄漏判定算法
- 与现有线程监控（20.25 节）的协同方案

### 🔹 Flow / StateFlow / SharedFlow 泄漏检测
- collect 与 collectLatest 的生命周期绑定
- repeatOnLifecycle / collectIn 语义与泄漏防护
- 冷热流区分对泄漏判定的影响
- produceIn / flatMapMerge 操作符链的资源释放

### 🔹 Android 17 协程相关行为变更
- Jetpack Lifecycle 2.8+ lifecycleScope 实现变更
- Compose 的 LaunchedEffect / rememberCoroutineScope 泄漏边界
- Android 17 后台执行限制对挂起函数的影响

## 扩展

### 🔸 协程与 ANR 的因果关系
- 主线程 dispatch 的挂起函数恢复时机
- delay/select 超时与 ANR 触发路径的交叉

### 🔸 协程性能 profiling 实操
- 使用 Android Studio Coroutine Debugger 分析挂起点
- Perfetto trace 中的协程标记解读

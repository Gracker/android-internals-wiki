# 20.4 ANR 治理策略

如果说性能优化关注的是"快不快""顺不顺"，那 ANR 治理关注的就是"能不能响"和"会不会卡"。ANR（Application Not Responding，应用无响应）是 Android 应用稳定性的重要指标，直接关系到用户体验和应用留存。

## ANR 的本质与影响

### ANR 的定义

ANR 是指应用在规定时间内无法响应用户输入或系统事件时，系统弹出的"应用无响应"对话框。Android 系统定义了不同场景下的超时时间：

| 场景类型 | 超时时间 | 检测线程 |
|---------|---------|---------|
| 输入事件（按键、触摸） | 5 秒 | InputReader |
| 前台广播接收器 | 10 秒 | 主线程 |
| 后台广播接收器 | 60 秒 | 主线程 |
| 服务启动 | 20 秒 | 主线程 |
| ContentProvider | 10 秒 | 主线程 |

### ANR 的业务影响

1. **用户体验**：应用卡顿、无响应，用户流失
2. **业务损失**：交易中断、关键操作失败
3. **品牌影响**：应用质量差评，影响应用商店排名
4. **资源浪费**：用户重复操作、客服压力增加

## Android 17 中的 ANR 检测机制

### Choreographer 与 VSync 优化

Android 17 在 Choreographer 中引入了更精确的 VSync 时间戳预测机制，提高了帧率计算的准确性：

```cpp
// Android 17 Choreographer doFrame 优化
void Choreographer::doFrame(int64_t frameTime) {
    // VSync 预测机制
    int64_t predictedVSync = predictNextVSync(frameTime);
    
    // 更精确的时间计算
    int64_t expectedFrameTime = calculateExpectedFrameTime(predictedVSync);
    
    // 帧时间监控
    monitorFrameTime(frameTime, expectedFrameTime);
    
    // 帧率控制
    if (isFrameTooSlow(frameTime, expectedFrameTime)) {
        reportSlowFrame(frameTime);
    }
}
```

#### Activity Manager (AMS) 监控

```cpp
void ActivityManagerService::checkForAnr() {
    // 检查各个线程的响应情况
    for (const auto& threadInfo : mThreadInfos) {
        if (threadInfo->isUnresponsive()) {
            // 检查是否超过 ANR 超时时间
```

#### Input System 监控

```cpp
// InputReader ANR 检测
void InputReader::monitorInputDispatchTimeout() {
    const nsecs_t currentTime = systemTime(SYSTEM_TIME_MONOTONIC);
    
    // 检查输入事件分发超时
    for (const auto& connection : mConnections) {
        if (connection->hasPendingEvents() &&

            // 触发输入 ANR
            triggerInputAnr(connection);
        }
    }
}
```

## ANR 的预防策略

### 1. 主线程优化

#### 避免长时间操作

主线程不能执行耗时操作，这是 ANR 预防的基本原则：

```java
// ❌ 错误：在主线程执行网络请求
new Thread(() -> {
    String result = fetchDataFromNetwork();
    // 切换到主线程更新UI
    runOnUiThread(() -> updateUI(result));
}).start();

// ✅ 正确：使用异步方式
public void loadData() {
    showLoading();
    
    // 使用更现代的异步方式
    fetchDataFromNetworkAsync()
        .subscribeOn(Schedulers.io())
        .observeOn(AndroidSchedulers.mainThread())
        .subscribe(
            result -> {
                hideLoading();
                updateUI(result);
            },
            error -> {
                hideLoading();
                showError(error.getMessage());
            }
        );
}
```

#### 协程优化（Kotlin）

```kotlin
// Kotlin 协程方式 - 更简洁
suspend fun loadData() {
    withContext(Dispatchers.IO) {
        val data = fetchHeavyData()  // 耗时操作
    }
    
    withContext(Dispatchers.Main) {
        updateUI(data)  // 更新UI
    }
}
```

## Android 17 特定优化

### 1. DeliQueue 无锁消息队列

Android 17 引入了 DeliQueue，这是一个无锁消息队列实现，可以提升消息传递效率：

```cpp
// Android 17 DeliQueue 优化
template<typename T>
class DeliQueue {
private:
    std::atomic<Node*> head;
    std::atomic<Node*> tail;
    
public:
    void push(T value) {
        Node* newNode = new Node(value);
        
        // 无锁实现
        Node* oldTail = tail.load();
        while (!tail.compare_exchange_weak(oldTail, newNode)) {
            // 重试
        }
        
        oldTail->next.store(newNode);
    }
    
    T pop() {
        Node* oldHead = head.load();
        while (oldHead == nullptr || !head.compare_exchange_weak(oldHead, oldHead->next.load())) {
            // 重试或返回空
        }
        
        T value = oldHead->value;
        delete oldHead;
        return value;
    }
};
```

## ANR 监控指标体系

### 1. 核心指标

| 指标名称 | 计算方式 | 目标值 |
|---------|---------|-------|
| ANR率 | ANR次数 / 总启动次数 | < 0.1% |
| 卡顿率 | 卡顿次数 / 总操作次数 | < 0.5% |
| 响应时间 | 操作到响应的平均时间 | < 200ms |
| 帧率 | 帧率稳定在60fps | > 55fps |

### 2. 监控实现

```java
// ANR 监控指标实现
public class AnrMetrics {
    private AtomicInteger anrCount = new AtomicInteger(0);
    private AtomicInteger totalLaunches = new AtomicInteger(0);
    
    public void recordAnr() {
        anrCount.incrementAndGet();
    }
    
    public void recordLaunch() {
        totalLaunches.incrementAndGet();
    }
    
    public double getAnrRate() {
        int total = totalLaunches.get();
        if (total == 0) return 0.0;
        return (double) anrCount.get() / total;
    }
    
    public void checkThresholds() {
        if (getAnrRate() > 0.001) {  // 0.1%
            onAnrRateWarning();
        }
    }
}
```

## 总结

ANR 治理是 Android 应用稳定性的重要环节，在 Android 17 环境下，通过引入 PSI、DeliQueue 等新特性，可以建立更加完善的 ANR 治理体系。预防 ANR 需要从架构设计、代码优化、性能监控等多个维度进行综合考量：

1. **架构层面**：采用异步架构，避免主线程阻塞
2. **代码层面**：合理使用线程池、协程等技术
3. **监控层面**：建立完善的检测和预警机制
4. **工具层面**：善用 Android Studio 和系统工具

通过这些综合措施，可以显著降低 ANR 发生率，提升用户体验和应用质量。

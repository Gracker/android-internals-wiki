# 23.26 ART 堆内存分布与 OOM 触发路径实战

<!-- outline-start -->
## 要点

### 🔹 ART 堆空间布局与实战含义
- RegionSpace / LargeObjectSpace / ZygoteSpace / BumpPointerSpace / FreeListSpace 的分工
- 不同 Space 对内存占用（PSS）的贡献差异
- 实战中通过 `dumpsys meminfo` 和 `showmap` 识别各 Space 占比

### 🔹 对象分配路径与 Space 选择策略
- 大对象阈值（LargeObjectThreshold）与 LargeObjectSpace 分配条件
- RegionSpace 分配的 Fast Path / Slow Path
- TLAB（Thread-Local Allocation Buffer）对分配性能的影响
- [结构参考: Clippings/Android 应用稳定性剖析与优化 - ART 堆内存分布与黑科技扩量：拯救 OOM 的利器.md]

### 🔹 OOM 触发的完整链路
- `Heap::Allocate` → `AllocateInternalWithGc` 的 GC 重试逻辑
- `throwOOME` 的触发条件：GC 后仍无法满足分配请求
- `java.lang.OutOfMemoryError` 的构造与堆栈填充开销
- FD / 线程数耗尽导致的伪 OOM 与真 OOM 的区分
- [结构参考: Clippings/Android 应用稳定性剖析与优化 - OOM 发生路径：了解 OOM 是如何产生的.md]

### 🔹 实战：线上 OOM 分类与归因
- Java heap OOM（堆内存不足）
- Native memory OOM（so 库 brk/mmap 耗尽）
- Thread OOM（pthread_create 失败 → OutOfMemoryError）
- FD OOM（too many open files）
- 虚拟内存地址空间耗尽（32-bit→64-bit 迁移后的变化）

### 🔹 ART 堆扩量黑科技评估
- `setNativeAllocThreshold` 等隐藏 API 的可行性与风险
- NonFreeableSize 的人工干预与副作用
- `LargeObjectSpace` 阈值调整的收益与代价
- Android 17 上的限制与兼容性边界
- [结构参考: Clippings/Android 应用稳定性剖析与优化 - ART 堆内存分布与黑科技扩量：拯救 OOM 的利器.md]

### 🔹 实战工具链
- `hprof-conv` + MAT 分析 heap dump 中各 Space 占比
- `Perfetto heap_profile` 抓取 Native 分配
- `dumpsys meminfo --package <pkg>` 的 DAVSS / Total 读取
- `adb shell am dumpheap` 在线抓取 Java heap dump

### 🔹 Android 17 变更要点
- MTE（Memory Tagging Extension）对堆布局的影响
- 16KB Page Size 对内存分配粒度的影响
- ART GC 策略调整对 OOM 触发阈值的影响

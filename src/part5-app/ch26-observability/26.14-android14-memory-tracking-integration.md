# 26.14 Android 14 内存跟踪 API 集成与性能可观测性

> **版本边界**: 内容基于 Android 17 (`android-17.0.0_r1`) 源码与 Android 10–17 公开行为整理；不引入 Android 18/API 38+ 结论。
>
> **能力边界**: `MemoryTrackable`、`MemoryCategory`、`MemoryTracker`、`MemoryPressureDetector`、`MemoryPressureLevel` 等类/接口未在 AOSP `system/memory/libmeminfo/` 与 `frameworks/base/core/jni/` 源码中找到。可验证的路径是 `android.os.Debug`、`ActivityManager.MemoryInfo`、`libmeminfo` 与 `libmemevents`。

## 26.14.1 真实能力边界：不是新的应用侧对象跟踪框架

Android 14 之后的内存可观测性增强，核心不应理解为「应用层新增一个对象级 `MemoryTracker` API」。从 Android 17 源码看，可靠的主线能力由三层构成：

1. **应用/框架 Java 入口**：`android.os.Debug.getMemoryInfo()`、`Debug.MemoryInfo` 与 `ActivityManager.MemoryInfo`。
2. **JNI 桥接**：`frameworks/base/core/jni/android_os_Debug.cpp` 把 Java 调用映射到 native 内存统计。
3. **Native 统计与事件库**：`system/memory/libmeminfo/` 提供进程/系统内存统计；`libmemevents` 通过 eBPF ring buffer 监听内核内存压力事件。

因此，应用开发者可以稳定依赖的是公开 Java API 与系统诊断工具；系统服务、平台组件或特权进程则可以进一步使用 native 层 `libmeminfo` / `libmemevents`。

## 26.14.2 Java 层入口：Debug.MemoryInfo 与 ActivityManager.MemoryInfo

### 26.14.2.1 进程内存快照

应用侧最常见的采样方式仍然是 `Debug.getMemoryInfo()`：

```java
Debug.MemoryInfo info = new Debug.MemoryInfo();
Debug.getMemoryInfo(info);

int totalPssKb = info.getTotalPss();
int privateDirtyKb = info.getTotalPrivateDirty();
int dalvikPssKb = info.dalvikPss;
int nativePssKb = info.nativePss;
int otherPssKb = info.otherPss;
```

这类指标适合做低频健康采样、问题现场快照和线上 APM 聚合。需要注意：PSS 是分摊后的驻留内存估计值，不等同于 Java 堆大小，也不能直接作为「还可以分配多少内存」的判断依据。

### 26.14.2.2 系统内存状态

系统可用内存与低内存状态仍通过 `ActivityManager.getMemoryInfo()` 获取：

```java
ActivityManager am = (ActivityManager) context.getSystemService(Context.ACTIVITY_SERVICE);
ActivityManager.MemoryInfo mi = new ActivityManager.MemoryInfo();
am.getMemoryInfo(mi);

long availMem = mi.availMem;
long totalMem = mi.totalMem;
boolean lowMemory = mi.lowMemory;
long threshold = mi.threshold;
```

在 Android 17 源码中，JNI 侧 `read_system_mem_info` 会通过 `SysMemInfo::kDefaultSysMemInfoTags` 读取 `/proc/meminfo` 相关 tag，并把结果拷贝到 Java `long[]`。锚定的源码路径显示 zram 等系统级字段进入统计链路；普通应用仍应把它们视为系统状态信号，而不是对象级泄漏定位 API。

## 26.14.3 Native 实现：libmeminfo

`libmeminfo` 位于 `system/memory/libmeminfo/`。它从 Android 12/S（API 31）开始作为系统侧原生库独立存在，`Android.bp` 中可见 `min_sdk_version: "S"`、`vendor_available: true` 与 APEX 可用性配置；这些属性说明它是平台/vendor/APEX 可复用的 native 基础库，不等同于普通应用可直接调用的新公开 Java API。核心类包括：

- `android::meminfo::ProcMemInfo`：按进程读取 VMA、PSS、USS、RSS、swap 等统计。
- `android::meminfo::SysMemInfo`：读取 `/proc/meminfo`、zram 与 vmalloc 等系统维度数据。
- `android::meminfo::MemUsage`：承载 `vss`、`rss`、`pss`、`uss`、`swap`、`swap_pss`、private/shared clean/dirty 等字段。

`Debug.getMemoryInfo()` 的 JNI 实现关键路径如下（源码锚点：`frameworks/base/core/jni/android_os_Debug.cpp:288-307`）：

```cpp
::android::meminfo::ProcMemInfo proc_mem(pid);
::android::meminfo::MemUsage stats;
if (proc_mem.SmapsOrRollup(&stats)) {
    pss += stats.pss;
    uss += stats.uss;
    rss += stats.rss;
    swapPss = stats.swap_pss;
    pss += swapPss;
}
```

Java 层看到的 PSS/USS/RSS/swap PSS 来自 native 层对 procfs 统计的封装，并没有新增 Java 对象跟踪接口。

## 26.14.4 两条采样路径：快照与深度诊断

### 26.14.4.1 `smaps_rollup` 快路径

`ProcMemInfo::SmapsOrRollup()` 会优先读取 `/proc/<pid>/smaps_rollup`，在不支持时退回 `/proc/<pid>/smaps`。`smaps_rollup` 是 Linux 4.14+ 的聚合视图，可以避免逐 VMA 解析，适合 Java 层 `Debug.getMemoryInfo()` 这类常规采样。

工程建议：

- 线上采样频率保持低频，例如 5 秒或更长间隔；
- 只上报关键聚合指标（PSS、private dirty、native/dalvik/other）；
- 避免在主线程或高频渲染路径中做同步采样。

### 26.14.4.2 VMA / pagemap 高精度路径

深度诊断可以使用 `ProcMemInfo` 的 VMA 级路径：读取 `/proc/<pid>/pagemap`，分块处理页表，再结合 `/proc/kpageflags` 与 `/proc/kpagecount` 计算 PSS/USS，并可在 `get_wss=true` 时结合 idle page tracking 估计 working set。

这条路径精度更高，但代价也明显更高：全量扫描大进程可能触发大量 syscall。生产环境只应在问题诊断、实验室复现或受控采样中使用，并尽量限定目标 VMA、采样窗口与页标志过滤条件。

## 26.14.5 Android 14 相关实时内存事件：libmemevents

Android 14 相关源码中更值得关注的「实时内存压力」路径是 `system/memory/libmeminfo/libmemevents/`，Android 17 代码中仍保留这条路径。该模块通过 eBPF ring buffer 监听内核 tracepoint，将内存压力事件推送给用户态监听者。

| 事件类型 | 内核 tracepoint | 语义 |
|---|---|---|
| `MEM_EVENT_OOM_KILL` | `oom/mark_victim` | OOM victim 标记 |
| `MEM_EVENT_DIRECT_RECLAIM_BEGIN` | `vmscan/mm_vmscan_direct_reclaim_begin` | direct reclaim 开始 |
| `MEM_EVENT_DIRECT_RECLAIM_END` | `vmscan/mm_vmscan_direct_reclaim_end` | direct reclaim 结束 |
| `MEM_EVENT_KSWAPD_WAKE` | `vmscan/mm_vmscan_kswapd_wake` | kswapd 被唤醒 |
| `MEM_EVENT_KSWAPD_SLEEP` | `vmscan/mm_vmscan_kswapd_sleep` | kswapd 休眠 |
| `MEM_EVENT_VENDOR_LMK_KILL` | `android_vendor_lmk/android_trigger_vendor_lmk_kill` | vendor LMK kill |
| `MEM_EVENT_UPDATE_ZONEINFO` | `kmem/mm_calculate_totalreserve_pages` | zoneinfo 更新 |

`libmemevents` 依赖 Linux 5.8+ 的 BPF ring buffer。能力边界应绑定到 Android 17 源码与具体设备内核配置，不能推广为所有 Android 14 设备都完整可用。

## 26.14.6 应用性能治理实践

### 26.14.6.1 线上监控指标

应用侧可建立如下低风险指标集：

```java
public final class MemorySnapshot {
    public final int totalPssKb;
    public final int nativePssKb;
    public final int dalvikPssKb;
    public final int otherPssKb;
    public final int privateDirtyKb;
    public final long availMemBytes;
    public final boolean lowMemory;

    public MemorySnapshot(Context context) {
        Debug.MemoryInfo process = new Debug.MemoryInfo();
        Debug.getMemoryInfo(process);

        ActivityManager.MemoryInfo system = new ActivityManager.MemoryInfo();
        ActivityManager am = context.getSystemService(ActivityManager.class);
        am.getMemoryInfo(system);

        totalPssKb = process.getTotalPss();
        nativePssKb = process.nativePss;
        dalvikPssKb = process.dalvikPss;
        otherPssKb = process.otherPss;
        privateDirtyKb = process.getTotalPrivateDirty();
        availMemBytes = system.availMem;
        lowMemory = system.lowMemory;
    }
}
```

采样结果应与业务场景一起解释：前后台切换、图片列表滚动、WebView 打开、数据库同步、冷启动与大文件 I/O 都可能改变内存曲线。

### 26.14.6.2 泄漏排查边界

`Debug.MemoryInfo` 可以发现「PSS 持续上涨」「nativePss 异常升高」「进入后台后未回落」等趋势，但不能直接告诉你哪个 Java 对象泄漏。对象引用链仍需要 LeakCanary、heap dump、Studio Profiler 或 ART/Perfetto 相关工具辅助。

建议流程：

1. 线上低频采样发现异常趋势；
2. 用场景标签定位触发路径；
3. 实验室复现并采集 heap dump / Perfetto trace；
4. 必要时结合 `dumpsys meminfo <pid>`、`/proc/<pid>/smaps_rollup` 或平台侧 `libmeminfo` 做交叉验证。

### 26.14.6.3 内存压力响应

应用侧不应依赖不存在的 `MemoryPressureDetector`。可用的响应信号包括：

- `ComponentCallbacks2.onTrimMemory(level)`：系统对应用发出的内存压力回调；
- `ActivityManager.MemoryInfo.lowMemory` 与 `threshold`：系统低内存状态；
- 自有 APM 趋势：PSS、nativePss、bitmap/cache 命中率、后台驻留时长等。

典型响应策略：

- `TRIM_MEMORY_RUNNING_LOW` / `RUNNING_CRITICAL`：降低缓存上限、暂停预加载、释放可重建资源；
- `TRIM_MEMORY_UI_HIDDEN`：释放 UI 专属缓存和大图资源；
- 后台长驻进程：降低定时任务频率，避免与系统 reclaim 周期叠加。

## 26.14.7 调试清单

- `adb shell dumpsys meminfo <package-or-pid>`：查看 Java/native/graphics/code/stack 等聚合分类。
- `adb shell cat /proc/<pid>/smaps_rollup`：快速核对 PSS/RSS/USS 聚合值。
- `adb shell cat /proc/meminfo`：观察系统维度内存、水位与 swap/zram 背景。
- Perfetto trace：把内存趋势与启动、渲染、I/O、binder、GC 等事件放在同一时间线上分析。
- 平台侧源码核对：`system/memory/libmeminfo/`、`system/memory/libmeminfo/libmemevents/`、`frameworks/base/core/jni/android_os_Debug.cpp`。

## 26.14.8 版本差异与注意事项

| 能力 | 版本边界 | 说明 |
|---|---|---|
| `smaps_rollup` 快路径 | Android 10/API 29 源码已包含相关探测/回退背景 | 实际依赖 Linux 4.14+ 内核支持，不支持时回退到 `/proc/<pid>/smaps` |
| `libmeminfo` 独立库 | Android 12/S/API 31 起 | `system/memory/libmeminfo/Android.bp` 中 `min_sdk_version: "S"` |
| `libmemevents` | Android 14/API 34 相关源码路径，Android 17 仍保留 | 通过 eBPF ring buffer 监听内存事件，依赖 Linux 5.8+ 与设备内核配置 |
| zram/系统内存字段增强 | Android 17 锚定源码中可见相关统计链路 | `SysMemInfo` 负责系统级 meminfo/zram 数据读取；不推导为应用侧对象跟踪 API |

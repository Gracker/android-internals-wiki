# 4.37 Android 17 LMKD 用户态迁移 + PSI 协同机制

<!-- outline-start -->
## 要点

### 🔹 LMKD 从内核到用户态的完整迁移
Android 17 LMKD从system/core迁移至system/memory/lmkd/，实现重大架构变革：
- 代码位置变更：系统服务独立模块化，职责更加清晰
- 决策逻辑重构：从内核vmpressure切换到用户态PSI机制
- 接口标准化：统一API设计，便于第三方实现兼容

### 🔹 PSI（Pressure Stall Information）核心机制
Android 17全面采用PSI替代传统的vmpressure：
- 三维决策模型：zone watermarks、thrashing、swap utilization
- BPF ring buffer实时监听：direct reclaim、kswapd、vendor kill事件
- pidfd等待机制：取代传统信号量，提升精确度
- 分级采样策略：10ms（高压力）和100ms（低压力）间隔

### 🔹 PSI协同工作流程
LMKD与PSI的协同工作采用事件驱动模式：
1. PSI监控实时内存压力指标
2. LMKD根据三维决策模型选择kill目标
3. BPF ring buffer传递内核事件
4. pidfd等待机制确保进程终止准确

### 🔹 响应时间与精度提升
用户态LMKD相比内核LMKD的优势：
- 响应时间：内核态决策延迟降低约40%
- 决策精度：PSI多维指标比单一vmpressure更准确
- 调试能力：用户态可添加详细日志和监控
- 热更新能力：无需重启即可修复逻辑bug

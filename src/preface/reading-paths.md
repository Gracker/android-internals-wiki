# 阅读路径推荐

可以先根据自己的角色和当前问题找到一条主线，再按需补前置章节。首次系统学习时也可以按第一部分到第三部分的顺序阅读。

## App 性能优化工程师

App 层性能优化可以从问题和工具出发，再按需补充系统机制。

**核心路径**：7.1-7.6（流畅性）→ 8.1-8.7（响应速度）→ 9.1-9.5（ANR）→ 14.1-14.5（Perfetto 基础）→ 16.1-16.3（方法论）

这条路径先建立问题分类方法，学会阅读系统跟踪数据（trace）并判断证据是否充分，再用 `2.4`、`2.9`、`4.4`、`10.x` 补充渲染与内存机制。

**按需深入**：2.4、2.9（App 绘制与系统合成）→ 4.4（App 内存优化）→ 10.1-10.4（内存性能）→ 11.2（App 耗电优化）→ 12.1-12.2（网络性能）→ 25.10（应用体积）→ 25.11（分发）

## Android Framework / 系统工程师

系统级开发或 ROM 定制适合先顺序阅读前半部分，后续性能问题会反复引用这些系统机制。

**核心路径**：1.1-1.6（架构全景）→ 2.1-2.8（完整渲染路径）→ 3.1-3.3（输入系统）→ 4.1-4.6（内存管理）→ 5.1-5.7（CPU 调度）→ 6.1-6.4（存储 I/O）

这条路径先建立系统对象、进程与线程、数据流和资源管理的整体关系。阅读第 `18`、`19` 章时，便能分清 Android 开源项目（AOSP）的公共机制、Android Common Kernel（Android 公共内核）的固定版本与厂商定制策略。

**进阶路径**：18.1-18.3（AOSP 优化）→ 19.1-19.3（厂商实践）→ 14.6-14.7（Perfetto 高级用法）

## 性能测试工程师

性能测试、质量平台或线上监控方向可以连续阅读分析方法、指标和工具章节。

**核心路径**：16.3（性能指标与线上监控）→ 16.5（测试最佳实践）→ 14.1-14.4（Perfetto）→ 15.1-15.11（其他工具）→ 16.6（竞品分析）

这条路径先说明该测什么、怎样采集、怎样验证和怎样追踪修复结果，再回到卡顿、启动与 ANR 场景做专项分析。

**场景深入**：7.2（卡顿分析方法论）→ 8.2（启动全流程）→ 9.2（ANR 分析方法）

## 按问题查阅

| 问题 | 去看 |
|------|------|
| 列表滑动卡顿 | 7.1 → 7.2 → 22.2 |
| App 启动慢 | 8.2 → 8.3 |
| ANR 频繁 | 9.2 → 9.3 → 9.4 |
| 内存持续增长 | 10.1 → 23.2 → 23.7 |
| 耗电量高 | 11.1 → 11.2 |
| 不知道怎么看 Perfetto | 14.1 → 14.2 → 14.3 |
| 区分系统问题还是 App 问题 | 16.2 |

带着实际问题阅读时，先把现象对应到正确章节，再补背景与版本差异。章节里的平台机制默认按 `android-17.0.0_r1` 核对，内核机制默认按 `android17-6.18-2026-06_r6` 核对；若设备版本更低，应按正文给出的版本范围切换到相应的历史源码标签（tag）。

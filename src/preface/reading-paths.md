# 阅读路径推荐

这本书不需要从第一页按顺序读到最后一页。  
更有效的读法，是先根据自己的角色和当前问题找到一条主线，再按需回头补前置章节。

## App 性能优化工程师

如果你主要做 App 层面的性能优化，最稳的读法是先从问题和工具出发，再回头补系统机制。

**核心路径**：7.1-7.7（流畅性）→ 8.1-8.6（响应速度）→ 9.1-9.5（ANR）→ 13.1-13.5（Perfetto 基础）→ 15.1-15.3（方法论）

这样读的好处是，读者会先建立“问题怎么分类、trace 怎么看、判断怎么下”的骨架，再回头补 `2.4`、`2.5`、`4.5`、`10.x` 这些更偏机制和专项的内容。

**按需深入**：2.4-2.5（渲染管线细节）→ 4.5（App 内存优化）→ 10.1-10.6（内存性能）→ 11.2（App 耗电优化）→ 12.1-12.2（包体积与网络）

## Android Framework / 系统工程师

如果你从事系统级开发或 ROM 定制，更适合先把前半本书顺着读下来，因为后面很多性能问题都建立在系统机制之上。

**核心路径**：1.1-1.6（架构全景）→ 2.1-2.10（渲染全链路）→ 3.1-3.3（输入系统）→ 4.1-4.6（内存管理）→ 5.1-5.7（CPU 调度）→ 6.1-6.4（存储 I/O）

这一条路径的意义，不是先“看性能案例”，而是先把系统图景搭稳。这样后面再看 `16`、`17` 章时，读者会更容易判断哪些优化真的落在系统设计上，哪些只是厂商定制策略。

**进阶路径**：16.1-16.3（AOSP 优化）→ 17.1-17.3（厂商实践）→ 13.6-13.7（Perfetto 高级用法）

## 性能测试工程师

如果你负责性能测试、质量平台或线上监控，更适合把方法论、指标和工具连着读。

**核心路径**：15.3（性能指标体系）→ 15.6（测试最佳实践）→ 13.1-13.4（Perfetto）→ 14.1-14.7（其他工具）→ 15.4（竞品分析）→ 15.5（线上监控）

这样读的价值是，读者会先知道“该量什么、怎么量、怎么验证、怎么把问题送进闭环”，再回到卡顿、启动、ANR 的场景里做专项分析。

**场景深入**：7.3（卡顿分析方法论）→ 8.2（启动全流程）→ 9.3（ANR 分析方法）

## "我遇到了一个具体问题"

| 问题 | 去看 |
|------|------|
| 列表滑动卡顿 | 7.4 → 7.5 → 7.7 |
| App 启动慢 | 8.2 → 8.3 |
| ANR 频繁 | 9.2 → 9.3 → 9.4 |
| 内存持续增长 | 10.2 → 10.3 → 10.6 |
| 耗电量高 | 11.1 → 11.2 |
| 不知道怎么看 Perfetto | 13.1 → 13.2 → 13.3 |
| 区分系统问题还是 App 问题 | 15.2 |

如果你现在就带着一个真实问题来读，这一节比“完整阅读路径”更重要。  
先把问题对上正确章节，再回头补背景，通常会比从头线性读完更容易建立自己的知识地图。

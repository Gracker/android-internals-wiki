# 2.52 Compose Pager 从基础到高级动画完整指南

Compose Pager（`HorizontalPager` / `VerticalPager`）是 Jetpack Compose Foundation 中用于替代传统 `ViewPager` / `ViewPager2` 的分页滚动组件。与基于 Adapter 的 View 体系不同，Pager 采用状态驱动模型，通过 `PagerState` 管理滚动位置和页面状态，开发者只需提供 Composable lambda 即可定义页面内容。

本章覆盖 Pager 的核心 API 架构、高级动画变换、性能优化策略以及与 Paging 3 的集成实践。所有 API 基于 Compose Foundation 1.7+ 稳定版本，适用 Android 12 (API 31) 至 Android 17 (API 37)。

[适用版本: Android 12 - Android 17]

---

## 要点

### 🔹 Compose Pager 基础架构

#### PagerState 核心管理机制

Pager 的设计核心是 `PagerState`，它负责追踪当前页面位置、滚动偏移、页面数量等全部状态。初始化通过 `rememberPagerState` 完成：

```kotlin
@Composable
fun rememberPagerState(
    initialPage: Int = 0,
    @FloatRange(from = -0.5, to = 0.5)
    initialPageOffsetFraction: Float = 0f,
    pageCount: () -> Int,
): PagerState
```

关键设计要点：

- **`pageCount` 为 lambda 而非 Int**：这使得页面数量可以响应式地跟随数据源变化。当底层数据增删时，Pager 自动更新滚动范围，无需手动 `notifyDataSetChanged`。
- **`initialPageOffsetFraction`**：允许初始时将页面偏移到 -0.5 ~ 0.5 之间的小数位置，用于实现起始页面部分可见等特殊效果。
- **编程式导航**：通过 `state.animateScrollToPage(page)` 实现动画滚动，该函数是 `suspend`，需在 `CoroutineScope` 中调用（通常使用 `rememberCoroutineScope`）。

[已验证: 官方文档, androidx.compose.foundation.pager.PagerState]

#### 页面生命周期与懒加载

HorizontalPager 和 VerticalPager 中的页面都是**懒加载**的——只在需要进入视口时才进行组合（Composition）和布局（Measure/Layout）。这是 Pager 与传统 ViewPager2 的关键性能差异：

- ViewPager2 基于 RecyclerView，持有固定数量的 View；Pager 基于 Compose 的组合树，页面内容在离开视口后被移除
- 默认情况下，`beyondViewportPageCount = 0`，仅组合当前可见页面
- 提高 `beyondViewportPageCount` 可预加载相邻页面，减少滑动时的组合延迟，但会增加内存和 CPU 开销

```kotlin
HorizontalPager(
    state = state,
    beyondViewportPageCount = 1  // 预加载前后各 1 页
) { page ->
    PagerItem(page)
}
```

⚠️ **性能警告**：`beyondViewportPageCount` 设得过高（如 ≥3）会导致大量离屏页面同时参与组合和测量，在页面内容复杂时引起帧丢失。建议根据页面复杂度动态调整而非静态设高值。

[已验证: 官方文档, androidx.compose.foundation.pager]

#### key 参数与状态保持

处理动态数据（增删、排序、移动）时，必须为每个页面提供稳定唯一的 `key`：

```kotlin
HorizontalPager(
    state = state,
    key = { page -> data[page].id }  // 使用业务 ID 而非位置索引
) { page ->
    PagerItem(data[page])
}
```

未提供 `key` 时，Pager 默认使用位置索引作为标识。在列表头部插入条目会导致所有后续页面的位置索引位移，造成：
- 滚动位置跳变
- 页面内部状态（如 `rememberSaveable`）丢失
- `LaunchedEffect` 误触发

[已验证: 官方文档, Compose Foundation key parameter]

### 🔹 高级动画特性

#### graphicsLayer 3D 变换

`PagerState` 暴露的 `currentPageOffsetFraction`（当前页面距吸附位置的偏移比例，范围 -1.0 ~ 1.0）是实现滚动驱动动画的核心数据源。结合 `graphicsLayer` 修饰符，可以实现旋转、缩放、透明度等复合视觉效果：

```kotlin
HorizontalPager(state = state) { page ->
    val pageOffset = ((state.currentPage - page) + state.currentPageOffsetFraction)
    PagerItem(
        modifier = Modifier.graphicsLayer {
            val distance = pageOffset.absoluteValue.coerceIn(0f, 1f)
            alpha = lerp(0.3f, 1f, 1f - distance)
            scaleX = lerp(0.8f, 1f, 1f - distance)
            scaleY = lerp(0.8f, 1f, 1f - distance)
            rotationY = pageOffset * -30f
            cameraDistance = 12 * density
        }
    )
}
```

关键计算逻辑：

| 属性 | 计算公式 | 效果 |
|------|----------|------|
| `alpha` | `lerp(minAlpha, 1f, 1f - distance)` | 远离中心时渐隐 |
| `scaleX/Y` | `lerp(minScale, 1f, 1f - distance)` | 远离中心时缩小 |
| `rotationY` | `pageOffset * maxRotationDegrees` | 3D 翻转效果 |
| `cameraDistance` | `12 * density` | 控制透视畸变程度 |

其中 `distance` 是页面到当前吸附位置的绝对偏移量（含小数部分），`lerp` 为 `androidx.compose.ui.util.lerp`。

[已验证: 官方文档, androidx.compose.ui.graphics.graphicsLayer]
[结构参考: 掘金 7618433588125007923]

#### 自定义 Fling 滑动距离

默认情况下，无论用户滑动速度多快，单次手势 Pager 最多移动一页。通过自定义 `flingBehavior` 可以放宽此限制：

```kotlin
val fling = PagerDefaults.flingBehavior(
    state = state,
    pagerSnapDistance = PagerSnapDistance.atMost(3)
)
HorizontalPager(
    state = state,
    flingBehavior = fling
) { page -> ... }
```

`PagerSnapDistance` 选项：
- `atMost(n)`：单次 fling 最多跨越 n 页
- 默认值等价于 `atMost(1)`

适用于图库浏览、长列表分页等需要快速导航的场景。注意设过高时，中间页面的组合/布局来不及完成，可能出现白屏闪烁。

[已验证: 官方文档, androidx.compose.foundation.pager.PagerDefaults]

#### 动态页面数与 Paging 3 集成

`pageCount` lambda 天然支持动态变化，与 Paging 3 配合时：

```kotlin
@Composable
fun PagingPagerView(viewModel: MyViewModel = viewModel()) {
    val items = viewModel.items.collectAsLazyPagingItems()
    val state = rememberPagerState(pageCount = { items.itemCount })
    HorizontalPager(state = state) { page ->
        items[page]?.let { item ->
            PagerItem(item)
        }
    }
}
```

要点：
- `collectAsLazyPagingItems()` 返回的 `LazyPagingItems` 自身也是懒加载的，只有被访问的 `page` 索引才会触发数据加载
- Pager 的懒加载 + Paging 3 的数据分块 = 双层懒加载，适合大量数据场景
- 注意 `items[page]` 可能为 `null`（加载中），需提供占位 UI

[已验证: 官方文档, androidx.paging.compose.collectAsLazyPagingItems]

### 🔸 实战技术要点

#### SnapPosition 对齐策略

当使用自定义 `PageSize`（如 `threePagesPerViewport`）使同一屏幕显示多个页面时，`snapPosition` 决定滚动结束后当前页面对齐到容器的哪个位置：

```kotlin
HorizontalPager(
    state = state,
    pageSize = threePagesPerViewport,
    snapPosition = SnapPosition.Center  // 当前页居中
) { page -> ... }
```

| SnapPosition | 对齐位置 | 适用场景 |
|---|---|---|
| `Start`（默认） | 容器左/上边缘 | 阅读器、引导页 |
| `Center` | 容器中心 | 轮播图、卡片展示 |
| `End` | 容器右/下边缘 | 反向导航 |

[已验证: 官方文档, androidx.compose.foundation.pager.SnapPosition]

#### contentPadding 窥探效果

`contentPadding` 与 `Modifier.padding()` 的关键区别在于：`contentPadding` 允许内容在滚动时覆盖该区域，而 `Modifier.padding()` 是不可滚动的固定留白。

```kotlin
HorizontalPager(
    state = state,
    contentPadding = PaddingValues(horizontal = 16.dp)
) { page -> ... }
```

设置水平 `contentPadding` 后，相邻页面会在边缘露出一部分，向用户暗示"还有更多内容"。这是 Material Design 推荐的分页体验模式。

[已验证: 官方文档, androidx.compose.foundation.layout.contentPadding]

#### 负间距重叠效果

`pageSpacing` 参数支持负值，实现页面重叠的堆叠效果：

```kotlin
HorizontalPager(
    state = state,
    pageSpacing = (-16).dp
) { page -> ... }
```

负间距使相邻页面互相覆盖，配合 `graphicsLayer` 透明度/缩放变换可创造卡片层叠动画。注意负间距下页面内容可能互相遮挡，需配合 `zIndex` 或绘制顺序控制。

[已验证: 官方文档, androidx.compose.foundation.pager.pageSpacing]

### 🔸 最佳实践与优化

#### beyondViewportPageCount 调优策略

| 页面复杂度 | 推荐 `beyondViewportPageCount` | 理由 |
|---|---|---|
| 简纯文本/图标 | 2-3 | 组合开销低，预加载提升滑动流畅度 |
| 图片/列表 | 1 | 平衡内存与流畅度 |
| 复杂布局（视频/地图） | 0 | 避免离屏组合造成卡顿 |

可以动态调整此值：

```kotlin
var beyondCount by remember { mutableIntStateOf(1) }
HorizontalPager(
    state = state,
    beyondViewportPageCount = beyondCount
) { page -> ... }
```

[已验证: 官方文档, androidx.compose.foundation.pager.beyondViewportPageCount]

#### key 使用规范

- **必须**：当数据源可能增删时，提供业务 ID 作为 key
- **可选**：当页面数量固定且不会变化时（如引导页），可省略
- **禁止**：使用 `page` 索引作为 key（等价于不传 key），会导致动态数据场景下的状态错乱

## 扩展

### 🔸 复杂场景支持

#### 多级嵌套 Pager

Compose 的组合性使 Pager 可以嵌套使用（如外层水平 + 内层垂直）。嵌套时需注意：
- 内层 Pager 会消费手势事件，外层不会响应——需通过 `nestedScroll` 连接滚动链
- 嵌套 Pager 的 `beyondViewportPageCount` 累积效应：外层 2 × 内层 2 = 最多 9 个页面同时存活
- 建议内层 Pager 设 `beyondViewportPageCount = 0`，仅外层预加载

#### 动画中断与恢复

`animateScrollToPage` 可被新的动画调用或用户手势中断。Compose 的动画系统基于协程，中断时：
- 当前动画帧立即停止
- 从当前位置开始新的动画/手势
- `PagerState` 的 `currentPage` 和 `currentPageOffsetFraction` 始终反映真实状态

[已验证: 官方文档, Compose animation coroutine-based interruption]

### 🔸 性能监控与调优

#### Pager 性能瓶颈定位

使用 Layout Inspector 和 Perfetto 可定位 Pager 性能问题：

1. **组合耗时**：Layout Inspector 的 Recomposition Counts 显示哪些页面被频繁重组
2. **布局抖动**：如果页面内容依赖 `PagerState` 的变化（如 `currentPage`），会导致所有可见页面在每次滚动帧都重组。解决方案：只让需要动画的页面订阅 `currentPageOffsetFraction`
3. **测量传递**：复杂页面布局（如深嵌套 `Column/Row`）会增加 measure pass 耗时

#### 内存优化建议

- 页面内容使用 `remember` 缓存计算结果，避免每次重组重复计算
- 图片加载使用 Glide/Coil 的 `rememberAsyncImagePainter`，自动管理 Bitmap 生命周期
- `beyondViewportPageCount = 0` 时，离开视口的页面会被垃圾回收，但 `rememberSaveable` 状态仍保留

# 2.3 Android 17 GPU 调试性能工具链源码调研

<!-- outline-start -->
## 要点

### 🔹 FPSReporter 分层 FPS 监控
Android 17 引入了全新的 FPSReporter 分层监控体系，通过 SurfaceFlinger 的三个关键组件实现精确的帧率监控：FPSMonitor（全局计数）、FrameCallback（窗口回调）、Perfetto 集成（系统级分析）。该系统支持不同窗口、不同场景的独立 FPS 统计，为性能问题定位提供了数据基础。

### 🔹 JankTracker 异步卡顿检测系统
JankTracker 是 Android 17 卡顿检测的核心组件，采用异步检测机制，避免影响 UI 线程性能。它通过 FrameTimeline 的插入点标记、FrameDeadline 的预测算法、JankClassification 的三态分类（轻度/中度/重度），实现了精准的卡顿类型识别和原因定位。

### 🔹 FrameTracer 与 Perfetto 集成的帧追踪管线
FrameTracer 实现了从提交到显示的完整帧追踪链路，与 Perfetto v57 深度集成。通过 FrameTimelineEvents 的时间戳记录、SurfaceFlinger 的渲染状态机追踪、Perfetto 协议的数据同步，实现了端到端的帧性能分析。

### 🔹 GPU 调试属性系统扩展
Android 17 扩展了 GPU 调试属性系统，新增了 20+ 个调试点，覆盖 GPU 负载检测、渲染延迟分析、内存带宽使用等关键指标。这些属性可通过 `adb shell dumpsys gfxinfo` 实时查询，支持 A/B 测试对比和性能基准建立。

### 🔹 gralloc 转换与性能开销分析
Android 17 的 gralloc 转换机制实现了 GPU 内存分配的高效管理，通过 BufferQueue 的缓冲区复用、GraphicBuffer 的智能分配策略、内存带宽优化，减少了 GPU 内存分配的开销，提升了渲染性能。

### 🔹 调试开销分析矩阵
Android 17 提供了完整的调试开销分析矩阵，量化了各种调试工具对性能的影响。FPSReporter 带来的开销 <1%，JankTracker 在后台检测时 <0.5%，FrameTracer 启用时增加 2-3ms 帧处理时间，帮助开发者做出合理的工具选择。

## 扩展

### 🔸 多窗口性能对比分析
分析 Android 17 在多窗口场景下的 GPU 性能分配策略，包括分屏模式、桌面模式、PIP 模式下的资源分配差异，以及不同窗口优先级的 GPU 调度机制。

### 🔸 独立进程 GPU 调试通道
Android 17 引入了独立的 GPU 调试通道，支持跨进程的性能数据收集和分析，为系统级性能优化提供了数据支撑。

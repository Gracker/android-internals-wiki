## 要点

### 🔹 锚点 1：Compose Pager 架构概述

Compose Pager 是 Jetpack Compose Foundation 提供的分页滚动组件，包含 `HorizontalPager` 和 `VerticalPager` 两个 API。它们是 View 体系中 `ViewPager2` 的 Compose 原生替代方案，自 **Compose 1.6**（2024 年 2 月稳定）起正式发布。

**核心架构特征**：

```
HorizontalPager / VerticalPager
├── PagerState（滚动状态控制器）
├── LazyList 风格的子项管理（按需组合 + 预取）
├── SnapBehavior（页面对齐物理引擎）
└── beyondBoundsPageCount（预组合窗口控制）
```

与 `ViewPager2` 基于 `RecyclerView` 的实现不同，Compose Pager 直接构建在 Compose Runtime 的组合系统之上，无需 View 层级介入。这意味着：

- **组合驱动**：页面内容通过 Composable 函数按需组合，而非 View 的 inflate
- **状态驱动**：`PagerState` 作为单一状态源，驱动 UI 更新和动画
- **PausableComposition 集成**：Compose 1.10+ 默认启用可暂停组合，复杂页面不再阻塞帧

[适用版本: Android 12+ (Compose 1.6+) - Android 17 (API 37)]
[来源: 官方文档, developer.android.com/jetpack/compose/layouts/pager]

### 🔹 锚点 2：PagerState 状态管理与滚动物理

`PagerState` 是 Pager 的核心状态持有者，承载当前页码、滚动偏移、滚动进度等关键信息：

```kotlin
@Stable
class PagerState {
    val currentPage: Int          // 当前停留的页码（已稳定）
    val targetPage: Int           // 滑动目标页码（尚未稳定）
    val settledPage: Int          // 已结算页码
    val scrollPosition: Int       // 滚动位置锚点
    
    // 滚动偏移信息（用于动画计算）
    val currentPageOffsetFraction: Float  // 当前页的偏移比例 [-1, 1]
    
    // 滚动控制
    suspend fun animateScrollToPage(page: Int, ...)
    suspend fun scrollToPage(page: Int, ...)
    fun dismissCurrentPage()  // Android 14+ 新增
}
```

**滚动物理模型**：

Pager 的滑动手势处理基于 Compose 的 ` AnchoredDraggable ` 机制（Compose Foundation 1.7+ 替代了早期的 ` anchoredDraggable ` 实验性 API），其核心是**锚点吸附（snap-to-anchor）**：

1. **拖拽阶段**：用户手指拖拽时，`PagerState` 持续更新 `currentPageOffsetFraction`
2. **释放阶段**：手指抬起后，根据当前速度和位置决定 `targetPage`
3. **吸附阶段**：使用 `AnimationSpec`（默认 SpringSpec）动画到目标页面

与 Choreographer 的交互遵循标准 Compose 渲染管线：每帧通过 `Choreographer.FrameData` 获取 Vsync deadline，在 `frameNanos` 预算内完成状态更新 → 重组 → 布局 → 绘制。详见 §2.4 Choreographer 与渲染流水线。

### 🔹 锚点 3：beyondBoundsPageCount 预组合策略

`beyondBoundsPageCount` 是 Compose Pager 中最关键的性能调优参数，控制**在可见页面之外预组合多少个页面**：

```kotlin
HorizontalPager(
    state = pagerState,
    pageCount = 10,
    beyondBoundsPageCount = 1,  // 默认 0
) { page ->
    // pageCount=10, beyondBoundsPageCount=1
    // 则左右各预组合 1 个页面，总计同时存在 3 个页面的组合状态
    MyPage(page)
}
```

**与 ViewPager2 OffscreenPageLimit 的对比**：

| 维度 | ViewPager2 OffscreenPageLimit | Compose beyondBoundsPageCount |
|------|-------------------------------|-------------------------------|
| 实现层 | RecyclerView 额外布局空间 | Compose 子树组合 |
| 默认值 | `OFFSCREEN_PAGE_LIMIT_DEFAULT`（按需预取） | `0`（不预组合） |
| 最大值建议 | 通常 ≤ 2 | 通常 ≤ 2 |
| 内存成本 | View 树膨胀 + 数据绑定 | Compose 节点树 + Remember 状态 |
| 回收机制 | RecyclerView 回收池 | Compose 组合销毁 |

[来源: obsidian/Cubox/动画图解- ViewPager2 OffscreenPageLimit 机制分析]

**性能权衡建议**：

- **`beyondBoundsPageCount = 0`**（默认）：适合页面内容轻量、预组合收益不大的场景。翻页时才组合新页面，首次显示可能出现短暂卡顿。
- **`beyondBoundsPageCount = 1`**：最常用的优化值。提前组合相邻页面，滑动时已有现成的组合结果，显著减少 jank。
- **`beyondBoundsPageCount ≥ 2`**：仅在页面极重（如复杂图表/大图加载）且设备性能充足时考虑。会成倍增加组合状态内存。

⚠️ 与 PausableComposition（§2.28）配合时，即使 `beyondBoundsPageCount = 1`，预组合也不会阻塞主线程——组合工作会在帧间空闲时间分片完成。

[已验证: 官方文档, developer.android.com/jetpack/compose/layouts/pager#beyondboundspagecount]
[详见: §2.28 Compose Pausable Composition 深度分析]

### 🔹 锚点 4：页面切换动画 — animateScrollToPage 与 AnimationSpec

`animateScrollToPage()` 是编程式页面切换的核心 API，支持自定义动画曲线：

```kotlin
// 基础用法
scope.launch {
    pagerState.animateScrollToPage(page = 5)
}

// 自定义 AnimationSpec（Compose Foundation 1.7+）
scope.launch {
    pagerState.animateScrollToPage(
        page = 5,
        animationSpec = springSpec(
            dampingRatio = Spring.DampingRatioMediumBouncy,
            stiffness = Spring.StiffnessLow
        )
    )
}
```

**动画类型选择指南**：

| 场景 | 推荐 AnimationSpec | 理由 |
|------|-------------------|------|
| 引导页/Onboarding | `spring(dampingRatio = MediumBouncy)` | 轻微回弹，增强引导感 |
| Tab 切换 | `tween(durationMillis = 300, easing = FastOutSlowInEasing)` | 快速、确定性时长 |
| 图片浏览器 | `spring(stiffness = StiffnessMedium)` | 自然物理感 |
| 数据分页 | `tween(durationMillis = 200)` | 简洁高效 |

**手势释放后的 Snap 动画**：

当用户手指释放后，Pager 根据以下规则决定目标页：
1. 如果滑动距离 > 页面宽度的 50%，翻到下一页
2. 如果滑动速度超过阈值（`VelocityThreshold`），根据速度方向翻页
3. 否则回到当前页

Snap 动画默认使用 `SpringSpec`，可通过 `SnapFlingBehavior` 自定义。

### 🔹 锚点 5：PausableComposition 与 Pager 滚动性能

**这是 Compose Pager 在 Android 17 时代最重要的性能改进。**

Compose 1.10（2025 年 12 月稳定）将 **PausableComposition 设为默认行为**，对 Pager 产生直接影响：

**问题（Compose 1.9 及之前）**：

当 Pager 配合 `beyondBoundsPageCount ≥ 1` 时，预组合新页面必须在**单帧内完成**。如果页面内容复杂（大量子组件、嵌套布局、图片加载），组合时间可能超过 16.67ms（60Hz）或 8.33ms（120Hz），直接导致掉帧。

**PausableComposition 的解决方案**：

1. Pager 发起预组合请求时，Compose Runtime 创建 `PausedComposition` 对象
2. 通过 `resume(shouldPause)` 分块执行组合工作
3. 每块完成后，`shouldPause` 回调检查 `FrameData.deadlineNanos`
4. 如果 deadline 临近 → 暂停组合，让出主线程给当前帧的渲染
5. 下一帧空闲时间继续 `resume()`，直到 `isComplete = true`
6. 最终 `apply()` 原子性提交，更新 UI 树

**实测影响**：

根据 Compose 1.6 官方基准测试，滚动性能平均提升约 **20%**。PausableComposition（1.10）在此基础上进一步优化了复杂 UI 的滚动体验——尤其是 Pager 配合重页面内容的场景。

> PausableComposition enables the Compose runtime to perform "prep work" for UI elements asynchronously, often utilizing the idle time between frames. Instead of attempting to compose an entire complex UI element within a single 16.7-millisecond frame, PausableComposition allows the runtime to break down the composition into smaller, more manageable pieces.
>
> —— Composables / Android Developers Blog

### 🔹 锚点 6：重组优化与性能调优实践

**1. 正确使用 key**

Pager 的内容 lambda 应始终使用 `key` 标识页面：

```kotlin
HorizontalPager(state = state, pageCount = 100) { page ->
    val item = dataList[page]
    key(item.id) {  // ✅ 使用稳定 ID 作为 key
        HeavyPageContent(item)
    }
}
```

未提供 key 时，Compose 使用位置索引（positional key），在页面增删时导致不必要的重组。

**2. derivedStateOf 减少无效重组**

利用 `derivedStateOf` 将基于 PagerState 滚动偏移的计算隔离：

```kotlin
val currentPage by remember { derivedStateOf { pagerState.currentPage } }
val isAtFirstPage by remember { derivedStateOf { pagerState.currentPage == 0 } }
```

避免每次 `currentPageOffsetFraction` 变化（每帧可能多次）都触发依赖 `currentPage` 的重组。

**3. Compose 1.6+ 性能改进的收益**

Compose 1.6 对 Pager 场景的关键改进包括：
- **Modifier.Node 重构**：减少了自定义 Modifier 的开销
- **编译器跳过无效 State 追踪**：只读取一次或从不读取的 State 不再触发重组
- **固有记忆（Intrinsic Remember）**：编译期内嵌 remember 判断逻辑，加速重组决策
- **稳定性配置文件**：可通过 `compose_compiler_config.conf` 标记外部类为 stable

## 扩展

### 🔸 扩展点 1：自定义页面变换效果

利用 `PagerState.currentPageOffsetFraction` 可实现页面切换时的视觉变换：

```kotlin
HorizontalPager(state = pagerState, pageCount = pageCount) { page ->
    val pageOffset = pagerState.currentPageOffsetFractionForPage(page)
    val scale = lerp(
        start = 0.85f,
        stop = 1f,
        fraction = 1f - pageOffset.absoluteValue
    )
    Box(
        Modifier
            .fillMaxSize()
            .graphicsLayer {
                scaleX = scale
                scaleY = scale
                // 还可添加 alpha、rotation、translation 等
            }
    ) {
        PageContent(page)
    }
}
```

常见变换效果：
- **缩放卡片**：非当前页缩小 + 透明度降低
- **深度层叠**：根据 offset 调整 translationZ
- **3D 翻转**：利用 rotationY 实现翻书效果
- **视差滚动**：页面内不同层以不同速度移动

⚠️ `graphicsLayer` 使用 GPU 合成，不会触发重组和重新布局，是性能最优的变换方式。

[适用版本: Compose 1.6+]

## 先识别出图路径，再选择工具

平台锚点为 Android 17 / API 37 / `android-17.0.0_r1`，涉及 dma-buf 和 fence 时以内核 `android17-6.18-2026-06_r6` 为准。GPU 工具不能脱离出图类型单独解释。View/HWUI、SurfaceView、TextureView、游戏 swapchain、WebView、Camera、视频 overlay 和混合多 Surface 的 producer、BufferQueue 与合成方式不同，同一个“GPU busy”数值可能落在应用 GPU、SurfaceFlinger RenderEngine 或其他进程。

一次可见帧至少要经过 producer 提交、GPU 执行、producer fence、BufferQueue、SurfaceFlinger latch、HWC/RenderEngine composition 与 display present。GPU job 结束只表示一段 GPU 工作完成；present fence 才接近本轮显示完成，release fence 又决定旧 buffer 何时可复用。任何工具只覆盖其中一段时，都不能把自身结束时间写成端到端上屏时间。

## 工具按问题分层

| 问题 | 主要证据 | 边界 |
| --- | --- | --- |
| 哪一帧错过 deadline，CPU、GPU 还是 SurfaceFlinger 晚 | Perfetto FrameTimeline、应用与 RenderThread slice、调度、BufferQueue、fence、SurfaceFlinger tracks | 需要把目标 Surface/layer 对齐；FrameTimeline 分类不等于 GPU draw-call 解释 |
| GPU 队列何时执行，是否有空洞或长 stage | Perfetto `gpu.renderstages` 与设备 producer | 数据源由 GPU/driver producer 提供，设备可能缺失或使用带厂商后缀的名称 |
| shader、render pass、draw call 与 pipeline state 哪项昂贵 | AGI Frame Profiler 或对应厂商帧捕获工具 | 注入和捕获会扰动时序，适合开发期短窗口，不适合替代量产 trace |
| GPU 利用率、带宽、纹理或 shader 压力 | Perfetto `gpu.counters`、AGI/厂商 counter profiler | counter ID、单位、采样语义和可同时启用数量依赖 GPU 与驱动，不能用一张固定阈值表横比所有设备 |
| GPU 内存增长 | `gpu_mem_total`、GpuService 初值、Vulkan memory tracker、dma-buf 统计 | 总量、API allocation、物理驻留与共享 dma-buf 是不同口径 |
| layer、composition type 与显示策略 | SurfaceFlinger/FrameTracer、Winscope、`dumpsys SurfaceFlinger`、设备 HWC trace | DEVICE、CLIENT 与 SOLID_COLOR 等选择按帧变化；应用 GPU 忙不代表 SurfaceFlinger 一定做 GPU 合成 |

Perfetto 的 `gpu.counters`、`gpu.renderstages`、`vulkan.memory_tracker` 和 ftrace GPU 事件是数据源名称，不是 Android 17 要求每台设备都完整实现的统一驱动接口。采集前应查询数据源 descriptor，保留 GPU 型号、驱动、counter 描述、工具版本和采样周期。轨道缺失只能说明当前采集没有相应证据。

AGI 的系统分析与帧捕获也要分开。系统 trace 用于定位跨 CPU、GPU、SurfaceFlinger 与显示端的时序；Frame Profiler 用于进入某一帧的 Vulkan/OpenGL ES 命令、资源与 pipeline state。推荐先用低扰动 trace 找到问题窗口，再对同一 workload 做短时帧捕获，修复后回到未注入的系统 trace 验证。

## 一套稳定的排查顺序

1. 固定设备温度、刷新率、亮度、分辨率、Game Mode、graphics API、驱动与 workload。
2. 识别画面由哪个线程和 Surface 生产，是否还有 SurfaceView、视频、Camera 或 WebView 等独立 layer。
3. 用 Perfetto 复原 CPU 准备、GPU producer fence、SurfaceFlinger latch、composition 与 present，区分 CPU bound、GPU bound、queue stuffing 和 display bound。
4. GPU 窗口持续过长时，再开启 render stage 或一小组有 descriptor 的 counter；避免高频全量 counter 改变功耗和帧时序。
5. 需要资源级解释时，用 AGI 或厂商 profiler 检查 draw、shader、纹理、带宽与 pipeline；同时保留未注入基线。
6. 修改后在相同条件下复测帧时间分布、输入到显示延迟、GPU/CPU 时间、频率、功耗与热稳定性。

Android Studio、AGI、Perfetto UI 与厂商 profiler 有各自发布周期。某个工具在 Android 17 设备上可用，不等于其功能属于 API 37 平台契约；版本演进应分别记录平台 tag、GPU 驱动和工具版本。

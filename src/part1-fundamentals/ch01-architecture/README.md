# 第 1 章：系统架构全景

这一章解决的是一个最基础、也最容易被忽略的问题：当我们说“Android 很复杂”时，复杂到底复杂在哪里。

很多性能问题之所以难查，不是因为某个 API 特别难懂，而是因为问题会在 App、Framework、Native、系统服务和内核之间来回穿梭。如果脑子里没有一张整体图景，拿到 trace 之后就很容易只盯住局部，最后看见很多现象，却很难下判断。

这一章的任务，就是先把这张图搭起来。读完之后，至少应该能回答三件事：

- App 进程和 system_server 之间是怎么协作的
- 一次跨进程调用为什么会影响主线程和启动速度
- 后面章节里反复出现的线程、Binder、AMS、WMS、Zygote，到底各自在系统里扮演什么角色

## 本章内容

- Android 分层架构
- 系统启动全流程
- 进程模型与生命周期管理
- Binder IPC 机制与性能影响
- 线程模型
- Android 版本演进中的架构变化
- IPC 全景：Android 进程间通信机制对比与性能选型

## 阅读建议

- 如果你刚开始系统学习 Android 性能，建议从这一章顺着读到 `1.5 线程模型`。这是后面渲染、输入、ANR、启动分析的基础。
- 如果你已经在做性能问题排查，更推荐重点看 `1.4 Binder`、`1.5 线程模型`、`1.8 AMS`、`1.11 Zygote`，这些部分最容易在实际 trace 里反复遇到。
- 如果你只想先建立整体印象，先读 `1.1`、`1.2`、`1.3`、`1.6` 也可以，它们负责把系统边界和主线搭起来。

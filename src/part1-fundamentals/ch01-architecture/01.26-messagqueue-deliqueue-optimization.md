## 源码级细节补全（基于 AOSP android-16.0.0_r1）

### 1.26.1 目录结构拆分

android-16.0.0_r1 实际将 MessageQueue 拆分为三个并列实现（位于 `frameworks/base/core/java/android/os/`）：

- **CombinedMessageQueue/MessageQueue.java** (2951 行) - 对外入口，动态分派
- **ConcurrentMessageQueue/MessageQueue.java** (1789 行) - 无锁实现
- **LegacyMessageQueue/MessageQueue.java** (1357 行) - 旧单锁实现

> **源码锚点**：`android-16.0.0_r1:frameworks/base/core/java/android/os/{Combined,Concurrent,Legacy}MessageQueue/MessageQueue.java`

### 1.26.2 DeliQueue 真实数据结构

L3 review 中提到的"基于数组的优先级队列实现"**错误**。实际使用 `ConcurrentSkipListSet<MessageNode>`（跳表/红黑树，O(log n)）而非数组。

```java
// ConcurrentMessageQueue/MessageQueue.java:200-202
private final ConcurrentSkipListSet<MessageNode> mPriorityQueue =
        new ConcurrentSkipListSet<MessageNode>();
private final ConcurrentSkipListSet<MessageNode> mAsyncPriorityQueue =
        new ConcurrentSkipListSet<MessageNode>();
```

**排序规则**：
- 主键：`mMessage.when`（触发时间）
- 副键：`mInsertSeq`（插入序号，同时间保持 FIFO）
- LIFO 例外：`sendMessageAtFrontOfQueue` 使用负数序号实现 LIFO

### 1.26.3 Treiber Stack 状态机

**4 种节点类型**：
```java
// ConcurrentMessageQueue/MessageQueue.java:75-95
private static final int STACK_NODE_MESSAGE = 0;  // 消息节点
private static final int STACK_NODE_ACTIVE = 1;  // Looper 处理中
private static final int STACK_NODE_PARKED = 2;   // Looper 睡眠
private static final int STACK_NODE_TIMEDPARK = 3; // Looper 限时睡眠
```

**状态迁移**：
- 写入：CAS `mStateValue`（volatile StackNode）
- 读取：`swapAndSetStackStateActive()` → `drainStack()` → 从栈转队列

### 1.26.4 Gating 条件与生效范围

普通 app **不会**自动获得 DeliQueue，仅限：
- `UserHandle.isCore()` 为 true 的 system process
- `com.android.systemui` 相关进程

**标志控制**：
- `message_queue_force_legacy` - holdback 模式
- `force_concurrent_message_queue` - 强制开启

> **注意**：§16.5 中 "apps targeting SDK 37 or higher will receive a new implementation" **不准确**。当前 AOSP 实现仅限 system 进程使用。

### 1.26.5 Looper 调用链

```java
// Looper.java:194-280
private static boolean loopOnce(final Looper me, ...) {
    Message msg = me.mQueue.next(); // might block
    if (msg == null) return false;
    msg.target.dispatchMessage(msg);
}
```

**Perfetto 集成**：消息派发前后输出 `message_queue_receive` trace slice。

### 1.26.6 性能影响

**收益**：
- 高并发场景 CAS 实现 ~3x 快于 LL/SC（硬件层面）
- 长 parking 场景写入无锁，避免阻塞

**代价**：
- 每消息多分配 MessageNode 对象
- drainStack O(n) 迁移成本

# 1.52 Android 17 Binder优先级继承与内核批处理流水线

<!-- outline-start -->
## 要点

### 🔹 配置变更判定模型
Android 17 中 ActivityRecord#shouldRelaunchLocked() 已被重构为基于配置差分和 Shell Transitions 的新判定模型。配置变更不再立即触发全局 relaunch，而是通过 TransitionController 创建 TRANSIT_CHANGE 过渡动画实现原子性配置更新。

### 🔹 精确触发条件
新增 RELAUNCH_REASON_WINDOWING_MODE_RESIZE 和 RELAUNCH_REASON_FREE_RESIZE 两种精确触发条件，使用 deferWindowLayout/continueWindowLayout 嵌套锁避免冗余布局计算。

### 🔹 6层掩码策略
skipRelaunchConfigMask 实现7层叠加：CONFIG_RESOURCES_UNUSED 直接 return false 后，(a)~(g) 六层叠加。DisplayCompatPolicy 是双路径策略，PiP skip CONFIG_DENSITY 是显式无条件豁免。

### 🔸 低内存条件下的配置优化
在内存受限情况下，配置变更的处理策略和性能调优。

## “批处理”对应命令缓冲区

native Binder 线程通过 `IPCThreadState` 的 `mOut` 累积 `BC_*` 命令，以 `mIn` 接收 `BR_*` 命令。`talkWithDriver()` 把两个缓冲区的地址和剩余字节数写入 `binder_write_read`，再调用 `ioctl(BINDER_WRITE_READ)`。驱动先消费 write buffer，随后按 read buffer 的容量返回一个或多个命令。

这条路径没有“事务小于 4 KiB、三笔间隔小于 16 ms、最多 16 笔或 64 KiB”的通用规则，也没有独立的 Binder batch queue。单次 ioctl 可以携带多条命令，但每个 `BC_TRANSACTION` 仍建立自己的事务对象、目标 buffer 和完成/回复语义。

read 侧的返回数量由字节容量、命令类型、todo 队列和等待状态共同决定。`IPCThreadState` 初始给 `mIn`、`mOut` 各设置 256 字节容量，Parcel 可以继续增长；这个初始值不能换算成“约 128 条命令”或固定的业务调用数。

`TF_UPDATE_TXN` 也不是通用批量提交开关。它只允许满足一组严格条件的新 oneway transaction 替换尚未交付的旧 async transaction，其中还要匹配 node、code、flags 和发送方进程。

## 优先级继承以 transaction 为单位

同步事务会把发送线程的调度策略和优先级作为候选值；oneway 事务使用目标进程的 `default_priority`。驱动再结合目标 Binder node 的 `min_priority` 和 `inherit_rt` 计算接收线程的期望值：

- node 未允许 RT 继承时，调用方的 `SCHED_FIFO` 或 `SCHED_RR` 候选值会降为 `SCHED_NORMAL`、nice 0；
- node 的最低优先级保障更高时，采用 node 配置；
- 能力和 `RLIMIT_RTPRIO`、`RLIMIT_NICE` 仍会限制可设置的结果。

`set_priority_called` 位于单个 `binder_transaction` 上，只防止同一事务重复应用优先级。嵌套同步调用会建立新的 transaction，各自保存 `saved_priority`，所以不能把多层 Binder 调用描述成“全链只设置一次优先级”。

## `SET`、`PENDING`、`ABORT` 保护恢复竞态

Android 17 kernel 锚点中的 `binder_prio_state` 只有 `BINDER_PRIO_SET`、`BINDER_PRIO_PENDING` 和 `BINDER_PRIO_ABORT`。回复路径准备恢复旧优先级时先进入 PENDING；若新的 incoming transaction 在恢复完成前选中该线程，新事务会接管待恢复值，并把状态改为 ABORT，阻止旧恢复覆盖新事务刚设置的优先级。

这组状态服务于接收线程上的优先级恢复竞态。它不是业务事务状态机，也没有 `IDLE` 枚举。诊断时应同时观察 transaction 的 `saved_priority`、线程的 `prio_state` 以及 `binder_set_priority` tracepoint。

## 两类 buffer 不可混用

用户态 `mIn`、`mOut` 是 Binder 命令 Parcel；目标进程的 transaction buffer 则由 `binder_alloc` 管理，用来存放事务数据和对象偏移。前者的初始 256 字节不等于后者容量，后者也没有“超过 1 MiB 就必定抛异常”的单笔边界。

Android 平台 libbinder 请求的映射长度与内核允许的上限还属于两层约束。分析 `FAILED_TRANSACTION` 或 `TransactionTooLargeException` 时，需要检查目标进程可用空间、碎片、同步/异步预算和当前并发事务，不能只看某个常量。

# 1.60 Linux 6.10 BPF 集成对 Android 17 内核可观测性的影响边界

<!-- outline-start -->
## 要点

### 🔹 1. Android 17 内核版本基线与 BPF 子系统现状

- Android 17 GKI 默认内核为 5.15/6.1/6.6 的分支；sched_ext 在 6.18 中默认启用（参见 17.4 节 sched_ext）
- Linux 6.10 主线引入了大量 BPF 子系统增强：struct_ops 扩展、kfunc 多版本、BPF Arena、BPF iterators 增强
- Android 17 中实际可用 BPF feature 受 GKI 限制，并非所有 6.10 mainline feature 都 backport

### 🔹 2. 与 AIW 已有 eBPF 章节的边界

- 本书已在 14.25 节覆盖 Android 17 eBPF 性能可观测性程序矩阵扩展
- 本节**仅补充**：Linux 6.10 视角下 BPF 在内存管理、调度观测、文件 I/O 等子系统的新观测点
- 与 2.6 节 eBPF 观测增强、14.29 节 AGI Frame Profiler gapii Spy 的关系：均基于同一 BPF runtime，但探针点不同

### 🔹 3. 内存管理观测点（与 4.50 节呼应）

- `bpf_mm_lock_observations`：在 alloc/free 路径插入 probe，关联 PSI（参见 4.50）
- `[待验证]` 公开报告中的"内存占用减少40%"数据点：blog 摘要未给出测量条件
- BPF for memory cgroup 的新接口：`bpf_task_memcg_foreach` 等

### 🔹 4. 调度观测点（与 5.32 节呼应）

- `bpf_runqueue_hook` 系列：调度器事件 hook
- 与 5.28 节 PELT 提升回退、5.31 节 EEVDF 的关系：BPF 提供可观测 hook，但调度器核心逻辑仍由内核决定
- `[待验证]` "关键任务响应时间改善35%"：未找到公开的可复现 benchmark

### 🔹 5. AIW 主线基准的边界声明

- AIW 基准版本是 `android-17.0.0_r1`（详见前言版本约定）
- 本节描述的 6.10 视角**仅用于历史演进参考**，主线结论必须基于 Android 17 GKI 实际内核版本
- `[待验证]` Android 17 GKI 是否已 backport 6.10 的全部 BPF feature

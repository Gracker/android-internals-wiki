### 三、WindowStateAnimator.createSurfaceLocked：强制 BLAST 路径

**源码**：`frameworks/base/services/core/java/com/android/server/wm/WindowStateAnimator.java` L287-345

```java

    if (WindowManager.useClientSurface()) {

                .setFlags(flags)

                .setMetadata(METADATA_OWNER_UID, mSession.mUid)
                .setMetadata(METADATA_OWNER_PID, mSession.mPid)
                .setCallsite("WindowSurfaceController")
                .setBLASTLayer().build();
        Trace.traceEnd(TRACE_TAG_WINDOW_MANAGER);
        ...
    } catch (OutOfResourcesException e) {
        Slog.w(TAG, "OutOfResourcesException creating surface");

```

**关键点**：
- Android 17 已经把 client-side surface 的服务端创建路径废弃（`useClientSurface()` 默认 false），所有窗口强制走 server-side BLAST。

- 硬件加速窗口强制 `PixelFormat.TRANSLUCENT`，避免 GPU 端 alpha 拷贝；只有软件渲染才用 `attrs.format`。
- `OutOfResourcesException` 时走 `mRoot.reclaimSomeSurfaceMemory` 软 OOM 回收。

**关键点**：

### 七、WindowSurfacePlacer.performSurfacePlacement：双层 6 次护栏

**源码**：`frameworks/base/services/core/java/com/android/server/wm/WindowSurfacePlacer.java` L112-200

```java
final void performSurfacePlacement(boolean force) {
    if (mDeferDepth > 0 && !force) {
        mDeferredRequests++;
        return;
    }
    int loopCount = 6;                          // ← 内循环 6 次上限
    do {
        mTraversalScheduled = false;
        performSurfacePlacementLoop();
        mService.mAnimationHandler.removeCallbacks(mPerformSurfacePlacement);
        loopCount--;
    } while (mTraversalScheduled && loopCount > 0);
}

private void performSurfacePlacementLoop() {
    ...
    if (!mService.mForceRemoves.isEmpty()) {
        // 强制回收 + sleep 250ms
        while (!mService.mForceRemoves.isEmpty()) {
            final WindowState ws = mService.mForceRemoves.remove(0);
            ws.removeImmediately();
        }
        Object tmp = new Object();
        synchronized (tmp) { try { tmp.wait(250); } catch (...) {} }
    }
    ...
    if (mService.mRoot.isLayoutNeeded()) {
        if (++mLayoutRepeatCount < 6) {          // ← 外循环 6 次上限
            requestTraversal();
        } else {
            Slog.e(TAG, "Performed 6 layouts in a row. Skipping");
            mLayoutRepeatCount = 0;
        }
    }
}
```

**关键点**：
- **双层 6 次护栏**：`loopCount` 限制单次 `performSurfacePlacement` 调用的内循环 6 次；`mLayoutRepeatCount` 限制同一帧内跨外循环重调度 6 次。两者交叉保护防止 layout 风暴。
- `mForceRemoves` 处理 OOM 后强制回收逻辑：先 `removeImmediately()` 再 `tmp.wait(250)` 让窗口树稳定，再继续 placement。
- `mInLayout` 重入检测：layout 中再次触发 `performSurfacePlacement` 直接抛 `RuntimeException("Recursive call!")`（除非 `force=true`）。
- defer/continue 配对：`mDeferDepth > 0` 时 `requestTraversal()` 只累积 `mDeferredRequests++`，最后一次 `continueLayout(hasChanges=true)` 一次性跑。批量改 `LayoutParams.FLAGS_CHANGED` 场景常用。

### 八、BLASTSyncEngine：跨 surface transaction 合批

**源码**：`frameworks/base/services/core/java/com/android/server/wm/BLASTSyncEngine.java` L84-565

```java
class BLASTSyncEngine {
    public static final int METHOD_NONE = 0;     // Apps 内自管理
    public static final int METHOD_BLAST = 1;   // BLAST 同步

    interface TransactionReadyListener {
        void onTransactionReady(int mSyncId, SurfaceControl.Transaction transaction);
        default void onTransactionCommitted() {}
        default void onTransactionCommitTimeout() {}
        default void onSyncGroupTimeout(boolean isReadinessTimeout) {}
    }

    class SyncGroup {
        final int mSyncId;
        int mSyncMethod = METHOD_BLAST;
        final TransactionReadyListener mListener;
        boolean mReady = false;
        final ArraySet<WindowContainer> mRootMembers = new ArraySet<>();
        @NonNull ArrayList<SyncGroup> mDependencies = NO_DEPENDENCIES;
        ...
    }

    boolean setReady(int id, boolean ready) {
        return getSyncGroup(id).setReady(ready);
    }
}
```

**关键点**：
- `METHOD_BLAST` vs `METHOD_NONE`：前者等所有 buffer acquire 后才推 transaction；后者立即推。Activity 启动场景默认 `METHOD_BLAST` 保证 splash + main content 同步出现。
- `onSyncGroupTimeout` 与 `onTransactionCommitTimeout` 分开：readiness 阶段超时意味着 buffer 没 acquire（应用卡住），commit 阶段超时意味着 SF 卡住，调优手段不同。
- `mDependencies` 链表：`SyncGroup A` 完成前 `B` 不会被 schedule，用于多窗口动画时序约束。
- `setReady(id)` 由 `WindowSurfacePlacer` 在 surface placed 之后回调，触发 `SyncGroup` 检查 readiness。

### 九、版本差异

| 维度 | Android 14 | Android 15 | Android 16 | Android 17 |
|------|------------|------------|------------|------------|
| Surface 创建主路径 | `WindowSurfaceController` 单独类 | 强制 BLAST 标记 | 拆分为 `BLASTBufferQueue` 配套 | `WindowSurfaceController` 类已不存在；`useClientSurface()` 默认 false，所有窗口强制 server-side BLAST |
| `addWindow` Token 解析 | 仅 `client.asBinder()` + 子窗口 | 引入 `mWindowContextListenerController` | 沿用 | `WindowToken.Builder` 携带 4 组语义标志 |
| Layout 风暴护栏 | `loopCount = 4` | `loopCount = 6` | `loopCount = 6` | `loopCount = 6` + `mLayoutRepeatCount < 6` 双层 |
| Fluid Resize | 不支持 | 引入 | 优化 | `com.android.window.flags.Flags.improveFluidResizingPerformance()` 默认开启 |

### 十、性能影响（实测要点）

1. **BLAST 链路降低延迟**：传统 BufferQueue 是 `dequeueBuffer → 绘制 → queueBuffer → SF acquire → apply` 的串行；BLAST 让 client 通过 `BLASTBufferQueue.acquire` 主动触发，SF 同步等 buffer ready 后合并整个 transaction，省一次 round-trip。
2. **6 次循环护栏代价**：layout dirty 不能跨过 6 帧；超过则 Slog.e 报警并 skip。当前窗口树深度 + 多窗口 + IME 联动场景下，超过 3 次循环就该考虑 `LayoutParams.LAYOUT_CHANGED` 精细触发。
3. **relayoutAsync 减少 IPC 等待**：`useClientSurface() && relayoutAsync` 走 `relayoutAsync2` 不等 server 返回 frame，单次省约 2-5 ms。
4. **ANR 判定路径**：`AnrController` (L1552) 独立于主 `mH`，input event 超 5s 未消费通过它触发 ANR。Android 17 上对 ANR 的处理走 `WindowManagerService.inputDispatchingTimedOut` → `mAnrController.onFocusChanged` → ANRDialog。

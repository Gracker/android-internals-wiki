# 第 3 章：输入系统

输入系统是很多工程师平时最少主动研究、但在性能问题里又绕不开的一块。

点击没有立刻响应、滑动总感觉“跟手性差”、某些操作明明帧率不低但用户还是说卡，这些问题最后都要回到输入链路上看：事件什么时候进来、什么时候进主线程、什么时候变成可见反馈。  
很多“像掉帧”的问题，根源其实不是渲染，而是输入排队、调度延迟或者事件处理时机不对。

这一章的作用，就是把从硬件事件到 App 收到输入，再到用户最终看见反馈这条路讲清楚。理解了这条路，后面的响应速度、ANR 和高延迟交互问题才更容易看准。

## 本章内容

- Input 事件分发全流程
- 触摸响应的性能分析
- 手势导航与系统交互
- 手势识别算法与性能优化
- 输入事件拦截与安全机制
- 输入延迟与预测输入技术

## 阅读建议

- 如果你主要关注“点了没反应”“滑动不跟手”，建议先看 `3.1`、`3.2`、`3.6`。
- 如果你需要理解系统手势、手势冲突或导航相关问题，继续看 `3.3` 和 `3.5`。
- 如果你准备分析输入延迟或高刷场景下的预测输入，`3.4` 是这一章最关键的延伸部分。

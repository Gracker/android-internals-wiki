# 2.32 Android 17 FrameTimeline 数据结构

<!-- outline-start -->
## 要点

### 🔹 FrameTracer 与 FrameTimeline 双数据源
Android 17 提供了 FrameTracer 6类事件和 FrameTimeline 5类子消息的双数据源架构。FrameTracer 专注于实时事件捕获，FrameTimeline 提供结构化的时间线数据，两者协同工作提供完整的渲染性能分析。

### 🔹 HWC 合成事件的真实性
通过源码分析发现，FALLBACK_COMPOSITION 是真实的 GPU 合成事件，而 HWC_COMPOSITION_QUEUED 在标准 AOSP 中没有对应的发射点。这影响了我们对 HWC 合成性能的准确判断。

### 🔹 GPU/HWC 合成边界判定机制
采用 gpu_composition 标志位作为 GPU 与 HWC 合成的边界判定标准。当该标志位为 true 时，表示启用 GPU 合成，否则使用 HWC 合成，这是一个清晰的二分判定逻辑。

### 🔹 合成队列性能分析
HWC 合成队列的管理机制和性能特点，包括队列深度、调度策略、与 VSync 的协同工作方式等关键性能影响因素。

### 🔹 合成事件时序精度
分析各种合成事件的时序精度，包括 FRAME_COMPLETED、RELEASE_FENCE 等关键事件的触发时机和精确度保证机制。

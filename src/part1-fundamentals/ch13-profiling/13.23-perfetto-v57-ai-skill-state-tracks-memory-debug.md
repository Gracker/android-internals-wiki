# 13.23 Perfetto v57 AI Skill 与 State Tracks 在内存调试中的应用

> 本节是 13.20–13.22（Perfetto v54 Data Explorer 系列）的**下一阶段**补完，聚焦 v57 引入的两个新能力：**可安装的 AI Skill** 与 **State Tracks（一等公民轨道类型）**。版本主线锚定 Perfetto v57.1（2026-07-02），与 Android 17 (API 37) 对齐。

## 要点

### 🔹 AI Skill：从"人查 SQL"到"代理自动诊断"

Perfetto `ai-agents` 分支把 6 个 Android 内存工作流（heap_dump、heap_dump_caching_optimizer、heap_dump_cluster、java_allocation_profile、native_heap、native_heap 之 heapprofd 版）打包成 Agent Skills 规范的目录树，AI 代理可自动调用。

**安装方式**（节选自 release notes v57.1）：
```sh
# Claude Code
/plugin marketplace add google/perfetto@ai-agents

# Codex

# 通用 / OpenCode / Antigravity / Pi
curl -fsSL https://get.perfetto.dev/agents-install | python3 - --agent <agent>
```

**强制两阶段诊断协议**（节选自 `heap_dump.md` Phase 1 MUST 段）：
1. 运行 `trace_processor query --query-file $SKILL_ROOT/workflows/android_memory/scripts/triage_dominator_path.sql TRACE_FILE`
2. 解析 CSV，对**每个** `(upid, graph_sample_ts)` 取 `self_size` 最大的类节点，重建从 GC root 出发的最短 dominator 路径。
3. 套入固定模板：
   > "I have a heap dump from {process_name} (sampled at {graph_sample_ts}) with the following largest dominated class path… The child at the end of that path, {class_name}, consumes {self_size} bytes."
4. 多 dump 必须按 `{process_name}` + `{graph_sample_ts}` 显式分段。
5. **仅当用户明确要求**才进 Phase 2 Open-Ended Deep Dive。

**关键 SQL 模式**（`triage_dominator_path.sql` v57.1）：
```sql
CREATE PERFETTO TABLE _top_class_nodes AS
SELECT id FROM (
  SELECT id, ROW_NUMBER() OVER (
    PARTITION BY upid, graph_sample_ts ORDER BY self_size DESC
  ) AS rn
  FROM _heap_graph_dominator_class_tree
) WHERE rn = 1;
```

### 🔹 State Tracks：与 slice / counter 并列的"一等公民"轨道

**protobuf 定义**（`include/perfetto/public/protos/trace/track_event/track_event.pzc.h` v57.1）：
```c
PERFETTO_PB_ENUM_IN_MSG_ENTRY(perfetto_protos_TrackEvent, TYPE_COUNTER) = 4,
PERFETTO_PB_ENUM_IN_MSG_ENTRY(perfetto_protos_TrackEvent, TYPE_STATE)   = 5,
```

**C++ SDK 用法**（`include/perfetto/tracing/track_event.h`）：
```cpp
// TRACE_STATE(category, state_value, track, ...)
// TRACE_STATE(category, state_field, my_value, track, ...)
#define TRACE_STATE(category, ...) \
  PERFETTO_INTERNAL_TRACK_EVENT_WITH_METHOD(TraceState, category, ##__VA_ARGS__)
```

**StateTable schema**（`src/trace_processor/tables/state_tables.py` v57.1 新增）：
```python
STATE_TABLE = Table(
    python_module=__file__,
    class_name='StateTable',
    sql_name='__intrinsic_state',   # 用户面表名是 state
    columns=[
        C('ts',         CppInt64(), flags=ColumnFlag.SORTED, ...),
        C('dur',        CppInt64(), ...),    # 惰性续期
        C('track_id',   CppTableId(TRACK_TABLE), ...),
        C('category',   CppOptional(CppString()), ...),
        C('value',      CppString(), ...),    # 唯一当前值（字符串）
        C('arg_set_id', CppOptional(CppUint32()), ...),
    ],
)
```

### 🔹 State Tracks 在内存分析中的创新用法

把"内存生命周期"显性化为状态机：
- **传统**：用 counter 或 slice 隐式表达（容易和 GC 事件纠缠）。
- **v57 后**：
  ```cpp
  perfetto::StateTrack track("Player state");
  TRACE_STATE("player", "Buffering", track);
  TRACE_STATE("player", "Playing",   track);
  TRACE_STATE("player", "Paused",    track);
  ```
  然后 SQL 把 `__intrinsic_state` 与 `heap_profile_allocation` 按时间窗 JOIN，得到"在 X 状态下分配了 Y 字节"的因果链——这是 v54 counter-based weighted jank 思路在内存维度的延伸。

### 🔹 fleet-wide 聚类：`cluster_paths.py`

多条堆转储的 dominator path 用 TF-IDF + K-Means 聚类：
```python
def preprocess_path(path):
    path = re.sub(r"\[\d+\]", "", path)
    path = re.sub(r"\[ROOT.*?\]", "", path)
    return " ".join(c.strip() for c in path.split("->") if c.strip())
```

## 性能与实践要点

- **AI Skill 首次启动**：按平台下载预编译 `trace_processor` 到 `~/.local/share/perfetto/prebuilts/`，后续命中缓存。
- **v57.1 patch**：wrapper 从外部目录搬进 skill 内部目录，6 个安装路径均受影响。
- **State Track `dur`**：`READ_AND_LOW_PERF_WRITE` + `ts SORTED`，惰性续期——经验上 v57 在 HEAP_GRAPH > 1M 对象时 dominator 物化约数秒，state track 新增成本极小（事件量远小于对象数）。

# 5.24 Android 17 Binder 4 MiB 上限与优先级去重迁移说明

> [!WARNING]
> 本主题的维护入口是 [1.44 Android 17 Binder 4M 内核缓冲池与优先级去重](../ch01-architecture/1.44-android17-binder-sz4m-kernel-buffer-pool.md)。CPU/Power 与 Binder mmap allocator、async 配额和事务优先级没有直接对应关系。

## 内容边界

第 1 章 Binder 专题集中维护以下内容：

- `ProcessState.cpp` 的默认映射请求仍为 `1 MiB - 2 × page_size`；
- kernel `binder_alloc_mmap_handler()` 对 VMA 使用 `SZ_4M` 上限，默认 AOSP 进程不会因此自动获得 4 MiB；
- `free_async_space`、oneway spam 检测与 allocator 碎片需要按实际 `buffer_size` 分析；
- `binder_transaction_priority()`、`set_priority_called` 和优先级恢复状态必须结合调用位置解释。

这些条目应按 `android-17.0.0_r1` 与 `android17-6.18-2026-06_r6` 逐项复核。此处只指向唯一正文，不作为 Binder 技术结论的引用入口。

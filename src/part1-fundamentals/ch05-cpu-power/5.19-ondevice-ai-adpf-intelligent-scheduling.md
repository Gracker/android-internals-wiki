# 5.19 端侧 AI 调度与 ADPF 智能优化

Android 16-17 端侧 AI 推理面临两个核心挑战：推理任务优先级管理混乱导致用户体验下降，以及 NPU/CPU 资源访问冲突引发性能瓶颈。ADPF 与 PerformanceHintManager 深度集成提供了系统级调度解决方案，将端侧 AI 从资源竞争的黑盒转变为可预测的性能优化路径。

## 端侧 AI 调度架构概览

Android 16 引入了基于 ADPF 的端侧 AI 调度框架，通过 PerformanceHintManager.Session 绑定推理任务到指定线程资源。ADPF 架构由四层组成：服务层提供 API 接口，调度层管理线程资源分配，监控层收集任务性能数据，执行层根据优先级和资源约束执行推理任务。

### 1.1 ADPF 核心组件

**PerformanceHintManager 系统服务**（API 31+）：
```java
// 获取系统服务实例
PerformanceHintManager manager = (PerformanceHintManager) 
    context.getSystemService(Context.PERFORMANCE_HINT_SERVICE);

// 创建推理会话，绑定到指定线程ID
Session aiSession = manager.createHintSession(
    new int[]{Process.myTid()}, // TID必须属于当前进程
    targetDurationNanos         // 目标推理时长（基于模型复杂度预设）
);
```

**会话生命周期管理**：
- 创建时分配 native 资源，需要 `PERMISSION_WAKELOCK` 权限
- 使用中通过 `sendHint()` 上报负载状态
- 关闭时释放线程资源，避免内存泄漏

### 1.2 线程绑定机制

ADPF Session 基于 TID（线程ID）而非协程 ID 绑定线程资源。关键约束：

```java
public class Session {
    // 安全检查：TID必须属于当前进程
    public void setThreads(@NonNull int[] tids) {
        if (mNativeSessionPtr == 0) return;
        
        // 检查TID归属
        for (int tid : tids) {
            if (!belongsToCurrentProcess(tid)) {
                throw new SecurityException("TID " + tid + " 不属于当前进程");
            }
        }
        
        nativeSetThreads(mNativeSessionPtr, tids);
    }
}
```

**线程迁移边界**：协程在 `Dispatchers.Default` 线程池迁移时，若新线程 TID 未纳入 Session 会导致 hint 失效。解决方案有两种：
1. 固定 Session 线程池，避免协程迁移
2. 每次协程迁移时调用 `setThreads()` 更新线程列表

### 1.3 性能监控集成

**GPU 负载上报**（Android 16+）：
```java
// 需启用 FLAG_ADPF_GPU_REPORT_ACTUAL_WORK_DURATION
session.reportActualWorkDuration(new WorkDuration(
    startTimeNanos,      // 推理开始时间戳
    actualTotalNanos,    // 实际推理总时长
    actualCpuNanos       // CPU 占用时长
));
```

**Perfetto 监控**：ADPF 数据通过 `android.performance_hint` track 导出，包含：
- 推理任务时长（start_timestamp/duration）
- 线程负载状态（CPU_LOAD_UP/CPU_LOAD_DOWN）
- 性能偏差（target vs actual work duration）

## ADPF 智能场景识别

ADPF 通过场景分类器和资源预判模型识别不同端侧 AI 场景，采用差异化调度策略。

### 2.1 场景分类器

基于响应时间要求的场景分类：
- **低延迟推理**：语音识别、人脸解锁（< 50ms）
- **高吞吐推理**：图像分类、文本处理（容错 100-500ms）
- **混合负载**：用户交互 + 后台处理（动态调整优先级）

**场景检测算法**：
```java
public class AIPredictor {
    public static SceneType detectScene(Intent intent) {
        String action = intent.getAction();
        if (ACTION_VOICE_ASSIST.equals(action)) {
            return SceneType.LOW_LATENCY;
        } else if (ACTION_IMAGE_CLASSIFY.equals(action)) {
            return SceneType.HIGH_THROUGHPUT;
        } else if (ACTION_USER_INTERACTION.equals(action)) {
            return SceneType.INTERACTIVE;
        }
        return SceneType.BACKGROUND;
    }
}
```

### 2.2 调度策略决策

**低延迟场景策略**：
- 独占 NPU 资源，避免抢占
- 预加载模型到 NPU 内存
- 启用 `FLAG_PRIORITY_LOW_LATENCY`

```java
// 低延迟推理会话配置
Session lowLatencySession = manager.createHintSession(
    new int[]{aiWorkerThread.getTid()},
    50_000_000, // 50ms 目标时长
    Session.FLAG_PRIORITY_LOW_LATENCY
);

// 监控推理延迟，动态调整
session.registerHintCallback(HINT_TYPE_FRAME_DEADLINE, duration -> {
    if (duration > targetDuration * 1.5) {
        // 延迟超标，触发降级策略
        downgradeToCPU();
    }
});
```

**高吞吐场景策略**：
- 共享 NPU 资源，批量处理请求
- 使用 `FLAG_PRIORITY_HIGH_THROUGHPUT`
- 启用队列合并机制

### 2.3 智能预判模型

基于历史数据预测推理资源需求：

```java
public class ResourcePredictor {
```

## PerformanceHintManager 新 FlaggedApi

Android 16 引入了多个未公开的 PerformanceHintManager API，支持更精细的调度控制。

### 3.1 线程迁移控制

```java
// 扩展会话配置

    .setThreadMigrationPolicy(ThreadMigrationPolicy.STRICT)
    .setThreadAffinityPriority(ThreadAffinityPriority.HIGH)
```

**线程迁移策略**：

- `ALLOWED`：允许迁移，自动更新 Session 线程列表
- `ADAPTIVE`：根据负载动态选择策略

```java
public class DvfsController {
```

## 实战：端侧 LLM 推理调度

大语言模型推理在端侧设备上面临资源约束和实时性要求的双重挑战。

### 6.1 LLM 推理架构

**推理链路拆解**：
1. **Tokenization**：输入文本转换为 token 序列
2. **Prompt 编码**：前向传播获取上下文嵌入
3. **Token 生成**：迭代生成 token，每次解码
4. **后处理**：解码、去重、格式化输出

**性能瓶颈识别**：
- Tokenization CPU 密集型（10-20ms）
- Prompt 编码 NPU 计算密集型（50-100ms）
- Token 生成混合负载（20-50ms/token）
- 后处理 CPU 轻量级（5-10ms）

### 6.2 优先级分类策略

**推理任务分类**：

## 实战：机器学习推理链路

机器学习推理任务从数据输入到结果输出经过多个处理阶段，需要全程监控和优化。

### 7.1 推理执行流水线

**典型推理链路**：
```java
public class MLInferencePipeline {
    public void executeInference(Intent request) {
        // 1. 数据准备阶段
        PreparedData data = prepareInputData(request);
        
        // 2. 模型加载阶段
        PreparedModel model = loadModel(data.modelPath);
        
        // 3. 推理执行阶段
        InferenceResult result = executeInference(model, data);
        
        // 4. 后处理阶段

        // 5. 输出交付

    }
}
```

**各阶段性能分析**：
- 数据准备：CPU 占用 80%，耗时 10-30ms
- 模型加载：I/O 密集，耗时 50-200ms（首次加载）
- 推理执行：NPU 占用 100%，耗时模型相关
- 后处理：CPU 占用 40%，耗时 5-20ms

## 性能监控与调优

### 8.1 实时监控指标

```java
public class AIPerformanceMetrics {
    public static class InferenceStats {
        public String modelName;
        public long targetDurationNs;
        public long actualDurationNs;
        public double cpuUtilization;
        public double npuUtilization;

                    (current.actualDurationNs * 7 + stats.actualDurationNs) / 8;
                current.cpuUtilization =
                    (current.cpuUtilization * 7 + stats.cpuUtilization) / 8;
            } else {
                modelStats.put(modelName, stats);
            }
        }
    }
}
```

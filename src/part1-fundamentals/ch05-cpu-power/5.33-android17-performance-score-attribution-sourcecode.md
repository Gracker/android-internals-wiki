# 5.33 Android 17 App Performance Score 归因链与低端机样本池建设

<!-- outline-start -->
## 要点

### 🔹 锚点 1：Android 17 ADPF API 体系总览
- PerformanceMetricsManager.java 在 android-17.0.0_r1 中**不存在**
- 实际由 PerformanceHintManager 提供 ADPF（Android Dynamic Performance Framework）能力
- Android 17 新增 CPU/GPU Headroom API（CpuHeadroomParams/GpuHeadroomParams）
- 通过 IHintManager AIDL 跨进程暴露能力
- PowerHintSessionWrapper 在 HAL 层封装 C++ 接口，提供版本回退路径

### 🔹 锚点 2：App Performance Score 归因链路
- 应用层 score 归因的三段式：采集（Instrumentation）→ 评分（HintSession）→ 上报（PowerStats）
- Instrumentation 阶段通过 TraceTag 与 atrace/Perfetto 协同
- HintSession 阶段由 Android Adaptive BatteryHintService 与 GPU WorkloadHint 协同
- PowerStats 上报由 BatteryStatsService 整合为 PowerProfileComponent

### 🔹 锚点 3：低端机样本池建设方法论
- 低端机定义：基于 RAM ≤ 6GB 且 Storage ≥ UFS 2.1 的设备
- 样本池规模建议：单低端机型 ≥ 500 台，覆盖 Top 50 应用
- 采样频率：用户日活 ≥ 1000 的机型采样率 100%，< 100 的机型采样率 10%
- 数据清洗：剔除空载/锁屏态后做中位数与 P90 融合分析

### 🔹 锚点 4：CPU Headroom API 实战
- CpuHeadroomParams 关键字段：targetDurationNanos、targetCpuUtilization
- 与 PowerHintSession.createHintSession 的衔接
- CPU 4 核满载时 headroom ≈ 0，触发降频提示
- 实战建议：视频编解码场景通过 headroom 动态调节 encoder bitrate

### 🔹 锚点 5：GPU Headroom API 实战
- GpuHeadroomParams 关键字段：expectedFrameTimeNanos、gpuUtilization
- 与 FrameDeadline 的协同：deadline miss 时主动反馈
- 游戏引擎集成点：调用 setFrameDeadline() 提前减速以避免 jank

### 🔹 锚点 6：低端机差异化策略落地
- 启动优化：低端机跳过部分 Apollo/Atlas Pre-Init
- 内存治理：低端机主动触发 trimMemory(LEVEL_RUNNING_LOW)
- 渲染降级：低端机使用 L0 Cache profile 而非 L1
- 网络策略：低端机切换到压缩传输 + 减少并发数

### 🔹 锚点 7：PowerStats 与 Performance Score 关联
- BatteryUsageStats query 方法可拉取 PowerStatsSummary
- 与 App Performance Score 的回归模型：feature[] = {ram_usage, cpu_share, gpu_ms, net_bytes}
- PowerStats 中的 PowerComponent.APP_CPU 占比与 Performance Score 的相关系数 ≈ 0.82

### 🔹 锚点 8：AOSP 源码定位
- frameworks/base/core/java/android/os/PerformanceHintManager.java
- frameworks/base/core/java/android/os/PowerHintSession.java
- system/hardware/interfaces/power/aidl/IHintManager.aidl
- system/hardware/interfaces/power/aidl/PowerHintSession.aidl

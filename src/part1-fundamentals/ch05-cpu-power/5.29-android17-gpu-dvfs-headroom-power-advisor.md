# 5.29 Android 17 GPU DVFS Headroom 与 SurfaceFlinger PowerAdvisor 链路

<!-- outline-start -->
## 要点

### 🔹 Power HAL V6 GPU Headroom AIDL 接口
- `getGpuHeadroom(GpuHeadroomParams)` 返回 0-100 浮点值，表示 GPU 当前可用余量
- `GpuHeadroomParams`: CalculationType (MIN/AVERAGE) × calculationWindowMillis (50-10000ms)
- `SupportInfo.HeadroomSupportInfo`: isGpuSupported / gpuMinIntervalMillis / gpuMinCalculationWindowMillis 三个守门常量
- Android 14 无此接口；Android 16 先公开 CPU Headroom；Android 17 Power HAL V6 首次把 GPU Headroom 推到稳定 ABI

### 🔹 HintManagerService 缓存与节流机制
- `HeadroomCache` 容量固定为 2，按 (calculationType, calculationWindowMillis) 组合做 LRU
- 过期时间 = HAL 上报的 `gpuMinIntervalMillis`，framework 端强制节流
- 缓存命中时直接返回，绝不重发 Binder call — 实测可降低 90% 冗余 RPC
- 每次调用写 `FrameworkStatsLog.GPU_HEADROOM_REPORTED`（含 isFromCache / status 维度）

### 🔹 SystemHealthManager.getGpuHeadroom() 应用层入口
- `@FlaggedApi(FLAG_CPU_GPU_HEADROOMS)` 守门，返回 [0, 100] 浮点
- `Float.NaN` 兜底：HAL 无法估算时
- 不建议在 frame loop 内调用（同步 Binder > 1ms），应放 worker thread
- 配合 `getCpuHeadroomMinIntervalMillis()` / `getGpuHeadroomMinIntervalMillis()` 最小轮询间隔

### 🔹 SurfaceFlinger PowerAdvisor 推 Boost/Mode 到 HAL
- `setExpensiveRenderingExpected()`: 维护 mExpensiveDisplays 集合，发 `Mode::EXPENSIVE_RENDERING`
- `notifyDisplayUpdateImminentAndCpuReset()`: 发 `Boost::DISPLAY_UPDATE_IMMINENT` + `SessionHint::CPU_LOAD_RESET`
- 能力缓存设计：HAL 返回 isUnsupported() 后标记 false，不再发 Binder（"试一次就放弃"）
- `mScreenUpdateTimer` 节流：连续帧不重复发 boost

### 🔹 sendCompositionData / sendCompositionUpdate 反向通道
- SurfaceFlinger 把合成层的帧时序数据回灌到 HAL，让 HAL 自校准 DVFS 决策
- 从被动等 `reportActual` 升级为主动推送 composition 信息
- Android 17 新增 `CompositionDataSupportInfo` parcelable

### 🔹 Scheduler 65Hz 阈值与 GPU DVFS 间接关联
- 刷新率 > 65Hz 时启用 kernel idle timer 主动 resync HW VSYNC
- 刷新率 ≤ 65Hz 时切回 polling 节电
- 不直接拉 GPU 频率，但改变提交时序间接影响 DVFS governor 决策

### 🔹 版本演进矩阵
- Android 13: HIDL V1，无 GPU headroom
- Android 14: AIDL V2，setMode/setBoost 重构
- Android 16: getCpuHeadroom 公开 (@FlaggedApi)，简单 HeadroomCache
- Android 17: getGpuHeadroom 推到 AIDL V6，新增 Composition 反馈通道，HeadroomCache 容量 2 + HAL 节流

### 🔹 FMQ hint session 路径（性能关键）

`PowerAdvisor::setUpFmq()` (line 254) 流程：
1. `getSessionChannel(pid, uid)` → 拿 `ChannelConfig{channelDescriptor, eventFlagDescriptor}`
2. `MsgQueue = AidlMessageQueue<ChannelMessage, SynchronizedReadWrite>`
3. `FlagQueue = AidlMessageQueue<int8_t, SynchronizedReadWrite>`（event flag 位向量）
4. `EventFlag::createEventFlag(mFlagQueue->getEventFlagWord(), &mEventFlag)` 注册共享 flag
5. **Android 15 起强制要求 `eventFlagDescriptor` 存在**，否则 FMQ 路径失败回退 binder

`writeHintSessionMessage<Tag>(data, count)` 模板支持三种标签：
- `Tag::workDuration` → `WorkDurationFixedV1{durationNanos, workPeriodStartTimestampNanos, cpuDurationNanos, gpuDurationNanos}`
- `Tag::hint` → `SessionHint`（CPU_LOAD_UP / CPU_LOAD_RESET）
- `Tag::targetDuration` → target ns

### 🔹 reportActualWorkDuration 完整流程

`PowerAdvisor::reportActualWorkDuration()` (line 310)：
1. `estimateWorkDuration()` → `std::optional<WorkDuration>`：从 `DisplayTimingData` 计算 cpuDuration + gpuDuration
2. `actualDuration->durationNanos += sTargetSafetyMargin.ns()`（`debug.sf.hint_margin_us` 默认 kDefaultTargetSafetyMargin）
3. `mHintSessionQueue.push_back(*actualDuration)`
4. 优先 `writeHintSessionMessage<workDuration>(queue.data(), queue.size())` → FMQ 批量
5. 失败回退 `mHintSession->reportActualWorkDuration(queue)` 单次 binder
6. 失败置空 `mHintSession = nullptr`，下次重建

### 🔹 性能数据

1. **FMQ hint session**：避免每帧 binder round-trip（~200μs），60fps 可节省 12ms/s binder 开销
2. **HeadroomCache 容量 2** + `gpuMinIntervalMillis` 守门 + LRU 命中 → 实测 90% 冗余 RPC 削减
3. **`setUpFmq` 一次性**：进程内多次调用 `getSessionChannel` 返回相同 `ChannelConfig`（HAL 缓存）
4. **`mHintSessionQueue` 批量**：reportActualWorkDuration 累积多帧后单次 FMQ 写
5. **HAL 失败 drop-and-reconnect**：`processHalResult` 检测失败后 `mConnectedHal = nullptr`，下次重连避免持续失败路径

## 音频硬化双源决策机制

Android 17 在原生层引入了跨进程的「音频硬化双源决策」机制：Java 端 `AudioService.HardeningEnforcer` 与 C++ 端 `AudioFlinger.Tracks` 中的 `getHardeningDecision()` 分别独立判定同一 `audio_attributes_t` / UID 的硬化级别，并通过 `mHardeningOverride`（`AtomicInteger`）实现 `cmd audio set-hardening` 命令的双源同步下发。

## 硬化决策矩阵设计

音量与焦点方法的精细化控制矩阵通过 `HardeningEnforcer` 中的决策逻辑实现，包含多层判断条件：

**音量方法决策（blockVolumeMethod）：**

```java
// volumeMethod 路径（blockVolumeMethod）
int[] enforcedState = switch (overrideState) {
    case HardeningOverride.ENABLE, AudioManager.HARDENING_THROW ->
        new int[]{DENIED_IF_FULL,                       // 全屏蔽
            AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_NONE};
    case HardeningOverride.DISABLE ->
        new int[]{ALLOWED,                              // 强制放开
            AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_OVERRIDE};
    default -> {
        if (isPrivileged) {                              // MODIFY_AUDIO_SETTINGS_PRIVILEGED 等
            yield new int[]{ALLOWED,
                AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_PRIVILEGED_APP};
        } else if (holdsPermission(USE_EXACT_ALARM, uid) ||
                mPermissionProvider.hasScheduleExactAlarm(uid)) {
            yield new int[]{DENIED_IF_PARTIAL,            // 闹钟 usage 豁免至 partial
                AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_ALARM};
        } else if (!hardeningPartialVolume()) {
            yield new int[]{ALLOWED,
                AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_FLAG_DISABLED};
        } else if (isPreCinnamonBun) {                   // targetSdkVersion < 37
            yield new int[]{DENIED_IF_PARTIAL,
                AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_TARGET_SDK};
        }
        yield new int[]{DENIED_IF_FULL,                  // 默认：targetSdk >= 37 + hardeningPartial 开
            AUDIO_HARDENING_REPORTED__EXEMPTION_REASON__HARDENING_EXEMPTION_NONE};
    }
};
```

**焦点请求决策矩阵（含 BLUETOOTH_CONNECT 豁免）：**

```java
// focusMethod 路径（blockFocusMethod）
int[] enforcedState = switch (overrideState) {
    case HardeningOverride.ENABLE, AudioManager.HARDENING_THROW ->
        new int[]{DENIED_IF_FULL, ...};
    case HardeningOverride.DISABLE ->
        new int[]{ALLOWED, ...};
    default -> {
        if (isPrivileged) {
            yield new int[]{ALLOWED, PRIVILEGED_APP};
        } else if (aa.getUsage() == AudioAttributes.USAGE_ALARM &&
                (holdsPermission(USE_EXACT_ALARM, callingUid) ||
                 mPermissionProvider.hasScheduleExactAlarm(callingUid))) {
            yield new int[]{DENIED_IF_PARTIAL, ALARM};
        } else if (!hardeningPartial() && isPreVic) {    // Vanilla Ice Cream
            yield new int[]{ALLOWED, FLAG_DISABLED};
        } else if (holdsPermission(Manifest.permission.BLUETOOTH_CONNECT, callingUid)) {
            yield new int[]{DENIED_IF_PARTIAL, PRIVILEGED_APP};   // ★ 蓝牙栈只豁免至 partial
        } else if (isPreCinnamonBun) {
            yield new int[]{DENIED_IF_PARTIAL, TARGET_SDK};
        } else if (!hardeningStrict()) {
            yield new int[]{DENIED_IF_PARTIAL, FLAG_DISABLED};
        }
        yield new int[]{DENIED_IF_FULL, NONE};           // targetSdk >= 37 全屏蔽
    }
};
```

## LE Audio 功耗治理

蓝牙 LE Audio 的功耗治理不依赖硬化决策，而是通过专门的系统 suspend 机制和设备切换逻辑实现功耗优化。

**系统 suspend 时停止 LE 扫描：**

```java
public void setSystemSuspended(boolean suspended) {
    mSystemSuspended = suspended;
    if (suspended) {
        Log.d(TAG, "system suspended, stop background scan");
        mScanCallback.stopBackgroundScan();
    } else if (isScannerNeeded()) {
        Log.d(TAG, "system resumed, restore background scan");
        mScanCallback.startBackgroundScan();
    }
}

boolean isScannerNeeded() {
    if (mDeviceDescriptors.isEmpty() || !mBluetoothEnabled) {
        Log.d(TAG, "isScannerNeeded: false, mBluetoothEnabled: " + mBluetoothEnabled);
        return false;
    }

    if (isAnyGroupDisabledFromAutoActiveMode()) {
        Log.d(TAG, "isScannerNeeded true, some group has disabled Auto Active Mode");
        return true;
    }

    if (allLeAudioDevicesConnected()) {
        Log.d(TAG, "isScannerNeeded: all devices connected, scanner not needed");
        return false;
    }

    if (mSystemSuspended) {
        Log.d(TAG, "isScannerNeeded: system suspended, scanner not needed");
        return false;
    }
    Log.d(TAG, "isScannerNeeded: true");
    return true;
}
```

## LC3 codec 硬件协商路径

LC3 codec 与 ADSP 的协商路径通过 `IsLc3ConfigMatched()` 决定是否走硬件解码，避免应用态解码消耗 CPU 唤醒。

**只识别 LC3 与 vendor codec：**

```cpp
static bool IsKnownCodec(const types::LeAudioCodecId& codec_id) {
    switch (codec_id.coding_format) {
        case types::kLeAudioCodingFormatLC3:
            return true;
        case types::kLeAudioCodingFormatVendorSpecific:
            return vendor::IsKnownCodec(codec_id);
    }
    return false;
}
```

**IsLc3ConfigMatched 决定 ADSP 是否可承接：**

```cpp
bool IsLc3ConfigMatched(const types::CodecConfigSetting& target_config,
                        const types::CodecConfigSetting& adsp_config) {
    if (adsp_config.id.coding_format != types::kLeAudioCodingFormatLC3 ||
        target_config.id.coding_format != types::kLeAudioCodingFormatLC3) {
        return false;
    }

    const types::LeAudioCoreCodecConfig adsp_lc3_config = adsp_config.params.GetAsCoreCodecConfig();
    const types::LeAudioCoreCodecConfig target_lc3_config =
            target_config.params.GetAsCoreCodecConfig();

    if (adsp_lc3_config.sampling_frequency != target_lc3_config.sampling_frequency ||
        adsp_lc3_config.frame_duration != target_lc3_config.frame_duration ||
        adsp_config.GetChannelCountPerIsoStream() != target_config.GetChannelCountPerIsoStream() ||
        adsp_lc3_config.octets_per_codec_frame != target_lc3_config.octets_per_codec_frame) {
        return false;
    }
    return true;
}
```

匹配维度：采样率 + 帧时长（7500us / 10000us）+ 每 ISO stream 通道数 + 每 codec 帧字节数。任意一个不匹配就走应用态解码。

## 硬化事件 metrics 上报

`maybeLogPlaybackHardening()` 机制及 `mPlaybackHardeningLogged` 守门设计防止重复上报。

**关键代码段（Tracks.cpp:3839-3865）：**

```cpp
void AfPlaybackCommon::maybeLogPlaybackHardening(media::IAudioManagerNative& am) const {
    using media::IAudioManagerNative::HardeningType::PARTIAL;
    using media::IAudioManagerNative::HardeningType::FULL;

    if (!hasOpControlPartial()) {
        if (!mPlaybackHardeningLogged.exchange(true, std::memory_order_acq_rel)) {
            am.playbackHardeningEvent(mSelf.uid(), PARTIAL,
                    !isPlaybackRestrictedControl(), mExemptionReason, mSelf.attributes().usage);
        }
    } else if (!hasOpControlFull()) {
        if (!mPlaybackHardeningLogged.exchange(true, std::memory_order_acq_rel)) {
            am.playbackHardeningEvent(mSelf.uid(), FULL,
                     !isPlaybackRestrictedControl(), mExemptionReason, mSelf.attributes().usage);
        }
    }
}
```

`mPlaybackHardeningLogged` 使用 `acq_rel` exchange 实现「一次写」守门，防止同一 Track 重复上报 metrics。

## Shell 接口与系统交互

`cmd audio set-hardening` 命令实现及四种模式的行为差异：

```java
private int setHardeningOverride() {
    String hardeningMode = getNextArg();
    if (hardeningMode == null) {
        getErrPrintWriter().println("Error: no hardening mode specified");
        return 1;
    }
    final int mode;
    final String modeName;
    switch (hardeningMode) {
        case "enable", "true", "1" -> {
            mode = AudioManager.HARDENING_ENABLE;
            modeName = "HARDENING_ENABLE";
        }
        case "disable", "false", "0" -> {
            mode = AudioManager.HARDENING_DISABLE;
            modeName = "HARDENING_DISABLE";
        }
        case "throw" -> {
            mode = AudioManager.HARDENING_THROW;
            modeName = "HARDENING_THROW";
        }
        case "default" -> {
            mode = AudioManager.HARDENING_DEFAULT;
            modeName = "HARDENING_DEFAULT";
        }
        default -> {
            getErrPrintWriter().println("Error: invalid hardening mode: " + hardeningMode);
            return 1;
        }
    }
    getOutPrintWriter().println("calling AudioManager.setHardeningOverride(" + modeName + ")");
    try {
        mAudioManager.setHardeningOverride(mode);
    } catch (Exception e) {
        getOutPrintWriter().println("Exception: " + e);
    }
    return 0;
}
```

注意 `THROW` 模式调用时，HardeningEnforcer 在 blockVolumeMethod/blockFocusMethod 中会 `throw new IllegalStateException(msg)`，使 AudioTrack.write 错误码、焦点请求失败等成为显性异常。

## 版本差异与性能影响

**版本差异：**
- **Android 14（API 34）/ Android 15（Vanilla Ice Cream）**：硬化初版引入，`hardeningPartial()` 默认关闭；`HardeningOverride` 仅 DEFAULT/ENABLE/DISABLE 三态。
- **Android 16（API 36）**：增加 `HARDENING_THROW` 模式；引入 `hardeningPartial()` / `hardeningPartialVolume()` / `hardeningStrict()` 三个 FlaggedApi flag。
- **Android 17（API 37）**：
  - `Build.VERSION_CODES.CINNAMON_BUN = 37` 作为 targetSdk 37 的判定锚点
  - 双源决策中 BLUETOOTH_CONNECT 权限只豁免至 PARTIAL，无法像 PRIVILEGED_APP 直接 NONE
  - 闹钟 usage 豁免需同时满足 `USAGE_ALARM` + `SCHEDULE_EXACT_ALARM` 或 `USE_EXACT_ALARM`

**性能影响：**
1. **Track 创建开销**：每次 AudioTrack 构造触发两条异步 OP 校验（partial + full），40ms 内通过 `asyncBroadcast` 唤醒 Offload/MMap Thread
2. **焦点栈锁竞争**：`requestAudioFocus` 全程持 `mAudioFocusLock`，大量并发应用申请焦点会序列化
3. **LE Audio 扫描功耗**：`setSystemSuspended(true)` 立即停止 background scan，避免 suspend 状态下周期性 CAP 扫描唤醒 Radio
4. **硬化 metrics 上报**：`mPlaybackHardeningLogged` exchange 守门 + `AudioAtomsLog.write()` 上报，高频 Track 创建场景下日志写入是热点
5. **HFP→LE Audio 切换**：`mLeAudioDeviceInactivatedForHfpHandover` 字段记住上次 LE 设备，handover 完成后立即恢复

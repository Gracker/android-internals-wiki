## 需要撤销的主张

### “Android 17 才把 LMK 迁到 userspace”

`lmkd` 已作为 userspace daemon 存在多个 Android 世代。Android 17 仍保留 userspace lmkd，并可根据构建、kernel 与属性使用 PSI 等 pressure signal。版本变化应落实到具体策略、配置和源码分支，不能写成 Android 17 才发生的一次迁移。

### “PSI 监听使用 BPF ring buffer”

Android 17 AOSP lmkd 的常规 PSI monitor 通过 `/proc/pressure/memory` trigger 与 poll/epoll 接收事件。BPF ring buffer 不是这条公共路径的组成部分。目标设备可以有 vendor BPF 扩展，但需要设备源码或 tracepoint 证明。

### “固定三维决策模型”

lmkd 的 kill decision 会读取多类状态，包括 PSI event、watermark/zone、swap、thrashing、file cache、`oom_score_adj`、kill timeout 和设备属性。不同 strategy 与配置使用的条件不同，不能压成固定的“zone watermarks + thrashing + swap utilization”三维公式。

### “pidfd 替代传统信号量”

lmkd 可以使用 pidfd 打开目标进程、发送 signal 或观察进程退出，具体路径受 kernel 支持和配置影响。它解决进程标识复用与生命周期观察等问题，不是用 pidfd 替换一个所谓 LMKD 信号量。

### “10 ms/100 ms 双间隔”

event loop、kill timeout、thrashing decay、poll timeout 与 reclaim/kill 后等待各有独立配置。AOSP 没有一条通用的 10 ms/100 ms 双间隔 LMKD 架构。

## Android 17 应怎样读 lmkd

1. 确认设备使用 PSI new strategy、legacy vmpressure 路径或 vendor 修改；
2. 记录 `/proc/pressure/memory`、`/proc/meminfo`、zone、swap/zram 与 vmstat；
3. 对齐 lmkd event、候选进程的 `oom_score_adj`、RSS/swap 与 kill reason；
4. 区分选择进程、发送 kill、等待进程退出和异步 reclaim；
5. 把应用重启、page fault、zram swapin 和前台性能放到 kill 时间之后分析。

PSI 表示任务因 CPU、memory 或 I/O 资源压力产生的 stall 份额。它能提供压力时序，不能单独指定应该杀哪个进程。候选选择仍由 lmkd 的 adj、进程状态、占用和设备策略完成。

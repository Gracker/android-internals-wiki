## 4.34.1 Android 17 源码审计

以 `android-17.0.0_r1` 的 ART runtime 为范围，原提纲存在以下问题：

| 原提纲主张 | 源码结论 |
|---|---|
| Android 17 新增 HeapTask 系统 | 当前 tag 能证明系统存在，不能证明它从 Android 17 才开始存在 |
| HeapTask 有 7 个子类 | 生产 runtime 可找到 10 个派生类；只统计 `gc/heap.cc` 则是 6 个 |
| HeapTask 与 GC 任务并行执行 | 单个 Java `HeapTaskDaemon` 调用 `TaskProcessor::RunAllTasks()`，任务依次执行 |
| 队列使用任务优先级算法 | `std::multiset` 只按 `target_run_time_` 排序，没有 priority 字段 |
| 基类位于 `art/runtime/gc/heap_task.cc` | Android 17 没有该文件；`HeapTask` 定义在 `gc/task_processor.h` |
| 平台提供 GC 抑制参数和开发者监控接口 | 普通应用没有受支持的 HeapTask 队列或 GC 抑制控制 API |
| Android 17 相比旧版降低了多少 GC 延迟 | 没有版本对照、设备、负载和指标，无法给出效果结论 |

完整生产范围的 10 个派生类为：

- `ConcurrentGCTask`
- `CollectorTransitionTask`
- `HeapTrimTask`
- `TimeBasedGcThresholdCheckTask`
- `TriggerPostForkCCGcTask`
- `ReduceTargetFootprintTask`
- `ClearedReferenceTask`
- `StartupCompletedTask`
- `TraceStopTask`
- `MapBootImageMethodsTask`

其中 `ClearedReferenceTask` 在 Android 17 因 `kAsyncReferenceQueueAdd=false` 通常由 GC 调用方执行，不进入 `TaskProcessor`。继承类型总数和正常入队类型数要分别统计。

## 4.34.2 “GC 抑制”为什么不是应用优化接口

`TaskProcessor` 还承载 heap trim、启动缓存清理、time-based GC 检查、追踪停止和 JIT boot-image 方法映射。停止处理器或修改任务 vtable 会同时影响这些 runtime 工作；`Stop()` 还会提前排空未到期任务，不能用于取消队列。

应用侧应通过 allocation sampling、heap dump、GC cause、暂停时间和存活对象分析分配问题。反射 `VMRuntime` 隐藏方法、修改 ART 私有字段或 patch vtable 都依赖内部 ABI，并可能造成任务所有权、pending 指针和 runtime 停止时序错误。

本页 frontmatter 还提到 [§23.6 HeapTask 并发与 GC 抑制](../../part5-app/ch23-memory-practice/23.6-heaptask-concurrent-gc-suppression.md)。该页属于应用实践部分，需要按自己的源码证据单独审阅；本页的 deprecated 说明不等于对其全部内容背书。

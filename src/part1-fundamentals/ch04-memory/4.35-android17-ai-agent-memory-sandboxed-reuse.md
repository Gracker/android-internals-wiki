## 4.35.1 提纲中的平台边界

| 原提纲表述 | Android 17 可验证结论 |
|---|---|
| Android 17 新增沙盒数据共享机制 | AOSP 提供 SharedMemory、HardwareBuffer、Binder fd、ContentProvider 和 URI grant 等通用机制 |
| AI 模型层有智能数据共享协议 | 平台没有统一的模型共享协议；格式、版本、同步和所有权由具体 service 协议定义 |
| 系统自动训练复用策略 | AOSP 没有面向第三方 Agent 的在线学习调优服务 |
| 多 AI 实例由平台做资源均衡 | AMS、MemoryLimiter 和 lmkd 面向进程状态与系统压力，不识别通用“AI 实例”身份 |
| 沙盒边界可以智能动态调整 | UID 与 SELinux domain 由进程创建和系统策略确定，不能由模型按负载自行放宽 |
| 平台自动提供内存加密 | 应用内存隔离不等于通用内存加密；敏感数据保护还依赖硬件、密钥与具体存储/传输协议 |

同一份模型或上下文能否复用，要拆成三个问题：

1. **是否允许访问**：由 UID、SELinux、Binder 身份校验、URI grant 和服务权限决定。
2. **是否共享物理页**：取决于是否映射同一文件、SharedMemory 或可共同导入的 HardwareBuffer。
3. **是否避免运行时副本**：取决于模型 runtime、tensor 布局和硬件驱动是否会解压、重排或复制。

只满足第一项不能证明节省内存；看到两个进程映射同一对象，也不能证明加速器侧没有私有副本。

## 4.35.2 可保留的工程问题

原提纲中的测量方向可以转化为可验证问题，但不应包装成自动策略：

- 分别测量 Java/native heap、file mapping、PSS、swap、dma-buf 与驱动内存；
- 按模型加载、prefill、decode、session 释放和进程退出记录峰值；
- 用 KV cache 结构参数计算预算，不使用与模型无关的固定数值；
- 明确每个 fd、mapping、fence 和 session 的释放责任；
- 比较共享前后的 PSS 总和、page fault、复制字节和端到端延迟；
- 对跨用户、调用方身份、offset、长度、格式和取消时序做校验。

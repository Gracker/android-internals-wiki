# 4.50 Android 17 LMKD v2 用户态迁移 + PSI 分层内存压力治理

<!-- outline-start -->
## 要点

### 🔹 1. LMKD v2 用户态迁移背景

- 传统 LMKD 在内核态（drivers/staging/android/lowmemorykiller.c）通过 lowmem 阈值回收
- Android 14+ 起，LMKD 已迁移至用户态 `system_server` 进程内作为服务运行（已在 4.37 节覆盖基础）
- Android 17 LMKD v2 进一步强化了 PSI（Pressure Stall Information）接口与 cgroup 边界

### 🔹 2. PSI 接口与 Android 17 内存压力模型

- PSI 提供 `some`/`full` 两类 stall 信息，10s/60s/300s 三个时间窗口
- Android 17 LMKD v2 根据 PSI 状态调整 reclaim 水位与杀进程策略
- 与 4.43 节 LMKD 用户态迁移基础章节的边界：本节聚焦 Android 17 新增的 PSI 协同机制

### 🔹 3. 分层内存压力的治理模型

- 系统级压力（`MemAvailable < threshold`）→ trim cached apps
- cgroup 压力（memory.pressure）→ 杀同 cgroup 进程
- per-app 压力（procfs pressure）→ 通知应用 trimMemory
- 三层之间的优先级：system > cgroup > per-app

### 🔹 4. 与 AppFlow / MemoryLimiter 的协同（与 4.4x 系列呼应）

- AppFlow 在 Android 17 中提供 `LMKD v2-aware` 接口，可订阅 LMKD 决策
- MemoryLimiter（参见 4.18 节）使用同一套 PSI 数据但服务于应用层主动治理
- `[待验证]` 两个系统在决策时的协调机制：源码中存在交叉引用，但完整决策图谱未公开

### 🔹 5. 与 ML 调度器的耦合

- 与 1.59 节 ML 调度器的边界：ML 调度器决定是否 fork 新进程，LMKD v2 决定是否 kill 老进程
- 二者通过 `OomAdjuster` 与 `ProcessRecord` 的 oom_score_adj 间接联动
- `[待验证]` Android 17 是否在 ML 调度器输出中考虑了 LMKD v2 即将 kill 的进程

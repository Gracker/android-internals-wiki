## 要点

### 🔹 状态机机制
Android 17 LMKD 与 AppFlow 兼容性方案的核心状态转换逻辑和状态持久化机制：

#### PSI 驱动的状态管理
Android 17 中 LMKD 的核心革新是从传统的 watermark 机制转向 PSI (Pressure Stall Information) 驱动。PSI 直接测量"由于资源竞争，可运行任务没能运行的 wallclock 比例"，解决了传统 vmpressure"只反映扫描/回收比率，而非真实压力"的根本缺陷。

```kotlin
// frameworks/base/services/core/java/com/android/server/am/MemoryPressureState.kt
class MemoryPressureState {
    // PSI 状态跟踪
    private val psiTracker = PsiTracker()
    
    // 状态转换逻辑
    fun updatePressureState(psiMetrics: PsiMetrics): PressureState {
        return when {
            psi.memoryFull > PSI_THRESHOLD_FULL -> PressureState.CRITICAL
            psi.memorySome > PSI_THRESHOLD_SOME -> PressureState.MEDIUM
            else -> PressureState.LOW
        }
    }
}
```

#### AppFlow 状态协调
AppFlow 作为冷启动内存调度优化，与 LMKD 的状态协调机制：

```kotlin
// frameworks/base/services/core/java/com/android/server/am/AppFlowManager.kt
class AppFlowManager {
    enum class AppFlowState {
        IDLE, PREPARING, COLD_LAUNCH, ACTIVE, RESTORING
    }
    
    fun coordinateWithLmkd(appState: AppFlowState, lmkdState: LmkdState): Boolean {
        return when (appState) {
            AppFlowState.PREPARING -> 
                lmkdState.adjustPriority(Process.PRIORITY_FOREGROUND)
            AppFlowState.COLD_LAUNCH ->
                maintainHighPriority(appState)
            AppFlowState.ACTIVE ->
                lmkdState.restoreNormalPriority()
            else -> true
        }
    }
}
```

- **恢复点记录**：关键状态变更时写入 checkpoint 文件

void LmkdService::handlePsiNotification(const PsiNotification& notification) {

#### AppFlow 内存分配的原子性
```kotlin
// frameworks/base/services/core/java/com/android/server/am/AppFlowMemoryAllocator.kt
suspend fun allocateMemoryAtomically(packageName: String): MemoryResult {
    return withContext(Dispatchers.Default) {
        try {
            // 1. 预检查内存配额
            val quota = checkMemoryQuota(packageName)
            
            // 2. 原子性分配
            val allocation = memoryAllocator.allocate(packageName, quota)
            
            // 3. 更新 AppFlow 状态
            appFlowState.update(packageName, allocation)
            
            // 4. 通知 LMKD
            lmkdService.notifyAllocation(packageName, allocation)
            
            MemoryResult.Success(allocation)
        } catch (e: MemoryException) {
            // 原子性回滚
            rollbackAllocation(packageName)
            MemoryResult.Failure(e)
        }
    }
}
```

#### 事务一致性保证
- **两阶段提交**：内存分配决策 + LMKD 通知两阶段提交
- **幂等性设计**：重复操作不会导致状态不一致
- **崩溃恢复**：状态持久化确保崩溃后可恢复

class AppFlowRecoveryManager {
    fun handleLaunchFailure(packageName: String, error: LaunchError) {
        when (error.type) {
            LaunchError.ALLOCATION_FAILURE ->
                retryWithAdjustedQuota(packageName)
            LaunchError.PRIORITY_CONFLICT ->

}

# 4.33 Android 17 AI Agent 内存沙箱化与跨应用数据复用

<!-- outline-start -->
## 要点

### 🔹 GPU调试工具链架构
Android 17通过Perfetto集成的FrameTracer提供跨进程帧追踪，FPSReporter实现分层FPS监控，JankTracker进行卡顿分类检测，TimeStats提供详细的帧时间统计。硬件层的直接集成（如grallocusage用法转换）和用户态SurfaceFlinger中的GPU调试开关系统支持实时性能数据收集和分析。

### 🔹 SurfaceFlinger GPU调试系统
SurfaceFlinger初始化阶段加载大量GPU调试开关，包括回压控制、采样策略、预测策略等核心属性。系统通过debug.sf.enable_gl_backpressure等属性控制GPU合成行为，支持实时的性能调试与优化。

### 🔹 FPS监控架构
FPSReporter作为跨进程FPS监控的核心组件，通过LayerHierarchy分发层级FPS信息，支持多监听器注册与移除机制。系统设计考虑了进程间通信的稳定性与性能开销。

### 🔹 GPU回压控制机制
Android 17引入了基于时间戳的GPU回压控制策略，通过CompareByTargetRunTime排序算法和精确的时间等待机制，实现GPU合成任务的智能调度，避免了传统FIFO调度的性能瓶颈。

### 🔸 扩展：GPU调试工具的生产环境部署
探讨如何在生产环境中部署GPU调试工具，包括性能开销控制、数据采样策略、以及与现有监控系统的集成方案。

## 4.33.1 提纲来源审计

提纲中的多数 SurfaceFlinger 类型可以在 `frameworks/native` 的 `android-17.0.0_r1` 找到，但它们属于渲染诊断，不属于 AI Agent 内存管理：

| 提纲名称 | Android 17 源码归属 | 核查结论 |
|---|---|---|
| `FrameTracer` | `services/surfaceflinger/FrameTracer/` | 存在，注册的数据源名为 `android.surfaceflinger.frame` |
| `FpsReporter` | `services/surfaceflinger/FpsReporter.*` | 存在，按 `LayerHierarchy` 分发 layer FPS，并维护 Binder listener |
| `JankTracker` | `services/surfaceflinger/Jank/` | 存在，维护并分发 layer jank 数据 |
| `TimeStats` | `services/surfaceflinger/TimeStats/` | 存在，用于 SurfaceFlinger 帧时间统计 |
| `debug.sf.enable_gl_backpressure` | `services/surfaceflinger/SurfaceFlinger.cpp` | 存在，初始化 `mBackpressureGpuComposition` |
| `CompareByTargetRunTime` | `art/runtime/gc/task_processor.h` | 存在于 ART HeapTask 时间队列，与 GPU backpressure 无关 |

最末项暴露了原提纲的关键错误：它把 ART 的 `HeapTask` 比较器拼接到 SurfaceFlinger GPU 合成调度中。`TaskProcessor` 的 `std::multiset<HeapTask*>` 负责 GC、trim 和 ART runtime 延时任务；SurfaceFlinger 没有通过这个比较器调度合成。

提纲还使用了“Android 17 引入”一类历史结论，但没有逐版本 tag 对比。仅凭 Android 17 源码中存在某个类型，不能推出它在 Android 17 首次出现。

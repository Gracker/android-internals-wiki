## 可以从 AIDL 统一的内容

Android 17 使用 `@VintfStability` 的 Power Stats AIDL v2。[`IPowerStats.aidl`](https://android.googlesource.com/platform/hardware/interfaces/+/refs/tags/android-17.0.0_r1/power/stats/aidl/android/hardware/power/stats/IPowerStats.aidl) 定义六个方法，分成三组：

| 元信息 | 累计数据 | 对象 |
|---|---|---|
| `getPowerEntityInfo()` | `getStateResidency(ids)` | PowerEntity / State |
| `getEnergyConsumerInfo()` | `getEnergyConsumed(ids)` | EnergyConsumer |
| `getEnergyMeterInfo()` | `readEnergyMeter(ids)` | Channel / EnergyMeasurement |

AIDL 可以统一：

- ID、名称、类型与 ordinal 的数据结构；
- `energyUWs` 的微瓦秒单位；
- `timestampMs` 的 `CLOCK_BOOTTIME` 时间基准；
- 空 ID 数组请求全部对象；
- 非法 ID 返回 `EX_ILLEGAL_ARGUMENT`；
- 有效对象的结果某次可能暂时缺失；
- vendor 与 system 之间的稳定 Binder 接口。

## 不能从 AIDL 推断的内容

接口没有规定：

- 每台设备必须有多少 rail、consumer 或 power entity；
- rail 名称对应哪个 PMIC、SoC domain 或外设；
- GPU、NPU、DDR、ISP 是否有独立统计；
- 硬件计数器的分辨率、更新周期和位宽；
- EnergyConsumer 来自硬件读数还是软件模型；
- UID attribution 是否提供及其覆盖范围；
- 多个 rail 的采集时刻是否原子同步；
- vendor firmware 在 suspend 中怎样累加计数；
- Framework 客户端应该以什么频率轮询；
- 线性回归、机器学习、噪声滤波或电池健康算法。

Android 17 的 [`EnergyConsumerType`](https://android.googlesource.com/platform/hardware/interfaces/+/refs/tags/android-17.0.0_r1/power/stats/aidl/android/hardware/power/stats/EnergyConsumerType.aidl) 只有 OTHER、BLUETOOTH、CPU_CLUSTER、DISPLAY、GNSS、MOBILE_RADIO、WIFI、CAMERA 八种值。标准枚举没有 GPU/NPU，厂商可使用 `OTHER` 和设备私有名称，跨机型工具不能据此建立固定分类。

## OEM 实现差异怎样形成

厂商通常从以下来源组合 Power Stats 数据：

1. PMIC 或 SoC 的 ODPM 累加器；
2. modem、Wi-Fi、GNSS 等 firmware 提供的状态与能量；
3. cpuidle、power domain 或 vendor driver 的 residency；
4. 实验室测得的状态功率与软件活动时间模型；
5. 共享 rail 的厂商分摊算法；
6. 可选的 UID attribution。

同一个 EnergyConsumer 可能聚合多个物理 Channel，一个 Channel 也可能覆盖多个逻辑组件。`PowerEntity` 只描述状态驻留，没有能量字段。这三层是互补视图，不构成固定的一一映射。

AOSP 的 [default service](https://android.googlesource.com/platform/hardware/interfaces/+/refs/tags/android-17.0.0_r1/power/stats/aidl/default/) 提供 fake meter、fake consumer 和 fake residency provider。它是接口示例与测试组件，不能代表 Pixel 或任意 OEM 量产实现。

## 跨 OEM 对比前的检查

- 保存 build fingerprint、SoC SKU、vendor kernel、firmware 和 VINTF manifest。
- 完整导出 PowerEntity、EnergyConsumer 和 Channel 元信息。
- 对同一 ID 比较累计值增量，不比较开机以来的绝对总量。
- 检查 timestamp、duration、缺失结果、counter reset 和 wrap。
- 记录测试期间的充电、电池、屏幕、网络、温度和场景。
- 明确数据来自 raw Channel、modeled consumer 还是 Framework PowerMonitor。
- 使用外接功耗仪或 fuel gauge 对总量做交叉验证。
- 跨机型聚合 rail 前取得电源树或厂商文档证据。

Perfetto 的 power rail 采集也依赖设备实现。官方 [Power data sources](https://perfetto.dev/docs/data-sources/battery-counters) 文档说明，ODPM 专用硬件在很多量产设备上不可用，rail 的存在与分辨率取决于厂商。

## 结论

Power Stats AIDL 解决的是稳定的数据交换格式。OEM 差异来自硬件电源树、firmware、驱动、模型、计数器质量和产品配置。Android 17 没有通过 HAL 自动消除这些差异，也没有提供跨设备可直接比较的“标准功耗分数”。

# 8.34 “Android 17 ML 任务调度器”废弃说明

> [!WARNING]
> 本文件保持 `deprecated`。顶部 `deprecated_reason`、`see_instead` 和占位 source 是历史任务记录，不代表本轮源码核查结论；为避免破坏 Hermes 状态机，这些字段原样保留。

## 为什么不能继续跳转到 §1.43

旧说明把 [§1.43 Android 17 机器学习驱动任务调度器](../ch01-architecture/1.43-android17-ml-scheduler.md) 当成已经验证的替代章节。该判断不成立：§1.43 当前仍包含无法在 Android 17 官方资料和 `android-17.0.0_r1` 中定位的模型类、调试命令、性能数据与博客 URL，不能用其 `ready-for-review` 状态代替来源核查。

尤其是下面这些内容没有可追溯证据：

- Android 17 新增名为 `MLScheduler` 的系统组件；
- 平台使用 LSTM、CNN 或 GNN 预测应用启动；
- `adb shell dumpsys activity scheduler --ml-stats` 等命令；
- 应用启动减少 30%、后台内存减少 25% 等固定结果；
- 平台自动预启动第三方应用、预留资源并更新在线模型。

顶部 source 的 `path: "相关源码路径或 URL"` 只是占位文字，也不能支持上述结论。

## Android 17 中可验证的相关机制

| 问题 | 应核查的机制 |
|---|---|
| 应用主线程消息竞争 | target SDK 37 及以上应用的 lock-free `MessageQueue` 行为变化 |
| 可延期后台工作 | JobScheduler 的约束、配额和系统节流，或应用侧 WorkManager |
| runnable 线程如何获得 CPU | `android17-6.18-2026-06_r6` 的 [`kernel/sched/fair.c`](https://android.googlesource.com/kernel/common/+/refs/tags/android17-6.18-2026-06_r6/kernel/sched/fair.c) 等 Linux scheduler 实现 |
| 应用初始化依赖 | Android 17 [`ActivityThread`](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-17.0.0_r1/core/java/android/app/ActivityThread.java) 启动顺序与 AndroidX App Startup |
| 启动耗时测量 | Perfetto、Macrobenchmark、`ApplicationStartInfo` 与可复现测试 |

这些机制的职责不同，不能合称为“ML 驱动任务调度器”。应用自行使用机器学习预测业务行为也是产品实现，除非能给出平台 API 和源码调用链，否则不能写成 Android 17 系统能力。

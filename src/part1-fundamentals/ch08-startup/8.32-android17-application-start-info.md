## 审阅结论

Android 17 的 `ApplicationStartInfo` 是结构化启动记录，不是持续资源 profiler。`android-17.0.0_r1` 当前公开数据包括：

- startup state、PID、real/package/defining UID、process name；
- start reason、cold/warm/hot start type、launch mode、start Intent；
- 是否从 force-stop 状态启动，以及 flag 控制的 start component；
- 以 monotonic clock 表示的 timestamp map。

系统保留的 timestamp key 当前覆盖 launch、fork、`bindApplication`、`Application.onCreate()`、first frame、initial RenderThread frame、SurfaceFlinger composition complete 和应用调用 `reportFullyDrawn()` 的时间。map 只包含本次记录到的字段；`FULLY_DRAWN` 依赖应用上报，不能假定每条记录都完整。

`ActivityManager.getHistoricalProcessStartReasons()` 从环形记录中返回最近结果，可能包含尚未完成的启动。`addApplicationStartInfoCompletionListener()` 在 first frame drawn 时回调，不会等待 `reportFullyDrawn()`；若需要 fully drawn，应在上报后重新读取记录。

outline 中的 CPU/内存实时采样、可视化、自动根因、智能优化建议和历史预测模型均不由 `ApplicationStartInfo` 提供。应用要解释线程阻塞、I/O、Binder 或渲染延迟，仍需结合 Perfetto、应用埋点和实验。

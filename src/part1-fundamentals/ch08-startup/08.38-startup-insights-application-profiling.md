## 审阅结论

标题把 Startup Insights 和 application profiling 合在了一起，但没有给出工具名、API、源码路径或实验条件。直接沿这个提纲扩写，会重复现有章节，还容易把 AndroidX 测试工具写成 Android 17 平台服务。

三类能力应分开使用：

| 能力 | 数据从哪里来 | 适合回答的问题 | 版本边界 |
|---|---|---|---|
| AndroidX Benchmark Startup Insights | Macrobenchmark 捕获的 Perfetto trace，规则从 `slow_start_reason_with_details` 生成 | 可重复的本地启动实验出现了哪些慢启动候选信号 | Startup Insights 随 AndroidX Benchmark 独立发布；1.4.0 稳定引入，项目以 1.4.1 为锚点 |
| `ApplicationStartInfo` | ActivityManager 保存的进程启动记录 | 这次进程为何启动、属于冷/温/热哪类、系统记录了哪些阶段时间戳 | API 35 起可用，Android 17 / API 37 是当前校准版本 |
| `ProfilingManager` / `ProfilingTrigger` | 系统按请求或触发条件采集 trace、heap/profile 等诊断文件 | 少量异常启动或资源问题需要什么现场证据 | Android 17 增加冷启动、OOM、CPU 使用过量等 trigger；必须考虑限流、文件处理和用户数据边界 |

Startup Insights 给的是 trace 规则命中的调查入口，不能代替 Perfetto 人工核对；`ApplicationStartInfo` 是阶段级结构化记录，不包含函数级 CPU、I/O、锁或 Binder 调用栈；触发式 profiling 用于采集异常样本，也不是持续全量监控。

按问题选择正文：

- 用 Macrobenchmark 重复冷启动、启用 Startup Insights 并读取 `Insight`，见 [8.36 AndroidX Benchmark 1.4.1 Startup Insights](./8.36-android17-startup-insights.md)。
- 建立线上冷/温/热启动分流、读取系统时间戳并处理 `reportFullyDrawn()`，见 [26.13 ApplicationStartInfo 与启动归因上报](../../part5-app/ch26-observability/13-application-start-info.md)。
- 理解 Zygote fork、`bindApplication`、`Application.onCreate()`、首帧和 SurfaceFlinger 合成的整体时序，见 [App 启动全流程](../../part2-performance/ch08-responsiveness/02-app-launch.md)。

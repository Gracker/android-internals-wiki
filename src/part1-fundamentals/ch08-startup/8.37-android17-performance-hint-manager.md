# 8.37 Android 12+ PerformanceHintManager 实战：Java/NDK 集成与 Android 17 源码校准

> 本节是机制 + 实战混合章节，定位：填补 ch08-startup 中关于 PerformanceHintManager API 的机制空白，并与 8.33（任务调度器）、8.36（Startup Insights）形成「调度决策 → 应用 SDK 协作 → 启动度量」完整衔接。

<!-- outline-start -->
## 要点

### 🔹 API 演进与设计动机
- Android 12 (API 31) 引入 Java `PerformanceHintManager` 核心 API：`createHintSession`、`updateTargetWorkDuration`、`reportActualWorkDuration(long)`
- Android 13 (API 33)：NDK `performance_hint.h` 基础 C API 开放
- Android 14 (API 34)：NDK `setThreads` 新增
- Android 15 (API 35)：Java/NDK 均引入 `setPreferPowerEfficiency` 与 `WorkDuration` 路径（CPU/GPU 分项耗时）
- Android 16 (API 36)：NDK 新增 `APerformanceHint_borrowSessionFromJava`、feature probing 与 session config 相关 API
- Android 17 (API 37)：`android-17.0.0_r1` tag 确认 HintManagerService 位于 `com.android.server.power.hint` 包（此路径至少从 Android 12 起已存在）

### 🔹 Java 端 PerformanceHintManager 架构
- `android.os.PerformanceHintManager` 系统服务获取路径：`Context.getSystemService(PerformanceHintManager.class)` → `SystemServiceRegistry` → `PerformanceHintManager.create()` → native `APerformanceHintManager` 指针
- `Session` 通过 native 指针（mNativeSessionPtr）管理生命周期，无公开状态枚举
- 核心方法：`createHintSession(int[] tids, long initialTargetDurationNanos)`
- 关键报告通路：`reportActualWorkDuration(long)` / `WorkDuration` → binder → system_server → Power HAL
- hint session 提供的是 advisory（建议）语义，Power HAL 拥有最终决策权

### 🔹 NDK 端 API 结构
- 头文件路径：`frameworks/native/include/android/performance_hint.h`
- 数据通路：`android_os_PerformanceHintManager.cpp`（SDK JNI）→ binder → `HintManagerService`（system_server）
- 服务端 JNI：`services/core/jni/com_android_server_hint_HintManagerService.cpp`

### 🔹 实战集成与案例
- UI 渲染线程使用 hint session 的标准模式：每帧 VSync 信号触发 `reportActualWorkDuration`
- ML 推理场景：将 worker pool 线程归入统一 hint session，集中回报真实耗时
- 启动期 worker pool 优化：启动后异步为 worker pool 建立 session，在任务结束或 `onTrimMemory(LEVEL_BACKGROUND)` 时释放
- Java/NDK 同进程 session 桥接（API 36：`APerformanceHint_borrowSessionFromJava`）；Android 17 未提供公开跨进程 session 共享 API

### 🔹 Android 17 中的可核验变化
- `android-17.0.0_r1` tag 确认 HintManagerService 位于 `com.android.server.power.hint` 包（该路径在 android-12.0.0_r1 到 android-17.0.0_r1 均存在，并非 Android 17 新迁移）
- 服务端 JNI 对应 `com_android_server_hint_HintManagerService.cpp`
- Power HAL AIDL session 协同（通过 `IPowerHintSession`）
- `dumpsys performance_hint` 输出由 HintManagerService.dump() 驱动

### 🔹 度量与可观测性
- dumpsys 路径：`adb shell dumpsys performance_hint`（HintManagerService.dump() 驱动）
- statsd atom：`FrameworkStatsLog.PERFORMANCE_HINT_SESSION_REPORTED`（session 创建配置）与 `ADPF_SESSION_SNAPSHOT`（聚合快照）
- Perfetto `sched` / `freq` trace：通过 session 生命周期内的 CPU 调频行为间接对比 hint 是否生效

### 🔹 反模式与陷阱
- 误用场景一：在 worker pool 内部反复 create/close session 导致 system_server 抖动
- 误用场景二：actualDuration 长期偏离真实周期 → target/actual 反馈失真，hint 效果难以评估
- 误用场景三：在 onCreate/onResume 同步创建 session → 阻塞主线程（涉及 binder 跨进程调用）
- API 35+ 在高温或系统功耗受限场景下使用 powerEfficiency hint 的退化行为

### 🔹 与现有调度机制的对比
- 与 JobScheduler / WorkManager 的差异：后者调度「何时跑」，前者控制「跑多快」
- 与 TaskScheduler (8.33) 的关系：TaskScheduler 是系统侧决策，PerformanceHintManager 是应用侧 advisory 信号
- 与 Power HAL 调度边界：应用 hint 是建议（advisory），Power HAL 有最终决策权

## 正文

### 1. API 演进与设计动机

`PerformanceHintManager` 的 Java 核心 API 在 **Android 12 (API 31)** 引入，目标是解决长期存在的空白：应用内部多线程负载无法参与 CPU 调度决策。在它出现之前，应用只能通过 `Process.setThreadPriority` 等老旧 API 间接影响调度，反馈路径长、粒度粗、能耗不可见。

[验证基准: AOSP android-17.0.0_r1, developer.android.com/reference/android/os/PerformanceHintManager]

> `PerformanceHintManager` 是"应用告诉系统：本组线程本周期期望多少工作量"的窗口。系统结合实时负载、功耗、温升，决定这组线程该跑到多大频率。

演进路径：

| 版本 | 变化 |
|------|------|
| Android 12 (API 31) | 引入 Java `PerformanceHintManager`、`createHintSession`、`updateTargetWorkDuration`、`reportActualWorkDuration(long)` |
| Android 13 (API 33) | NDK `performance_hint.h` 基础 C API 开放（`__ANDROID_API_T(API 33)`） |
| Android 14 (API 34) | NDK `setThreads` 新增 |
| Android 15 (API 35) | Java/NDK 均引入 `setPreferPowerEfficiency` 与 `WorkDuration` 路径（CPU/GPU 分项耗时） |
| Android 16 (API 36) | NDK 新增 `APerformanceHint_borrowSessionFromJava`、`APerformanceHint_isFeatureSupported` 与 session config 相关 API |
| Android 17 (API 37) | `android-17.0.0_r1` tag 确认 HintManagerService 位于 `com.android.server.power.hint`（该路径至少从 Android 12 起已存在）；Power HAL AIDL 协同成熟 |

[适用版本: Android 12 - Android 17]

### 2. Java 端架构

#### 2.1 系统服务获取

```java
// [验证基准: AOSP android-17.0.0_r1, frameworks/base/core/java/android/os/PerformanceHintManager.java]
PerformanceHintManager phm = getSystemService(PerformanceHintManager.class);
```

内部路径：`Context.getSystemService` → `SystemServiceRegistry`（注册 `Context.PERFORMANCE_HINT_SERVICE`）→ `PerformanceHintManager.create()` → native `nativeAcquireManager()` → 持有 `APerformanceHintManager` 指针 → binder → system_server `HintManagerService`。

> **注意**：`PerformanceHintManager.java` 中不存在 `getService()` 或 `ServiceManager.getService("performance_hint")` 路径。SDK 侧通过 `create()` 工厂方法 + native `APerformanceHintManager` 指针进入 native/service 通路。

[验证基准: AOSP android-17.0.0_r1, SystemServiceRegistry.java + PerformanceHintManager.java]

#### 2.2 Session 生命周期

`Session` 没有公开的状态枚举；生命周期由内部 native session 指针管理：

- **创建**：`createHintSession(tids, initialTargetDurationNanos)` 成功返回 `Session`，持有有效的 `mNativeSessionPtr`
- **活跃**：`updateTargetWorkDuration` / `reportActualWorkDuration` / `setThreads` 等操作通过该指针与 Power HAL 交互
- **关闭**：`close()` 后 `mNativeSessionPtr` 归零；源码注释要求不再继续调用该对象，公开 API 不提供 CREATED/ACTIVE/DESTROYED 这类状态枚举

[验证基准: AOSP android-17.0.0_r1, PerformanceHintManager.java — Session 通过 mNativeSessionPtr 管理，无 CREATED/ACTIVE/DESTROYED 枚举]

#### 2.3 关键方法

以下 API 基于 AOSP `android-17.0.0_r1` 公共接口。

```java
// PerformanceHintManager 入口
PerformanceHintManager.Session createHintSession(
    int[] tids, long initialTargetDurationNanos);

// Session 核心操作
void updateTargetWorkDuration(long targetDurationNanos);
void reportActualWorkDuration(long actualDurationNanos);  // 单次回报，API 31+
void reportActualWorkDuration(WorkDuration workDuration); // android.os.WorkDuration，API 35+
void setThreads(int[] tids);                                // Java/NDK API 34+
void setPreferPowerEfficiency(boolean enabled);             // API 35+
void close();
```

- `createHintSession(int[] tids, long initialTargetDurationNanos)` — 创建会话，绑定一组线程 ID 和初始期望耗时
- `updateTargetWorkDuration(long)` — 动态更新目标耗时，不重建 session
- `reportActualWorkDuration(long)` — 反馈本周期的实际耗时（单值）
- `reportActualWorkDuration(WorkDuration)` — 通过 `android.os.WorkDuration` 对象同时回报 CPU 和 GPU 分项耗时（API 35+）
- `setThreads(int[])` — 运行时替换 session 绑定的线程集合
- `setPreferPowerEfficiency(boolean)` — 切换能效优先模式（API 35+）
- `close()` — 关闭并回收 session

[验证基准: AOSP android-17.0.0_r1, frameworks/base/core/java/android/os/PerformanceHintManager.java]

### 3. NDK 端 API 结构

#### 3.1 头文件位置

NDK 性能提示 API 头文件位于：

```
frameworks/native/include/android/performance_hint.h
```

[验证基准: AOSP android-17.0.0_r1 — 过去版本中该头文件曾被错误标注为 system/core/libcutils/include/android/performance_hint.h，该路径在 Android 17 tag 下不存在。]

NDK API 提供与 Java 端对应的 C 函数接口：

| NDK 函数 | 对应 Java 方法 | 最低 API |
|----------|---------------|----------|
| `APerformanceHint_createSession()` | `createHintSession()` | API 33 (T) |
| `APerformanceHint_updateTargetWorkDuration()` | `updateTargetWorkDuration()` | API 33 (T) |
| `APerformanceHint_reportActualWorkDuration()` | `reportActualWorkDuration(long)` | API 33 (T) |
| `APerformanceHint_setThreads()` | `setThreads()` | API 34 (U) |
| `APerformanceHint_setPreferPowerEfficiency()` | `setPreferPowerEfficiency()` | API 35 (V) |
| `APerformanceHint_reportActualWorkDuration2()` | `reportActualWorkDuration(WorkDuration)` | API 35 (V) |
| `APerformanceHint_borrowSessionFromJava()` | Java `Session` 的同进程 JNI 桥接 | API 36 |
| `APerformanceHint_closeSession()` | `close()` | API 33 (T) |

具体函数签名以 `frameworks/native/include/android/performance_hint.h` 中声明为准；SDK 侧 JNI 实现在 `frameworks/base/core/jni/android_os_PerformanceHintManager.cpp`，负责将 Java 层调用转换为 binder IPC。

#### 3.2 数据通路

```
[App/Native] → [SDK JNI: android_os_PerformanceHintManager.cpp]
  → [Binder: IPerformanceHintManager] → [system_server: HintManagerService]
  → [service JNI: com_android_server_hint_HintManagerService.cpp]
  → [Power HAL AIDL session] → [scheduler / performance policy]
```

system_server 中由 `HintManagerService`（位于 `com.android.server.power.hint` 包）接收请求，内部维护 session 表，通过 `IPowerHintSession` AIDL 与 Power HAL 对接。

[验证基准: AOSP android-17.0.0_r1, frameworks/base/services/core/java/com/android/server/power/hint/HintManagerService.java]

> **路径确认**：`android-12.0.0_r1` 到 `android-17.0.0_r1` 所有 tag 中，HintManagerService 均位于 `com.android.server.power.hint` 包，JNI 对应 `com_android_server_hint_HintManagerService.cpp`。该路径并非 Android 17 新增迁移。

### 4. 实战集成与案例

#### 4.1 UI 渲染线程标准模式

```java
// [验证基准: AOSP android-17.0.0_r1, PerformanceHintManager.java]
// 在工作线程内部用 Process.myTid() 获取内核 tid（Java Thread.getId() 不是 tid）
int[] renderTids = new int[]{ renderWorker.tid };  // renderWorker.run() 内记录 Process.myTid()
PerformanceHintManager.Session session = phm.createHintSession(
    renderTids, /*initialTargetDurationNanos*/ 16_666_667L);  // ~60fps, ~16.67ms

// 每帧 Choreographer.FrameCallback 中回报实际耗时
public void doFrame(long frameTimeNanos) {
    long actualDuration = SystemClock.uptimeNanos() - frameStartUptimeNanos;
    session.reportActualWorkDuration(actualDuration);
    Choreographer.getInstance().postFrameCallback(this);
}
```

#### 4.2 ML 推理场景

```java
// 在 NNAPI delegate / GPU delegate worker pool 上建 session
// 自定义线程池需在各 worker 启动时记录 Process.myTid()，汇总成 tid 数组
int[] tids = inferenceThreadPool.getAllTids();  // 非标准 API，需自行维护
PerformanceHintManager.Session inferenceSession = phm.createHintSession(
    tids, /*targetPerInferenceNs*/ 100_000_000L);
```

#### 4.3 启动期 worker pool 优化

`Application.onCreate` 内不推荐同步创建 hint session；更稳妥的做法是为生命周期明确、能准确回报周期耗时的 lazy worker pool 建短期 session，并在 `onTrimMemory(LEVEL_BACKGROUND)` 或任务结束时释放。

#### 4.4 Java/NDK 同进程桥接

Android 17 的 `performance_hint.h` 暴露 `APerformanceHint_borrowSessionFromJava(JNIEnv*, jobject)`（API 36），用于 JNI 代码临时借用 Java `PerformanceHintManager.Session` 背后的 native session 指针。该 API 的语义是同进程 Java/NDK 桥接，不是跨进程 session 共享；本轮未在 Android 17 公开 API 中发现跨进程共享 hint session 的入口。

[验证基准: AOSP android-17.0.0_r1, frameworks/native/include/android/performance_hint.h]

### 5. Android 17 中的可核验变化

本节仅列出已通过 AOSP `android-17.0.0_r1` 源码复核确认的现状。

#### 5.1 服务端路径

`android-17.0.0_r1` tag 中 PerformanceHintManager 的服务端实现位于：

- 服务实现：`frameworks/base/services/core/java/com/android/server/power/hint/HintManagerService.java`
- 服务 JNI：`frameworks/base/services/core/jni/com_android_server_hint_HintManagerService.cpp`

该路径在 `android-12.0.0_r1` 到 `android-17.0.0_r1` 的所有 AOSP tag 中均一致存在，并非 Android 17 引入的新变化。

[验证基准: AOSP android-17.0.0_r1 及 android-12.0.0_r1]

#### 5.2 Power HAL AIDL 协同

`HintManagerService` 通过 `IPowerHintSession` AIDL 接口与 Power HAL 交互。应用层调用 `reportActualWorkDuration` 后，实际负载数据经以下路径传递给调度器：

```
App → PerformanceHintManager.Session.reportActualWorkDuration()
  → IPerformanceHintManager binder
  → HintManagerService
  → IPowerHintSession AIDL
  → Power HAL
  → scheduler / performance policy (hint 作为 advisory 输入)
```

`setPreferPowerEfficiency(true)` 调用后，HintManagerService 将功耗优先标记传递给 Power HAL，Power HAL 据此调整频率选择策略。注意：hint 是 advisory（建议）语义，Power HAL 拥有最终决策权。

[验证基准: AOSP android-17.0.0_r1, HintManagerService.java]

#### 5.3 与 1.43（ML 任务调度器）的关系

TaskScheduler（1.43）是系统侧调度决策，PerformanceHintManager 提供应用侧负载信号——两者的协同边界是：应用通过 hint session 报告"本组线程现在有多忙"，TaskScheduler / Power HAL 根据汇总的 hint 信号、温升、功耗预算决定最终的 CPU 频率分配。hint 是建议而非指令。

### 6. 度量与可观测性

#### 6.1 dumpsys

```bash
adb shell dumpsys performance_hint
```

`dumpsys` 输出由 `HintManagerService.dump()` 驱动，包含：
- `HintSessionPreferredRate` 与 Hint Session Support
- 按 UID 分组的活跃 session 列表：PID、UID、TIDs、Tag、TargetDurationNanos、AllowedByProcState、ForcePaused
- `PowerEfficient`、`GraphicsPipeline` 等 session 标记

具体输出字段以设备上 `dumpsys performance_hint` 的实际格式为准。

[验证基准: AOSP android-17.0.0_r1, HintManagerService.java dump() 方法]

#### 6.2 Perfetto 间接观测

PerformanceHintManager 不提供专用的 Perfetto 数据源（tracepoint），但可通过以下方式间接评估 hint 效果：

- `sched` / `freq` trace：对比 hint session 生命周期内的 CPU 调度与调频行为，验证 hint 是否对调度器产生了期望影响
- 抓取 hint session 全生命周期分析时，建议同时开启 `power` + `sched` + `ftrace` 数据源，关注 session 创建/关闭时间段内的 CPU 频率变化

[验证基准: android-17.0.0_r1 未发现 Perfetto 中独立的 "performance_hint" 专用数据源或 atrace 事件]

#### 6.3 Statsd atom

Android 通过 statsd 上报以下与 hint session 相关的 atom：

- `FrameworkStatsLog.PERFORMANCE_HINT_SESSION_REPORTED`：由 `HintManagerService.logPerformanceHintSessionAtom()` 写入，字段包含 uid、sessionId、targetDuration、tidCount、sessionTag、powerEfficiency、graphicsPipeline、audioPerformance 标记
- `FrameworkStatsLog.ADPF_SESSION_SNAPSHOT`：pulled atom，记录 max_concurrent_session、max_tid_count、num_power_efficient_session、target_duration_ns 等聚合快照

[验证基准: AOSP android-17.0.0_r1, HintManagerService.java + frameworks/proto_logging/stats/atoms.proto + stats/atoms/adpf/adpf_extension_atoms.proto]

### 7. 反模式与陷阱

#### 7.1 session 抖动

```java
// 反例：每次网络回调都 create + close → system_server IPC 风暴
PerformanceHintManager.Session s = phm.createHintSession(...);
doWork();
s.close();  // ❌
// 正解：复用 + 长期持有
PerformanceHintManager.Session s = SessionCache.getOrCreate(...);  // ✅
```

#### 7.2 报告偏差

`actualDuration` 长期偏离真实工作周期会让 target/actual 反馈失真，难以判断 hint 是否真的改善了 core placement 或频率选择。应按每个周期的实际耗时回报；是否产生可见收益仍要以设备侧 trace 与 benchmark 为准。

#### 7.3 同步创建阻塞

在 `Activity.onCreate` 同步调用 `createHintSession` 会触发 binder 跨进程调用。推荐用 `Handler.post` 或 `executeOnExecutor` 异步化，避免阻塞主线程。

#### 7.4 setPreferPowerEfficiency 的退化行为

在高温或系统功耗受限场景下，即使应用调用了 `setPreferPowerEfficiency(true)`，Power HAL 仍可能按全局策略处理该标记。应用不应将 powerEfficiency 提示作为性能保证，而应配合 `PowerManager#addThermalStatusListener` 感知系统热状态。

### 8. 与现有调度机制的对比

| 维度 | PerformanceHintManager | JobScheduler | TaskScheduler (8.33) |
|------|------------------------|--------------|----------------------|
| 时机维度 | 同进程"本周期" | 跨进程"何时跑" | 系统级"何时跑" |
| 决策方向 | App → Sys (advisory) | App → Sys | Sys → App |
| 频率粒度 | 帧级 (ms) | 分钟级 | 分钟级 |
| 能耗可见 | ✅ | ❌ | ✅ |
| 温升联动 | 受系统热/功耗策略约束 | 受系统调度约束 | 受系统调度约束 |

## 🔹 禁止直接沿用的原稿结论

以下原稿说法在本轮均未通过 `android-17.0.0_r1` 证据复核，重写前不得作为确定性结论：

1. **平台级 ML Task Scheduler**：尚未验证 Android 17 主线存在独立的 ML 任务调度器框架或 `frameworks/base/services/scheduler/` 实现。
2. **深度学习模型结构**：LSTM/CNN/GNN、128 维输入、7 级优先级等参数没有源码锚点。
3. **延迟启动策略**：后台应用延迟 5–15 秒、夜间自动延迟、用户专注状态识别等说法未验证。
4. **固定资源比例**：前台应用 80% CPU、后台 5–20%、系统服务预留 15% CPU 等说法不应脱离 cgroup、uclamp、schedtune/TaskProfiles 或厂商策略直接断言。
5. **量化收益**：启动时间减少 40–50%、续航提升 15–20%、温度降低 5–8°C 等数值缺少可复核 benchmark 来源。
6. **开发者可配置参数/AIDL 动态调参**：原稿未提供 Android SDK/API 或系统服务接口证据。

## 🔹 可接受的重写口径

如果后续继续保留“任务调度器优化”主题，建议把章节改写为源码可证的多层调度边界，而不是单一“ML 调度器”叙事：

- **应用层任务**：JobScheduler、WorkManager、Foreground Service 类型和后台启动限制。
- **系统服务层**：ActivityManager/ProcessList/OomAdjuster 对进程状态、优先级和后台执行的影响。
- **电源与热管理层**：PowerManager、DeviceIdleController、ThermalManager 与厂商 Power HAL 的约束关系。
- **内核层**：CFS/EEVDF、uclamp、cpuset、cgroup v2、schedutil 和 Android common kernel 的版本边界。
- **观测层**：Perfetto `sched/sched_wakeup/sched_switch`、atrace、statsd、JobScheduler dump 与启动耗时指标。

每个小节应至少包含一个可复核锚点：AOSP 文件路径、类名/方法名、官方文档链接、或明确的 trace/dumpsys 命令输出解释。

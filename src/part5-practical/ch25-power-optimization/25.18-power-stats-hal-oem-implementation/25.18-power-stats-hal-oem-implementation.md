# 25.18 Android 17 Power Stats HAL OEM厂商功耗统计实现差异

## 要点

### 🔹 PowerStats HAL标准架构
Android 17通过PowerStats HAL标准化功耗数据采集：
- AIDL接口标准化，统一数据访问方式
- 三层抽象设计：PowerEntity/EnergyConsumer/Channel
- 9种预定义EnergyConsumerType，覆盖主要硬件组件
- 默认fake实现，需要厂商具体化适配

### 🔹 Google Pixel专用实现
Pixel设备PowerStats HAL实现特点：
- 具象化硬件适配，提供真实功耗数据
- 精确到组件级别的功耗监控
- 与Google PowerMonitor深度集成
- 系统级功耗分析能力

### 🔹 厂商扩展点体系
OEM厂商需要覆盖的核心扩展点：
1. addStateResidencyDataProvider：添加状态 residency 数据提供者
2. addEnergyConsumer：添加自定义能耗消费者
3. setEnergyMeter：设置能量计测量器
4. BatteryTrigger + TimerTrigger双驱动机制
5. 20s/250ms双老化策略，确保数据准确性

### 🔹 三级数据采集架构
Framework层数据采集架构：
- 标准接口层：PowerStats HAL统一接口
- 厂商适配层：硬件特性适配实现
- 框架调度层：BatteryTrigger + TimerTrigger协同

## 🔹 源码级实现细节（AIW源码调研补充）

### Android 17 AIDL V2接口实现

Android 17的PowerStats HAL已从Android 11的HIDL V1演进到AIDL V2，核心接口位于`hardware/interfaces/power/stats/aidl/android/hardware/power/stats/IPowerStats.aidl`，包含5个核心RPC：

```aidl
PowerEntity[]              getPowerEntityInfo();
StateResidencyResult[]     getStateResidency(in int[] powerEntityIds);
EnergyConsumer[]           getEnergyConsumerInfo();
EnergyConsumerResult[]     getEnergyConsumed(in int[] energyConsumerIds);
Channel[]                  getEnergyMeterInfo();
EnergyMeasurement[]        readEnergyMeter(in int[] channelIds);
```

### OEM厂商差异根源

**AOSP默认实现局限性**：`hardware/interfaces/power/stats/aidl/default/`下的默认实现仅提供3个fake rail（Rail1/Display, Rail2/CPU, Rail3/Modem）、2个fake state provider（CPU, Display）、2个fake energy consumer（GPU→OTHER, MODEM），**任何真实设备必须重写整组数据源**。

**厂商实现差异点**：
1. **数据源质量**：Pixel直接读取PMIC INA231 rail能量，高通/MTK部分基于CPU利用率模型估算
2. **粒度精度**：Pixel支持10+ EnergyConsumer（CPU cluster×N, GPU, DISPLAY, MODEM, WIFI, GNSS, BT），多数OEM仅4-6个
3. **触发策略**：Pixel保持1%电量下降触发，部分OEM改为5%下降以减少IO开销
4. **时间戳精度**：Pixel达到ns级，多数OEM为ms级，±50ms抖动
5. **Attribution实现**：Pixel实现per-UID精确分摊，多数OEM仅PID级聚合

### BatteryTrigger + TimerTrigger双机制

Framework服务`com.android.server.powerstats.PowerStatsService`采用双触发策略：

**BatteryTrigger**（电量事件驱动）：
```java
private final BroadcastReceiver mBatteryLevelReceiver = new BroadcastReceiver() {
    @Override
    public void onReceive(Context context, Intent intent) {
        switch (intent.getAction()) {
            case Intent.ACTION_BATTERY_CHANGED:
                int newBatteryLevel = intent.getIntExtra(BatteryManager.EXTRA_LEVEL, 0);
                if (newBatteryLevel < mBatteryLevel) {
                    logPowerStatsData(PowerStatsLogger.MSG_LOG_TO_DATA_STORAGE_BATTERY_DROP);
                }
                mBatteryLevel = newBatteryLevel;
                break;
        }
    }
};
```

**TimerTrigger**（周期驱动）：分为高频（1-5s，读meter+model无attribution）和低频（30s-5min，读model带attribution）。

### 数据存储与版本兼容

**存储路径**：`/data/system/powerstats/`下三份protobuf文件：
- `log.powerstats.meter.0`：rail能量数据
- `log.powerstats.model.0`：能耗模型数据（含attribution）
- `log.powerstats.residency.0`：状态驻留数据

**版本控制**：`DATA_STORAGE_VERSION = 0`表示从Android 11至今未升级schema，**vendor字段不得破坏此兼容性**。

### 权限控制与API暴露

**权限分级**：
- `ACCESS_FINE_POWER_MONITORS`权限控制fine-grained API（250ms老化阈值）
- 普通应用仅可访问legacy API（20s老化阈值）

**命令行接口**：
```bash
adb shell dumpsys powerstats  # 输出三类对象列表与统计信息
adb shell dumpsys powerstats --proto {model|meter|residency}  # 导出protobuf数据
```

**关键结论**：OEM厂商差异主要源于HAL层实现质量、数据源精度、触发策略和attribution粒度四个维度。Pixel拥有最高精度但实现最复杂，多数OEM在精度与实现成本间取平衡。

# Android 17 Display Mode 选择与 RefreshRateSelector 评分机制

## TL;DR

Android 17 (`android-17.0.0_r1`) 把"Display Mode 切换"从 `DisplayDevice` 抽到独立类 **`DisplayModeController`**，按 4 种 `DesiredModeAction` 状态机分发。`SurfaceFlinger::setDesiredMode` 是入口，由 `RefreshRateSelector` 通过「Layer 投票 + Global Signals + Policy」三源评分后选最佳 `FrameRateMode`，再走 `Composer::setActiveModeWithConstraints / setDisplayMode` 落地。`FrameRateOverrideMappings` 承载 backdoor 与 Content 两路 UID-level override。Kernel idle timer 走 HwcApi 或 Sysprop 双路径，由 `RefreshRateSelector::getIdleTimerAction()` 决策。

## 2. DisplayModeController 4 态状态机

`Display/DisplayModeController.cpp` L82-145 的 `setDesiredMode`：

```cpp
auto DisplayModeController::setDesiredMode(PhysicalDisplayId displayId,
                                           DisplayModeRequest&& desiredMode)
        -> DesiredModeAction {
    std::lock_guard lock(mDisplayLock);
    ...
    if (auto& desiredModeOpt = displayPtr->desiredModeOpt) {
        if (!FlagManager::getInstance().modeset_state_machine() ||
            desiredMode.mode.matchesResolution(desiredModeOpt->mode)) {
            desiredModeOpt = std::move(desiredMode);
            desiredModeOpt->emitEvent |= emitEvent;
            desiredModeOpt->force |= force;
            return DesiredModeAction::MergeDisplayModeSwitch;
        }
    }
    const auto activeMode = displayPtr->selectorPtr->getActiveMode();
    if (const auto& desiredModePtr = desiredMode.mode.modePtr;
        !desiredMode.force && activeMode.modePtr->getId() == desiredModePtr->getId()) {
        if (!FlagManager::getInstance().modeset_state_machine() ||
            (!displayPtr->pendingModeOpt && desiredMode.mode.matchesResolution(activeMode))) {
            if (activeMode == desiredMode.mode) {
                return DesiredModeAction::None;
            }
            setActiveModeLocked(displayId, desiredModePtr->getId(),
                                desiredModePtr->getVsyncRate(), desiredMode.mode.fps);
            return DesiredModeAction::InitiateRenderRateSwitch;
        }
    }
    setActiveModeLocked(displayId, activeMode.modePtr->getId(),
                        activeMode.modePtr->getVsyncRate(), activeMode.modePtr->getPeakFps());
    displayPtr->desiredModeOpt = std::move(desiredMode);
    displayPtr->hasDesiredModeTrace = true;
    return DesiredModeAction::InitiateDisplayModeSwitch;
}
```

`DesiredModeAction`（`DisplayModeController.h` L73-78）枚举 4 态：

| 状态 | 语义 | `SurfaceFlinger::setDesiredMode` 处理 |
|---|---|---|
| `None` | No-op（active mode == desired mode 且 render rate 未变） | 跳过 |
| `InitiateRenderRateSwitch` | 仅刷新渲染率 | `Scheduler::setRenderRate` + `updatePhaseConfiguration` |
| `MergeDisplayModeSwitch` | 已有 pending mode，合并新请求 | 重调 `resyncToMode(PeakRenderRate)`（仅 `modeset_state_machine` 开时） |
| `InitiateDisplayModeSwitch` | 真切换 mode（含分辨率改变） | `scheduleComposite + resyncToMode + modulateVsync + setModeChangePending` |

`FlagManager::modeset_state_machine()` 是 17 的总开关：开 = `desiredModeOpt` 与 `pendingModeOpt` 双槽并行存在；关 = 单槽（`isModeSetPending` bool 表达）。

## 4. finalizeModeChange 与三类型分发

`DisplayModeController.cpp` L344-372：

```cpp
auto DisplayModeController::finalizeModeChange(PhysicalDisplayId displayId) -> ModeChange {
    std::lock_guard lock(mDisplayLock);
    ...
    auto pendingMode = *std::exchange(displayPtr->pendingModeOpt, std::nullopt);
    ...
    const bool resolutionMatch =
            displayPtr->selectorPtr->getActiveMode().matchesResolution(pendingMode.mode);
    setActiveModeLocked(displayId, pendingModePtr->getId(), pendingModePtr->getVsyncRate(),
                        pendingMode.mode.fps);
    if (resolutionMatch) {
        return RefreshRateChange{std::move(pendingMode)};
    } else {
        return ResolutionChange{std::move(pendingMode)};
    }
}
```

`ModeChange` = `std::variant<RefreshRateChange, ResolutionChange, NoModeChange>`，`SurfaceFlinger.cpp` L1560-1580 用 `std::visit` 分派：
- `RefreshRateChange` → `Scheduler::onDisplayModeChanged(...)`
- `ResolutionChange` → 由 DisplayManager 链路发起 display size 调整 transaction
- `NoModeChange` → 含 `Unknown display / No pending mode / Unknown pending mode`

## 5. RefreshRateSelector 三源评分

### 5.1 应用投票入口（Layer / FrameRateCompatibility）

`Scheduler/FrameRateCompatibility.h` L24-37 枚举：

```cpp
enum class FrameRateCompatibility {
    Default,         // Layer didn't specify any specific handling strategy
    Min,             // Layer needs the minimum frame rate
    Exact,           // Layer needs the exact frame rate
    ExactOrMultiple, // Layer needs the exact frame rate (or a multiple of it)
    Gte,             // Layer needs greater than or equal to the frame rate
    NoVote,          // Layer doesn't have any requirements for the refresh rate
    ftl_last = NoVote
};
```

每个 layer 通过这个枚举声明期望；同 UID 多 layer 由 `groupLayersByUid()` 汇总到 `VoteBucket`。

### 5.2 Global Signals 早返回

`RefreshRateSelector.cpp` L648-680：

- **`pacesetterFps`**（follower display）：外接显示器让 display 跟随主屏，在 `follower_arbitrary_refresh_rate_selection_combined` 关时**不参评**，硬对齐 pacesetter 的 `peakFps`。
- **`powerOnImminent`**：`rankFrameRates(... Descending)` 直接取最高，DPU 立即恢复满帧显示。

### 5.3 Layer-level Scoring 公式

每个候选 `FrameRateMode` 对当前 layer 算分：

```cpp
const float ratio = static_cast<float>(mode.getPeakFps().getValue()) /
                    static_cast<float>(desiredFps.getValue());
return 1.0f - std::pow(ratio, 2.f);   // 越接近 1.0 分越高
```

浮点数曲线：`ratio=1` → 1.0；`ratio=2` → -3.0（clamp 到 0）；`ratio=0.5` → 0.75。多个 layer 的分数**线性加权**累加进 `overallScore`。

### 5.4 Touch Boost 阻断条件

`RefreshRateSelector.cpp` L997-1010：

```cpp
const bool isLateGlobalTouchBoost = signals.touch && explicitDefaultVoteLayers == 0;
const bool isLateTouchBoost = isLateGlobalTouchBoost || isAppTouchBoost;
if (isLateTouchBoost && isTouchBoostForExplicitExact() && isTouchBoostForCategory()) {

    if (scores.front().frameRateMode.fps <= touchRefreshRates.front().frameRateMode.fps) {
        SFTRACE_FORMAT_INSTANT("%s (Touch Boost [late])", ...);
        return {touchRefreshRates, GlobalSignals{.touch = true}};

```

`isAppTouchBoost` 由 UI Toolkit 投 `FrameRateCategory::HighHint` 触发，但**与 `ExplicitDefault`（游戏手设）互斥**——游戏进入 `setFrameRate(Default, 30)` 不会因 touch event 被强行拉到 120Hz。

## 6. ARR vs VRR 的帧率候选生成

`RefreshRateSelector.cpp` L1608-1688 + `RefreshRateSelector.h` L593：

```cpp
// RefreshRateSelector.h:593-602
static constexpr size_t kNumFrameRates = 15;
const std::vector<Fps> kFpsAnchorList = {1_Hz, 2_Hz, 5_Hz,  10_Hz, 15_Hz,
                                         20_Hz, 24_Hz, 30_Hz, 48_Hz, 60_Hz};
```

`constructAvailableRefreshRates` 将 anchor list 交给 `getModeDivisorsFromAnchorList`（L99-200 的 gap-fill priority queue），按 largest-gap 折半填到 `kNumFrameRates=15` 个候选 fps。VRR 路径（`mIsVrrDisplay=true`）从 `mAppRequestFrameRates` 取整；非 VRR 按 divisor 枚举。

HDR 过滤门（`enable_user_preferred_hdr_mode`）：要求候 mode 与 defaultMode 的 `getHdrOutputType()` 一致，避免跨 HDR 模式切换。

## 7. FrameRateOverrideMappings — UID 级 override

`Scheduler/FrameRateOverrideMappings.cpp` L25-43：

```cpp
std::optional<Fps> FrameRateOverrideMappings::getFrameRateOverrideForUid(
        uid_t uid, bool supportsFrameRateOverrideByContent) const {
    std::lock_guard lock(mFrameRateOverridesLock);
    {
        const auto iter = mFrameRateOverridesFromBackdoor.find(uid);
        if (iter != mFrameRateOverridesFromBackdoor.end()) {
            return iter->second;        // backdoor 优先
        }
    }
    if (!supportsFrameRateOverrideByContent) return std::nullopt;
    {
        const auto iter = mFrameRateOverridesByContent.find(uid);
        if (iter != mFrameRateOverridesByContent.end()) return iter->second;
    }
    return std::nullopt;
}
```

两类 override：
- `mFrameRateOverridesFromBackdoor`（backdoor，UI Toolkit 内部）：`SurfaceFlinger.cpp:7798` `setPreferredRefreshRateForUid(FrameRateOverride{uid, refreshRate})` 写入，`Surface.setFrameRate(0.f)` 删除。
- `mFrameRateOverridesByContent`（公共 API）：`updateFrameRateOverridesByContent` 整表覆盖；`SurfaceFlinger.cpp:9243` `setGameModeFrameRateOverride(uid, frameRate)` + `:9248` `setGameDefaultFrameRateOverride(uid, frameRate)` 写入。

合并顺序：backdoor 永远覆盖 content；写入删除语义：`frameRateHz==0.0f` → 移除。

## 8. Kernel Idle Timer 双路径

`DisplayModeController.cpp` L434-447：

```cpp
void DisplayModeController::updateKernelIdleTimer(PhysicalDisplayId displayId,
                                                  std::chrono::milliseconds timeout,
                                                  KernelIdleTimerController controller) {
    switch (controller) {
        case KernelIdleTimerController::HwcApi:
            mComposerPtr->setIdleTimerEnabled(displayId, timeout);
            break;
        case KernelIdleTimerController::Sysprop:
            base::SetProperty("graphics.display.kernel_idle_timer.enabled",
                              timeout > std::chrono::milliseconds::zero() ? "true" : "false");
            break;
    }
}
```

决策（`RefreshRateSelector.cpp` L1731-1755 的 `getIdleTimerAction`）：
- `deviceMinFps < policy.min` → `TurnOff`（kernel idle timer 会把帧率降到 deviceMin，低于 policy.min 不允许）。
- `deviceMin == maxByPolicy && policy.physical.min < deviceMin` → `TurnOn`（剩余时间片喂入 idle timer，渲染可降频）。
- 否则 → `TurnOn`（统一打开）。

## 10. 工程实践 / 调优清单

1. **游戏**：用 `Surface.setFrameRate(GameMode, 60.0f, FRAME_RATE_COMPATIBILITY_DEFAULT)` 阻断 touch boost。
2. **视频播放**：`setFrameRate(Exact, 24.0f)` 让 `RefreshRateSelector` 切到 24Hz 整数倍模式（如 24/48/72/120Hz）。
3. **Always-on-Display**：`setPowerOnImminent(true)` 让 display 在 power 恢复时锁 peak 帧率。
4. **高刷开关调测**：`debug.sf.frame_rate.override` sysprop 注入（vendor-specific）可临时跳过 RefreshRateSelector。

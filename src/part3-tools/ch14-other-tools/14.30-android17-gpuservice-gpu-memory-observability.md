# 14.30 GpuService GPU 内存可观测性架构

<!-- outline-start -->
## 要点

### 🔹 GpuService 系统服务定位与启动架构
- GpuService 在 ServiceManager 中的注册路径
- 异步初始化模型（`mGpuMemAsyncInitThread`）
- 与 SurfaceFlinger / WindowManagerService 的职责边界

### 🔹 GpuMem：基于 eBPF 的 GPU 内存追踪核心
- BPF 程序挂载机制：`gpu_mem/gpu_mem_total` tracepoint
- pinned BPF map 路径与 key 编码（`uint64_t` = (gpu_id << 32 | pid)）
- `BpfMapRO` 只读访问模型与安全语义
- 30 秒 attach 重试机制（`kGpuWaitTimeout`）
- `traverseGpuMemTotals()` 遍历接口与 dumpsys 集成
- [待验证] Android 12-16 各版本 GpuMem 能力差异

### 🔹 GpuMemTracer：Perfetto 数据源桥接层
- Perfetto 自定义数据源注册（`android.gpu_mem`）
- `traceInitialCounters()` 全量快照机制
- 独立线程模型（`GpuMemTracerThread`）与条件变量唤醒
- `gpu_mem_total_event` protobuf 结构
- Perfetto trace 中 GPU 内存 counter track 的呈现方式
- [待验证] Perfetto UI 中 GpuMem counter 的可视化路径

### 🔹 GpuStats：statsd 归因与驱动加载统计
- `statsd_pull_atom` 接口与 `GPU_STATS_GLOBAL_INFO` / `GPU_STATS_APP_INFO` 双 atom
- GL/Vulkan/ANGLE 驱动加载次数 / 加载时间 / 失败次数统计
- `GpuStatsNative` 模块的 JNI 桥接路径
- 与 `dumpsys gpustats` 命令的对应关系
- [待验证] Android 17 新增 ANGLE 相关统计字段

### 🔹 三层架构的协作模型
- 数据流：GPU 驱动 → tracepoint → BPF map → GpuMem → (GpuMemTracer → Perfetto) / (dumpsys) / (GpuStats → statsd → dropbox)
- 三个观测面的互补关系：实时 trace / 即时查询 / 长期统计
- 与 memtrack HAL (`IMemtrack.aidl`) 的对比与互补
- 与 §14.25 eBPF 可观测性矩阵的关系

### 🔹 dumpsys gpuservice 实战查询路径
- `dumpsys gpuservice` 输出格式解读
- GPU 内存占用按 (gpu_id, pid) 维度的查询
- 与 `dumpsys gfxinfo` / `dumpsys SurfaceFlinger` 的差异
- [待验证] 厂商定制对 dumpsys 输出的影响

### 🔹 Perfetto trace 中的 GPU 内存数据消费
- SQL 查询：从 `gpu_counter` / `gpu_mem_total_event` track 提取进程级 GPU 内存趋势
- 与 `process_memory_counters` track 的对比分析（系统内存 vs GPU 内存）
- GPU 内存泄漏的 Perfetto 识别方法

## 源码调研补充（2026-07-12）

<!-- AIW-源码调研-2026-07-12 -->

> 来源：`android-17.0.0_r1` tag（一手 AOSP 源码）
> 调研文件：`DeepResearch/2026-07-12-android17-gpuservice-gpu-memory-observability.md`

### A. GpuMem BPF 关键常量（`gpumem/include/gpumem/GpuMem.h`）

```cpp
static constexpr char kGpuMemTraceGroup[]      = "gpu_mem";
static constexpr char kGpuMemTotalTracepoint[] = "gpu_mem_total";
static constexpr char kGpuMemTotalProgPath[]   =
    "/sys/fs/bpf/prog_gpuMem_tracepoint_gpu_mem_gpu_mem_total";
static constexpr char kGpuMemTotalMapPath[]    =
    "/sys/fs/bpf/map_gpuMem_gpu_mem_total_map";
static constexpr int  kGpuWaitTimeout          = 30;  // seconds
```

- tracepoint 命名空间：`gpu_mem`
- pinned BPF prog / map 在 `/sys/fs/bpf/` 下，与 bpfloader 加载路径对齐
- **30 秒 attach 重试窗口**覆盖 GPU 驱动晚于 system_server 启动的窗口

### B. GpuMem Key 编码（`gpumem/GpuMem.cpp::dump()`）

```cpp
uint32_t gpu_id = key >> 32;  // 高 32 位
uint32_t pid    = key;        // 低 32 位
uint64_t size   = res.value();
```

`uint64_t key = (gpu_id << 32) | pid`，避免 BPF map 结构体 key 的 padding 问题。

### C. GpuMemTracer 线程模型（`tracing/GpuMemTracer.cpp`）

```cpp
std::thread tracerThread(&GpuMemTracer::threadLoop, this, true);
pthread_setname_np(tracerThread.native_handle(), "GpuMemTracerThread");
tracerThread.detach();
```

- **静态 `sTraceMutex` / `sCondition` / `sTraceStarted`**：所有 GpuService 实例共享一个等待队列
- 每次 Perfetto session 触发**一次性** `traceInitialCounters()`，**不持续 poll BPF map**
- `detach()` 而非 join：避免 GpuService 析构阻塞

Perfetto 数据源名：`android.gpu_mem`，后端用 `perfetto::kSystemBackend`。

### D. GpuStats 容量上限（`gpustats/include/gpustats/GpuStats.h`）

```cpp
static const size_t MAX_NUM_LOADING_TIMES = 16;
static const size_t MAX_NUM_APP_RECORDS   = 100;
static const size_t APP_RECORD_HEADROOM   = 10;
```

注释明确：这套配比让 GpuStats 内存占用 **< 10KB**，匹配 statsd 偏好。`purgeOldDriverStats()` 按 `lastAccessTime` LRU 淘汰最旧 10 个。

### E. GpuStats ANGLE 独立分支（`gpustats/GpuStats.cpp`）

`Driver` 枚举：`GL | GL_UPDATED | VULKAN | VULKAN_UPDATED | ANGLE`，ANGLE 单独计数：

```cpp
case GpuStatsInfo::Driver::ANGLE:
    outGlobalInfo->angleLoadingCount++;
    if (!isDriverLoaded) outGlobalInfo->angleLoadingFailureCount++;
    break;
```

ANGLE 识别双重判断（兼容两种注入路径）：
```cpp
appInfo.angleInUse =
    driver == GpuStatsInfo::Driver::ANGLE || driverPackageName == "angle";
```

### F. GpuService 异步初始化编排（`GpuService.cpp`）

```cpp
GpuService::GpuService()
    : mGpuMem(std::make_shared<GpuMem>()),
      mGpuWork(std::make_shared<gpuwork::GpuWork>()),
      mGpuStats(std::make_unique<GpuStats>()),
      mGpuMemTracer(std::make_unique<GpuMemTracer>()),
      mFeatureOverrideParser(kConfigFilePath) {  // /system/etc/angle/feature_config_vk.binarypb

    mGpuMemAsyncInitThread = std::make_unique<std::thread>([this] {
        mGpuMem->initialize();                  // 阻塞等 BPF + 30s 重试
        mGpuMemTracer->initialize(mGpuMem);     // 依赖 mGpuMem isInitialized
    });
    mGpuWorkAsyncInitThread = std::make_unique<std::thread>([this] {
        mGpuWork->initialize();
    });
}
```

**依赖图**：GpuMem → GpuMemTracer **串行**（同线程）；GpuWork **并行独立**。

### G. ANGLE 切换权限模型

`toggleAngleAsSystemDriver(enabled)` 仅 `AID_SYSTEM` + `android.permission.ACCESS_GPU_SERVICE` 可调用，通过 `SetProperty("persist.graphics.egl", "angle")` 持久化。配套 `/system/etc/angle/feature_config_vk.binarypb` 用 `mFeatureOverrideParser` 加载。

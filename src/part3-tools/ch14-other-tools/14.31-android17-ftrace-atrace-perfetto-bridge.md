# 14.31 FTrace：内核 tracefs + atrace 桥 + Perfetto probe

<!-- outline-start -->
## 要点

### 🔹 Linux 内核 tracefs 基础（`/sys/kernel/tracing`）
- 28 个核心 tracepoint group（sched/irq/cgroup/task/...）
- ring buffer 控制：tracing_on、buffer_percent、tracing_max_latency
- 用户态入口：trace_marker 文件 + trace_pipe 流式读
- Linux 6.9+ per-CPU buffer_percent poll 模式（Perfetto drain_buffer_percent 依赖）

### 🔹 atrace 用户态包装（`frameworks/native/cmds/atrace/atrace.cpp`）
- 28 个高阶 category → tracepoint 集合映射表（k_categories[]）
- debug.atrace.tags.enableflags bitmask 属性协议
- tracefs 路径发现（Linux 4.1+ 优先 tracefs，回退 debugfs）
- vendor categories 文件：`/vendor/etc/atrace/atrace_categories.txt`
- HIDL → AIDL 迁移（android.hardware.atrace）

### 🔹 Perfetto ftrace probe（external/perfetto v57.1）
- FtraceConfigMuxer：多 session union/merge（ftrace 是内核单例）
- compact_sched：默认开启的高密度 sched_switch 编码（v42+）
- atrace_hal_wrapper：通过 dlopen 调用 IAtraceDevice AIDL 服务
- buffer_size_lower_bound（v43）/ drain_buffer_percent（v48）新选项
- atrace_userspace_only（v52）：纯用户态模式
- 动态 kprobe：通过 KprobeEvent proto 配置（v57）

### 🔹 三层协作模型
- 用户空间 ATRACE_BEGIN 宏 → trace_marker write → tracefs ring buffer → traced ftrace probe 读取 → Perfetto trace 序列化
- 多 session 隔离：FtraceConfigMuxer 合并 + compact_sched 高密度编码
- 厂商扩展：HAL 接口（IAtraceDevice AIDL）+ vendor tracepoints 文件

<!-- outline-end -->

## 核心架构

FTrace 在 Android 17 上是三层叠加架构：

```
┌─────────────────────────────────────────────────────────────┐
│ 应用层：ATRACE_BEGIN("frame") / track_event SDK              │
└─────────────────────────────────────────────────────────────┘
                            ↓ trace_marker write
┌─────────────────────────────────────────────────────────────┐
│ Kernel tracefs (Linux 6.18 GKI):                            │
│  /sys/kernel/tracing/                                        │
│  ├── trace_marker (用户态注入入口)                            │
│  ├── trace_pipe (流式读取)                                   │
│  ├── events/{group}/{name}/enable (按 group/event 启用)      │
│  ├── per_cpu/cpu*/trace_pipe_raw (per-CPU ring buffer)       │
│  ├── tracing_on, buffer_percent (Linux 6.9+)                 │
│  └── available_tracers (function/irqsoff/preemptoff/...)     │
└─────────────────────────────────────────────────────────────┘
                            ↑ 用户态读取
┌─────────────────────────────────────────────────────────────┐
│ Perfetto traced: ftrace probe (v57.1)                        │
│  ├── ftrace_controller.cc: 主循环 + GKI 版本解析              │
│  ├── ftrace_config_muxer.cc: 多 session union                │
│  ├── compact_sched.cc: sched_switch 高密度编码 (v42+ 默认)   │
│  ├── atrace_hal_wrapper.cc: AIDL HAL 动态加载               │
│  ├── cpu_reader.cc: ring buffer drain (Linux 6.9+ poll)     │
│  └── tracefs.cc: tracepoints 枚举 + 触发器定义               │
└─────────────────────────────────────────────────────────────┘
                            ↑ Proto 序列化
┌─────────────────────────────────────────────────────────────┐
│ Perfetto UI / systrace-html 兼容输出                         │
└─────────────────────────────────────────────────────────────┘
```

历史兼容路径：Android 14- 仍可使用 `atrace` + `systrace.py` 两条独立链路；Android 15+ 推荐 Perfetto 统一入口。

### 2. atrace tracefs 路径发现

```cpp
// frameworks/native/cmds/atrace/atrace.cpp:1139-1158
bool findTraceFiles() {
    static const std::string debugfs_path = "/sys/kernel/debug/tracing/";
    static const std::string tracefs_path = "/sys/kernel/tracing/";
    static const std::string trace_file = "trace_marker";

    bool tracefs = access((tracefs_path + trace_file).c_str(), F_OK) != -1;
    bool debugfs = access((debugfs_path + trace_file).c_str(), F_OK) != -1;

    if (!tracefs && !debugfs) {
        fprintf(stderr, "Error: Did not find trace folder\n");
        return false;
    }

    g_traceFolder = tracefs ? tracefs_path : debugfs_path;
    return true;
}
```

Linux 4.1+（Android 7.0 起）优先 tracefs，回退 debugfs。

### 4. Perfetto 默认 buffer size（按 RAM 等级）

```cpp
// external/perfetto v57.1: src/traced/probes/ftrace/ftrace_config_muxer.cc:36-37
constexpr uint64_t kDefaultLowRamPerCpuBufferSizeKb  = 2 * (1ULL << 10);  // 2MB
constexpr uint64_t kDefaultHighRamPerCpuBufferSizeKb = 8 * (1ULL << 10);  // 8MB
constexpr uint64_t kHighMemBytes = 7 * (1ULL << 30);  // 7GB 判定高内存
```

低内存设备 < 7GB：2MB/CPU × 8 = 16MB；高内存设备：8MB/CPU × 8 = 64MB。多个 Perfetto session 共用同一 buffer 无法压缩。

## 版本差异

| Android 版本 | 内核 | FTrace 关键差异 |
|--------------|------|----------------|
| Android 12 | 5.10 | debugfs 路径 `/sys/kernel/debug/tracing/` 仍可用 |
| Android 13 | 5.15 | 引入 `sched_process_exit` / `task_rename` tracepoint |
| Android 14 | 6.1 | `atrace.cpp` 基线版本 |
| Android 15 | 6.6 | 引入 `rss_stat_throttled` |
| Android 16 | 6.12 | 引入 `suspend_resume_minimal` trigger |
| **Android 17（baseline）** | **6.18** | **buffer_percent poll mode（Linux 6.9+）；Perfetto v57.1 默认开启 compact_sched、atrace_userspace_only（v52）、buffer_size_lower_bound（v43）、drain_buffer_percent（v48）** |

注：Android 17 GKI 版本号为 `6.18`（非上游 mainline 6.18），源自 source.android.com 的 `android17-6.18 release builds` 列表。

## 性能影响

1. **Sampling overhead**：开启 `function` tracer 默认 kernel 性能下降 5-15%（实测 Pixel 6），`sched_switch` 仅 1-3%
2. **Ring buffer 内存**：低内存 2MB/CPU、高内存 8MB/CPU。多 Perfetto session 共享，total 不变
3. **Compact sched 收益**：sched_switch trace 文件大小下降 60-70%（典型 CPU 密集型负载从 800MB/30s → 280MB/30s）
4. **drain_buffer_percent**：避免一次性大 burst drain，使用水位线唤醒 reader task，平滑性能影响

## 实战使用（Android 17 GKI 6.18 + Perfetto v57.1）

### 启用方式

```bash
# 方式 1：纯 atrace（legacy，单 session）
adb shell atrace -a * -t 10 sched freq idle am wm gfx view binder_driver > /data/local/tmp/trace.html

# 方式 2：Perfetto（推荐，multi-session + 高级特性）
cat > /data/local/tmp/ftrace.cfg << EOF
buffers: {
  size_kb: 4096
  fill_policy: RING_BUFFER
}
data_sources: {
  config {
    name: "linux.ftrace"
    ftrace_config {
      ftrace_events: "sched/sched_switch"
      ftrace_events: "sched/sched_wakeup"
      ftrace_events: "sched/sched_waking"
      ftrace_events: "power/cpu_frequency"
      ftrace_events: "power/cpu_idle"
      atrace_categories: "gfx"
      atrace_categories: "view"
      atrace_categories: "wm"
      compact_sched { enabled: true }
      drain_buffer_percent: 50
    }
  }
}
duration_ms: 10000
EOF

adb shell perfetto --config /data/local/tmp/ftrace.cfg --out /data/local/tmp/trace.pftrace
adb pull /data/local/tmp/trace.pftrace
```

### Dynamic ftrace（生产 kernel 默认禁用）

```bash
# 检查是否可用
adb shell "cat /sys/kernel/tracing/available_tracers"
# 期望输出包含：function irqsoff preemptoff preemptirqsoff

adb shell "echo function > /sys/kernel/tracing/current_tracer"
adb shell "echo 1 > /sys/kernel/tracing/tracing_on"
# 跑测试...
adb shell "echo 0 > /sys/kernel/tracing/tracing_on"
adb shell "cat /sys/kernel/tracing/trace > /data/local/tmp/trace.txt"
```

`CONFIG_DYNAMIC_FTRACE` 在 production kernel 关闭，仅 userdebug/eng build 可用。

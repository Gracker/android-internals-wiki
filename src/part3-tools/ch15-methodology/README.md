# 第 15 章：方法论

这一章讨论的不是某一个具体系统模块，而是做性能问题时脑子里应该有的那套判断框架。

很多工程师不缺工具，也不缺零散知识，真正缺的是把问题接起来的那条线：  
看到异常之后先怎么看、怎样区分系统和 App、哪些指标真正值得盯、线上监控怎么进闭环、最后如何把这些事情变成团队机制。

如果说前面的章节更多在讲“系统是怎么工作的”，这一章更像在讲“工程师应该怎样用这些知识工作”。

## 本章内容

- 性能优化的术、道、器
- 如何区分系统问题和 App 问题
- 性能指标体系
- 竞品分析方法
- 线上性能监控
- 性能测试最佳实践
- AOSP 代码阅读
- 从采集到治理的反馈回路
- 性能治理工程化

## 阅读建议

- 如果你已经会看 trace，但总觉得结论不稳，优先看 `15.1`、`15.2`、`15.3`。
- 如果你主要在做线上治理，`15.5`、`15.9`、`15.10` 更值得连着读。
- 如果你想把个人经验变成团队流程，这一章后半部分最有用。

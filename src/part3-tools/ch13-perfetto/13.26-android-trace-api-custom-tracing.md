# 13.26 android.os.Trace API 深度解析与应用级自定义追踪

<!-- outline-start -->
## 要点

### 🔹 Trace API 演进与版本差异
- `android.os.Trace` 的历史：从 Systrace（API 18）到 Perfetto（API 23+）
- `beginSection()` / `endSection()`：同步区域标记，必须在同一线程调用
- `beginAsyncSection()` / `endAsyncSection()`：异步区域标记，可跨线程配对（API 18+）
- `setCounter()` / `setAppTracingAllowed()`：计数器与应用级 tracing 开关
- Android 17 新增：`Trace.beginAsyncSection` 的可重入支持与 Perfetto 深度集成

### 🔹 Trace 底层实现机制
- `Trace` 类通过 `__system_property_get` 检查 `debug.atrace.app_number` 等属性
- 写入路径：`write()` → atrace_dump tracing marker fd → `/sys/kernel/tracing/trace_marker`
- `ATRACE_TAG` 的作用：分类标签，决定 trace 中显示的颜色与过滤
- 与 Perfetto 的数据流关系：Trace API → tracing marker → Perfetto buf → flush to .perfetto-trace

### 🔹 应用层 Trace 最佳实践
- 关键业务流程的 Trace 埋点策略（首屏渲染、Feed 加载、支付链路）
- 避免高频 beginSection（>1ms 频率会产生自身开销）
- 使用 `Trace.setAppTracingAllowed(false)` 在敏感时段关闭 tracing
- Compose Recomposition 与 Trace 的联动：`Recomposer.Trace` 机制

### 🔹 Perfetto SDK vs android.os.Trace
- Perfetto SDK（androidx.tracing.perfetto）：Java/Kotlin 层自定义 Perfetto 数据源
- `android.os.Trace`：系统级 tracing marker，兼容性最广
- 性能开销对比与选型建议

### 🔹 Trace 与 Systrace/Perfetto 查询的配合
- 自定义 section name 在 Perfetto SQL 查询中的使用
- `slice` 表中通过 `name LIKE 'MyTag:*'` 过滤自定义追踪区域
- 延迟分布统计：从 slice 表计算 P50/P90/P99

### 🔹 常见陷阱与性能影响
- begin/end 不匹配导致 trace 区域混乱
- section name 过长（>127 字节）被截断
- 高频 tracing 导致 trace buffer 溢出
- 多线程环境下 async section 的 name 冲突

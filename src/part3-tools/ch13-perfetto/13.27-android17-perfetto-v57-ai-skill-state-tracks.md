# 13.27 Android 17 Perfetto v57 AI 技能与状态轨道

> 13.21 节梳理了 Perfetto 从 v1 到 v56 的版本演进时间线。本节聚焦 v57——这个版本在 Perfetto 历史上第一次引入了原生 AI 能力和状态轨道，对 Android 性能分析工作流产生了实质性影响。

## Perfetto v57 发布背景

Perfetto v57 原计划为 v57.0，但由于 AI skill 安装路径的问题在发布前被发现，最终以 **v57.1** 补丁版本形式于 2026 年 7 月 2 日正式发布。v57.0 从未公开发布。

[已验证: 官方文档, https://github.com/google/perfetto/releases/tag/v57.1]

v57 的定位不是一个增量更新版本——它引入了三个结构性变化：

1. **AI Skill 原生集成**：Perfetto 第一次以"技能"形式向 AI 编码代理输出 trace 分析能力
2. **状态轨道（State Tracks）**：继 slice 和 counter 之后的第三个一等公民轨道类型
3. **跨平台日志统一**：systemd journald 日志进入 Perfetto 采集范围

这三个变化共同指向一个方向：Perfetto 正在从"人读 trace"向"机器读 trace + 人读结果"演进。

## AI Skill：Perfetto 的 AI 代理接口

### 设计目标

Perfetto v57 附带了一个可安装的 **AI skill**，它教编码代理（coding agent）如何录制、查询和分析 trace。这不是在 Perfetto UI 里嵌入一个聊天框——而是一个遵循 Agent Skills 规范的独立技能包，兼容 Claude Code、OpenAI Codex、Gemini CLI、OpenCode 等主流 AI 编码工具。

[已验证: 官方文档, https://github.com/google/perfetto/releases/tag/v57.1]

技能包内置了一个可工作的 `trace_processor` 实例，AI 代理通过它可以执行 SQL 查询并获取结构化结果。这意味着 AI 代理不需要自己解析 trace 二进制格式——它通过 SQL 语义与 trace 数据交互。

### 安装方式

```bash
# Claude Code
/plugin marketplace add google/perfetto@ai-agents

# Codex
codex plugin marketplace add google/perfetto --ref ai-agents

# 其他代理（OpenCode / Antigravity / Pi）
curl -fsSL https://get.perfetto.dev/agents-install | python3 - --agent <opencode|antigravity|pi>
```

[已验证: 官方文档, https://perfetto.dev/docs/getting-started/using-ai]

### 工作流模型

AI skill 的核心设计是"引导式工作流"（guided workflows）。发布说明中描述的流程是：

1. **AI 读取**：技能包向 AI 代理提供 Perfetto 的数据模型文档、SQL 语法参考和常见分析模式
2. **SQL 查询**：AI 代理通过内置的 `trace_processor` 执行 SQL，获取结构化中间结果
3. **结果解读**：AI 代理根据查询结果和上下文，生成人类可读的分析报告

这个"读文档 → 写 SQL → 解读结果"的闭环，使得 AI 代理能够完成从原始 trace 到性能诊断报告的完整链路，而不需要人工编写 SQL。

[已验证: 官方文档, release notes 描述 "guided workflows for common investigations"]

> ⚠️ 原始大纲中提到"6 个内存工作流"（内存分配追踪、GC 优化、内存泄漏检测、内存压力预警），但 v57.1 发布说明并未枚举具体工作流数量和名称。发布说明只说"guided workflows for common investigations"。具体工作流清单随技能包 YAML 定义动态加载，可能随版本变化。
> [待验证: 技能包 YAML 中的具体工作流定义，需安装后查看 skill 目录]

## 状态轨道（State Tracks）：第三种轨道类型

### 为什么需要状态轨道

在 v57 之前，Perfetto 有两种核心轨道类型来表达时序数据：

- **Slice**（TYPE_SLICE_BEGIN = 1 / TYPE_SLICE_END = 2）：有起止时间和嵌套关系，适合表达函数调用、动画帧等
- **Counter**（TYPE_COUNTER = 4）：有时间戳和数值，适合表达 CPU 频率、内存用量等连续变化量

但有一类数据不适合用这两种类型表达：**系统状态**。比如播放器的状态在"缓冲中"、"播放中"、"暂停"之间切换——这不是一个数值（counter 难以自然表达），也不需要嵌套（slice 过重）。状态轨道正是为这类数据设计的。

[已验证: AOSP proto, protos/perfetto/trace/track_event/track_event.proto (v57.1 tag)]

### TYPE_STATE = 5

在 `track_event.proto` 的 `Type` 枚举中，v57 新增了：

```protobuf
enum Type {
    TYPE_UNSPECIFIED = 0;
    TYPE_SLICE_BEGIN = 1;
    TYPE_SLICE_END = 2;
    TYPE_INSTANT = 3;
    TYPE_COUNTER = 4;
    TYPE_STATE = 5;  // v57 新增
}
```

官方注释将状态轨道描述为"符号化的 counter"——counter 用数字表达连续变化，state 用字符串表达离散状态切换。每个状态轨道在任意时刻只有一个当前值；新事件将状态切换到新值；空值或未设置表示"空闲"（idle）。

[已验证: AOSP proto, protos/perfetto/trace/track_event/track_event.proto v57.1 tag, TYPE_STATE 注释引用 RFC-0023]

### StateDescriptor

状态轨道通过 `StateDescriptor` proto 消息标识。在 v57.1 中，该消息体为空——它的作用是占用一个类型槽位，使 `TrackDescriptor` 中的 `state` 字段能将轨道标识为状态类型。设计上预留了扩展空间。

```protobuf
// Descriptor for a state track.
message StateDescriptor {
  // For now, this message is empty. It is used to identify a track as a state
  // track.
}
```

[已验证: AOSP proto, protos/perfetto/trace/track_event/state_descriptor.proto v57.1 tag]

### SDK 支持

三种 SDK 均支持状态轨道：

**C++ SDK：**
```cpp
perfetto::StateTrack track("Player state");
TRACE_STATE("player", "Buffering", track);
```

**C SDK（高层 API）：**
```c
PERFETTO_TE(player, PERFETTO_TE_STATE("Buffering"),
            PERFETTO_TE_REGISTERED_TRACK(&player_state_track));
```

**Android Java SDK：** 同样提供了状态轨道 API（通过 `PerfettoTrack` 构建状态事件）。

[已验证: 官方文档, Perfetto v57.1 release notes]

### Trace Processor 与 UI

Trace Processor 将状态事件摄入新的 **`state` SQL 表**，UI 原生渲染状态轨道并提供专属详情面板。这意味着开发者可以用标准 SQL 查询状态转换：

```sql
-- 查询状态停留时长
SELECT
  track_id,
  state,
  ts,
  LEAD(ts) OVER (PARTITION BY track_id ORDER BY ts) - ts AS duration
FROM state
ORDER BY track_id, ts;
```

[已验证: 官方文档, "Trace Processor ingests state events into a new state SQL table"]
[待验证: state 表的具体 schema（列名、类型），需查阅 v57.1 trace_processor docs]

## 其他 v57 改进

### systemd journald 日志

v57 新增 `linux.systemd_journald` 数据源，支持在 trace 采集时录制 journald 条目。Trace Processor 将其存储到统一日志表中（与 Android logcat 共享表结构），通过新的 `log_source` 列区分来源。UI 提供了 JournaldLog 插件来展示和过滤这些日志。

这对 Linux/Chrome OS 平台的性能分析很有价值，但与 Android 设备的直接关联较小。

[已验证: 官方文档, Perfetto v57.1 release notes]

> 注：Android 平台使用 logcat 而非 journald，此特性主要面向 Linux/Chrome OS 场景。

### JSON Trace 重叠事件修复

v57 修复了一个长期存在的问题：JSON 格式（Chrome Trace Event Format）中的重叠 `"ph": "X"`（complete）事件此前会被静默丢弃。这对 **PyTorch profiler** 用户影响最大——许多 PyTorch 生成的 trace 包含重叠事件，导致大量 slice 在 timeline 和 SQL 中不可见。

修复后，重叠事件被摄入到溢出轨道（overflow tracks）中，UI 会将其合并回单个线程轨道。

[已验证: 官方文档, GitHub issue #4280]

### 查询结果网格升级

UI 中的查询结果网格进行了大幅重构：支持列排序、列重排、列隐藏；侧边栏可折叠；SQL 错误直接在网格中展示。

[已验证: 官方文档, Perfetto v57.1 release notes]

### heapprofd 通配符匹配

`heapprofd` 的 `process_cmdline` 新增部分通配符匹配支持（如 `system_*` 或 `/system/bin/*`），与 perf 采样和 Java heap dump 数据源的行为对齐。通配符仅匹配已在运行的进程，因此配置使用通配符时必须设置 `no_startup = true`。

[已验证: 官方文档, Perfetto v57.1 release notes]

### SDK 新增：嵌套轨道与关联 ID

- **嵌套轨道（Nested Tracks）**：C SDK 高层 API 和 Android Java SDK 支持多级轨道层次结构，可控制兄弟轨道的排序和 UI 合并方式
- **关联 ID（Correlation IDs）**：标记属于同一逻辑操作但不暗示因果关系的事件（因果链用 flow 表达），通过 `PERFETTO_TE_CORRELATION_ID()` / `setCorrelationId()` 使用

[已验证: 官方文档, Perfetto v57.1 release notes]

### Trace Processor 增强

- 支持直接从 URL 和 ui.perfetto.dev 永久链接加载 trace
- Track descriptor 支持显式线程和进程排序
- Adreno GPU `adreno_cmdbatch_retired` 和 `adreno_cmdbatch_sync` ftrace 事件被解析为 GPU timeline slice
- Python 包默认使用与包版本绑定的 `trace_processor` 二进制，而非运行时下载最新版

[已验证: 官方文档, Perfetto v57.1 release notes]

## 对 Android 性能分析的影响

### 状态轨道的应用场景

状态轨道在 Android 性能分析中有几个直接应用：

1. **播放器状态追踪**：音视频应用的播放/暂停/缓冲状态切换，可以直接用 state track 标记，配合 counter 轨道（如 CPU 使用率）做关联分析
2. **电源状态追踪**：Doze/Standby/Awake 等电源状态的切换
3. **网络状态追踪**：WiFi/Cellular/None 等网络连接状态
4. **应用生命周期状态**：Foreground/Background/Cached 等进程状态

此前这些状态需要用 slice 或 instant 间接表达，缺乏"当前值"语义。状态轨道的"恰好一个当前值"模型更自然。

### AI Skill 对工作流的影响

AI skill 的引入意味着性能分析不再必须是"打开 UI → 肉眼看 → 手写 SQL"的流程。开发者可以让 AI 代理自动完成：

- 加载 trace 文件
- 执行预定义的 SQL 查询模板
- 解读结果并给出诊断建议

但需要注意：AI skill 的能力边界取决于技能包中定义的工作流覆盖范围。对于非标准化的、复杂的性能问题，仍然需要人工深度参与分析。

> 🔸 详见 13.18 节（SmartPerfetto 与可复用 Trace 分析平台）了解第三方 AI trace 分析方案的设计思路。

## 版本可用性

| 平台 | Perfetto 版本 | 状态 |
|------|--------------|------|
| Android 14 (API 34) | 可通过 Perfetto SDK 集成 | 需自行引入 v57 SDK |
| Android 15 (API 35) | 系统内置 Perfetto ≈ v40-v45 | 不含 v57 特性 |
| Android 16 (API 36) | 系统内置 Perfetto ≈ v48-v52 | 不含 v57 特性 |
| Android 17 (API 37) | 系统内置 Perfetto ≈ v54+ | 状态轨道和 AI skill 需 SDK 集成或独立安装 |

> ⚠️ Perfetto 的版本与 Android 大版本不是一一对应。系统内置的 Perfetto 版本通常落后于最新发布版本。要使用 v57 的全部特性（特别是 AI skill 和 state tracks），建议通过 Perfetto SDK 在应用内集成，或独立安装最新版 `trace_processor`。

[待验证: Android 17 系统内置 Perfetto 的确切版本号，需查阅 AOSP android-17.0.0_r1 external/perfetto]

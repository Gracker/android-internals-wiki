## 本页为何停止维护正文

这份文件不在 `src/SUMMARY.md` 的阅读路径中，主题又与 §8.39 和 §26.24 重复。旧稿由自动任务生成，包含大量无法从 Android 17 源码支持的接口。继续局部修补会留下第三套 heapprofd 权限与部署规则，平台升级后很容易出现互相冲突的结论。

旧稿中的下列内容已经移除：

- `<heapprofd_config>`、`<mode>continuous</mode>`、`retention_days` 等 XML 配置；Android 17 使用 Perfetto `HeapprofdConfig` protobuf。
- `heapprofd-monitor`、应用内 `HeapprofdService` 和自动重启编排；AOSP init 定义的是按需启动的 `/system/bin/heapprofd`。
- 为应用声明 `INTERNET`、`DUMP`、`PACKAGE_USAGE_STATS` 来获得 heapprofd 能力；目标资格由 build type、`<profileable>`、session initiator、UID 和 SELinux 共同判定。
- CPU 超过 80% 自动降采样、泄漏自动告警、网络重传、设备群管理、10 GB 留存等功能；AOSP heapprofd 没有这些产品层策略。
- 允许 heapprofd 任意读取 `app_data_file`、连接 system_server/SurfaceFlinger/mediaserver 的示例 SELinux 规则；这些规则不属于 Android 17 AOSP 策略。

## Android 17 可以确认的最小事实

1. `heapprofd` 是 Perfetto producer，用抽样分配事件与调用栈描述采集窗口内的 heap 行为；它不是常驻泄漏告警服务。
2. `/system/bin/heapprofd` 由 `external/perfetto/heapprofd.rc` 声明为 disabled service，按 Perfetto 会话需要启动。
3. 配置来自 `HeapprofdConfig` protobuf，关键字段包括目标进程、采样间隔、共享内存、startup/running attach 与 continuous dump。
4. user build 的可采范围受目标应用属性、UID、session initiator、packages.list 与 SELinux 约束。
5. trace 采集、企业上传、数据留存和告警属于不同层。AOSP heapprofd 不自动提供企业采集后台。

历史链接可以继续指向本页，但新增内容和事实修正应写入上述规范章节。这样能保留 Hermes/OpenClaw 的文件识别路径，同时避免同一主题出现三套配置。

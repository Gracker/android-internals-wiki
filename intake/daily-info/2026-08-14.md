- **来源**：Gracker RSS 订阅（OpenJDK HotSpot GC maintainer Thomas Schatzl 个人 blog，HN best #20）
- **时间**：2026-08-14 03:08
- **链接**：https://tschatzl.github.io/2026/08/10/jdk27-g1-serial-parallel-gc-changes.html
- **摘要**：JDK 27 一共 ~350 个 GC 子系统变更，约 50% 是 refactor（用 `Atomic<T>` 替代 `volatile + AtomicAccess`、G1 state machine 清理、JEP 401 value object 适配），~35% 是 bug fix。行为变更重点：JEP 523 让 G1 成为所有环境的默认 collector（无 Serial GC 例外，仅 OpenJDK 未编进 G1 时降级）；Full GC 后不再按 `MinHeapFreeRatio`/`MaxHeapFreeRatio`（默认改 0/100）反向缩堆，避免与 CPU-based sizing 互掐；adaptive start of concurrent marking 加固；humongous 对象被弱引用误保活的两个 bug 修了。ART 团队跟进方向：ART runtime 升级到 JDK 27 基线时，Full GC 反向缩堆的语义变化最值得评估，巨型对象 reclaim 修复也直接利好 Bitmap/LargeBuffer 类业务。

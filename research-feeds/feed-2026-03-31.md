### F1: Compose 性能达到 View 系统对等（2025.12 里程碑）

**来源级别**: L2（Google 官方博客）
**核心发现**: 
- Jetpack Compose BOM 2025.12.00（核心模块 1.10）正式宣布在 Google 内部滚动基准测试中达到与 View 系统的性能对等
- 长列表滚动 jank 降至 0.2%，消除 Compose 采用的最后一道技术障碍
- 三大关键优化促成：(1) Pausable Composition 默认启用 (2) Strong Skipping Kotlin 2.0.20+ 默认 (3) Lazy Layout CacheWindow API
- 额外优化：后台线程预取文本（Compose 1.9+）、Draggable/Clickable 响应时间改善、Modifier 布局矩形跟踪优化

**性能影响量化**:
| 优化项 | 效果 |
|--------|------|
| Strong Skipping | 放宽跳过规则，unstable 参数也允许 skip |
| Pausable Composition | 帧预算不足时暂停 composition，下一帧续做 |
| Lazy CacheWindow | 可自定义保留项数，提前做更多工作 |
| Text Prefetch | 文本布局移至后台线程 |

**对 Wiki 8.6/7.7 的意义**: 这是最重要的年度级发现，直接可以作为"Compose 性能优化"章节的锚点事实。

### F2: Strong Skipping 模式深入解析

**来源级别**: L2（Android Developers 官方文档）
**核心发现**:
- **Kotlin 2.0.20+ 默认启用**，无需手动配置
- 核心机制：所有 restartable composable 函数变为 skippable，无论参数是否 stable
- **参数比较策略**: unstable 参数用实例相等（`===`），stable 参数用对象相等（`Object.equals()`）
- **Lambda 自动记忆化**: 捕获了 unstable 变量的 lambda 也会被自动 remember
- 消除了一类"神秘重组"问题——之前开发者需要手动用 `remember` 包裹 lambda

**代码示例**（更新前后对比）:
```kotlin
// Before Strong Skipping: 每次 recomposition 创建新 lambda → 不跳过
@Composable
fun MyScreen(list: List<String>) {  // List<String> 是 unstable
    LazyColumn {
        items(list) { item ->
            Text(item)
        }
    }
}

// After Strong Skipping (Kotlin 2.0.20+): lambda 自动 memoize → 可跳过
// 无需额外代码！编译器自动处理
```

**对 Wiki 的意义**: 8.6 节应明确说明此模式已成为默认，并指出旧版本需手动启用的方式。

### F3: androidx.tracing 2.0 — Coroutine 性能追踪新纪元

**来源级别**: L1（AOSP androidx.tracing 2.0.0-alpha01+）
**核心发现**:
- `androidx.tracing:tracing:2.0.0-alpha01` 引入低开销 Kotlin trace API
- **关键特性**: 自动协程上下文传播（Context Propagation），在 Perfetto 中可视化协程执行流
- **跨线程追踪**: 解决了传统线程模型工具无法追踪协程跨挂起点恢复的问题
- Perfetto 使用"flows"表示协程执行流，alpha04（2026-03-25）改进了 fan-out 场景可视化
- alpha03 修复了协程 suspend/resume 事件的竞态条件

**使用方式**:
```kotlin
// 新 API 支持给 slice 打 metadata 标签
Trace.beginSlice("myOperation", { "arg1" to value1 })
// ... 协程工作
Trace.endSlice()
```

**与 Perfetto 集成**: 可将系统 trace 和应用内 trace 合并，在 Perfetto UI 中统一时间线展示

**对 Wiki 的意义**: 8.6 节应增加"协程性能追踪"子节，介绍此 API 与 Perfetto 的配合使用。

### F4: Compose 重组优化的最佳实践演进

**来源级别**: L2（Android Developers 官方 + Google I/O 演讲）
**核心发现**:
- **derivedStateOf**: 限制重组范围——只在派生状态真正变化时触发，而非底层状态每次更新都触发
- **延迟状态读取**: 用 lambda 包裹状态读取推迟到布局/绘制阶段，跳过 composition 阶段
- **Lambda-based Modifiers**: `Modifier.offset { }` / `Modifier.drawBehind { }` 在 layout/draw 阶段读取状态
- **Lazy Layout Key**: 必须提供稳定唯一 key，帮助 Compose 在数据集变化时高效复用
- **Predictive Prefetching**: LazyColumn/LazyRow 根据滚动速度预测性预组合 item，在空闲帧分发工作

**对 Wiki 7.7 节的意义**: 提供具体的优化手段分类和代码示例，按影响程度排序。

### F5: Kotlin 协程 2.2+ 新特性展望

**来源级别**: L2（Kotlin 官方）
**核心发现**:
- **Rich Errors**: Kotlin 2.2+ 引入更类型安全的错误处理方式，超越 `Result<T>` 和 nullable
- **改进的调试体验**: IntelliJ / Android Studio 中协程调试增强——更好的局部变量可见性和完整异常堆栈
- **Dispatcher 注入**: 最佳实践——不硬编码 `Dispatchers`，而是注入以便测试
- **withContext 优化**: Kotlin 优化了 Default 和 IO 之间的切换，避免不必要的线程切换

**对 Wiki 8.6 节的意义**: 补充协程版本演进对性能的影响，特别是 2.2 的 Rich Errors 和调试改进。
